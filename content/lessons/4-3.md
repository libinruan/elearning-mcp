## Summary
When a server misbehaves inside Claude Desktop you see almost nothing: a missing connector, a silent tool failure. The fix is to take the host out of the loop. The official **MCP Inspector** ships one package with three clients: a web UI for exploring, a CLI for scripts and CI (with stable exit codes), and a TUI for terminals, plus the experimental `mcpdo`, which keeps connections open. Because 2026-07-28 changed so much, the Inspector treats the **protocol era** (legacy vs modern) as a per-server setting. This lesson covers those tools, the official debugging guide (stderr logging, Claude Desktop logs, working directory, environment variables, `server/discover` and `-32022`), and a test strategy: in-memory clients, contract tests on schemas, golden wire tests and a debugging walkthrough of a deliberately broken server.

## Lesson
### Take the host out of the loop
The debugging guide lists three levels of tooling: the **MCP Inspector** ("your first stop"), **server logging** (structured logs to stderr on stdio, or OpenTelemetry on any transport), and **client developer tools** such as Claude Desktop's logs. The Inspector recipes describe a loop that works well in practice:

1. **Start with the CLI.** `--method initialize` confirms the server starts, connects and reports the capabilities you expect, in about a second. "Most 'it doesn't work' turns out to be here."
2. **Explore in the web client.** Schema-driven forms, rendered results and the Protocol tab side by side.
3. **Test the edges.** Invalid inputs, missing prompt arguments, concurrent calls and, for HTTP servers, **both protocol eras**. "Verify the *errors* are as intentional as the successes."
4. **Lock it in with the CLI.** Turn findings into CI assertions (`--format json | jq -e`, with `--stored-auth-only`).

### One package, three clients (and mcpdo)
`@modelcontextprotocol/inspector` needs **Node 22.19.0+** and runs via `npx` with no install:

| Client | Invocation | For |
| --- | --- | --- |
| Web | `npx @modelcontextprotocol/inspector [server command]` | the richest UI; the default mode |
| CLI | `npx @modelcontextprotocol/inspector --cli … --method tools/list` | scripts, CI, coding agents; one request per run |
| TUI | `npx @modelcontextprotocol/inspector --tui …` | terminals and SSH; needs a real TTY |
| `mcpdo` | `npx -p @modelcontextprotocol/inspector mcpdo …` | experimental; connect once, run many commands |

All of them share one core: the same transports, configuration files, OAuth state on disk and protocol-era negotiation. A few launcher rules trip people up:

- The binary is a thin launcher that owns only the **mode flag** (`--web`/`--cli`/`--tui`, at most one, recognised only at the front of the command line) and `-h`.
- Everything else belongs to the client. Pass a stdio server's environment and working directory with `-e KEY=VALUE` and `--cwd`.
- The **`--` separator** splits differently by client. For web and TUI, what follows `--` goes to *your server*. For the CLI, what precedes `--` is the target and what follows is the Inspector's own options.
- Servers can come from a positional command (stdio), `--server-url` + `--transport http|sse`, or a file. `--catalog` is writable (default `~/.mcp-inspector/mcp.json`). `--config` is read-only, which is ideal for pointing at `claude_desktop_config.json` without touching it. Catalog entries use the familiar `mcpServers` shape plus Inspector fields such as `protocolEra` and `modernLogLevel`.

> **Pitfall.** The Inspector stores secrets (OAuth tokens, client secrets, stdio `env:` values) in the OS keychain. On machines without one (headless Linux, SSH, containers) they go to `~/.mcp-inspector/secrets.json`, **unencrypted unless you supply a key**.

### Protocol eras: legacy, auto, modern
2026-07-28 changed enough that the Inspector makes the era a first-class, per-server setting, orthogonal to transport:

| Era | At connect |
| --- | --- |
| `legacy` (**default**) | plain `initialize`, no probing |
| `auto` | probe `server/discover`, fall back to `initialize` on any non-modern outcome |
| `modern` | pin exactly `2026-07-28`; no fallback, so a non-modern server fails loudly |

Why is `legacy` the default? "A debugging tool must not auto-probe." A `server/discover` probe stalls against silent legacy stdio servers and pollutes the transcript you came to read. So to test 2026-07-28 behaviour you must opt in (`--protocol-era modern`). The official build guide tells you to run `tools/list` in **both** eras. What differs:

| Feature | Legacy | Modern (2026-07-28) |
| --- | --- | --- |
| Logging | session-wide `logging/setLevel` | per-request `_meta["io.modelcontextprotocol/logLevel"]`; no stamp, no logs ("silence is correct behavior") |
| Resource subscriptions | `resources/subscribe` | `subscriptions/listen` stream, acknowledged by `notifications/subscriptions/acknowledged` |
| Tasks | `capabilities.tasks`, `tasks/list`, blocking `tasks/result` | the `io.modelcontextprotocol/tasks` extension, poll `tasks/get`, result inlined |
| Server→client questions | `elicitation/create` request | multi round-trip: `input_required` result, then retry under a new id |
| Cancellation | `notifications/cancelled` | close the request's SSE stream (HTTP); stdio still uses `notifications/cancelled` |
| Sessions | optional `Mcp-Session-Id`, `DELETE` on disconnect | sessionless; disconnect is purely local |

On modern connections the Inspector also highlights mirrored `Mcp-Param-*` headers (`x-mcp-header`), lists tools a conforming client must **exclude** for invalid header annotations, and renders the error taxonomy distinctly. That covers `-32020` (header mismatch), `-32021` (missing client capability), `-32022` (unsupported version, with `data.supported`) and `-32601` (method not found), and it tells "Unknown Tool" and "Invalid Parameters" apart even though both use `-32602`.

### The web client
The command prints a URL with a **per-launch API token**. Open that URL rather than typing `localhost:6274`, because the backend spawns processes and every `/api/*` call needs the token. It binds `127.0.0.1` by default and refuses wildcard binds without `DANGEROUSLY_BIND_ALL_INTERFACES=true`. Never combine that with `DANGEROUSLY_OMIT_AUTH`. Tabs appear according to the server's capabilities: **Tools**, **Resources**, **Prompts**, **Apps**, **Skills**, **Tasks** and **Logs**. Three monitor tabs show the same traffic at different depths:

- **Protocol**: the JSON-RPC transcript, with requests paired to responses and MRTR rounds grouped.
- **Network**: raw HTTP status, headers and bodies (HTTP/SSE only).
- **Console**: a stdio server's **stderr**. Check here first "when a connection fails for no visible reason".

**Server Settings** holds the era, the per-request log level, which extensions to advertise (a server may register different tools depending on them), roots, headers, timeouts, OAuth and one-page-at-a-time pagination.

### The CLI: scripts, CI and exit codes
Each run connects, sends the single request named by `--method`, prints the result and exits. The methods are `initialize`, `tools/list`, `tools/call` (`--tool-name`, `--tool-arg k=v` or `--tool-args-json`), `resources/list|read|templates/list`, `prompts/list|get`, `logging/setLevel` (legacy only), `skills/list|get` and catalog management (`servers/*`). `--tool-arg` JSON-parses each value (`count=1` sends a number), then coerces strings to the schema type. `--tool-args-json` sends the object as given. `--format json` prints one clean JSON object for `jq`.

| Exit | Meaning |
| --- | --- |
| `0` | success |
| `1` | usage/unexpected error |
| `2` | no MCP App on the tool (`--app-info`) |
| `3` | authentication required (401/403) |
| `4` | server unreachable |
| `5` | tool error: `isError: true` or tool not found |
| `6` | `--strict` found an error-severity tool-schema portability problem |
| `7`/`8`/`9` | skills `--verify` failures |

On any non-zero exit the CLI writes **one JSON line to stderr** (`{"error": {"code": "auth_required", "message": …}}`) with stable codes like `unreachable`, `tool_not_found`, `tool_is_error` and `schema_unportable`. A `tools/call` returning `isError: true` still prints its payload but exits `5`, so `&&` chains stop. For CI, add `--stored-auth-only` (never start interactive OAuth) and `--strict` on `tools/list`:

```bash
set -euo pipefail
mcp-inspector --cli --config ./ci-servers.json --server my-server \
  --stored-auth-only --method tools/list --format json \
  | jq -e '.result.tools | map(.name) | index("get_weather")' > /dev/null
mcp-inspector --cli --config ./ci-servers.json --server my-server --method tools/list --strict > /dev/null
```

### The TUI and mcpdo
The **TUI** offers the web client's exploration in a terminal, with one-key tabs: `t` Tools, `r` Resources, `m` Prompts, `p` Protocol, `o` Console, `n` Network, `c` to connect, `?` for help. It needs a real TTY, so use the CLI in CI. **`mcpdo`** keeps named connections in a background daemon (`mcpdod`): `mcpdo connect my-server`, `mcpdo @my-server tools/call echo message:=hi`, `mcpdo disconnect my-server`. It suits multi-step flows (tasks, subscriptions, elicitation) and coding agents. From a non-TTY an unqualified command is an error, so a script never acts on "whichever server you last used". To contain an untrusted stdio server, make its command a container: `mcpdo connect @sandboxed -- docker run -i --rm --network none …`.

### Logs: where to look
- **Your server.** On stdio, log to **stderr**, which hosts capture automatically. Never log to stdout. On HTTP the client does not capture stderr, so use your own log aggregation or **OpenTelemetry**, plus curl or browser DevTools for requests and SSE streams. Log startup steps, resource access, tool execution, errors and timings, with request ids. Sanitize credentials and personal data.
- **Protocol logging** (`notifications/message`) is **deprecated** in 2026-07-28 and only sent for requests carrying `io.modelcontextprotocol/logLevel`.
- **Claude Desktop.** `~/Library/Logs/Claude` (macOS), `%APPDATA%\Claude\logs` (Windows), `~/.config/Claude/logs/` (Linux, per the build guide). `mcp.log` holds connection events. `mcp-server-NAME.log` holds that server's stderr. Run `tail -n 20 -F ~/Library/Logs/Claude/mcp*.log`. For client-side errors, enable DevTools with `{"allowDevTools": true}` in `developer_settings.json` and press Cmd-Option-I (Ctrl+Alt+I on Windows).

### Common issues from the debugging guide
- **Working directory.** A host may launch your server with an undefined working directory (`/` on macOS). Use **absolute paths** in the config and in `.env` files, and resolve data files relative to your code, not `cwd`.
- **Environment variables.** Stdio servers inherit only a limited, platform-dependent subset. Add an `env` map to the server entry.
- **Startup.** Path problems (wrong executable, missing files, permissions; try an absolute `command`), configuration errors (invalid JSON, missing fields, type mismatches) and environment problems.
- **Connection problems.** Check the client logs, check the process is running, test standalone with the Inspector, then check protocol compatibility. Call `server/discover` to see `supportedVersions`. An `UnsupportedProtocolVersionError` (**`-32022`**) lists them in `data`. A request missing `io.modelcontextprotocol/protocolVersion` or `clientCapabilities` in `_meta` gets **`-32602`**, and a missing required client capability gets **`-32021`**.
- **Applying changes.** Restart the client after config *and* server code changes. For Claude Desktop that means a full quit. Use the Inspector for quick iteration.

### Automated tests: a practical strategy
The docs give you tools; the test pyramid is **[practice]**, and it works well with the Python SDK:

1. **In-memory unit tests.** `async with Client(server)` runs the real protocol handlers in-process, with no subprocess and no ports, so tests are fast and deterministic. Assert on `structured_content`, `is_error` and the text the model will read. With pytest, mark async tests `@pytest.mark.anyio` (anyio ships the plugin).
2. **Contract tests on definitions.** Snapshot the normalized `tools/list` (names, schemas, annotations) into a golden file and fail on any diff. A renamed parameter breaks every prompt and client that depended on it, so changes should be deliberate and reviewed.
3. **Golden wire tests.** Store representative results dumped exactly as on the wire (`model_dump(by_alias=True, exclude_none=True, mode="json")`). Strip volatile fields (ids, timestamps, `_meta`) before comparing.
4. **Transport smoke tests.** Launch the real entry point over stdio (and HTTP) once, to catch import-time crashes, stdout pollution, missing env vars and path bugs that in-memory tests cannot see.
5. **Error-path tests.** Assert that bad inputs produce `isError: true` with actionable text, not crashes.
6. **CI gate.** Add the Inspector CLI (`--strict`, exit codes) as a black-box check against the built artifact.

The Python SDK's `mcp dev server.py` (from `mcp[cli]`) launches your server under the Inspector during development.

## Key points
- The **MCP Inspector** is one npm package (Node 22.19.0+) with **web**, **CLI** and **TUI** clients on a shared core, plus the experimental **`mcpdo`** for persistent connections.
- **Protocol era** is per server: `legacy` (the default, no probe), `auto` (probe `server/discover`, then fall back) and `modern` (pin 2026-07-28). Test servers in **both** eras.
- CLI exit codes are stable: `3` auth, `4` unreachable, `5` tool error or not found, `6` `--strict` schema problem. Failures also print a one-line JSON error envelope on stderr.
- Web client: open the printed URL with its **per-launch token**. **Protocol** shows JSON-RPC, **Network** shows HTTP, and **Console** shows a stdio server's stderr.
- Stdio servers log to **stderr**, which hosts capture (Claude Desktop: `mcp.log` plus `mcp-server-NAME.log`). HTTP servers need their own logs or OpenTelemetry.
- Classic failures: relative paths (the working directory may be `/`), missing env vars (limited inheritance, so use `env`), invalid config JSON, and stdout pollution.
- Version and envelope problems surface as `-32022` (with `data.supported`), `-32602` (missing `_meta` fields) and `-32021` (missing client capability).
- Test pyramid: in-memory `Client(server)` tests, **contract snapshots** of `tools/list`, **golden wire** results, a stdio smoke test, and the Inspector CLI in CI.

## Pitches
### How do you debug an MCP server?
I take the host out of the loop. First the Inspector CLI with method initialize or tools/list, which tells me in a second whether the server starts and what it advertises, and in which protocol era. Then the web Inspector to call tools by hand while watching the Protocol and Console tabs. If it only fails inside Claude Desktop, I read mcp.log and the server's own stderr log, and I check absolute paths, environment variables and stray prints to stdout.

### Why does the Inspector default to the legacy protocol era?
Because a debugging tool shouldn't change what it observes. Probing server/discover first can stall against an older stdio server that ignores unknown methods, and it adds noise to the transcript I'm trying to read. So legacy means a plain initialize, auto probes and falls back, and modern pins 2026-07-28 and fails loudly. In practice I run my checks in both eras, because real clients are on both sides of that line.

### How do you test an MCP server automatically?
Mostly in-process: the Python SDK's Client can connect straight to the server object, so pytest exercises the real handlers with no ports or subprocesses. I snapshot tools/list as a contract, because a renamed parameter breaks every client and prompt that depended on it. I keep golden results for key calls and assert that bad inputs return actionable isError results. One smoke test launches the real stdio entry point, and in CI the Inspector CLI gives me stable exit codes.

## Interview
### Your server works in the Inspector but not in Claude Desktop. What's different?
The launch environment. The Inspector ran it from your shell, with your `PATH`, your working directory and your full environment. Claude Desktop is a GUI app: the working directory may be `/`, only a limited set of environment variables is inherited, and `uv`/`node` may not be on its `PATH`. So check that every path in the config is absolute, give the full path to the command, pass needed variables through the entry's `env`, and resolve data files relative to `__file__`. Then read `mcp.log` (did the spawn fail?) and `mcp-server-NAME.log` (the stderr traceback), and remember a full quit and restart is required after changes. You can also point the Inspector at the real config read-only with `--config` to reproduce it exactly.

### What do the Inspector CLI's exit codes give you in CI?
A stable failure taxonomy without scraping text: `0` success, `1` usage or unexpected, `3` auth required, `4` unreachable, `5` tool returned `isError: true` or wasn't found, `6` `--strict` found an error-severity schema portability problem, and `7`–`9` skills verification failures. Each failure also writes a single JSON error envelope (`code`, `message`, optional `status`/`url`/`cause`) to stderr. A pipeline can branch on the code, for example "needs auth" versus "server down". With `--stored-auth-only` it never hangs on a browser OAuth flow.

### A modern-era Inspector shows no logs from your server. Bug?
Not necessarily. In 2026-07-28 protocol logging is deprecated and **per request**: the server MUST NOT send `notifications/message` unless that request's `_meta` carries `io.modelcontextprotocol/logLevel`. The Inspector's modern connections stamp `debug` by default, but if **Log Level per Request** is set to Off, silence is the correct behaviour. In legacy era the mechanism is the session-wide `logging/setLevel`. Also check what the server does: SDK 2.x `ctx.info()` only sends when the client opted in. The better fix is to log to stderr (visible in the Console tab) or OpenTelemetry.

### How would you design a test suite for an MCP server in Python?
Use pytest with anyio and `async with Client(server)` in-process for most tests, so they are fast and need no ports. Layers: behaviour tests per tool (happy path plus error path asserting `is_error` and an actionable message); a **contract test** that compares the normalized `tools/list` to a committed golden file so schema changes are explicit; **golden wire tests** of selected results dumped with `by_alias=True`, volatile fields stripped; one **stdio smoke test** launching the real entry point to catch import-time crashes, stdout pollution and env/path issues; and the Inspector CLI in CI with `--strict`. Run the suite against both protocol eras where the SDK allows (`mode="legacy"`).

### A client reports `-32022`. What does it mean and what do you do?
`-32022` is `UnsupportedProtocolVersionError`: the request's `io.modelcontextprotocol/protocolVersion` names a revision the server doesn't support. Its `data` carries `supported` (and the `requested` version), so the client can retry with a mutually supported version or fall back to the legacy `initialize` handshake. To debug, call `server/discover` and read `supportedVersions`, then check the client's `_meta`. Related codes: `-32602` when required `_meta` fields are missing, `-32021` when a required client capability wasn't declared. Over HTTP these come with a `400`.

## Glossary
- MCP Inspector | MCP 检查器 | The official developer tool (`@modelcontextprotocol/inspector`) with web, CLI and TUI clients for testing servers.
- Protocol era | 协议时代 | The Inspector's per-server choice of legacy (`initialize`), auto (probe then fall back) or modern (2026-07-28) negotiation.
- mcpdo | mcpdo（持久连接客户端） | An experimental Inspector client that holds named connections in a daemon so many commands share one connection.
- Exit code | 退出码 | The Inspector CLI's stable numeric failure class (e.g. 3 auth, 4 unreachable, 5 tool error).
- Catalog file | 服务器目录文件 | The Inspector's writable `mcpServers`-shaped server list (`--catalog`); `--config` is a read-only alternative.
- Console tab | 控制台标签页 | The Inspector view of a stdio server's stderr output.
- Contract test | 契约测试 | A test that snapshots a server's advertised definitions and fails when they change unexpectedly.
- Golden test | 黄金样本测试 | A test that compares output to a committed known-good file, with volatile fields stripped.
- Wire transcript | 线路报文记录 | A recording of the raw JSON-RPC messages exchanged between client and server.
- OpenTelemetry | OpenTelemetry（可观测性标准） | The vendor-neutral observability standard recommended for server logs and traces in place of protocol logging.

### 2. A server under test
A small notes server with tools, a resource, a template and a prompt. It resolves its data file **relative to its own source file** and logs to **stderr**: two habits this lesson explains.

```python
import json
import os
import sys
import tempfile
import warnings
from pathlib import Path

warnings.filterwarnings("ignore", category=DeprecationWarning)
workdir = Path(tempfile.mkdtemp(prefix="inspect-"))
server_path = workdir / "notes_server.py"
(workdir / "notes.json").write_text(json.dumps({
    "mcp": "MCP is USB-C for AI applications.",
    "lsp": "The Language Server Protocol inspired MCP.",
    "eras": "The Inspector supports legacy, auto and modern protocol eras.",
}))
print("workdir:", workdir)
```

```python
%%writefile {server_path}
import json
import logging
import sys
from pathlib import Path
from typing import Annotated, Literal

from pydantic import Field

from mcp.server import MCPServer
from mcp.server.mcpserver.exceptions import ToolError
from mcp_types import ToolAnnotations

logging.basicConfig(level=logging.INFO, stream=sys.stderr, format="%(levelname)s %(name)s: %(message)s")
log = logging.getLogger("notes")
NOTES: dict[str, str] = json.loads((Path(__file__).parent / "notes.json").read_text())
log.info("loaded %d notes", len(NOTES))

mcp = MCPServer("notes", version="1.2.0")
RO = ToolAnnotations(readOnlyHint=True, openWorldHint=False)


@mcp.tool(annotations=RO)
def notes_search(query: Annotated[str, Field(description="Case-insensitive text to look for")],
                 match: Annotated[Literal["any", "all"], Field(description="Match any or all words")] = "any") -> list[str]:
    """Return the ids of notes whose text matches the query. Read one with notes_get."""
    words = query.lower().split()
    test = any if match == "any" else all
    return sorted(nid for nid, text in NOTES.items() if test(w in text.lower() for w in words))


@mcp.tool(annotations=RO)
def notes_get(note_id: Annotated[str, Field(description="A note id from notes_search")]) -> str:
    """Return the full text of one note."""
    if note_id not in NOTES:
        raise ToolError(f"Unknown note {note_id!r}. Call notes_search to list valid ids.")
    return NOTES[note_id]


@mcp.resource("notes://index")
def index() -> str:
    """All note ids, one per line."""
    return "\n".join(sorted(NOTES))


@mcp.resource("notes://{note_id}")
def note(note_id: str) -> str:
    """One note as a resource."""
    return NOTES[note_id]


@mcp.prompt()
def summarize(note_id: str) -> str:
    """Ask the model to summarise a note."""
    return f"Summarise note {note_id} in one sentence: {NOTES.get(note_id, '')}"


if __name__ == "__main__":
    mcp.run(transport="stdio")
```

### 3. A mini Inspector
The Inspector CLI connects, runs one method and exits with a meaningful code. Our `inspect_server` does the "list everything, then call every tool" pass. It builds **sample arguments from each `inputSchema`** (first enum value, default, or a type-based placeholder) and returns an Inspector-style exit code: `0` when all calls succeed, `5` when any tool returns `isError`.

```python
import time

from mcp import Client, StdioServerParameters
from mcp.client.stdio import stdio_client


def sample_args(schema: dict, overrides: dict | None = None) -> dict:
    samples = {"string": "mcp", "integer": 1, "number": 1.0, "boolean": True, "array": [], "object": {}}
    args = {}
    for name, prop in schema.get("properties", {}).items():
        if name not in schema.get("required", []):
            continue                                    # like a form left at its defaults
        if "enum" in prop:
            args[name] = prop["enum"][0]
        else:
            args[name] = prop.get("default", samples.get(prop.get("type"), "mcp"))
    return args | (overrides or {})


async def inspect_server(target, overrides: dict | None = None) -> int:
    exit_code = 0
    async with Client(target) as c:
        caps = c.server_capabilities.model_dump(exclude_none=True)
        print(f"server: {c.server_info.name} {c.server_info.version} | protocol {c.protocol_version}")
        print("capabilities:", sorted(caps))
        tools = (await c.list_tools()).tools
        print("resources:", [str(r.uri) for r in (await c.list_resources()).resources],
              "| templates:", [t.uri_template for t in (await c.list_resource_templates()).resource_templates],
              "| prompts:", [p.name for p in (await c.list_prompts()).prompts])
        for tool in tools:
            args = sample_args(tool.input_schema, (overrides or {}).get(tool.name))
            started = time.perf_counter()
            r = await c.call_tool(tool.name, args)
            ms = (time.perf_counter() - started) * 1000
            status = "ERROR" if r.is_error else "ok"
            exit_code = 5 if r.is_error else exit_code
            hints = tool.annotations.model_dump(by_alias=True, exclude_none=True) if tool.annotations else {}
            print(f"  {status:5} {tool.name}({json.dumps(args)}) {ms:5.1f} ms  hints={hints}")
            shown = r.structured_content if r.structured_content is not None else r.content[0].text
            print(f"        -> {json.dumps(shown)[:90]}")
    return exit_code


params = StdioServerParameters(command=sys.executable, args=[str(server_path)])
with open(workdir / "notes.stderr.log", "w") as errlog:
    code = await inspect_server(stdio_client(params, errlog=errlog))
print("exit code:", code)
```

`notes_get("mcp")` happened to succeed because our placeholder string is a real id. Try `overrides={"notes_get": {"note_id": "nope"}}` and the exit code becomes `5`, just like `mcp-inspector --cli … --method tools/call` when a tool returns `isError: true`.

### 4. A wire recorder: the Protocol tab, in 30 lines
The Inspector's Protocol tab is a transcript of JSON-RPC messages. We get the same by putting a tiny **stdio proxy** between client and server. It forwards every line unchanged and appends it to a JSONL transcript, flagging anything on stdout that is not JSON. Because it is just another command, it works with any stdio client, including Claude Desktop (`"command": "python", "args": ["proxy.py", "log.jsonl", "python", "server.py"]`).

```python
proxy_path = workdir / "wire_proxy.py"
proxy_path.write_text('''
import json, subprocess, sys, threading, time
log_path, *cmd = sys.argv[1:]
child = subprocess.Popen(cmd, stdin=subprocess.PIPE, stdout=subprocess.PIPE)
lock = threading.Lock()

def record(direction, raw):
    text = raw.decode("utf-8", "replace").rstrip("\\n")
    try:
        entry = {"t": time.time(), "dir": direction, "msg": json.loads(text)}
    except json.JSONDecodeError:
        entry = {"t": time.time(), "dir": direction, "invalid": text}
    with lock, open(log_path, "a") as f:
        f.write(json.dumps(entry) + "\\n")

def client_to_server():
    for line in sys.stdin.buffer:
        record("->", line)
        child.stdin.write(line)
        child.stdin.flush()
    child.stdin.close()

threading.Thread(target=client_to_server, daemon=True).start()
for line in child.stdout:
    record("<-", line)
    sys.stdout.buffer.write(line)
    sys.stdout.buffer.flush()
sys.exit(child.wait())
''')


def show_transcript(path: Path, width: int = 150) -> list[dict]:
    entries = [json.loads(l) for l in path.read_text().splitlines()]
    for e in entries:
        if "invalid" in e:
            print(f"{e['dir']} !! NOT JSON-RPC: {e['invalid']!r}")
            continue
        m = e["msg"]
        kind = m.get("method") or ("result" if "result" in m else "error")
        body = m.get("params") or m.get("result") or m.get("error")
        print(f"{e['dir']} id={m.get('id', '-')!s:4} {kind:22} {json.dumps(body)[:width]}")
    return entries


transcript = workdir / "wire.jsonl"
recorded = StdioServerParameters(command=sys.executable,
                                 args=[str(proxy_path), str(transcript), sys.executable, str(server_path)])
with open(workdir / "notes.stderr.log", "w") as errlog:
    async with Client(stdio_client(recorded, errlog=errlog)) as c:
        await c.call_tool("notes_search", {"query": "protocol eras", "match": "all"})
        await c.call_tool("notes_get", {"note_id": "nope"})
entries = show_transcript(transcript)
```

### 5. Protocol compatibility checks by hand
The debugging guide's connection checklist ends with "verify protocol compatibility" and "check the per-request `_meta` fields". Here are the three answers you should recognise: a good `server/discover`, a missing `_meta` (`-32602`), and an unsupported version (`-32022` with `data.supported`).

```python
import subprocess

proc = subprocess.Popen([sys.executable, str(server_path)], text=True,
                        stdin=subprocess.PIPE, stdout=subprocess.PIPE, stderr=subprocess.DEVNULL)
META = {"io.modelcontextprotocol/protocolVersion": "2026-07-28",
        "io.modelcontextprotocol/clientCapabilities": {},
        "io.modelcontextprotocol/clientInfo": {"name": "by-hand", "version": "0"}}


def rpc(id_, method, params):
    proc.stdin.write(json.dumps({"jsonrpc": "2.0", "id": id_, "method": method, "params": params}) + "\n")
    proc.stdin.flush()
    return json.loads(proc.stdout.readline())


ok = rpc(1, "server/discover", {"_meta": META})
print("server/discover ->", {k: ok["result"][k] for k in ("supportedVersions", "capabilities")})
print("missing _meta   ->", rpc(2, "tools/list", {})["error"])
old = dict(META, **{"io.modelcontextprotocol/protocolVersion": "2020-01-01"})
print("bad version     ->", rpc(3, "tools/list", {"_meta": old})["error"])
proc.stdin.close()
_ = proc.wait(timeout=10)
```

### 6. A test suite: behaviour, contract and golden wire tests
We write a real pytest-style test file next to the server. It uses in-memory `Client(server)` for speed and one stdio smoke test. The first run records the **golden files** (the tool contract and a wire-format result). Later runs compare against them. If `pytest` is installed it runs the file directly; otherwise a 15-line runner executes the same test functions, awaiting the async ones.

```python
tests_path = workdir / "test_notes_server.py"
tests_path.write_text('''
import importlib.util, json, os, sys

import pytest
from mcp import Client, StdioServerParameters

GOLDEN = HERE / "golden"

notes_server = importlib.util.module_from_spec(spec)
spec.loader.exec_module(notes_server)

def wire(model):
    data = model.model_dump(by_alias=True, exclude_none=True, mode="json")
    data.pop("_meta", None)                      # volatile/identity fields don't belong in goldens

def check_golden(name, value):
    path = GOLDEN / f"{name}.json"
    text = json.dumps(value, indent=2, sort_keys=True)
    if os.environ.get("UPDATE_GOLDEN") or not path.exists():
        GOLDEN.mkdir(exist_ok=True)
        path.write_text(text)
    if text != path.read_text():
        path.with_suffix(".actual.json").write_text(text)     # keep the new version for the diff
        raise AssertionError(f"{name} changed; review the diff, then re-run with UPDATE_GOLDEN=1")
```

### 7. Debug a broken server, step by step
Here is a server that "works on my machine": it runs fine from its own folder in a terminal. A host launches it differently, though: absolute script path, working directory `/`, and a minimal environment. We launch it the way a host would, read the stderr log the way you would read `mcp-server-NAME.log`, and fix one bug per step.

```python
broken_path = workdir / "broken_notes.py"
broken_path.write_text('''
import json, os
from mcp.server import MCPServer

NOTES = json.load(open("notes.json"))           # bug 1: relative to the *working directory*
TOKEN = os.environ["NOTES_TOKEN"]               # bug 2: env var the host does not pass
print(f"Loaded {len(NOTES)} notes", flush=True) # bug 3: stdout is the wire

mcp = MCPServer("broken-notes")

@mcp.tool()
def count_notes() -> int:
    """How many notes exist."""
    return len(NOTES)

if __name__ == "__main__":
    mcp.run()
''')


def leaf_error(exc: BaseException) -> BaseException:
    while isinstance(exc, BaseExceptionGroup):
        exc = exc.exceptions[0]
    return exc


async def launch_like_a_host(env: dict | None = None, record_to: Path | None = None) -> None:
    log_path = workdir / "mcp-server-broken-notes.log"
    command = [str(broken_path)]
    if record_to:
        command = [str(proxy_path), str(record_to), sys.executable, str(broken_path)]
    params = StdioServerParameters(command=sys.executable, args=command, cwd="/", env=env)
    try:
        with open(log_path, "w") as errlog:
            async with Client(stdio_client(params, errlog=errlog)) as c:
                r = await c.call_tool("count_notes", {})
                print("CONNECTED: count_notes ->", r.structured_content)
    except Exception as exc:
        print("CLIENT SAW:", repr(leaf_error(exc)))
        tail = log_path.read_text().strip().splitlines()[-1:]
        print("LOG TAIL  :", tail)


print("step 1: launch it like a host would")
await launch_like_a_host()
```

The client only sees `Connection closed`, which is all a host can tell you. The **log** has the cause: `notes.json` was looked up in `/`. Fix 1: resolve data relative to the source file.

```python
src = broken_path.read_text()
src = src.replace('json.load(open("notes.json"))',
                  'json.load(open(os.path.join(os.path.dirname(os.path.abspath(__file__)), "notes.json")))')
broken_path.write_text(src)
print("step 2: after fixing the path")
await launch_like_a_host()
```

New failure, new log line: `KeyError: 'NOTES_TOKEN'`. Stdio servers inherit only a limited environment, so pass it explicitly, which is the equivalent of an `"env"` entry in `claude_desktop_config.json`.

```python
print("step 3: pass the environment explicitly, and record the wire")
wire_log = workdir / "broken-wire.jsonl"
await launch_like_a_host(env={"NOTES_TOKEN": "dev-token"}, record_to=wire_log)
_ = show_transcript(wire_log, width=90)
```

It connects, because the Python client tolerates the junk line, but the recorder exposes **bug 3**: a non-JSON line on stdout before the first response. A stricter host could drop the connection here. Fix 3: log to stderr. Then confirm the transcript is clean.

```python
broken_path.write_text(broken_path.read_text().replace(
    'print(f"Loaded {len(NOTES)} notes", flush=True)', 'print(f"Loaded {len(NOTES)} notes", file=sys.stderr)')
    .replace("import json, os", "import json, os, sys"))
wire_log.unlink()
print("step 4: after logging to stderr")
await launch_like_a_host(env={"NOTES_TOKEN": "dev-token"}, record_to=wire_log)
bad_lines = [e for e in map(json.loads, wire_log.read_text().splitlines()) if "invalid" in e]

print("server log:", (workdir / "mcp-server-broken-notes.log").read_text().strip())
```

Each bug became visible only by **reproducing the host's launch conditions** and **reading the right log**. Turn every fix into a regression test: section 6's `test_stdio_smoke` already launches with `cwd="/"`.
