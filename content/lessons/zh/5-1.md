## Summary
能提供东西的并不只有服务器一方。客户端（Client）也可以反过来为服务器（Server）提供三样东西：**征询（Elicitation）**（向用户索取信息）、**根目录（Roots）**（告诉服务器哪些目录是相关的）和**采样（Sampling）**（借用宿主的 LLM）。2026-07-28 版本带来了两项重大变化。第一，服务器不能再主动向客户端发送自己的请求。三项特性如今都通过**多轮往返请求（Multi Round-Trip Request，MRTR）**模式传递：服务器返回一个 `InputRequiredResult`，客户端带着答案重试这次调用。第二，**根目录和采样已被弃用**（SEP-2577），征询因此成为唯一的核心客户端特性（Client Features）。本课介绍每项特性的作用、它的用户交互与安全模型、能力（Capability）规则，以及你应当改用的迁移方案。

## Lesson
### 客户端既索取，也给予
**宿主（Host）**（Claude Desktop、IDE 或你自己的智能体）为每个服务器创建一个**客户端（Client）**。大多数时候，客户端是在*消费*服务器提供的东西：工具、资源、提示模板。规范还定义了**客户端特性（Client Features）**，让服务器在处理请求的过程中向客户端索取某些东西：

| 特性 | 服务器得到什么 | 文档中的示例 | 在 2026-07-28 中的状态 |
| --- | --- | --- | --- |
| **征询（Elicitation）** | *来自用户*的信息，按模式（Schema）结构化，或通过 URL 在带外收集 | 旅行服务器询问座位偏好，并最后确认“确认 $3,000 的预订” | **有效**，核心客户端特性 |
| **根目录（Roots）** | 客户端认为在范围内的 `file://` 目录列表 | `file:///Users/agent/travel-planning` | **已弃用**（SEP-2577） |
| **采样（Sampling）** | 由*宿主的*模型生成的 LLM 补全结果 | “分析这 47 个航班并推荐最好的一个” | **已弃用**（SEP-2577） |

三者都让**客户端掌握控制权**。用户能看到是谁在提出请求、为什么提出，并且可以拒绝。服务器永远不会直接接触用户的界面、文件选择器或模型 API 密钥。

### 客户端特性如今如何传递：MRTR
在 2026-07-28 之前，服务器会在客户端的请求仍未结束时，反向向客户端发送它自己的 JSON-RPC *请求*（`elicitation/create`、`roots/list`、`sampling/createMessage`）。这需要一条长期存在的双向通道和粘性状态，而这恰恰是无状态（Stateless）修订版所去掉的东西。变更日志说得很直接：**多轮往返请求（Multi Round-Trip Requests，MRTR）**模式（SEP-2322）*取代了*服务器发起的请求。服务器**必须（MUST）**使用它，旧模式“不再受支持。这是一项破坏性变更。”

```text
client                                     server
  │ tools/call {name, arguments}  (id 1)     │
  │─────────────────────────────────────────▶│  needs user input / roots / an LLM answer
  │◀─────────────────────────────────────────│  result: {resultType: "input_required",
  │                                          │           inputRequests: {key: {method, params}},
  │  ask user / list dirs / call LLM         │           requestState: "opaque"}
  │ tools/call {..., inputResponses, requestState}  (id 2)
  │─────────────────────────────────────────▶│  rebuilds context from requestState
  │◀─────────────────────────────────────────│  result: {resultType: "complete", ...}
```

这三种请求类型如今是 **`InputRequiredResult.inputRequests` 中的值**，而不再是线路上的消息。只有 `tools/call`、`prompts/get` 和 `resources/read` 可以返回 `InputRequiredResult`。第 5.3 课会深入讲解其机制：`requestState` 的完整性、重试和错误处理。

一切仍然由能力（Capability）把关，而且能力是在 `_meta.io.modelcontextprotocol/clientCapabilities` 中**逐请求**声明的：

```json
{"_meta": {"io.modelcontextprotocol/clientCapabilities": {
  "elicitation": {"form": {}, "url": {}},
  "roots": {},
  "sampling": {"tools": {}}
}}}
```

> **规范规则。** 服务器**不得（MUST NOT）**在 `inputRequests` 中放入客户端未声明支持的输入请求。如果客户端没有发送 `elicitation` 能力，它就不会收到 `elicitation/create`。如果它有 `sampling` 但没有 `sampling.tools`，就不会收到带工具的采样请求。为了向后兼容，空的 `"elicitation": {}` 表示仅支持表单模式。

### 征询：在操作中途询问用户
征询（Elicitation）让服务器可以*暂停并提问*，而不是直接失败，或者要求一开始就提供所有参数。它有两种模式：

- **表单模式（Form Mode）**（`mode: "form"`，或省略）：请求携带一个 `message` 和一个 `requestedSchema`。客户端渲染表单、校验输入并返回结果。这些数据**对客户端可见**。该模式（Schema）是刻意**受限的 JSON Schema**：一个扁平对象，其属性只能是字符串（`format` 可为 `email`、`uri`、`date` 或 `date-time`）、数字/整数、布尔值，或单选/多选枚举。不允许嵌套对象和对象数组，这样任何客户端都能渲染这个表单。
- **URL 模式（URL Mode）**（`mode: "url"`，外加 `url`）：客户端展示该 URL，并在获得同意后打开它。交互过程（输入 API 密钥、OAuth 授权同意、付款）在**带外**进行，永远不会经过客户端或 LLM 的上下文。

用户以三种**动作（Action）**之一作答：`accept`（表单模式下附带 `content`）、`decline`（明确拒绝）或 `cancel`（未作选择就关闭）。服务器必须处理全部三种情况。

**用户交互模型**规定了规则。客户端**必须（MUST）**清楚地表明是*哪个服务器*在提问，提供明确的拒绝和取消选项，允许用户在发送前检查并修改表单答案；对于 URL 模式，必须显示完整的 URL 和域名，并在跳转前获得同意。服务器**不得（MUST NOT）**使用表单模式索取密码、API 密钥、访问令牌（Token）或支付凭据。这些**必须（MUST）**通过 URL 模式处理。

### 根目录：建议性的文件系统范围（已弃用）
一个根目录形如 `{ "uri": "file:///home/user/projects/myproject", "name": "My Project" }`。其中 `uri` **必须（MUST）**是 `file://` URI。服务器通过 `roots/list` 输入请求索取根目录，客户端以 `{"roots": [...]}` 作答。宿主（Host）通常根据用户打开的文件夹或工作区自动推导根目录，有时也允许用户手动添加或排除目录。

关键词是**建议性（Advisory）**。文档称根目录（Roots）是“一种协调机制……而不是安全边界”：服务器“应当（SHOULD）尊重根目录边界”，而不是“必须（MUST）强制执行”，因为客户端无法控制在服务器中运行的代码。真正的强制执行属于操作系统：文件权限、沙箱（Sandbox）、容器（第 6.3 课）。安全规则依然适用。客户端**必须（MUST）**只暴露具有适当权限的根目录，校验根目录 URI 以防止路径穿越（Directory Traversal），并实施访问控制；客户端**应当（SHOULD）**在暴露根目录之前征得同意。服务器**应当（SHOULD）**对照所提供的根目录校验每一条路径。

2026-07-28 中的变化：`notifications/roots/list_changed` 与其他被移除的通知一起被**移除**了，因此服务器会在下一次索取时看到更新后的列表。根目录整体上已被**弃用**。新实现**不应当（SHOULD NOT）**采用它。迁移方式是*通过工具参数、资源 URI 或服务器配置传递目录或文件*。`directory` 参数是显式的，会出现在工具调用审批（Tool Approval）界面中，并且在每个宿主中的行为都一样。

### 采样：借用宿主的模型（已弃用）
采样（Sampling）让服务器可以请求一次 LLM 补全，“无需服务器持有 API 密钥”。模型的访问权、选择和权限都由客户端掌握。`sampling/createMessage` 的参数如下：

- `messages`（`role` 为 `user` 或 `assistant`，内容为文本、图像或音频），以及一个**必填的** `maxTokens`，客户端**必须（MUST）**遵守它。
- `modelPreferences`。服务器无法可靠地指定模型名称，因为客户端可能使用另一家提供商。因此服务器发送的是 `hints`（例如 `"claude"` 这样的子字符串，按顺序尝试，客户端**可以（MAY）**将其映射到其他提供商的等效模型）以及三个 0–1 之间的优先级：`costPriority`、`speedPriority` 和 `intelligencePriority`。最终选择始终由客户端做出。
- `systemPrompt`、`temperature`、`stopSequences`、`metadata`：这些客户端都**可以（MAY）**修改或忽略。
- `includeContext`：`"none"`（默认值），或 `"thisServer"`/`"allServers"`。后两者已被**弃用**（SEP-2596），除非客户端声明了 `sampling.context`，否则**不应当（SHOULD NOT）**使用。

结果为 `{role: "assistant", content, model, stopReason}`，停止原因可以是 `endTurn`、`stopSequence`、`maxTokens` 或 `toolUse`。

**带工具的采样。** 服务器可以附带 `tools` 和 `toolChoice`（`{mode: "auto" | "required" | "none"}`），使宿主的模型能够调用*仅限于该次采样请求*的工具。这些工具不必是服务器对外暴露的工具。客户端**必须（MUST）**声明 `sampling.tools`，否则服务器**不得（MUST NOT）**发送带工具的请求。在 MRTR 下，这会变成一个跨越多次重试的循环。模型以 `tool_use` 块作答（`stopReason: "toolUse"`），服务器执行这些工具，然后发送一个新的采样请求，其中包含历史记录以及 `tool_result` 块，如此反复，直到 `endTurn`。这里有两条约束。包含工具结果的用户消息**必须（MUST）***只*包含工具结果，并且每个 `tool_use` id **必须（MUST）**有一个 `toolUseId` 相同的 `tool_result` 与之对应。双方都**应当（SHOULD）**限制迭代次数，例如在最后一轮使用 `toolChoice: {mode: "none"}`。

**交互模型。** 始终**应当（SHOULD）**有一个可以拒绝采样请求的人在回路（Human in the Loop）中。用户应当能够在提示词*发送之前*检查并修改它，并在生成结果*返回服务器之前*看到它。客户端**应当（SHOULD）**对请求进行限流，双方都**必须（MUST）**妥善处理敏感数据。

**为什么要弃用它？** 规范记录的是这一决定（SEP-2577）和迁移方案，而没有给出长篇理由。不过其中的工程权衡并不难看出。采样把宿主的模型、预算和会话信任交给任意一个已连接的服务器支配，于是服务器可以构造出在用户模型上运行的提示词。要安全地做到这一点，每次调用的两端都需要审批界面。它还需要在工具调用中途嵌套一次模型调用，这与无状态协议（Stateless Protocol）很不契合。迁移很简单：在服务器中**直接集成 LLM 提供商的 API**，使用服务器自己的密钥和自己的成本核算。

### 准确理解“弃用”
根据特性生命周期（Feature Lifecycle）策略（SEP-2596），*已弃用（Deprecated）*的特性“仍然是规范的一部分，但已计划移除”。它会在**至少十二个月**内保持完全可用，最早的移除时间是*在 2027-07-28 当天或之后发布的第一个修订版*。你的客户端和服务器仍会在实际环境中遇到根目录和采样，尤其是来自 2025 年代 SDK 的实现，因此你需要能识别它们，在用户需要的窗口期内支持它们，并引导新设计远离它们。

| 已弃用 | 替代方案 |
| --- | --- |
| 根目录 | 工具参数（`directory: str`）、资源 URI 或服务器配置（启动时给定的目录白名单） |
| 采样 | 在服务器内直接调用 LLM 提供商的 API |
| `includeContext: "thisServer"/"allServers"` | 省略它或使用 `"none"` |
| 日志（服务器特性） | stdio 使用 `stderr`；可观测性使用 OpenTelemetry |

> **陷阱。** “我们用根目录来阻止服务器读取 `~/.ssh`。”根目录阻止不了任何事。它们只是给行为规范的服务器的提示。能阻止恶意服务器的是沙箱、容器或操作系统用户。

### 2026-07-28 中从征询里移除的内容
`2025-11-25` 修订版新增了 `notifications/elicitation/complete` 和 `elicitationId`，使服务器可以告知客户端某次 URL 模式交互已经结束。这两者都已被**移除**。在 MRTR 下，客户端通过**重试**原始请求来获知结果。需要跨多次重试关联 URL 交互的服务器，会把自己的标识符放进 `requestState`。第 5.3 课会实现这一点。

## Key points
- 客户端特性（Client Features）让服务器可以在请求中途向客户端索取东西：**征询**（用户输入）、**根目录**（范围内的目录）、**采样**（一次 LLM 补全）。
- 在 2026-07-28 中，它们都以**输入请求的形式放在 `InputRequiredResult.inputRequests` 中**传递（多轮往返请求（MRTR），SEP-2322）。服务器发起的请求已不复存在，这是一项破坏性变更。
- 只有 `tools/call`、`prompts/get` 和 `resources/read` 可以返回 `InputRequiredResult`，并且服务器**不得（MUST NOT）**发送客户端未在 `clientCapabilities` 中声明的输入请求。
- 征询（Elicitation）有**表单模式**（受限的扁平 JSON Schema，数据对客户端可见）和 **URL 模式**（带外进行，用于密钥、OAuth 和付款）。响应为 `accept`/`decline`/`cancel`。
- 永远不要用表单模式（Form Mode）索取密码、API 密钥、令牌或支付凭据。请使用 URL 模式。
- **根目录（Roots）**是建议性的 `file://` 边界，而不是安全控制手段。它们已被弃用，因此请改为通过工具参数、资源 URI 或服务器配置传递目录。
- **采样（Sampling）**使用 `modelPreferences`（提示加上成本/速度/智能优先级）、必填的 `maxTokens`、受 `sampling.tools` 把关的可选 `tools`/`toolChoice`，以及人工审核。它已被弃用，因此请直接调用 LLM 提供商的 API。
- 已弃用特性（Deprecated Feature）会继续工作**至少 12 个月**，最早在 **2027-07-28** 当天或之后的第一个修订版中移除。`"none"` 以外的 `includeContext` 取值同样已被弃用。
- `notifications/elicitation/complete`、`elicitationId` 和 `notifications/roots/list_changed` 已被**移除**。

## Pitches
### 什么是 MCP 客户端特性？
MCP 客户端除了消费工具、资源和提示模板之外，还可以反过来为服务器服务，这就是客户端特性（Client Features）。征询（Elicitation）让服务器可以向用户索取结构化输入，或者在涉及敏感信息时把用户引导到一个 URL。根目录（Roots）用来告诉服务器哪些文件夹在范围内。采样（Sampling）让服务器借用宿主的模型。在 2026-07-28 修订版中，这些都承载在一个“需要输入”的结果里，客户端通过重试调用来作答；而且根目录和采样已经被弃用，所以我的设计主要围绕征询来展开。

### 为什么根目录和采样被弃用了？
两者在信任方面都有别扭之处。根目录（Roots）看起来像安全边界，实际上只是建议性的，于是大家把它用在了不该用的地方。把目录作为工具参数或服务器配置传入，既显式又对用户可见。采样（Sampling）让任何服务器都能用自己构造的提示词花费宿主的模型预算，要保证安全就需要大量人工审核。需要 LLM 的服务器完全可以自己调用提供商的 API。两者都还会继续可用至少一年。

### 征询如何保证安全？
控制权始终在客户端手里。征询（Elicitation）要求客户端必须显示是哪个服务器在提问、为什么提问，允许用户检查和修改答案，并始终提供拒绝和取消选项。表单模式（Form Mode）只能包含扁平的基本类型字段，而且绝不能用来索取密码、API 密钥或支付信息。这些都要走 URL 模式（URL Mode），用户在提供商自己的页面上输入，数据永远不会经过客户端或模型的上下文。

## Interview
### 请讲解在 MCP 2026-07-28 中，服务器是如何向用户提问的。
服务器收到一个 `tools/call`，发现自己需要输入。它不会发送自己的 `elicitation/create` 请求（这已经不被允许），而是**返回**一个结果，其中包含 `resultType: "input_required"`、一个 `inputRequests` 映射，例如 `{"confirm": {"method": "elicitation/create", "params": {"mode": "form", "message": ..., "requestedSchema": ...}}}`，以及可选的不透明 `requestState`（请求状态）。客户端展示表单，收集 `accept`/`decline`/`cancel`，然后用新的 JSON-RPC id、`inputResponses: {"confirm": {...}}` 以及原样回传的 `requestState` **重试**同一个 `tools/call`。服务器重建上下文并完成处理。只有当客户端在该请求的能力（Capability）中声明了 `elicitation`（以及相应模式）时，服务器才会这样做。

### 表单模式和 URL 模式的征询有什么区别？什么情况下必须使用 URL 模式？
表单模式（Form Mode）在**带内**收集结构化数据。客户端渲染一个由基本类型和枚举构成的扁平模式（Schema），答案会经过客户端。URL 模式（URL Mode）则把用户在**带外**引导到一个 URL。客户端只能得知用户是否同意（`accept` 不带内容），真正的数据直接发送到目标网站。对于敏感信息，服务器**必须（MUST）**使用 URL 模式：密码、API 密钥、访问令牌、支付凭据，以及 MCP 服务器作为 OAuth 客户端时的第三方 OAuth。URL 模式不是用来授权客户端访问 MCP 服务器本身的，那属于 MCP 授权（Authorization）。

### 有位同事提议用根目录把一个第三方文件系统服务器限制在项目文件夹内。你会怎么说？
根目录（Roots）是**建议性的**。规范说服务器*应当（SHOULD）*尊重它们，因为客户端无法控制服务器代码，所以有缺陷或恶意的服务器完全可以无视它们。而且它们在 2026-07-28 中已被**弃用**。就范围而言，我会显式传入目录（作为工具参数，或放在服务器的启动配置中，例如一个白名单参数），并让服务器在解析符号链接和 `..` 之后校验每一条路径。就*安全*而言，我会在操作系统层面强制执行：在只挂载了该文件夹的容器或沙箱（Sandbox）中运行服务器，或者以受限用户身份运行它。

### modelPreferences 是如何工作的？为什么不直接发送模型名称？
服务器和客户端可能使用不同的提供商，所以模型名称对客户端来说可能毫无意义。`modelPreferences`（模型偏好）把建议性的 `hints`（按顺序评估的子字符串，客户端**可以（MAY）**将其映射到其他提供商的等效模型，例如把 “sonnet” 级别的提示映射到某个 Gemini 模型）与归一化到 0–1 的 `costPriority`、`speedPriority` 和 `intelligencePriority` 组合在一起。最终选择由客户端做出。这是一种在不与特定厂商耦合的前提下表达需求的方式。不过，整个特性现在都已被弃用。

### 陷阱题：服务器发送了一个带工具的采样请求，客户端却报错。可能的原因有哪些？
第一，客户端可能没有声明 `sampling.tools`。没有它，服务器**不得（MUST NOT）**发送 `tools`/`toolChoice`（Python SDK 会以 `-32021` MissingRequiredClientCapability（缺少必需客户端能力）拒绝）。第二，消息历史可能违反了配对规则：每个助手的 `tool_use` 之后必须紧跟一条*只*由 `tool_result` 块组成、且 `toolUseId` 相互匹配的用户消息，其中不能混入文本。第三，循环可能触及了迭代上限。从长远看，正确的做法是迁移出采样（Sampling），直接调用提供商。

### 你的服务器曾用采样来总结文档。你会如何迁移它？
把 `sampling/createMessage` 输入请求替换为在服务器中直接调用 LLM 提供商，使用服务器自己从环境变量或密钥存储中取得的 API 密钥，并由服务器自行决定模型选择、`max_tokens`、限流和成本跟踪。在需要的地方保留人在回路（Human in the Loop）的特性：把同意环节移到*工具调用*上（宿主在调用工具前询问用户），或者在执行昂贵或敏感的步骤之前通过征询（Elicitation）请求确认。在弃用窗口期内，我可以把采样路径保留在能力检查之后，供较旧的宿主使用，但新的部署不应依赖它。

## Glossary
- Client features | 客户端特性 | 客户端提供给服务器的能力（征询、根目录、采样），在操作中途通过输入请求来索取。
- Elicitation | 征询（信息征询） | 服务器向用户索取信息的请求，可以通过由模式驱动的表单，也可以通过带外的 URL。
- Form mode | 表单模式 | 通过客户端收集扁平的、基本类型的、经模式校验的数据的征询方式。
- URL mode | URL 模式 | 把用户引导到外部 URL 的征询方式，使敏感数据永远不会经过客户端或 LLM。
- Roots | 根目录 | 已弃用的、建议性的 `file://` 目录列表，表示客户端认为对某个服务器而言在范围内的目录。
- Sampling | 采样 | 已弃用的特性，让服务器通过 `sampling/createMessage` 向宿主的模型请求一次 LLM 补全。
- Model preferences | 模型偏好 | 服务器发送的提示加上成本/速度/智能优先级，供客户端挑选合适的模型。
- InputRequiredResult | 需输入结果（InputRequiredResult） | 一种 `resultType: "input_required"` 的结果，携带 `inputRequests` 和/或 `requestState`；客户端通过重试来作答。
- Deprecated feature | 已弃用特性 | 仍在规范中且可以正常工作，但计划在不早于 12 个月之后移除的特性。
- MissingRequiredClientCapability | 缺少必需客户端能力（-32021） | 当请求需要某项客户端未声明的能力时，服务器返回的错误。

### 1. 准备：客户端声明什么取决于它的回调
在 Python SDK 中，你通过**传入回调**来声明一项客户端特性（Client Features）。`Client(elicitation_callback=...)` 会声明 `elicitation: {form, url}`，`list_roots_callback=` 会声明 `roots`，`sampling_callback=` 会声明 `sampling`。服务器会在请求的 `_meta.io.modelcontextprotocol/clientCapabilities` 中看到这些能力。我们用一个回显所收到内容的工具来验证这一点。

```python
import json
import logging
import warnings

import mcp_types as types
from mcp import Client
from mcp.server import MCPServer
from mcp.server.mcpserver import Context

logging.getLogger("mcp").setLevel(logging.CRITICAL)    # keep the SDK's own server-side logs quiet
warnings.filterwarnings("ignore", message=".*deprecated.*")


def wire(model) -> str:
    """A pydantic MCP object exactly as it travels on the wire."""
    return json.dumps(model.model_dump(by_alias=True, exclude_none=True, mode="json"), indent=2)


probe = MCPServer("capability-probe")


@probe.tool()
def my_capabilities(ctx: Context) -> str:
    """Return the client capabilities declared on this request."""
    caps = ctx.client_capabilities
    return json.dumps(caps.model_dump(by_alias=True, exclude_none=True) if caps else {})


async def noop(*args):          # placeholder callbacks: we only care about what gets declared
    return types.ErrorData(code=-1, message="unused")

async with Client(probe) as plain:
    print("no callbacks      ->", (await plain.call_tool("my_capabilities", {})).content[0].text)

async with Client(probe, elicitation_callback=noop, list_roots_callback=noop, sampling_callback=noop) as rich:
    print("all three         ->", (await rich.call_tool("my_capabilities", {})).content[0].text)
```

### 2. 征询：旅行服务器询问预订详情
这是文档中的巴塞罗那示例。在 `MCPServer` 中，2026 年惯用的提问方式是使用**解析器（Resolver）**：一个返回 `Elicit(message, Schema)` 的函数。你通过 `Annotated[..., Resolve(fn)]` 把它挂到某个工具参数上。框架会把这个问题转换成 `InputRequiredResult`，当客户端带着答案重试时，框架会注入结果并运行工具函数体。把参数标注为 `ElicitationResult[Schema]`，你就能针对全部三种结果进行分支处理。

这个 Pydantic 模型会被渲染为**受限的扁平模式（Schema）**：一个布尔值、一个字符串枚举（`Literal`）和一个带默认值的布尔值。嵌套模型会被拒绝。

```python
from typing import Annotated, Literal

from pydantic import BaseModel, Field

from mcp.server.elicitation import AcceptedElicitation, ElicitationResult
from mcp.server.mcpserver import Elicit, Resolve


class BookingDetails(BaseModel):
    confirmBooking: bool = Field(description="Confirm the booking (Flights + Hotel = $3,000)")
    seatPreference: Literal["window", "aisle", "no preference"] = Field(description="Preferred seat type")
    travelInsurance: bool = Field(default=False, description="Add travel insurance ($150)")


travel = MCPServer("travel")


def ask_booking_details(destination: str) -> Elicit[BookingDetails]:
    return Elicit(f"Please confirm your {destination} vacation booking details:", BookingDetails)


@travel.tool()
def book_trip(destination: str,
              details: Annotated[ElicitationResult[BookingDetails], Resolve(ask_booking_details)]) -> str:
    """Book a vacation package after the user confirms the details."""
    if isinstance(details, AcceptedElicitation):
        d = details.data
        if not d.confirmBooking:
            return "User reviewed the form but did not confirm. Nothing booked."
        extra = " + insurance" if d.travelInsurance else ""
        return f"Booked {destination}: {d.seatPreference} seat{extra}."
    return f"Booking not made: user chose '{details.action}'."


async with Client(travel) as c:
    tool = (await c.list_tools()).tools[0]
    print("book_trip input schema (what the LLM fills):", json.dumps(tool.input_schema))
```

接下来是**客户端这一侧**。真实的宿主（Host）会渲染一个表单。我们脚本化的“用户”会打印出界面上应当显示的内容（哪个服务器在提问、消息内容、各个字段），然后作答。我们运行三次，分别观察 `accept`、`decline` 和 `cancel`。

```python
script = []          # the scripted user's next answers


async def form_ui(context, params: types.ElicitRequestFormParams):
    """Stand-in for a host's elicitation dialog."""
    print(f"  ┌ [travel server] asks: {params.message}")
    for name, prop in params.requested_schema["properties"].items():
        choices = prop.get("enum")
        print(f"  │  {name:<16} {prop['type']:<8} {choices or ''} default={prop.get('default', '-')}")
    action, content = script.pop(0)
    print(f"  └ user -> {action} {content or ''}")
    return types.ElicitResult(action=action, content=content)


script[:] = [("accept", {"confirmBooking": True, "seatPreference": "window", "travelInsurance": True}),
             ("decline", None),
             ("cancel", None)]

async with Client(travel, elicitation_callback=form_ui) as client:
    for _ in range(3):
        result = await client.call_tool("book_trip", {"destination": "Barcelona"})
        print("tool result:", result.content[0].text, "\n")
```

### 3. 深入内部：线路上的输入请求
`client.call_tool` 隐藏了这次往返。`client.session.call_tool(..., allow_input_required=True)` 则会返回原始的中间结果，这里就是 `InputRequiredResult`，其中*包含*了 `elicitation/create` 请求。第 5.3 课会手动驱动这个循环。现在先看看它的结构。

```python
async with Client(travel, elicitation_callback=form_ui) as client:
    interim = await client.session.call_tool("book_trip", {"destination": "Barcelona"}, allow_input_required=True)
    print(type(interim).__name__)
    text = wire(interim)
    print(text[:1400] + ("\n  ..." if len(text) > 1400 else ""))
```

注意 `resultType: "input_required"`、`inputRequests` 中由服务器选定的键，以及被 SDK **加密**过的 `requestState`（请求状态）。客户端必须原封不动地把它回传。

### 4. 制造故障：没有能力，就没有提问
服务器**不得（MUST NOT）**发送客户端未声明的输入请求。*不*提供 `elicitation_callback` 进行连接，SDK 就会以规范中的 `-32021` MissingRequiredClientCapability（缺少必需客户端能力）错误拒绝，并指明缺少的是什么。

```python
from mcp.shared.exceptions import MCPError

async with Client(travel) as client:          # no elicitation_callback -> no elicitation capability
    try:
        await client.call_tool("book_trip", {"destination": "Barcelona"})
    except MCPError as err:
        print("code:", err.error.code)
        print("message:", err.error.message)
        print("data:", err.error.data)
```

### 5. 采样（已弃用）：服务器借用宿主的模型
在弃用窗口期内，采样（Sampling）仍然可用。解析器返回一个 `Sample(...)`，其中包含消息、必填的 `max_tokens` 和 `model_preferences`。客户端的 `sampling_callback` 是宿主展示提示词供审批、根据提示和优先级**挑选模型**、调用其 LLM 并展示答案供审核的地方。我们的模拟宿主有三个模型，并按规范所描述的方式进行提示匹配（按顺序进行子字符串匹配，然后看优先级）。

```python
from mcp.server.mcpserver import Sample

flights = MCPServer("flights")
FLIGHTS = "IB3101 07:10 €180 direct | VY1307 06:30 €95 1 stop | BA478 21:40 €70 red-eye"


def analyse(preferences: str) -> Sample:
    return Sample(
        [types.SamplingMessage(role="user", content=types.TextContent(
            type="text", text=f"Recommend the best flight.\n{FLIGHTS}\nUser preferences: {preferences}"))],
        max_tokens=200,
        system_prompt="You are a travel expert.",
        model_preferences=types.ModelPreferences(
            hints=[types.ModelHint(name="sonnet"), types.ModelHint(name="claude")],
            cost_priority=0.3, speed_priority=0.2, intelligence_priority=0.9),
    )


@flights.tool()
def find_best_flight(preferences: str,
                     advice: Annotated[types.CreateMessageResult, Resolve(analyse)]) -> str:
    """Recommend a flight using the client's LLM (deprecated sampling)."""
    return f"[{advice.model}] {advice.content.text}"


HOST_MODELS = {"claude-opus-5-5": {"intelligence": 0.95, "speed": 0.4, "cost": 0.2},
               "claude-haiku-fast": {"intelligence": 0.6, "speed": 0.95, "cost": 0.9},
               "gemini-pro": {"intelligence": 0.9, "speed": 0.6, "cost": 0.5}}


def choose_model(prefs: types.ModelPreferences | None) -> str:
    for hint in (prefs.hints or []) if prefs else []:
        matches = [m for m in HOST_MODELS if hint.name and hint.name in m]
        if matches:
            return matches[0]
    p = prefs or types.ModelPreferences()
    score = lambda m: ((p.intelligence_priority or 0) * HOST_MODELS[m]["intelligence"] +
                       (p.speed_priority or 0) * HOST_MODELS[m]["speed"] +
                       (p.cost_priority or 0) * HOST_MODELS[m]["cost"])
    return max(HOST_MODELS, key=score)


async def host_llm(context, params: types.CreateMessageRequestParams):
    model = choose_model(params.model_preferences)
    print(f"  [host] approve sampling? prompt={params.messages[0].content.text.splitlines()[0]!r} "
          f"maxTokens={params.max_tokens} -> approved, using {model}")
    reply = "VY1307: morning departure, one stop, cheapest option that fits."   # a deterministic 'LLM'
    return types.CreateMessageResult(role="assistant", model=model, stop_reason="endTurn",
                                     content=types.TextContent(type="text", text=reply[: params.max_tokens * 4]))


async with Client(flights, sampling_callback=host_llm) as client:
    interim = await client.session.call_tool("find_best_flight", {"preferences": "morning, max 1 stop"},
                                              allow_input_required=True)
    request = next(iter(interim.input_requests.values()))
    print("input request on the wire:\n", wire(request)[:900])
    final = await client.call_tool("find_best_flight", {"preferences": "morning, max 1 stop"})
    print("\nfinal:", final.content[0].text)
```

我们的宿主里没有 “sonnet” 模型，所以第一个提示没有命中，而 `"claude"` 匹配成功。这正是规范所描述的那种建议性的、基于子字符串的行为。

### 6. 同一个服务器，旧协议：旧版模式使用服务器发起的请求
使用 `mode="legacy"` 时，客户端讲的是 2025-11-25 协议，SDK 会在调用中途把 `sampling/createMessage` 作为一个真正的**服务器到客户端请求**发送出去，这就是 MRTR 之前的做法。解析器代码不需要改动。不过，像 `ctx.elicit(...)` 这样旧式的命令式辅助函数只能在旧时代协议（Legacy Era）下工作。在 2026-07-28 连接上没有反向通道，它们会失败。

```python
legacy_demo = MCPServer("legacy-demo")


class Answer(BaseModel):
    name: str


@legacy_demo.tool()
async def ask_name_old_style(ctx: Context) -> str:
    """Ask for a name the pre-2026 way (server-initiated elicitation/create)."""
    result = await ctx.elicit("What is your name?", Answer)
    return f"{result.action}: {getattr(result, 'data', None)}"


async def name_ui(context, params):
    return types.ElicitResult(action="accept", content={"name": "Ada"})

async with Client(flights, mode="legacy", sampling_callback=host_llm) as old:
    print("legacy era", old.protocol_version, "->", (await old.call_tool(
        "find_best_flight", {"preferences": "cheap"})).content[0].text)

for mode in ["legacy", "auto"]:
    async with Client(legacy_demo, mode=mode, elicitation_callback=name_ui) as c:
        try:
            r = await c.call_tool("ask_name_old_style", {})
            print(f"{c.protocol_version}: ctx.elicit ->", r.content[0].text)
        except Exception as err:
            print(f"{c.protocol_version}: ctx.elicit -> {type(err).__name__}: {err}")
```

这就是用代码讲述的迁移课：**用解析器或显式的 `InputRequiredResult`（需输入结果）编写新服务器**（第 5.3 课），而不是使用服务器发起的调用。

### 7. 带工具的采样（同样已弃用）：需要 `sampling.tools`
服务器可以为宿主的模型提供一组仅限于该请求的工具。如果没有 `sampling.tools` 能力（Capability），SDK 会拒绝发送这样的请求。有了这项能力，回调会收到 `tools` 和 `toolChoice`，模型可以用 `tool_use` 块和 `stopReason: "toolUse"` 作答。

```python
weather = MCPServer("weather")
GET_WEATHER = types.Tool(name="get_weather", description="Get current weather for a city",
                         input_schema={"type": "object", "properties": {"city": {"type": "string"}}, "required": ["city"]})


def plan(question: str) -> Sample:
    return Sample([types.SamplingMessage(role="user", content=types.TextContent(type="text", text=question))],
                  max_tokens=300, tools=[GET_WEATHER], tool_choice=types.ToolChoice(mode="auto"))


@weather.tool()
def compare_weather(question: str,
                    step: Annotated[types.CreateMessageResultWithTools, Resolve(plan)]) -> str:
    """Let the client's model decide which weather lookups to make."""
    return json.dumps(step.model_dump(by_alias=True, exclude_none=True, mode="json"))


async def tool_llm(context, params):
    print("  [host] tools offered:", [t.name for t in params.tools or []], "| toolChoice:", params.tool_choice.mode)
    return types.CreateMessageResultWithTools(
        role="assistant", model="claude-opus-5-5", stop_reason="toolUse",
        content=[types.ToolUseContent(type="tool_use", id="call_1", name="get_weather", input={"city": "Paris"}),
                 types.ToolUseContent(type="tool_use", id="call_2", name="get_weather", input={"city": "London"})])

async with Client(weather, sampling_callback=tool_llm) as c:          # sampling, but not sampling.tools
    try:
        await c.call_tool("compare_weather", {"question": "Paris or London?"})
    except MCPError as err:
        print("without sampling.tools ->", err.error.code, err.error.message)

tools_cap = types.SamplingCapability(tools=types.SamplingToolsCapability())
async with Client(weather, sampling_callback=tool_llm, sampling_capabilities=tools_cap) as c:
    out = await c.call_tool("compare_weather", {"question": "Paris or London?"})
    print("with sampling.tools    ->", out.content[0].text)
```

在完整的循环中，服务器接下来会运行两次 `get_weather`，并发送一个*新的*采样请求，其历史记录以一条**只**包含 `tool_result` 块（`toolUseId` 为 `call_1` 和 `call_2`）的用户消息结尾，如此反复，直到 `endTurn`。

### 8. 根目录（已弃用），以及推荐的替代方案
先看已弃用的方式。一个 `ListRoots()` 解析器让服务器向客户端索取其 `file://` 根目录（Roots）。然后是**迁移方案**：服务器在启动时从**配置**中获取允许的目录，工具则把目录作为**参数**接收。它通过解析每一条路径（这能挫败 `..` 和符号链接）并检查其是否仍位于某个允许的目录内，来校验每一条路径。

```python
import tempfile
from pathlib import Path

from mcp.server.mcpserver import ListRoots
from mcp.server.mcpserver.exceptions import ToolError

workspace = Path(tempfile.mkdtemp())
(workspace / "itineraries").mkdir()
(workspace / "itineraries" / "barcelona.md").write_text("Day 1: Sagrada Familia")
(workspace / "secrets.txt").write_text("do not leak")

# --- deprecated: roots via an input request ---
roots_server = MCPServer("roots-demo")


def fetch_roots() -> ListRoots:
    return ListRoots()


@roots_server.tool()
def list_workspace(roots: Annotated[types.ListRootsResult, Resolve(fetch_roots)]) -> list[str]:
    """List files under the client's roots (deprecated mechanism)."""
    files = []
    for root in roots.roots:
        base = Path(str(root.uri).removeprefix("file://"))
        files += [str(p.relative_to(base)) for p in sorted(base.rglob("*")) if p.is_file()]
    return files


async def my_roots(context):
    return types.ListRootsResult(roots=[types.Root(uri=f"file://{workspace / 'itineraries'}", name="Itineraries")])

async with Client(roots_server, list_roots_callback=my_roots) as c:
    print("roots-based listing:", (await c.call_tool("list_workspace", {})).structured_content)

# --- recommended: server configuration + explicit tool parameter ---
ALLOWED_DIRS = [(workspace / "itineraries").resolve()]       # e.g. from argv/env when the host launches the server
files_server = MCPServer("files")


@files_server.tool()
def read_text_file(directory: str, filename: str) -> str:
    """Read a text file from a directory the server is configured to allow."""
    target = (Path(directory) / filename).resolve()
    if not any(target.is_relative_to(allowed) for allowed in ALLOWED_DIRS):
        raise ToolError(f"{filename!r} resolves outside the allowed directories")
    return target.read_text()


async with Client(files_server) as c:
    ok = await c.call_tool("read_text_file", {"directory": str(workspace / "itineraries"), "filename": "barcelona.md"})
    print("allowed  :", ok.is_error, ok.content[0].text)
    bad = await c.call_tool("read_text_file", {"directory": str(workspace / "itineraries"), "filename": "../secrets.txt"})
    print("traversal:", bad.is_error, bad.content[0].text)
```

路径穿越（Directory Traversal）的尝试在*服务器内部*失败，并以 `isError: true` 的形式返回，附带一个模型能读懂的原因。我们是有意抛出 `ToolError` 的：`MCPServer` 会隐藏任何*意外*异常的消息（普通的 `ValueError` 到达客户端时只会显示 “Error executing tool read_text_file”）。另外请注意，目录现在出现在了**工具调用**本身之中，因此宿主的审批界面会向用户准确展示模型想要访问哪个文件夹。

### 9. 可选：把采样迁移为直接调用提供商
采样（Sampling）的替代方案就是普通代码：服务器用*自己的*密钥调用 LLM API。当设置了 `ANTHROPIC_API_KEY` 时，这个工具会直接询问 Claude。否则它会使用一个确定性的回退结果，以保证笔记本仍能运行。

```python
import os

direct = MCPServer("flights-direct")


@direct.tool()
def recommend_flight(preferences: str) -> str:
    """Recommend a flight by calling the LLM provider directly (no sampling)."""
    prompt = f"Recommend the best flight in one sentence.\n{FLIGHTS}\nUser preferences: {preferences}"
    if os.environ.get("ANTHROPIC_API_KEY"):
        import anthropic
        response = anthropic.Anthropic().messages.create(
            model="claude-opus-5-5", max_tokens=16000, messages=[{"role": "user", "content": prompt}])
        return "".join(b.text for b in response.content if b.type == "text")
    return "(offline fallback) VY1307 — morning, one stop, cheapest that fits."


async with Client(direct) as c:   # note: no sampling_callback, no sampling capability needed
    print((await c.call_tool("recommend_flight", {"preferences": "morning, max 1 stop"})).content[0].text)
```
