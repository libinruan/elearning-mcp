## Summary
一个会接触用户数据的远程 MCP 服务器，需要知道调用者*是谁*、以及*可以做什么*。MCP 并没有另起炉灶发明自己的方案，而是对 **OAuth 2.1** 做了一份配置规范（profile）。MCP 服务器是 OAuth 的**资源服务器（Resource Server）**，MCP 客户端是 OAuth 的**客户端（Client）**，另有一个独立的**授权服务器（Authorization Server）**负责与用户交互并签发令牌（Token）。本课一次一个请求地跟踪整个流程：带 `resource_metadata` 的 `401`、受保护资源元数据（Protected Resource Metadata，RFC 9728）、授权服务器元数据（Authorization Server Metadata，RFC 8414 / OIDC Discovery）、注册客户端的三种方式、使用 `S256` 的 PKCE、`resource` 参数（RFC 8707）、`iss` 校验（RFC 9207），以及权限范围质询（Scope Challenge）。Notebook 会在 localhost 上搭建一个玩具授权服务器和一个受保护的 SDK 服务器，先手动、再借助 SDK 跑通整个流程。

## Lesson
### 何时适用授权——何时不适用
授权（Authorization）在 MCP 中是**可选的（OPTIONAL）**，但在以下情况强烈建议启用：服务器访问用户专属数据、需要记录“谁做了什么”的审计日志（Audit Trail）、前置了需要用户同意的 API、运行在访问控制严格的企业环境中，或者希望按用户限流。

规范把这套机制与传输（Transport）绑定在一起：

- 使用**基于 HTTP 的传输**的实现**应当（SHOULD）**遵循授权规范。
- 使用 **stdio** 的实现**不应当（SHOULD NOT）**遵循它，而应**从环境中获取凭据**（放在服务器 `env` 中的 API 密钥，或嵌入在服务器里的某个库）。stdio 服务器是用户自己启动的本地进程，在那里跳一遍浏览器重定向的舞步毫无收益。
- 其他传输**必须（MUST）**遵循其协议既有的安全最佳实践。

### 三种角色
| 角色 | OAuth 术语 | 职责 |
| --- | --- | --- |
| MCP 服务器 | **资源服务器** | 接收携带访问令牌的请求并校验令牌。发布受保护资源元数据。 |
| MCP 客户端 | **OAuth 客户端** | 发现授权服务器，代表用户（资源所有者）获取令牌，并在每个请求中发送令牌。 |
| 授权服务器（AS） | 授权服务器 | 认证用户、征求同意、签发令牌。可以与 MCP 服务器部署在一起，也可以独立部署（Keycloak、Entra ID、Auth0、Okta……）。 |

授权服务器的内部实现不在 MCP 的范围之内。MCP 标准化的是：一个从未见过某服务器的客户端，如何*找到*正确的授权服务器，并拿到一个*绑定到该服务器*的令牌。

### 它所依托的标准
MCP 实现了以下标准中精选的一个子集：OAuth 2.1（draft-ietf-oauth-v2-1-13）、Bearer 令牌用法（Bearer Token Usage，RFC 6750）、授权服务器元数据（Authorization Server Metadata，RFC 8414）、动态客户端注册（Dynamic Client Registration，RFC 7591）、资源指示符（Resource Indicators，RFC 8707）、受保护资源元数据（Protected Resource Metadata，RFC 9728）、授权服务器颁发者标识（Authorization Server Issuer Identification，RFC 9207）、OAuth 客户端 ID 元数据文档（Client ID Metadata Documents，draft-ietf-oauth-client-id-metadata-document-00）、OpenID Connect Discovery 1.0 以及 OIDC 动态客户端注册。规范性核心如下：

1. 授权服务器**必须（MUST）**为机密客户端（Confidential Client）和公共客户端（Public Client）实现 OAuth 2.1。
2. 授权服务器与客户端**应当（SHOULD）**支持客户端 ID 元数据文档；**可以（MAY）**支持动态客户端注册（已弃用）。
3. MCP 服务器**必须（MUST）**实现受保护资源元数据；客户端**必须（MUST）**用它来发现授权服务器。
4. 授权服务器**必须（MUST）**提供 RFC 8414 元数据或 OIDC Discovery；客户端**必须（MUST）**两者都支持。

### 流程，一步一步来
```text
Client                     MCP server (RS)                 Authorization server
  │ POST /mcp (no token)        │                                │
  │────────────────────────────►│                                │
  │ 401 WWW-Authenticate:       │                                │
  │   Bearer resource_metadata=…, scope="files:read"             │
  │◄────────────────────────────│                                │
  │ GET /.well-known/oauth-protected-resource[/mcp]              │
  │────────────────────────────►│  {resource, authorization_servers, scopes_supported}
  │ GET /.well-known/oauth-authorization-server (or openid-configuration)
  │─────────────────────────────────────────────────────────────►│
  │ register: CIMD URL | pre-registered id | DCR POST /register  │
  │ browser → /authorize?…&code_challenge&resource&state         │
  │ ◄── redirect ?code&state&iss  (validate state + iss)         │
  │ POST /token  code + code_verifier + resource                 │
  │◄───────────────────────────────────── access (+refresh) token│
  │ POST /mcp  Authorization: Bearer …  (every request)          │
```

**1. 质询。** 未经认证的请求会得到 `401 Unauthorized` 和一个 `WWW-Authenticate` 头。服务器**必须（MUST）**通过该头中的 `resource_metadata`（RFC 9728 §5.1）或某个 well-known URI 公布其元数据；它**应当（SHOULD）**再加一个 `scope` 参数，列出所需的权限范围（Scope）。

```http
HTTP/1.1 401 Unauthorized
WWW-Authenticate: Bearer resource_metadata="https://mcp.example.com/.well-known/oauth-protected-resource",
                         scope="files:read"
```

**2. 受保护资源元数据（PRM）。** 若头中给出了 URL，客户端**必须（MUST）**使用它；否则按顺序依次尝试：插入路径的 URI（对于位于 `/public/mcp` 的端点，即 `https://example.com/.well-known/oauth-protected-resource/public/mcp`），然后是根路径（`/.well-known/oauth-protected-resource`）。该文档**必须（MUST）**包含 `authorization_servers`，且至少有一项：

```json
{"resource": "https://your-server.com/mcp",
 "authorization_servers": ["https://auth.your-server.com"],
 "scopes_supported": ["mcp:tools", "mcp:resources"]}
```

如果列出了多个授权服务器，由**客户端**来选择。它们彼此独立：凭据和令牌**按授权服务器**分别保存，绝不假定在另一个授权服务器上同样有效。

**3. 授权服务器元数据。** MCP 使用默认的 `oauth-authorization-server` 后缀。对于带路径的颁发者（Issuer，如 `https://auth.example.com/tenant1`），客户端**必须（MUST）**依次尝试：`/.well-known/oauth-authorization-server/tenant1`、`/.well-known/openid-configuration/tenant1`、`/tenant1/.well-known/openid-configuration`。不带路径时：先 `/.well-known/oauth-authorization-server`，再 `/.well-known/openid-configuration`。取回文档后，其中的 `issuer` **必须（MUST）**与用来构造 URL 的颁发者完全一致；否则客户端**不得（MUST NOT）**使用它（位于 `attacker.example`、却声称 `"issuer": "https://honest.example"` 的文档会被拒绝）。

元数据同时也是 PKCE 的闸门：如果 `code_challenge_methods_supported` **缺失**，客户端**必须拒绝继续（MUST refuse to proceed）**——OAuth 没有其他途径来发现是否支持 PKCE。为 MCP 提供服务的 OIDC 提供方**必须（MUST）**包含该字段。

**4. 客户端注册。** 客户端**必须（MUST）**获得一个 `client_id`。对于支持所有方式的客户端，优先级顺序如下：

| 优先级 | 机制 | 适用场景 |
| --- | --- | --- |
| 1 | **预注册（Pre-registration）** | 客户端已持有该授权服务器的凭据（硬编码，或由用户输入）。 |
| 2 | **客户端 ID 元数据文档（CIMD）** | 授权服务器声明 `client_id_metadata_document_supported: true`。`client_id` *本身就是*一个带路径的 HTTPS URL（例如 `https://app.example.com/oauth/client-metadata.json`），指向的 JSON 至少包含 `client_id`、`client_name`、`redirect_uris`；其中的 `client_id` 必须与该 URL 完全相同。授权服务器会取回它、校验它，并据此核对请求中的重定向 URI。 |
| 3 | **动态客户端注册（DCR，RFC 7591）** | 授权服务器声明了 `registration_endpoint`。**在 2026-07-28 中已弃用**，由 CIMD 取代；为向后兼容而保留。客户端**必须（MUST）**发送合适的 `application_type`——桌面/CLI/localhost 应用用 `"native"`，远程浏览器应用用 `"web"`——因为 OIDC 默认是 `"web"`，会拒绝原生应用风格的重定向 URI。 |
| 4 | 提示用户 | 其他方式都行不通时。 |

CIMD 契合 MCP 的常态——客户端与服务器**事先毫无关系**——同时又不会让授权服务器堆积成千上万条匿名注册。**授权服务器绑定（Authorization Server Binding）**（2026-07-28 新增）：预注册或通过 DCR 获得的凭据**必须（MUST）**以授权服务器的 `issuer` 为键保存；如果之后 PRM 指向了另一个授权服务器，客户端**不得（MUST NOT）**复用这些凭据，并且**必须（MUST）**重新注册。CIMD 的客户端 ID 则是可移植的，因为任何授权服务器都能按需解析那个 URL。

**5. 带 PKCE 的授权请求。** 客户端生成一个随机的 `code_verifier`，并发送 `code_challenge = BASE64URL(SHA256(code_verifier))` 以及 `code_challenge_method=S256`（只要技术上可行，就**必须（MUST）**使用 `S256`）。它再加上 `state`、选定的 `scope` 以及 `resource` 参数，然后打开浏览器。在重定向之前，客户端**必须（MUST）**把已校验过的授权服务器 `issuer` 与 verifier 和 state 一起记录下来。

**6. 回调与 `iss` 校验（RFC 9207）。** 授权服务器重定向回来，带上 `code`、`state`，并且**应当（SHOULD）**带上 `iss`。会发送 `iss` 的授权服务器**必须（MUST）**声明 `authorization_response_iss_parameter_supported: true`。在把授权码发往任何地方之前，客户端按下表处理：

| `…iss_parameter_supported` | 是否带有 `iss`？ | 处理 |
| --- | --- | --- |
| `true` | 是 | 与记录的颁发者比较（简单字符串比较） |
| `true` | 否 | **拒绝** |
| false / 缺失 | 是 | 照样比较 |
| false / 缺失 | 否 | 继续 |

不允许做任何规范化（大小写折叠、默认端口、末尾斜杠），一旦不匹配，客户端**不得（MUST NOT）**依据 `error`/`error_description` 采取行动或将其展示出来。这能挫败**混淆攻击（Mix-up Attack）**：恶意授权服务器诱骗客户端把另一个授权服务器的授权码发给它。规范预计未来的修订版会把授权服务器携带 `iss` 的要求从 SHOULD 升级为 MUST。

**7. 令牌请求。** 向 `token_endpoint` 发送 `POST`，带上 `grant_type=authorization_code`、`code`、`redirect_uri`、`client_id`、`code_verifier` 和 `resource`。授权服务器对 verifier 做哈希并比较——没有它，被截获的授权码毫无用处。

**8. 调用服务器。** 每个 HTTP 请求都携带 `Authorization: Bearer <token>`。令牌**不得（MUST NOT）**放在查询字符串里。

### 资源指示符与服务器规范 URI
客户端**必须（MUST）**在授权请求和令牌请求**两处**都发送 `resource`（资源指示符（Resource Indicator），RFC 8707），**必须（MUST）**使用 MCP 服务器的**规范 URI（Canonical URI）**，并且无论授权服务器是否支持，都**必须（MUST）**发送。规范 URI 是标识该服务器的最具体的绝对 URI：`https://mcp.example.com/mcp`、`https://mcp.example.com`、`https://mcp.example.com:8443`。无效示例：`mcp.example.com`（没有 scheme）、`https://mcp.example.com#fragment`。优先不带末尾斜杠；小写的 scheme 和 host 是规范形式，但实现**应当（SHOULD）**接受大写。

为什么重要：授权服务器可以把该资源写进令牌的受众（Audience，`aud`），这样为你的日历服务器签发的令牌就无法被重放到你的薪资服务器上。

### 服务器必须检查什么
- 按 OAuth 2.1 §5.2 校验令牌，并**校验受众（Audience Validation）**：令牌**必须（MUST）**是专门为本服务器签发的（RFC 8707 §2）。无效或过期 → **401**。
- **不得（MUST NOT）**接受或转发任何其他令牌。如果服务器要调用上游 API，它应以该 API 的 OAuth 客户端身份获取一个*单独的*令牌——绝不透传自己收到的那个（见第 6.2 课）。
- 客户端**不得（MUST NOT）**向某个服务器发送并非由该服务器的授权服务器签发的令牌。

| 状态码 | 含义 |
| --- | --- |
| 401 | 需要授权，或令牌无效/过期 |
| 403 | 权限范围/权限不足 |
| 400 | 授权请求格式错误 |

### 权限范围选择与递进授权
初始权限范围（Scope）按优先级：(1) 401 的 `WWW-Authenticate` 中的 `scope`；(2) 否则取 PRM 的全部 `scopes_supported`；(3) 再否则省略 `scope`。客户端**必须（MUST）**把质询给出的权限范围视为当前操作的权威依据，并且**不得（MUST NOT）**假设它与 `scopes_supported` 之间存在任何子集/超集关系——后者本意是基本功能所需的*最小*集合。

运行时，缺少某项权限的令牌会收到一个**权限范围质询（Scope Challenge）**：

```http
HTTP/1.1 403 Forbidden
WWW-Authenticate: Bearer error="insufficient_scope",
                         scope="files:write",
                         resource_metadata="https://mcp.example.com/.well-known/oauth-protected-resource",
                         error_description="File write permission required for this operation"
```

服务器**应当（SHOULD）**在一次质询中给出该操作所需的*全部*权限范围（不要挤牙膏式地逐个给）。代表用户行事的客户端**应当（SHOULD）**执行**递进授权流程（Step-up Flow）**：计算此前请求过的权限范围与质询中权限范围的**并集**（权限范围的累积是*客户端*的职责，这样服务器就能保持无状态（Stateless）），重新授权，有限次数地重试，并记录尝试次数以避免死循环。服务器**必须（MUST）**遵循权限范围的层级关系（更宽的权限范围蕴含更窄的）。

### 刷新令牌
希望获得刷新令牌（Refresh Token）的客户端**必须（MUST）**在传输中和存储时对其保密，**应当（SHOULD）**在其 `grant_types` 中列出 `refresh_token`，当授权服务器的 `scopes_supported` 包含 `offline_access` 时**可以（MAY）**把它加进 `scope`，并且**不得（MUST NOT）**假定一定会签发刷新令牌。MCP 服务器**不应当（SHOULD NOT）**在其质询或 PRM 中放入 `offline_access`——刷新是客户端的事，而不是资源的要求。对于公共客户端，授权服务器**必须（MUST）**轮换刷新令牌。

### Keycloak 教程速览
官方教程在 Docker 中运行 Keycloak（`start-dev`，admin/admin，端口 8080，切勿用于生产），创建一个 `mcp:tools` 客户端权限范围（类型为 *Default*，开启 *Include in token scope*），添加一个**受众映射器（Audience Mapper）**使令牌携带 `aud: http://localhost:3000`，为测试放宽 DCR 的 *Trusted Hosts* 策略，并为 MCP 服务器自身注册一个机密客户端，以便它调用 Keycloak 的**令牌内省（Token Introspection）**端点。Python 服务器是一个 `MCPServer`，带有 `token_verifier=IntrospectionTokenVerifier(...)` 和 `auth=AuthSettings(issuer_url=..., required_scopes=["mcp:tools"], resource_server_url=...)`；之后 SDK 会发布 PRM、用带 `resource_metadata` 的 401 作答，并把每个 Bearer 令牌交给校验器，校验器先检查 `active`，再将 `aud` 与服务器 URL 比对。测试客户端是 VS Code：它会打开同意页面并列出工具。教程提醒，固定受众只是测试捷径——在生产环境中，受众必须跟随 `resource` 参数。

### 常见陷阱（来自文档）
- **不要手写令牌校验**——使用久经考验的库。
- **访问令牌要短期有效**；缓存的令牌加密存储并设置淘汰策略。
- **始终校验**——收到令牌什么也证明不了。拒绝 `api` 这类泛化受众。
- **处处使用 HTTPS**，开发期间的 `localhost` 除外。
- **最小权限范围**，在服务器端按工具/路由逐一检查。
- **绝不记录** `Authorization` 头、令牌、授权码或密钥。
- **分离**服务器自身的客户端密钥与终端用户流程。
- **规范的质询**：401 时包含 `Bearer`、`realm`、`resource_metadata`。
- 如果保留 DCR，**要把它锁紧**：未经认证的 DCR 让任何人都能注册任意客户端。
- **固定颁发者/租户**：拒绝来自其他 realm 的令牌，即使它们由同一个授权服务器签名。
- 对客户端返回**通用错误**，详细原因连同关联 ID（Correlation ID）记录在内部日志中。

> **2026-07-28 中的规范变化。** 授权响应中的 `iss`（对授权服务器是 SHOULD，对客户端是 MUST 校验，SEP-2468）；DCR 中必须带 `application_type`（SEP-837）；凭据绑定到签发它的授权服务器（SEP-2352）；DCR **已弃用**，由 CIMD 取代。针对 2025-06-18 或 2025-11-25 编写的代码库通常仍以 DCR 为主——两种都要做好遇到的准备。

## Key points
- 授权是可选的；HTTP 传输（Transport）**应当（SHOULD）**使用 OAuth 2.1 配置规范，**stdio 不应当（SHOULD NOT）**使用，而是从环境中获取凭据。
- MCP 服务器 = **资源服务器（Resource Server）**，MCP 客户端 = **OAuth 客户端**，外加一个独立或同址部署的**授权服务器（Authorization Server）**。
- 发现链：`401` + `WWW-Authenticate: resource_metadata=…` → 带有 `authorization_servers` 的**受保护资源元数据（PRM，RFC 9728）** → **授权服务器元数据（RFC 8414 / OIDC Discovery）**，其 `issuer` 必须完全匹配。
- 注册优先级：**预注册 → CIMD（以 HTTPS URL 作为 `client_id`）→ DCR（已弃用，需要 `application_type`）→ 询问用户**；非 CIMD 的凭据绑定到授权服务器（Authorization Server）的 `issuer`。
- **使用 `S256` 的 PKCE** 是强制的；授权服务器元数据中没有 `code_challenge_methods_supported` → 拒绝继续。
- `resource`（资源指示符（Resource Indicator），RFC 8707）= 服务器的**规范 URI（Canonical URI）**，在授权请求和令牌请求中都要发送；服务器**必须（MUST）**拒绝受众不是自己的令牌。
- 在兑换授权码之前，于回调中校验 **`iss`**（RFC 9207）——这是对混淆攻击（Mix-up Attack）的防御。
- `403` + `error="insufficient_scope"` + `scope=…` 触发**递进授权（Step-up Authorization）**；客户端以新旧权限范围的**并集**重新授权。
- 令牌只放在每个请求的 `Authorization: Bearer` 中——绝不放进查询字符串，绝不写进日志。

## Pitches
### MCP 中的授权是怎么工作的？
MCP 复用了 OAuth 2.1。MCP 服务器是一个资源服务器（Resource Server）；我不带令牌去调用它，它会回 401，并把我指向它的受保护资源元数据（Protected Resource Metadata），里面写明了授权服务器（Authorization Server）。我去取那个授权服务器的元数据，完成注册——最好用客户端 ID 元数据文档（Client ID Metadata Document）——然后跑一遍带 PKCE 的授权码流程，把服务器的规范 URI 作为 resource 参数传进去。拿回来的令牌就绑定在这台服务器上，之后每个请求我都把它放在 Bearer 头里发送。

### 为什么资源指示符在 MCP 里这么重要？
一个用户会把一个客户端连到很多服务器上，而且往往走的是同一个身份提供方（Identity Provider）。如果没有受众（Audience）绑定，给一个无害的笔记服务器的令牌，同样能拿去访问薪资服务器；恶意服务器也可以把收到的令牌重放出去。资源指示符（Resource Indicator）告诉授权服务器这个令牌是给哪台 MCP 服务器的，它就能把这一点写进受众，而每台服务器都会拒绝不是签发给自己的令牌。就这一项检查，同时撑起了防令牌窃取和禁止令牌透传（Token Passthrough）这两件事。

### 2026-07-28 版本里 MCP 授权有哪些变化？
我会讲四点。第一，动态客户端注册（Dynamic Client Registration）现在已弃用，改用客户端 ID 元数据文档（Client ID Metadata Document），客户端 ID 就是一个指向客户端自身元数据的 HTTPS URL。第二，客户端必须校验授权响应里 RFC 9207 的 iss 参数，这能挡住混淆攻击（Mix-up Attack）。第三，通过预注册或 DCR 拿到的凭据现在绑定到签发它的授权服务器上，授权服务器一变就不能再复用。第四，DCR 请求必须带上 application_type，这样 OIDC 提供方才会接受 localhost 的重定向地址。

## Interview
### 讲一讲客户端第一次连接受保护的 MCP 服务器时会发生什么。
客户端不带令牌（Token）发出请求，得到 **401** 和 `WWW-Authenticate: Bearer resource_metadata="…"`（最好还有 `scope="…"`）。它去取**受保护资源元数据（Protected Resource Metadata）**（RFC 9728）——如果没有这个头，就依次回退到插入路径的、再到根路径的 `/.well-known/oauth-protected-resource`——并从 `authorization_servers` 中选一个授权服务器（Authorization Server）。它按规定顺序通过 RFC 8414 或 OIDC Discovery 获取**授权服务器元数据**，检查 `issuer` 完全匹配、且 `code_challenge_methods_supported` 存在。它拿到一个 `client_id`（预注册、CIMD，或已弃用的 DCR），生成 PKCE 和 `state`，带着 `resource=<canonical URI>` 和选定的权限范围打开 `/authorize`，同时记录预期的颁发者。在回调中，它校验 `state` 和 `iss`，再到 `/token` 用 `code_verifier` 和 `resource` 兑换授权码，然后带着 `Authorization: Bearer` 重试 MCP 请求。

### 为什么 stdio 不使用 OAuth？
规范规定 stdio 实现**不应当（SHOULD NOT）**遵循授权规范，而应从环境中获取凭据。stdio 服务器是用户启动的本地子进程，它本来就以用户的权限运行，所以既没有需要保护的远程资源服务器（Resource Server），也没有 Bearer 令牌需要跨越的网络边界。凭据来自每个服务器的 `env` 配置，或嵌入在服务器里的某个库（这个库仍可能自行对上游服务跑一遍浏览器登录）。OAuth 是为远程 HTTP 服务器设计的——在那种场景下，客户端必须向另一个独立服务证明用户已经授权给它。

### PKCE 防的是什么？为什么光有它还不够？
PKCE 把授权码（Authorization Code）绑定到发起流程的那个客户端实例上：客户端保留一个随机的 `code_verifier`，在授权请求中只发送它的 SHA-256 哈希（`S256`），兑换授权码时必须出示 verifier。截获授权码的攻击者——无论是通过监听 localhost 端口的恶意应用、日志还是 referrer——都无法用它换到令牌。但它**挡不住混淆攻击（Mix-up Attack）**：如果恶意授权服务器诱骗客户端把诚实授权服务器的授权码发到攻击者的令牌端点，客户端会连 verifier 一起交出去。这就是 2026-07-28 增加 RFC 9207 `iss` 校验的原因，也是客户端必须在元数据中检查 PKCE 支持、不支持就拒绝的原因。

### 客户端收到一个带 `error="insufficient_scope", scope="files:write"` 的 403，应该怎么做？
把质询中的权限范围（Scope）视为本次操作的权威依据，计算此前请求过的权限范围与 `files:write` 的**并集**（否则重新授权会丢掉 `files:read`，导致其他工具失效），用这个集合重新走一遍授权流程，然后重试原始请求。它应该限制重试次数（最多几次），记住失败情况，以免在用户或授权服务器一直拒绝的权限范围上陷入死循环，并把反复失败视为永久失败。以自身名义行事的 `client_credentials` 客户端则可以直接放弃。

### 陷阱题：我们的服务器校验了 JWT 签名和过期时间。这就够了吗？
不够。令牌可能完全有效——只不过是给*另一个*资源的。MCP 服务器**必须（MUST）**检查令牌是为自己签发的（`aud` 声明或内省结果中的受众（Audience）与规范 URI 匹配），并且应当固定预期的颁发者/租户，因为同一个授权服务器下其他 realm 的令牌可能共用签名密钥。权限范围也必须在服务器端按工具逐一强制执行——“令牌里写着 `admin`”算不上授权逻辑。没有受众检查，用户从该授权服务器拿到过的任何令牌都能用来访问你，一个被攻破的兄弟服务也能把令牌重放到你这里。

### 什么时候你会选 CIMD，而不是预注册或 DCR？
对于 MCP 的常见情形——一个客户端（比如某个 IDE）和一个素未谋面的服务器——CIMD（客户端 ID 元数据文档（Client ID Metadata Document））是默认选择。客户端在一个稳定的 HTTPS URL 上托管一份 JSON 文档，并把这个 URL 用作 `client_id`；任何声明了 `client_id_metadata_document_supported` 的授权服务器都能校验它，而且它可以跨授权服务器移植。当双方*确实*已有关系时——比如一个已在公司 IdP 注册过的企业应用——预注册胜出，它在优先级顺序中也排第一。DCR 已被弃用：它会产生数量不受限的匿名注册，而且除非锁紧，任何人都能注册任意客户端。只为遗留的授权服务器保留它。

## Glossary
- Resource server | 资源服务器 | MCP 服务器所扮演的 OAuth 角色：在受保护的请求中接收并校验访问令牌。
- Authorization server (AS) | 授权服务器 | 认证用户、获取同意并签发访问令牌的服务。
- Protected Resource Metadata (RFC 9728) | 受保护资源元数据 | 位于 `/.well-known/oauth-protected-resource` 的 JSON 文档，列出服务器的 `authorization_servers` 和 `scopes_supported`。
- Authorization Server Metadata (RFC 8414) | 授权服务器元数据 | 授权服务器的发现文档，包含 `issuer`、各端点以及 `code_challenge_methods_supported` 等受支持特性。
- PKCE (`S256`) | PKCE 授权码证明密钥 | 一对 verifier/challenge，使被截获的授权码除原始客户端外谁都无法使用。
- Resource indicator (RFC 8707) | 资源指示符 | 指明服务器规范 URI 的 `resource` 参数，使令牌绑定到该受众。
- Audience (`aud`) | 受众 | 说明令牌是为哪个资源签发的令牌声明；服务器必须拒绝不属于自己的令牌。
- Client ID Metadata Document (CIMD) | 客户端 ID 元数据文档 | 一种注册方式：`client_id` 是一个指向客户端自身元数据 JSON 的 HTTPS URL。
- Dynamic Client Registration (DCR) | 动态客户端注册 | 通过 `registration_endpoint` 进行的 RFC 7591 注册；在 MCP 2026-07-28 中已弃用。
- Step-up authorization | 递进授权（权限提升） | 在收到 `403 insufficient_scope` 后，以已授予与质询中权限范围的并集重新授权。

### 1. 手动实现 PKCE
PKCE 不过是一个随机密钥及其 SHA-256 哈希。客户端在浏览器重定向（可能泄露）中发送 **challenge**，而把 **verifier** 一直保留到后端信道的令牌请求（Token Request）时才使用。

```python
import base64
import hashlib
import json
import logging
import secrets

logging.getLogger("httpx").setLevel(logging.WARNING)
logging.getLogger("httpx2").setLevel(logging.WARNING)
logging.getLogger("mcp").setLevel(logging.ERROR)


def b64url(raw: bytes) -> str:
    return base64.urlsafe_b64encode(raw).rstrip(b"=").decode()


def make_pkce() -> tuple[str, str]:
    verifier = b64url(secrets.token_bytes(48))              # 64 chars, within the 43..128 allowed
    challenge = b64url(hashlib.sha256(verifier.encode()).digest())
    return verifier, challenge


verifier, challenge = make_pkce()
print("code_verifier :", verifier, f"({len(verifier)} chars, stays on the client)")
print("code_challenge:", challenge, "(goes in the authorization URL)")
print("method        : S256")
# the AS later recomputes the hash from the verifier the client presents:
print("verifies?     :", b64url(hashlib.sha256(verifier.encode()).digest()) == challenge)
```

### 2. 一个玩具授权服务器
真实部署会使用 Keycloak、Entra ID、Auth0……这里由一个约 60 行的 Starlette 应用扮演授权服务器（Authorization Server），让你看清每个字段。它发布 RFC 8414 元数据（带有 `code_challenge_methods_supported` 和 `authorization_response_iss_parameter_supported`），在 `/authorize` 自动批准用户 “alice”（代替登录 + 同意页面），在 `/token` 强制执行重定向 URI 精确匹配和 PKCE，并把请求中的 `resource` 写进令牌的 `aud`。令牌是 HMAC 签名的 JWT——用于教学没问题，**生产环境中绝不要自己手写这些**。

```python
import hmac
import socket
import threading
import time
from urllib.parse import parse_qs, urlencode, urlparse

import uvicorn
from starlette.applications import Starlette
from starlette.responses import JSONResponse, RedirectResponse
from starlette.routing import Route


def free_port() -> int:
    with socket.socket() as s:
        s.bind(("127.0.0.1", 0))
        return s.getsockname()[1]


def serve(app, port):
    server = uvicorn.Server(uvicorn.Config(app, host="127.0.0.1", port=port, log_level="warning"))
    threading.Thread(target=server.run, daemon=True).start()
    while not server.started:
        time.sleep(0.02)
    return server


AS_PORT, MCP_PORT = free_port(), free_port()
ISSUER = f"http://127.0.0.1:{AS_PORT}"
RESOURCE = f"http://127.0.0.1:{MCP_PORT}/mcp"          # the MCP server's canonical URI
SIGNING_KEY = secrets.token_bytes(32)
REDIRECT_URI = "http://127.0.0.1:33418/callback"


def mint_jwt(claims: dict) -> str:
    head = b64url(json.dumps({"alg": "HS256", "typ": "JWT"}).encode())
    body = b64url(json.dumps(claims).encode())
    sig = b64url(hmac.new(SIGNING_KEY, f"{head}.{body}".encode(), hashlib.sha256).digest())
    return f"{head}.{body}.{sig}"


def read_jwt(token: str) -> dict | None:
    """Return the claims if the signature is valid, else None."""
    try:
        head, body, sig = token.split(".")
        good = b64url(hmac.new(SIGNING_KEY, f"{head}.{body}".encode(), hashlib.sha256).digest())
        if not hmac.compare_digest(sig, good):
            return None
        return json.loads(base64.urlsafe_b64decode(body + "=" * (-len(body) % 4)))
    except ValueError:
        return None


CLIENTS = {"notes-cli": {"redirect_uris": [REDIRECT_URI]}}   # pre-registered clients
CODES: dict[str, dict] = {}
REFRESH: dict[str, dict] = {}


async def as_metadata(request):
    return JSONResponse({
        "issuer": ISSUER,
        "authorization_endpoint": f"{ISSUER}/authorize",
        "token_endpoint": f"{ISSUER}/token",
        "response_types_supported": ["code"],
        "grant_types_supported": ["authorization_code", "refresh_token"],
        "code_challenge_methods_supported": ["S256"],
        "token_endpoint_auth_methods_supported": ["none"],
        "scopes_supported": ["notes:read", "notes:write"],
        "authorization_response_iss_parameter_supported": True,
    })


async def authorize(request):
    q = request.query_params
    client = CLIENTS.get(q.get("client_id"))
    if client is None or q.get("redirect_uri") not in client["redirect_uris"]:   # exact match only
        return JSONResponse({"error": "invalid_request", "error_description": "unknown client or redirect_uri"}, 400)
    if q.get("code_challenge_method") != "S256" or not q.get("code_challenge"):
        return JSONResponse({"error": "invalid_request", "error_description": "PKCE S256 required"}, 400)
    # ... a real AS shows a login + consent page here; we auto-approve user "alice" ...
    code = secrets.token_urlsafe(16)
    CODES[code] = {"client_id": q["client_id"], "redirect_uri": q["redirect_uri"], "challenge": q["code_challenge"],
                   "scope": q.get("scope", ""), "resource": q.get("resource"), "sub": "alice"}
    back = {"code": code, "state": q.get("state", ""), "iss": ISSUER}             # RFC 9207 iss
    return RedirectResponse(f"{q['redirect_uri']}?{urlencode(back)}", status_code=302)


def issue_tokens(sub, client_id, scope, resource, ttl=300):
    now = int(time.time())
    access = mint_jwt({"iss": ISSUER, "sub": sub, "aud": resource, "client_id": client_id,
                       "scope": scope, "iat": now, "exp": now + ttl})
    refresh = secrets.token_urlsafe(24)
    REFRESH[refresh] = {"sub": sub, "client_id": client_id, "scope": scope, "resource": resource}
    return {"access_token": access, "token_type": "Bearer", "expires_in": ttl, "refresh_token": refresh, "scope": scope}


async def token(request):
    form = await request.form()
    if form.get("grant_type") == "authorization_code":
        rec = CODES.pop(form.get("code"), None)                                   # codes are single-use
        if rec is None or rec["client_id"] != form.get("client_id") or rec["redirect_uri"] != form.get("redirect_uri"):
            return JSONResponse({"error": "invalid_grant"}, 400)
        if b64url(hashlib.sha256(form.get("code_verifier", "").encode()).digest()) != rec["challenge"]:
            return JSONResponse({"error": "invalid_grant", "error_description": "PKCE verification failed"}, 400)
        if form.get("resource") != rec["resource"]:
            return JSONResponse({"error": "invalid_target"}, 400)
        return JSONResponse(issue_tokens(rec["sub"], rec["client_id"], rec["scope"], rec["resource"]))
    if form.get("grant_type") == "refresh_token":
        rec = REFRESH.pop(form.get("refresh_token"), None)                         # rotation: old one dies
        if rec is None:
            return JSONResponse({"error": "invalid_grant", "error_description": "unknown or reused refresh token"}, 400)
        return JSONResponse(issue_tokens(rec["sub"], rec["client_id"], rec["scope"], rec["resource"]))
    return JSONResponse({"error": "unsupported_grant_type"}, 400)


as_app = Starlette(routes=[Route("/.well-known/oauth-authorization-server", as_metadata),
                           Route("/authorize", authorize),
                           Route("/token", token, methods=["POST"])])
as_server = serve(as_app, AS_PORT)
print("authorization server:", ISSUER)
```

### 3. 用 SDK 搭建受保护的 MCP 服务器
SDK 负责资源服务器（Resource Server）的底层管线：给定 `token_verifier=` 和 `auth=AuthSettings(...)`，它会发布 PRM，用 `401` + `resource_metadata` 回应未认证的请求，并且——在 `validate_token_resource=True` 时——拒绝 `AccessToken.resource` 不等于 `resource_server_url` 的令牌。`required_scopes` 作用于*每一个*请求，因此按工具区分的权限范围（Scope）需要你自己检查：一个小小的 ASGI 包装层读取 2026-07-28 的 `Mcp-Method` / `Mcp-Name` 请求头，除非令牌拥有 `notes:write`，否则对 `delete_note` 返回 `403 insufficient_scope`。

```python
from mcp.server import MCPServer
from mcp.server.auth.provider import AccessToken
from mcp.server.auth.settings import AuthSettings


class HmacTokenVerifier:
    """Signature + issuer + expiry. The SDK then compares `resource` (the aud) with resource_server_url."""

    async def verify_token(self, token: str) -> AccessToken | None:
        claims = read_jwt(token)
        if not claims or claims.get("iss") != ISSUER or claims.get("exp", 0) < time.time():
            return None
        return AccessToken(token=token, client_id=claims["client_id"], scopes=claims["scope"].split(),
                           expires_at=claims["exp"], resource=claims["aud"], subject=claims["sub"])


notes_server = MCPServer(
    "notes",
    token_verifier=HmacTokenVerifier(),
    auth=AuthSettings(issuer_url=ISSUER, resource_server_url=RESOURCE,
                      required_scopes=["notes:read"], validate_token_resource=True),
)
NOTES = {"n1": "buy milk", "n2": "renew passport"}


@notes_server.tool()
def list_notes() -> list[str]:
    """List the ids of the user's notes."""
    return sorted(NOTES)


@notes_server.tool()
def delete_note(note_id: str) -> str:
    """Delete one note (needs notes:write)."""
    NOTES.pop(note_id, None)
    return f"deleted {note_id}"


PRM_URL = f"http://127.0.0.1:{MCP_PORT}/.well-known/oauth-protected-resource/mcp"
TOOL_SCOPES = {"delete_note": "notes:write"}
inner_app = notes_server.streamable_http_app()


async def scope_gate(scope, receive, send):
    """Per-tool scope check that emits a spec-shaped 403 challenge."""
    if scope["type"] == "http":
        headers = {k.decode().lower(): v.decode() for k, v in scope["headers"]}
        needed = TOOL_SCOPES.get(headers.get("mcp-name")) if headers.get("mcp-method") == "tools/call" else None
        auth = headers.get("authorization", "")
        if needed and auth.lower().startswith("bearer "):
            claims = read_jwt(auth[7:]) or {}
            if needed not in claims.get("scope", "").split():
                challenge = (f'Bearer error="insufficient_scope", scope="{needed}", '
                             f'resource_metadata="{PRM_URL}", error_description="{needed} required"')
                await send({"type": "http.response.start", "status": 403,
                            "headers": [(b"content-type", b"application/json"),
                                        (b"www-authenticate", challenge.encode())]})
                await send({"type": "http.response.body", "body": b'{"error": "insufficient_scope"}'})
                return
    await inner_app(scope, receive, send)        # lifespan and everything else pass straight through


mcp_server = serve(scope_gate, MCP_PORT)
print("protected MCP server:", RESOURCE)
```

### 5. 第 2–3 步——先取受保护资源元数据，再取授权服务器元数据
顺着指针走，然后按规范规定的顺序构造授权服务器的 well-known URL。客户端**必须**做两项检查：文档中的 `issuer` 等于我们用来构造 URL 的颁发者（Issuer），以及声明了对 PKCE 的支持。

```python
prm = (await http.get(challenge["resource_metadata"])).json()
print("PRM:", json.dumps(prm, indent=2))


def as_metadata_urls(issuer: str) -> list[str]:
    u = urlparse(issuer)
    base, path = f"{u.scheme}://{u.netloc}", u.path.rstrip("/")
    if path:
        return [f"{base}/.well-known/oauth-authorization-server{path}",
                f"{base}/.well-known/openid-configuration{path}",
                f"{base}{path}/.well-known/openid-configuration"]
    return [f"{base}/.well-known/oauth-authorization-server", f"{base}/.well-known/openid-configuration"]


print("\ndiscovery order for a tenant issuer:", *as_metadata_urls("https://auth.example.com/tenant1"), sep="\n  ")

as_issuer = prm["authorization_servers"][0]
for url in as_metadata_urls(as_issuer):
    resp = await http.get(url)
    if resp.status_code == 200:
        asm = resp.json()
        print("\nfound AS metadata at", url)
        break

assert asm["issuer"] == as_issuer, "issuer mismatch -> MUST NOT use this metadata"
assert "S256" in asm.get("code_challenge_methods_supported", []), "no PKCE support -> MUST refuse"
print("issuer matches, S256 supported, iss-in-response advertised:",
      asm.get("authorization_response_iss_parameter_supported"))
```

### 6. 第 4 步——选择注册机制
把客户端注册页面中的优先级顺序写成一个函数。我们的授权服务器既没有 `registration_endpoint`，也不支持 CIMD，但我们已以 `notes-cli` 预注册（Pre-registration）——并绑定到这个颁发者。

```python
PRE_REGISTERED = {ISSUER: "notes-cli"}           # keyed by issuer: credentials are bound to their AS


def choose_registration(asm: dict, cimd_url: str | None) -> str:
    if asm["issuer"] in PRE_REGISTERED:
        return f"pre-registered client_id={PRE_REGISTERED[asm['issuer']]}"
    if cimd_url and asm.get("client_id_metadata_document_supported"):
        return f"CIMD: client_id={cimd_url}"
    if asm.get("registration_endpoint"):
        return "DCR (deprecated): POST registration_endpoint with application_type='native'"
    return "ask the user to enter client information"


print(choose_registration(asm, "https://app.example.com/oauth/client.json"))
print(choose_registration({"issuer": "https://other.example", "client_id_metadata_document_supported": True},
                          "https://app.example.com/oauth/client.json"))
print(choose_registration({"issuer": "https://legacy.example", "registration_endpoint": "https://legacy.example/register"}, None))
```

### 7. 第 5–6 步——授权请求、回调、`state` 与 `iss`
我们用 `httpx`（不跟随重定向）扮演浏览器，并读取授权服务器发回的 `Location` 头。权限范围（Scope）选择：401 中没有 `scope`，所以我们采用 PRM 的 `scopes_supported`。在使用授权码之前，我们检查 `state` 并套用 RFC 9207 的那张表。

```python
def check_iss(as_meta: dict, recorded_issuer: str, iss: str | None) -> None:
    """The 2026-07-28 Authorization Response Validation table."""
    supported = as_meta.get("authorization_response_iss_parameter_supported") is True
    if iss is not None:
        if iss != recorded_issuer:                 # simple string comparison, no normalisation
            raise ValueError(f"iss mismatch: {iss!r} != {recorded_issuer!r} (possible mix-up attack)")
    elif supported:
        raise ValueError("iss missing although the AS advertises it")


verifier, challenge_s256 = make_pkce()
state = secrets.token_urlsafe(16)
pending = {"verifier": verifier, "state": state, "issuer": asm["issuer"]}      # recorded BEFORE redirecting
scope = challenge.get("scope") or " ".join(prm.get("scopes_supported", []))

auth_url = asm["authorization_endpoint"] + "?" + urlencode({
    "response_type": "code", "client_id": "notes-cli", "redirect_uri": REDIRECT_URI, "state": state,
    "code_challenge": challenge_s256, "code_challenge_method": "S256", "scope": scope, "resource": RESOURCE})
print("authorization URL:\n ", auth_url, "\n")

redirect = await http.get(auth_url)
callback = {k: v[0] for k, v in parse_qs(urlparse(redirect.headers["location"]).query).items()}
print("callback params:", json.dumps(callback, indent=2))

assert callback["state"] == pending["state"], "state mismatch -> discard"
check_iss(asm, pending["issuer"], callback.get("iss"))
print("state and iss OK")
for bad_iss in ["http://evil.example", ISSUER + "/", None]:
    try:
        check_iss(asm, pending["issuer"], bad_iss)
    except ValueError as exc:
        print("rejected:", exc)
```

末尾斜杠的情况是故意被拒绝的：规范禁止在比较之前做规范化。

### 8. 第 7 步——兑换授权码

### 9. 第 8 步——带着令牌调用服务器
`Client(url)` 会构建自己的 HTTP 客户端；要添加请求头，就传入一个用 `streamable_http_client(url, http_client=...)` 构建的传输（Transport）（SDK 使用 `httpx2`）。**每个**请求上都带同一个令牌。

```python
import httpx2

        result = await client.call_tool("list_notes", {})
        print("list_notes ->", result.structured_content)

# the same thing on the wire
r = await http.post(RESOURCE, json=LIST_TOOLS, headers={**MCP_HEADERS, "Authorization": f"Bearer {access_token}"})
```

### 10. 搞破坏——服务器必须拒绝的令牌
下面每一个看起来都是合法令牌。只有受众（Audience）绑定正确、未被篡改、未过期、且来自*本*颁发者的那一个能用。

```python
now = int(time.time())
good = read_jwt(access_token)
candidates = {
    "correct token": access_token,
    "audience = another service": mint_jwt({**good, "aud": "https://payroll.example.com/mcp"}),

    "other issuer (same key!)": mint_jwt({**good, "iss": "https://other-tenant.example"}),
```

### 11. 手动完成权限范围质询与递进授权
我们的令牌只有 `notes:read`。调用 `delete_note` 会在运行时得到带所需权限范围（Scope）的 **403**。客户端以新旧权限范围的**并集**重新授权并重试——这就是递进授权（Step-up Authorization）。

```python
call = {"jsonrpc": "2.0", "id": 2, "method": "tools/call",
        "params": {"name": "delete_note", "arguments": {"note_id": "n2"},
                   "_meta": LIST_TOOLS["params"]["_meta"]}}
call_headers = {**MCP_HEADERS, "Mcp-Method": "tools/call", "Mcp-Name": "delete_note"}

r = await http.post(RESOURCE, json=call, headers={**call_headers, "Authorization": f"Bearer {access_token}"})
print("HTTP", r.status_code, "\nWWW-Authenticate:", r.headers["www-authenticate"])
step = parse_www_authenticate(r.headers["www-authenticate"])

granted = set(tokens["scope"].split())
wanted = " ".join(sorted(granted | set(step["scope"].split())))      # union, so notes:read is not lost
print("re-authorizing with scope =", repr(wanted))


async def authorize_and_redeem(scope: str) -> dict:
    v, c = make_pkce()
    s = secrets.token_urlsafe(16)
    loc = (await http.get(asm["authorization_endpoint"] + "?" + urlencode({
        "response_type": "code", "client_id": "notes-cli", "redirect_uri": REDIRECT_URI, "state": s,
        "code_challenge": c, "code_challenge_method": "S256", "scope": scope, "resource": RESOURCE}))).headers["location"]
    cb = {k: x[0] for k, x in parse_qs(urlparse(loc).query).items()}
    assert cb["state"] == s
    check_iss(asm, asm["issuer"], cb.get("iss"))
    return (await http.post(asm["token_endpoint"], data={
        "grant_type": "authorization_code", "code": cb["code"], "redirect_uri": REDIRECT_URI,
        "client_id": "notes-cli", "code_verifier": v, "resource": RESOURCE})).json()


tokens = await authorize_and_redeem(wanted)
r = await http.post(RESOURCE, json=call, headers={**call_headers, "Authorization": f"Bearer {tokens['access_token']}"})
print("retry ->", r.status_code, r.json()["result"]["content"][0]["text"])
```

### 12. 刷新令牌轮换
访问令牌短期有效；刷新令牌（Refresh Token）无需浏览器即可换来新的访问令牌。我们的授权服务器会轮换刷新令牌（规范对公共客户端有此要求），因此被盗且已被使用过的刷新令牌就作废了。

```python
old_refresh = tokens["refresh_token"]
fresh = (await http.post(token_endpoint, data={"grant_type": "refresh_token", "refresh_token": old_refresh,
                                               "client_id": "notes-cli", "resource": RESOURCE})).json()
print("new access token aud/scope:", read_jwt(fresh["access_token"])["aud"], "|", fresh["scope"])
print("refresh token rotated:", fresh["refresh_token"] != old_refresh)
reuse = await http.post(token_endpoint, data={"grant_type": "refresh_token", "refresh_token": old_refresh,
                                              "client_id": "notes-cli", "resource": RESOURCE})
print("reusing the old refresh token ->", reuse.status_code, reuse.json())
```

### 13. 让 SDK 包办一切
`mcp.client.auth.OAuthClientProvider` 是一个 `httpx2.Auth`，它在遇到 401 时跑完整个流程——带回退的 PRM 发现、带颁发者校验的授权服务器元数据、注册、PKCE、`state` + `iss` 检查、带 `resource` 的令牌请求——并在遇到 `403 insufficient_scope` 时执行**递进授权（Step-up Authorization）**。你只需提供存储（这里是内存存储，预注册并绑定到我们的颁发者）以及两个浏览器钩子。一个事件钩子会打印每一次 HTTP 交互。

```python
from mcp.client.auth import AuthorizationCodeResult, OAuthClientProvider
from mcp.shared.auth import OAuthClientInformationFull, OAuthClientMetadata

NOTES["n2"] = "renew passport"


class MemoryStorage:
    def __init__(self):
        self.tokens = None
        self.client = OAuthClientInformationFull(client_id="notes-cli", redirect_uris=[REDIRECT_URI],
                                                 token_endpoint_auth_method="none", issuer=ISSUER)

    async def get_tokens(self): return self.tokens
    async def set_tokens(self, tokens): self.tokens = tokens
    async def get_client_info(self): return self.client
    async def set_client_info(self, info): self.client = info


browser = {}


async def redirect_handler(url: str) -> None:          # a desktop app would open the system browser
    print("    [browser] user approves at", url.split("?")[0])
    async with httpx.AsyncClient(trust_env=False) as b:
        browser["location"] = (await b.get(url)).headers["location"]


async def callback_handler() -> AuthorizationCodeResult:  # ...and listen on the redirect URI
    q = {k: v[0] for k, v in parse_qs(urlparse(browser["location"]).query).items()}
    return AuthorizationCodeResult(code=q["code"], state=q.get("state"), iss=q.get("iss"))


provider = OAuthClientProvider(
    server_url=RESOURCE,
    client_metadata=OAuthClientMetadata(client_name="notes-cli", redirect_uris=[REDIRECT_URI],
                                        grant_types=["authorization_code", "refresh_token"],
                                        token_endpoint_auth_method="none"),
    storage=MemoryStorage(), redirect_handler=redirect_handler, callback_handler=callback_handler)


async def log_exchange(response):
    req = response.request
    print(f"  {req.method:4} {req.url.path:48} -> {response.status_code}  {req.headers.get('mcp-method', '')}")


async with httpx2.AsyncClient(auth=provider, trust_env=False, event_hooks={"response": [log_exchange]}) as hc:
    async with Client(streamable_http_client(RESOURCE, http_client=hc)) as client:
        print("list_notes ->", (await client.call_tool("list_notes", {})).structured_content)
        print("granted scope:", provider.context.current_tokens.scope, "\n")
        r = await client.call_tool("delete_note", {"note_id": "n2"})
        print("delete_note ->", r.content[0].text)
        print("granted scope:", provider.context.current_tokens.scope)
```

看日志：一次 401、PRM、授权服务器元数据、浏览器、`/token`、重试；之后一次 403、带着权限范围**并集**再次打开浏览器、`/token`、重试。SDK 有两个值得了解的怪癖：它在服务器端（由 `required_scopes` 产生）的 403 不带 `scope=` 参数；而客户端 provider 本身并不会拒绝元数据缺少 `code_challenge_methods_supported` 的授权服务器——如果你的授权服务器可能这样，就自己检查。

```python
await http.aclose()
mcp_server.should_exit = True
as_server.should_exit = True
print("servers stopped")
```
