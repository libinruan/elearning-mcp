## Summary
工具让模型去*行动*；**资源（Resource）**让应用去*读取*。资源可以是任何一段上下文——一个文件、一份数据库模式、一份日历、一次 API 响应——它由 URI 标识，并通过 `resources/read` 以文本或 base64 二进制的形式提供。服务器（Server）通过 `resources/list` 公布固定的资源，通过**资源模板（Resource Template）**（`resources/templates/list`）公布整族资源；资源模板是遵循 RFC 6570 的参数化 URI，例如 `weather://forecast/{city}/{date}`。本课涵盖：由应用驱动的交互模型、`resources` 能力（Capability）及其 `subscribe`/`listChanged` 标志、数据类型、帮助宿主（Host）挑选上下文的注解（Annotations）、常见 URI 方案、新的 `-32602` 未找到规则、变更通知如何改为经由 `subscriptions/listen` 传递，以及围绕 URI 和路径的安全职责。

## Lesson
### 资源由应用驱动
规范给出的一句话定义是：资源（Resource）让服务器共享能为语言模型提供上下文的数据——文件、数据库模式、应用特有的信息——每一项都由一个 **URI**（RFC 3986）唯一标识。它与工具（Tool）的关键区别在于由谁控制。资源是**应用驱动（Application-driven）**的：由*宿主（Host）*决定取什么、怎么用——可以弹出选择器，让用户搜索和筛选，按启发式规则自动纳入上下文，也可以让模型自己挑。取回之后，应用可能把全部内容交给模型，也可能只选取其中一部分，或者先用嵌入向量建立索引。协议对这些 UI 一概不作强制规定。

| | 工具 | 资源 |
| --- | --- | --- |
| 控制方 | 模型 | 应用（通常依据用户的选择） |
| 效果 | 可能改变外部世界 | 只读上下文 |
| 寻址方式 | `name` + 参数 | `uri` |
| 典型 UI | 审批对话框 | 文件树、选择器、“@ 提及” |

当数据是用户或应用会*附加*进来的东西（一份文档、一份模式、今天的值班表）时，用资源；当模型必须在推理过程中*决定*去获取或计算某样东西时，用工具。

### `resources` 能力
```json
{"capabilities": {"resources": {"listChanged": true, "subscribe": true}}}
```
两个标志都是可选的，且彼此独立：

- `listChanged`——当可用资源的集合发生变化时，服务器会发出 `notifications/resources/list_changed`。
- `subscribe`——服务器支持对通过 `subscriptions/listen` 的 `resourceSubscriptions` 过滤器请求的 URI 发送**逐资源的更新通知（Notification）**。

两者都不支持的服务器可以声明 `"resources": {}`。与工具一样，`resources/list` 返回的是请求方当前可用的资源；该集合可以（MAY）为空，也可以（MAY）变化，**不得（MUST NOT）**因连接不同或作为其他请求的副作用而变化，但可以（MAY）随请求的授权（Authorization）而不同。

### 协议操作
| 方法 | 用途 | 分页 | 可缓存 |
| --- | --- | --- | --- |
| `resources/list` | 固定的（“直接”）资源 | 是 | 是 |
| `resources/templates/list` | 参数化的资源模板 | 是 | 是 |
| `resources/read` | 获取单个 URI 的内容 | 否 | 是 |
| `subscriptions/listen` | 变更通知流（第 3.4 课） | — | — |

一条 `resources/list` 条目：

```json
{"uri": "file:///project/src/main.rs", "name": "main.rs",
 "title": "Rust Software Application Main File", "description": "Primary application entry point",
 "mimeType": "text/x-rust", "icons": [{"src": "https://example.com/rust-file-icon.png", "mimeType": "image/png", "sizes": ["48x48"]}]}
```

`Resource` 的字段包括必填的 `uri` 和 `name`，以及可选的 `title`、`description`、`icons`、`mimeType`、`annotations`、`size`（字节数——让宿主在把一个 40 MB 的日志塞进上下文窗口之前先发出警告）和 `_meta`。

读取只需按 URI 发起一次请求（Request）：

```json
{"jsonrpc": "2.0", "id": 2, "method": "resources/read", "params": {"uri": "file:///project/src/main.rs"}}
```
```json
{"jsonrpc": "2.0", "id": 2, "result": {"resultType": "complete",
  "contents": [{"uri": "file:///project/src/main.rs", "mimeType": "text/x-rust",
                "text": "fn main() {\n    println!(\"Hello world!\");\n}"}],
  "ttlMs": 60000, "cacheScope": "private"}}
```

注意 `contents` 是一个**数组**：服务器可以（MAY）为一次读取返回多个条目——读取一个目录资源可以返回其中多个文件的内容。与工具和提示模板（Prompt）一样，`resources/read` 也可以（MAY）以 `InputRequiredResult` 作答（多轮往返，第 5.3 课），客户端（Client）随后携带 `inputResponses` 和 `requestState` 重试。如果 URI 是 `https://`，客户端也可以直接自己从网上获取。

### 文本内容与二进制内容
`contents` 中的每一项恰好携带以下二者之一：

```json
{"uri": "file:///example.txt", "mimeType": "text/plain", "text": "Resource content"}
{"uri": "file:///example.png", "mimeType": "image/png", "blob": "base64-encoded-data"}
```

`text` 用于一切文本类内容（源代码、Markdown、JSON）；`blob` 是 base64 编码，用于其余一切——图片、PDF、压缩包。`mimeType`（MIME 类型）告诉宿主（Host）如何处理这些字节：渲染 PNG、把 PDF 交给解析器、对 `text/x-rust` 做语法高亮。二进制数据**必须（MUST）**正确编码。

### 资源模板（RFC 6570）
许多数据源并不是固定的列表：“*任意*城市和日期的天气预报”“项目下的*任意*文件”。把它们一一列举出来是不可能的，所以服务器转而发布**模板（Resource Template）**：

```json
{"uriTemplate": "weather://forecast/{city}/{date}", "name": "weather-forecast",
 "title": "Weather Forecast", "description": "Get weather forecast for any city and date",
 "mimeType": "application/json"}
```

客户端（Client）用具体值**展开**模板（`weather://forecast/barcelona/2026-08-01`），然后调用普通的 `resources/read`；服务器把该 URI **匹配**回模板并提取出变量。RFC 6570 支持的不只是简单的 `{var}`：还有 `{+path}`（保留字符展开，斜杠得以保留——适合文件路径）、`{?q,lang}`（查询参数）等等。模板参数可以通过 `completion/complete` 配合 `ref/resource` 引用进行**自动补全（Completion）**（第 3.3 课）——输入 “Par”，就能得到 “Paris”“Park City”。`ResourceTemplate` 的字段包括：`uriTemplate`、`name`，以及可选的 `title`、`description`、`mimeType`（适用于所有匹配的资源）、`icons`、`annotations`、`_meta`。

文档把固定 URI 称为**直接资源（Direct Resource）**（`calendar://events/2024`），把参数化 URI 称为**资源模板**（`travel://activities/{city}/{category}`）。

### 工具结果和提示模板中的资源
资源也会*嵌在*其他原语（Primitive）里传递。工具结果或提示消息可以携带一个 `resource_link` 内容块（`uri`、`name`、`mimeType`）——这是一个指针，客户端可以用 `resources/read` 获取它，或监听它的变化——也可以携带一个**嵌入式（Embedded）** `resource` 块，直接内联上文所示的同一种 `text`/`blob` 内容结构。资源链接（Resource Link）能让体积较大的结果在有人确认需要之前不进入模型的上下文；当内容很小且肯定相关时，嵌入可以省去一次往返。工具返回的链接不保证出现在 `resources/list` 中；嵌入资源的服务器应当（SHOULD）声明 `resources` 能力，以便客户端日后可以再次读取它们。

### 注解：挑选上下文的提示
资源、模板和内容块都支持可选的注解（Annotations）：

| 注解 | 取值 | 用途 |
| --- | --- | --- |
| `audience` | 由 `"user"`、`"assistant"` 组成的数组 | 数据是给谁的——展示给用户、喂给模型，还是两者皆有 |
| `priority` | 0.0 – 1.0 | 1 = 实际上必需，0 = 完全可选 |
| `lastModified` | ISO 8601，例如 `"2025-01-12T15:00:58Z"` | 显示新旧程度、排序、检测是否过期 |

上下文预算有限的宿主（Host）可以按受众筛选，按优先级顺序纳入资源直到预算用完，并在选择器里显示“3 小时前编辑”。这些只是提示，并非保证。

### 常见 URI 方案
规范列举了几种（并非穷尽）：

- **`https://`**——网络上的资源。服务器**应当（SHOULD）**仅在客户端（Client）*无需*借助服务器就能直接获取时才使用它；否则应优先选用其他方案或自定义方案，即使服务器自己是从互联网下载的。
- **`file://`**——*表现得像*文件系统的资源；它们不必对应真实的物理文件系统。目录等非普通文件可以（MAY）使用 XDG MIME 类型，如 `inode/directory`。
- **`git://`**——Git 版本控制集成。
- **自定义方案**（`weather://`、`calendar://`、`db://`）可以使用，但**必须（MUST）**符合 RFC 3986。

### 错误：“未找到”现在是 `-32602`
如果请求的资源不存在，服务器**必须（MUST）**返回 JSON-RPC 错误 **`-32602`（Invalid Params，无效参数）**；内部故障应当（SHOULD）返回 `-32603`。

```json
{"jsonrpc": "2.0", "id": 5, "error": {"code": -32602, "message": "Resource not found", "data": {"uri": "file:///nonexistent.txt"}}}
```

> **2026-07-28 版本变更。** 早期修订版用 `-32002` 表示“资源未找到”。为与 JSON-RPC 保持一致，它改为了 `-32602`。出于向后兼容，客户端**应当（SHOULD）**同时把 `-32002` 视为未找到——在较旧的服务器上你仍会遇到它。

> **规范规则。** 对于不存在的资源，服务器**不得（MUST NOT）**返回空的 `contents` 数组。空数组含义模糊：既可能表示“存在但为空”，也可能表示“不存在”。

### 变更通知与订阅
有两类变化值得关注：

1. **列表变了**（新增了一个文件）：带有 `listChanged` 的服务器应当（SHOULD）发送 `notifications/resources/list_changed`；客户端随后重新列举。
2. **某个资源的内容变了**：客户端发送 `subscriptions/listen`，把想要监听的 URI 放进 `notifications.resourceSubscriptions` 中；每当其中一个发生变化，服务器就在该流上发送 `notifications/resources/updated`，客户端随后重新读取。

```json
{"jsonrpc": "2.0", "method": "notifications/resources/updated",
 "params": {"_meta": {"io.modelcontextprotocol/subscriptionId": 4}, "uri": "file:///project/src/main.rs"}}
```

该通知（Notification）只携带 URI——从不携带内容——并且该 URI 可能是所订阅资源的一个*子资源*。

> **2026-07-28 版本变更。** 旧的 `resources/subscribe` 和 `resources/unsubscribe` RPC 以及独立的 HTTP GET 流，已被统一的机制 `subscriptions/listen` 取代，它带有显式的选择加入过滤器、确认机制以及 `subscriptionId` 标记。第 3.4 课会完整讲解。

### 安全考量
1. 服务器**必须（MUST）**校验所有资源 URI。
2. 对敏感资源**应当（SHOULD）**实施访问控制，并且**应当（SHOULD）**在操作前检查权限。
3. 二进制数据**必须（MUST）**正确编码。
4. 提供 `file://` 资源时，服务器**必须（MUST）**净化文件路径以防止**目录穿越（Directory Traversal）**——`file:///project/../../etc/passwd` 绝不能逃出根目录。

还要记住，资源内容会流入模型的上下文：一份文档可能夹带提示注入（Prompt Injection）载荷。请把资源文本当作不可信数据（第 6 模块）。

## Key points
- 资源（Resource）是**应用驱动**的只读上下文，每一项由一个 **URI** 标识；由宿主决定取什么、怎么用。
- 能力（Capability）`resources` 带有两个独立的可选标志 `listChanged` 和 `subscribe`；列表不得（MUST NOT）因连接而异，但可以（MAY）随授权而异。
- 操作：`resources/list`、`resources/templates/list`（都支持分页、可缓存），`resources/read`（可缓存，可能返回多个内容项或 `input_required`）。
- 内容要么是 `text`，要么是 base64 编码的 `blob`，每项都带有 `uri` 和 `mimeType`；`Resource` 还可以声明以字节计的 `size`。
- **模板（Resource Template）**使用 RFC 6570（`{city}`、`{+path}`、`{?q}`）；客户端负责展开，服务器负责匹配；参数可以自动补全。
- 注解（Annotations）`audience`、`priority`（0–1）和 `lastModified`（ISO 8601）帮助宿主挑选和展示上下文。
- 未找到 → **`-32602`**（以前是 `-32002`；客户端应当（SHOULD）两者都接受）；绝不能用空的 `contents` 数组作答。
- 逐资源的更新现在以 `notifications/resources/updated` 的形式，通过 **`subscriptions/listen`** 流送达（`resources/subscribe` 已移除）。
- 服务器（Server）必须（MUST）校验 URI，并净化 `file://` 路径以防目录穿越；资源内容对模型而言是不可信输入。

## Pitches
### 什么是 MCP 资源？它和工具有什么不同？
资源（Resource）是服务器在某个 URI 下暴露的只读上下文——一个文件、一份模式、一份日历。什么时候读取由应用决定，通常是因为用户选中了它，或者某个启发式规则认为它相关，然后应用再决定给模型多少内容。工具（Tool）正好相反：是模型决定去调用它，而且它可能改变东西。所以我会把文档或数据库模式暴露成资源，而把搜索、写入或任何有副作用的操作做成工具。

### 资源模板是用来做什么的？
模板（Resource Template）用于那些没法一一列举的数据。服务器不去列出每一份天气预报或每一个文件，而是按照 RFC 6570 发布一个模式，比如 weather 冒号斜杠斜杠 forecast，再跟上 city 和 date。客户端把变量填进去——补全功能会帮用户挑出有效值——然后对展开后的 URI 做一次普通的 resources/read。服务器把它匹配回模板，提取出参数。这样既让发现阶段保持精简、自带说明，又能访问到一个庞大的资源空间。

### 在 2026-07-28 版本中，客户端如何得知某个资源变了？
客户端（Client）发起一个 subscriptions/listen 请求，把它关心的 URI 放进 resourceSubscriptions 过滤器。服务器先确认它会遵从过滤器的哪些部分，之后每当其中某个资源变化，就在这条流上发送 notifications/resources/updated，并打上订阅 id 的标记。通知里只写了 URI，所以客户端要重新读取该资源。它用一套在 stdio 和 HTTP 上表现一致的机制，取代了旧的 resources/subscribe RPC 和 HTTP GET 流。

## Interview
### 客户端读取了一个不存在的 URI，服务器应该返回什么？
返回一个错误码为 **`-32602`（Invalid Params，无效参数）**的 JSON-RPC 错误，最好在 `data` 里带上该 URI——例如 `{"code": -32602, "message": "Resource not found", "data": {"uri": "..."}}`。读取过程中的内部故障应返回 `-32603`。服务器（Server）**不得（MUST NOT）**返回空的 `contents` 数组，因为那与一个存在但为空的资源无法区分。加分项：早期协议版本使用的是 `-32002`，所以健壮的客户端会把这两个错误码都当作未找到。

### 什么时候返回 `blob` 而不是 `text`？`mimeType` 起什么作用？
`text` 用于一切文本类内容——源代码、Markdown、JSON、CSV；`blob`（base64）用于二进制内容，比如 PNG、PDF 或压缩包，这些如果当作文本处理就会损坏。`mimeType`（MIME 类型）告诉宿主（Host）如何对待这些字节：渲染图片、运行 PDF 提取器、高亮代码，或者判定该条目根本不适合模型读取。二进制数据必须（MUST）正确编码；在列表中声明 `size` 能让宿主避免去获取超出其上下文预算的内容。

### 为一个“项目文件”服务器设计资源。
暴露一个模板（Resource Template），比如 `file:///{+path}`（保留字符展开会保留斜杠）或自定义的 `project://{+path}`，再为几个关键文件（`README.md`、一份模式）提供直接资源。设置准确的 `mimeType`、`size` 和 `lastModified` 注解；把生成的或体积巨大的文件标为低 `priority`。把目录的子项作为多个 `contents` 返回，或返回一个 `inode/directory` 条目。把每条路径都规范化并限制在项目根目录内以阻止目录穿越，实施访问检查，声明 `subscribe` 并在文件变化时发出 `notifications/resources/updated`，同时为 `path` 参数支持补全。

### `resources/list` 能否给不同用户返回不同的资源？
可以，但只能依据**授权（Authorization）**：该集合可以（MAY）随请求所携带的凭据而不同，例如只列出该令牌（Token）有权访问的文档。它不得（MUST NOT）因连接不同或因先前的请求而变化——2026-07-28 版本中没有会话，所以任何实例对同一个请求都必须给出相同的答案。如果列表是按用户区分的，就把结果标记为 `cacheScope: "private"`，以免共享缓存把它泄露给其他用户。

### 陷阱题：一个订阅了 `file:///repo/` 的客户端收到了 `file:///repo/src/a.py` 的更新。这是 bug 吗？
不是。模式（Schema）中写明，`notifications/resources/updated` 里的 URI “可能是客户端实际所订阅资源的一个子资源”——订阅一个类似目录的资源，完全可能收到其下层内容的更新。客户端应当按层级关系匹配更新（而不仅仅是精确字符串匹配），使受影响 URI 的所有已缓存 `resources/read` 结果失效，并重新读取。还要记住，通知不携带内容；它所在的流由 `_meta` 中的 `subscriptionId` 标识，这能告诉客户端是自己的哪一个订阅请求了它。

## Glossary
- Resource | 资源 | 由服务器暴露、以 URI 标识的只读上下文数据。
- URI | 统一资源标识符 | 用于命名资源的 RFC 3986 标识符，例如 `file:///project/README.md`。
- Direct resource | 直接资源 | 拥有固定 URI、由 `resources/list` 列出的资源。
- Resource template | 资源模板 | 一个 RFC 6570 URI 模板，用于公布一族参数化的资源。
- RFC 6570 | URI 模板规范（RFC 6570） | 定义 URI 模板语法与展开规则的标准，例如 `{var}`、`{+path}`、`{?q}`。
- MIME type | MIME 类型（媒体类型） | 诸如 `image/png` 的标签，告诉客户端如何解读内容。
- Blob | 二进制内容（base64） | 以 base64 编码的二进制资源内容。
- Annotations | 注解 | 帮助客户端挑选和展示内容的提示（`audience`、`priority`、`lastModified`）。
- Directory traversal | 目录穿越 | 利用 `..` 或绝对路径逃出允许目录的攻击。
- `notifications/resources/updated` | 资源更新通知 | 在 `subscriptions/listen` 流上发送的通知，表明某个被监听的资源发生了变化。

## Notebook
### 1. 一个带直接资源和模板的服务器
`MCPServer` 根据 URI 来判断：不含 `{...}` 的是直接资源（Direct Resource，出现在 `resources/list` 中），只要含有任何变量就是模板（Resource Template，出现在 `resources/templates/list` 中）。返回 `str` 得到 `text`，返回 `bytes` 得到 base64 编码的 `blob`。我们还用 `FileResource` 以 `file://` URI 注册了一个真实文件。

```python
import base64
import json
import logging
import struct
import tempfile
import zlib
from pathlib import Path

import mcp_types as types
from mcp import Client
from mcp.server import MCPServer
from mcp.server.mcpserver.resources.types import FileResource

def tiny_png() -> bytes:
    chunk = lambda kind, body: (struct.pack(">I", len(body)) + kind + body
                                + struct.pack(">I", zlib.crc32(kind + body) & 0xFFFFFFFF))
    return (b"\x89PNG\r\n\x1a\n" + chunk(b"IHDR", struct.pack(">IIBBBBB", 1, 1, 8, 2, 0, 0, 0))
            + chunk(b"IDAT", zlib.compress(b"\x00\xff\x00\x00")) + chunk(b"IEND", b""))
```

### 3. 读取文本、二进制和模板化资源
模板（Resource Template）在**客户端**按 RFC 6570 规则展开（这里用的是 SDK 的 `UriTemplate`；注意空格和 `ã` 被百分号编码了），然后用普通的 `resources/read` 读取。

```python
from mcp.shared.uri_template import UriTemplate

async with Client(server) as client:

    blob = (await client.read_resource("images://logo.png")).contents[0]
    raw = base64.b64decode(blob.blob)
    png_ok = raw.startswith(bytes([0x89]) + b"PNG")
    print(f"\nblob: mimeType={blob.mime_type}, {len(raw)} bytes after base64 decoding, PNG signature ok: {png_ok}")
```

### 4. 未找到是 `-32602`——而且绝不是空数组
先读取一个什么都匹配不上的 URI，再读取一个模板能匹配但数据缺失的 URI。然后通过一个 stdio 子进程，在线路上以原始 JSON 的形式查看同样的错误。

```python
async with Client(server) as client:
    for uri in ["calendar://events/1999", "docs://guides/nonexistent.md"]:
        try:
            await client.read_resource(uri)
        except MCPError as err:
            print(f"{uri:<32} -> code={err.code} message={err.message!r} data={err.data}")
```

第二种情况暴露了一个 SDK 细节：模板处理函数抛出异常（这里是 `KeyError`）时，会变成 `-32603` *内部错误*，而不是未找到。要遵循规范，就应在处理函数中抛出 SDK 的 `ResourceNotFoundError`：

```python
from mcp.server.mcpserver.exceptions import ResourceNotFoundError


@server.resource("guides://{+path}", mime_type="text/markdown")
def guides(path: str) -> str:
    if path not in DOCS:
        raise ResourceNotFoundError(f"Resource not found: guides://{path}")
    return DOCS[path]


async with Client(server) as client:
    try:
        await client.read_resource("guides://nope.md")
    except MCPError as err:
        print("fixed:", err.code, err.message, err.data)


def is_not_found(err: MCPError) -> bool:
    """Client-side: accept the 2026-07-28 code and the legacy one."""
    return err.code in (-32602, -32002)


print("treat as not found:", is_not_found(MCPError(-32002, "Resource not found")))
```

### 5. 动手破坏：目录穿越
规范规定服务器必须（MUST）净化路径。SDK 的模板默认会拒绝提取出的参数中含有 `..` 组件或绝对路径的情况（`ResourceSecurity`），因此这类请求根本到不了我们的处理函数。

```python
async with Client(server) as client:
    for uri in ["docs://guides/visas.md", "docs://../../etc/passwd", "docs:///etc/passwd", "docs://guides/%2e%2e/%2e%2e/secret"]:
        try:
            text = (await client.read_resource(uri)).contents[0].text
            print(f"{uri:<38} OK   {text}")
        except MCPError as err:
            print(f"{uri:<38} {err.code} {err.message}")
```

如果你自己拼接路径（自定义的底层处理函数、`FileResource` 工厂），也要做同样的检查：先解析路径，再验证它仍位于根目录之内。

```python
def safe_join(root: Path, relative: str) -> Path:
    candidate = (root / relative).resolve()
    if not candidate.is_relative_to(root.resolve()):
        raise PermissionError(f"path escapes root: {relative}")
    return candidate


for rel in ["README.md", "../../etc/passwd"]:
    try:
        print(rel, "->", safe_join(project, rel))
    except PermissionError as exc:
        print(rel, "->", exc)
```

### 6. 用注解挑选上下文的宿主
资源（Resource）是应用驱动的：由宿主（Host）来选择。这个小小的选择器只保留面向助手的条目，按优先级排序，并在达到字符预算时停止。

```python
async def select_context(client, budget_chars=120):
    resources = (await client.list_resources()).resources
    for_model = [r for r in resources
                 if not r.annotations or not r.annotations.audience or "assistant" in r.annotations.audience]
    ranked = sorted(for_model, key=lambda r: (r.annotations.priority if r.annotations and r.annotations.priority is not None else 0.5),
                    reverse=True)
    chosen, used = [], 0
    for r in ranked:
        item = (await client.read_resource(str(r.uri))).contents[0]
        text = getattr(item, "text", None)
        if text is None or used + len(text) > budget_chars:
            print(f"skip   {r.uri} ({'binary' if text is None else 'over budget'})")
            continue
        chosen.append((str(r.uri), text))
        used += len(text)
        print(f"attach {r.uri} ({len(text)} chars)")
    return chosen


async with Client(server) as client:
    context = await select_context(client)
print("\nprompt context:\n" + "\n".join(f"<resource uri='{u}'>{t.strip()}</resource>" for u, t in context))
```

徽标（`audience: ["user"]`）永远不会被考虑交给模型，日历（priority 0.9）排在最前。

### 7. 预览：监听资源变化
在 2026-07-28 版本中，客户端（Client）通过 `subscriptions/listen` 监听 URI（第 3.4 课有详细介绍）。一个工具修改了日历并发布 `notifications/resources/updated`；该通知（Notification）只写明 URI，因此客户端会重新读取。

```python
from mcp.server.mcpserver import Context

busy_days = ["2026-08-03", "2026-08-04"]


@server.resource("calendar://busy", mime_type="application/json")
def busy() -> str:
    return json.dumps(busy_days)


@server.tool()
async def block_day(day: str, ctx: Context) -> str:
    """Mark a day as busy in the calendar."""
    busy_days.append(day)
    await ctx.notify_resource_updated("calendar://busy")
    return f"blocked {day}"


async with Client(server) as client:
    print("before:", (await client.read_resource("calendar://busy")).contents[0].text)
    async with client.listen(resource_subscriptions=["calendar://busy"]) as sub:
        await client.call_tool("block_day", {"day": "2026-08-10"})
        event = await anext(sub)
        print("event:", event)
        print("after: ", (await client.read_resource(event.uri)).contents[0].text)
```
