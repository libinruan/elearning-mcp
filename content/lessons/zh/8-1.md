## Summary
这个综合项目把整门课串成一个贴近真实的智能体（Agent）工作流：一个研究助理，它检索文档库、阅读资料来源、在笔记服务里起草一份带引用的报告、修改它，然后发布——但只有在人类点头之后才会发布。三个 MCP 服务器（Server）分别运行在三种传输（Transport）上（进程内、**stdio** 子进程、带 Bearer 令牌（Token）的 **Streamable HTTP**），一个宿主（Host）连接它们，对它们的工具（Tool）做命名空间前缀（Namespacing）和缓存，执行白名单与步数预算，对每一次调用做链路追踪和审计，并驱动一个 Claude 形态的工具调用循环。你将对照 2026-07-28 规范论证每一个设计决策，用一个确定性规划器离线运行整个工作流，注入故障，再用端到端测试把行为固定下来。

## Lesson
### 需求简介
一个产品团队想要这样一个助理，它能回答：*“研究一下 MCP 服务器如何水平扩展，在我的笔记里写一份简短的带引用报告，然后发布到团队 wiki。”* 它很适合作为综合项目，因为它用到了你学过的每一层：**资源（Resource）**和**工具（Tool）**（第 3 模块）、服务器设计（第 4 模块）、宿主（Host）及其循环、**MRTR**（多轮往返请求，Multi Round-Trip Request）和**征询（Elicitation）**（第 5 模块）、授权与提示注入（Prompt Injection）防御（第 6 模块）。这也是你在面试中会遇到的题型：*“设计一个智能体，它从系统 A 读取、向系统 B 写入，并且绝不能自作主张地做任何不可逆的事。”*

按照写设计文档的方式列出需求：

- **功能性：** 对语料库做关键词检索；读取完整文档；跨多次调用创建和编辑草稿；发布最终报告。
- **安全性：** 发布不可逆 → 需要明确的人工确认；模型只能使用这个工作流需要的工具；从文档中读到的内容不可信。
- **运维性：** 每次调用都可审计、可追踪；成本有上限（步数上限、截断输出）；起草状态必须能在进程重启后存活；一切都能在没有 LLM 的情况下测试。

### 架构
```text
 user task
     │
┌────▼──────────────────────────── Host (research assistant) ──────────────────────────────┐
│  planner: Claude  or  ScriptedPlanner   ⇄   agent loop (max_steps, tool_result+is_error) │
│                                │                                                         │
│  policy layer: namespacing · allowlist · catalog cache (ttlMs) · host__read_resource     │
│                truncation · audit log · traceparent in _meta                             │
│        ┌───────────────────────┼──────────────────────────────┐                          │
│  Client "library"        Client "notes"               Client "publisher"                 │
└────────┼───────────────────────┼──────────────────────────────┼──────────────────────────┘
   in-process (tests)      stdio subprocess          Streamable HTTP + Bearer token
         │                       │                              │
┌────────▼─────────┐ ┌───────────▼────────────┐ ┌───────────────▼───────────────┐
│ library          │ │ notes                  │ │ publisher (resource server)   │
│ resources:       │ │ create_draft → handle  │ │ publish → InputRequiredResult │
│  library://docs/ │ │ add / revise / get     │ │   (elicitation/create), retry │
│ tool: search_docs│ │   (draft_id argument)  │ │ unpublish (not allowlisted)   │
│  (paginated)     │ │ store: <user>:<handle> │ │ token_verifier, -32021 guard  │
└──────────────────┘ └────────────────────────┘ └───────────────────────────────┘
```

正常路径（happy path）共八个模型轮次：`search_docs` → `search_docs(cursor)` → 两个并行的 `host__read_resource` → `create_draft` → 两个并行的 `add_section` → `revise_section` → `get_draft` → `publish`（一次确认对话框）→ 最终答复。

### 各部分如何对应到协议特性

| 部分 | 协议特性 | 驱动设计的规则 |
| --- | --- | --- |
| 文档库中的文档 | **资源** + 模板 `library://docs/{doc_id}` | 资源是由应用控制的上下文；`resources/read` 携带 `ttlMs` 和 `cacheScope` |
| 文档库检索 | 带 `outputSchema` 和游标分页的**工具** | 结果以 `structuredContent` 提供给程序、以文本提供给模型；每页保持很小 |
| 笔记草稿 | **有状态工具**模式（显式句柄） | 无状态协议：跨请求的状态**必须（MUST）**通过显式标识符引用 |
| 笔记的传输 | **stdio** | 凭据来自环境；进程*不是*会话 |
| 发布服务的传输 | **Streamable HTTP** + OAuth 资源服务器 | `401` + `WWW-Authenticate`；令牌必须是为本服务器签发的 |
| 确认 | 携带 `elicitation/create` 的 **MRTR**（`InputRequiredResult`） | 在 2026-07-28 中，服务器不得（MUST NOT）发送由服务器发起的请求 |
| 链路追踪 | `_meta.traceparent`（W3C Trace Context） | 为 OpenTelemetry 传播保留的 `_meta` 键 |
| 工具目录 | `tools/list` + 缓存提示 | 遵循 `ttlMs`；把 `list_changed` 视为失效信号 |

### 决策 1——每个信任边界一种传输
传输层（Transport）不是可以随意替换的装饰；它编码了**代码在哪里运行、信任谁**。文档库在进程内运行，因为它是我们自己的代码，而且我们想要快速、确定性的测试（`Client(server)`）。笔记服务是一个本地程序，所以它作为 **stdio** 子进程运行：宿主掌控它的生命周期，并通过环境变量传递身份（规范指出，stdio 实现不应当（SHOULD NOT）使用 HTTP 授权框架，而应“从环境中获取凭据”）。发布服务是一个共享的远程服务，所以它使用 **Streamable HTTP**，校验 Bearer 令牌，并且在本地运行时会校验 `Origin`、只绑定 localhost。构建服务器指南中的日志规则适用于 stdio 服务器：**绝不要写 stdout**——那是 JSON-RPC 通道；日志写到 stderr。

### 决策 2——数据作为资源，检索作为分页工具
把文档直接倒进工具结果里，会浪费上下文窗口（Context Window），也会模糊控制权。文档库把文档暴露为**资源（Resource）**，并提供一个 `search_docs` 工具，每次最多返回三条命中，每条带 160 个字符的摘要片段和一个不透明的 `next_cursor`。模型决定*读什么*；宿主通过一个宿主级工具 `host__read_resource` 执行读取，该工具只接受已连接服务器的 URI，并截断过长的内容。资源在设计上由应用控制，这就是让它进入智能体循环、又不给模型一个“随便抓取任何东西”能力的方式。

### 决策 3——通过句柄而不是会话来保存状态
2026-07-28 移除了协议会话（`Mcp-Session-Id`、`initialize` 握手）。规范明确指出“一个打开的连接，例如一个 STDIO 进程，并不是一次对话或会话”，并且客户端不应当（SHOULD NOT）把 stdio 进程的生命周期绑定到一次对话上。因此 `create_draft` 生成一个不透明、高熵的 `draft_id`，其他每个工具都把它作为参数接收，工具描述中写明其生命周期（“24 小时内无修改即过期”），未知句柄会返回一个**工具执行错误（Tool Execution Error）**，告诉模型去新建一份草稿。存储以 `<user>:<handle>` 为键，其中用户取自经过验证的环境，这实现了安全指南的要求：服务器**不得（MUST NOT）**把持有句柄当作认证，并且应当（SHOULD）把句柄绑定到主体（principal）上。Notebook 证明了这样做的回报：杀掉子进程、启动一个新的，句柄依然有效。

### 决策 4——通过 MRTR 进行确认
在 2025-11-25 中，工具可以在调用中途暂停，在 SSE 流上向客户端发送 `elicitation/create`。在 2026-07-28 中这已经不存在了：`publish` **返回** `{"resultType": "input_required", "inputRequests": {"confirm": {...elicitation/create...}}, "requestState": "..."}` 并结束。客户端显示对话框，然后用一个**新的 JSON-RPC id**、`inputResponses` 以及原样回传的 `requestState` 重试 `tools/call`。你应该能脱口而出的推论：

- 服务器在两轮之间不保存任何状态，所以**任何副本**都能完成这次重试——前提是所有副本都能校验 `requestState`（共享密钥；见 8.2 课）。
- `requestState` 是攻击者可控的输入。SDK 会对它进行封装（AES-GCM、TTL、主体绑定）；我们的工具还额外把批准绑定到内容摘要上，因此带着被改动报告的重试无法复用那个“同意”。
- 服务器**不得（MUST NOT）**发送客户端没有声明支持的输入请求——当缺少 `elicitation` 时，我们的工具返回 `-32021`（`MissingRequiredClientCapability`，HTTP 400）。
- 表单模式**不得（MUST NOT）**索取机密信息；是/否式的批准没有问题。拒绝（decline）和取消（cancel）必须处理——我们的工具把它们转换为清晰的 `isError` 结果，告诉模型不要重试。

### 决策 5——宿主就是策略引擎
服务器是信任程度各异的插件；除非服务器本身可信，否则工具描述和注解都不可信。因此每一项保证都放在宿主（Host）中：

- **命名空间前缀（Namespacing）。** 工具名只在单个服务器内唯一，规范指出聚合方应当（SHOULD）做消歧（并且不应当（SHOULD NOT）依赖 `serverInfo.name`）。我们暴露 `library__search_docs` 这样的名字，所用字符对 MCP 和模型提供方的工具名都合法。
- **最小权限。** 白名单既过滤工具目录，*又*在调用时再次检查，因为模型可能会点名一个从未展示给它的工具（幻觉或注入）。`publisher__unpublish` 在服务器上存在，但这个工作流无法触达它。
- **缓存。** 合并后的工具目录会被缓存，直到最小的 `ttlMs` 过期——客户端最佳实践指南建议在宿主端缓存工具定义，并在收到 `list_changed` 时刷新。稳定的 `tools` 数组还能保住模型提供方的提示缓存（Prompt Caching）。
- **审计与链路追踪。** 每次调用一条记录（工具、参数、结果、延迟），并在每个请求的 `_meta` 中放入同一 trace id 下的一个新 `traceparent` span——工具规范指出客户端应当（SHOULD）为审计记录工具使用情况，而保留的 `traceparent`/`tracestate`/`baggage` 键让后端能够把链路串起来。
- **上下文卫生。** 工具输出在到达模型之前会被截断；协议错误和传输故障会被转换为 `is_error` 工具结果，因此循环永远不会崩溃。

### 循环及其护栏
构建客户端教程只做了一轮工具调用；工作流需要一个**循环**：调用模型；只要 `stop_reason == "tool_use"`，就执行每一个 `tool_use` 块，追加助手轮次，然后追加一个包含所有带 `is_error` 的 `tool_result` 块的用户轮次，再次调用模型。教程中的两条规则很重要：MCP 工具失败**不会**在客户端抛出异常——要检查 `result.is_error` 并把这个标志传下去，让模型能自我纠正；而且循环需要一个预算（`max_steps`），因为一个永不收敛的模型是要花钱的。并行工具调用（两次读取、两次 `add_section`）在这种结构下是天然支持的。

### 测试一个智能体工作流
LLM 的输出是非确定性的，所以要用一个确定性规划器来测试**系统**：它与 `messages.create` 的签名完全一致，并产出 Anthropic 形态的 `tool_use` 块。它像模型一样读取工具结果（游标、URI、`draft_id`），因此真正驱动了真实的服务器、传输、策略和循环。然后对可观察的行为做断言：审计日志中的调用顺序、恰好一次确认对话框、HTTP 服务器收到的 trace id、发布出去的正文，以及各种故障（不稳定的工具、被注入的指令、一个“不”）都变成可恢复的错误。只有在可选的实时运行中才换上 Claude。

### 权衡，以及规模变大后有什么变化
- **服务器很多时：** 到了几十个服务器，就切换到渐进式发现（Progressive Discovery）（`search_tools`，按需连接服务器）；指南建议当工具定义超过上下文窗口的大约 1–5% 时切换。
- **中间数据很大时：** 让读取 → 转换 → 写入链条全部经过模型代价很高；程序化工具调用（Programmatic Tool Calling，即“代码模式”）在沙箱中运行模型编写的脚本，代理层中仍然执行同样的逐次调用授权。
- **确认的用户体验：** 逐次审批最安全但令人疲惫；按类别授权（“本次运行允许 `publish`”）只有在宿主仍然对每次调用做评估时才可以接受。
- **长时任务：** 需要几分钟的发布操作应改用 Tasks 扩展，而不是一直挂着一个请求（见 7.1 课）。
- **真正的认证：** 用 OAuth 2.1 授权服务器、受众绑定的令牌和权限范围递进授权（第 6 模块）替换演示用的令牌字典——绝不要把用户的令牌透传给下游 API。

## Key points
- 一个综合项目级别的 MCP 系统把**服务器（Server）**（能力）和**宿主（Host）**（策略）分开：命名空间前缀、白名单、缓存、截断、审计和链路追踪全都放在宿主里。
- 按信任边界选择传输层（Transport）：测试用进程内，本地程序用 **stdio**（凭据来自环境变量，绝不打印到 stdout），共享服务用 **Streamable HTTP** + OAuth 资源服务器。
- 把大量数据暴露为**资源（Resource）**，给模型一个小巧、分页的检索**工具**；通过一个校验 URI 并截断内容的宿主工具来桥接读取。
- 跨调用的状态使用绑定到用户的**显式、高熵句柄（State Handle）**；一个打开的 stdio 进程不是会话，重启也不能丢失工作成果。
- 不可逆操作通过 **MRTR**（多轮往返请求）确认：`resultType: "input_required"` + `elicitation/create`，用新的 id、`inputResponses` 和原样回传、受完整性保护的 `requestState` 重试。
- 在调用时再次检查白名单：模型可能调用从未展示给它的工具，而**提示注入（Prompt Injection）**要靠宿主代码来挫败，而不是靠模型的表现。
- 只要 `stop_reason == "tool_use"`，循环（Agent Loop）就继续运行，把所有 `tool_result` 连同 `is_error` 放进一个用户轮次返回，并以 `max_steps` 为上限。
- 在每个请求的 `_meta` 中放入 W3C `traceparent`，并且每次调用保留一条审计记录（Audit Trail）——这是 8.2 课可观测性的骨架。
- 用一个与模型 API 形态完全一致的确定性规划器（Scripted Planner）来测试智能体，然后对审计日志、副作用和故障恢复做断言。

## Pitches
### 讲讲你在 MCP 上构建的一个智能体工作流。
我做过一个研究助理（Agent），它会检索文档库、起草一份带引用的报告，然后发布出去。它用了三个 MCP 服务器，跑在三种传输上：一个进程内的文档库，把文档暴露为资源（Resource），再配一个分页的检索工具；一个走 stdio 的笔记服务器，用显式句柄来保存草稿；还有一个用 Bearer 令牌保护的 HTTP 发布服务，它的发布工具会通过 MRTR 征询（Elicitation）去问人。宿主（Host）负责给工具加命名空间前缀和缓存，执行白名单，对每次调用做链路追踪和审计，并跑一个有步数上限的工具调用循环。

### 对于不可逆操作，你如何保持人在回路？
我让服务器去问，而不是让模型去问。在 MCP 2026-07-28 里，发布工具会返回一个“需要输入”的结果（`InputRequiredResult`），里面带一个征询请求和一个不透明、经过封装的请求状态（`requestState`）；客户端弹出确认对话框，再带着用户的回答重试这次调用。我把批准绑定到内容摘要上，这样它就不能被挪去批准别的东西；拒绝和取消都处理成干净的工具错误；在这之上，宿主只把这个工作流真正需要的工具放进白名单。

### 在无状态协议里，你如何保存状态？
我让状态变得显式。一个创建类工具生成一个不透明、高熵的句柄（State Handle），之后每次调用都把它作为参数传进来，服务器把状态存在数据库里，以用户和句柄为键。工具描述里写明句柄能活多久，遇到未知句柄就返回一个工具错误，告诉模型重新开始。因为什么都不依赖于连接，所以任何副本都能处理任何调用，stdio 进程可以重启，而且光是持有句柄永远不会获得访问权限。

## Interview
### 既然你已经过滤了模型能看到的工具列表，为什么还要在宿主中执行工具白名单？
因为工具目录只能控制模型*被告知*什么，控制不了它*要求*什么。模型可能会幻觉出一个工具名，文档里的提示注入（Prompt Injection）也可能指示它按名字调用一个破坏性工具——在这个综合项目中，一份文档里的“SYSTEM NOTE”就让智能体去调用 `publisher__unpublish`。如果宿主只是把每个 `tool_use` 路由给拥有该前缀的服务器，这次调用就会成功。在调用时再次检查工具白名单（Tool Allowlist），就把策略变成了无论模型怎么表现都成立的代码，而且这次拒绝会作为一种独立的结果记录在审计日志中。

### 如何确定性地测试一个 LLM 智能体工作流？
把**规划器**和**系统**分开。写一个假的 LLM（即脚本化规划器，Scripted Planner），签名与 `messages.create` 完全一致，返回 Anthropic 形态的 `tool_use` 块，并读取 `messages` 中的 `tool_result` 来决定下一步。让它跑在*真实的*服务器、传输、宿主策略和循环之上。然后对可观察的效果做断言：审计日志中的调用顺序、副作用（发布出去的报告）、确认对话框的次数、HTTP 服务器收到的 trace id，以及从注入的故障中恢复（不稳定的工具、被拒绝的调用、被拒绝的确认、失控循环撞上 `max_steps`）。另外保留一套可选的、用真实模型跑的评估套件来衡量质量。

### 工作流进行到一半时某个工具失败了。宿主应该给模型返回什么？什么时候应该停下来？
区分两条错误通道。**工具执行错误（Tool Execution Error）**（`isError: true`）携带可操作的文本——“检索后端超时，请重试”“未知 draft_id，请新建草稿”——应当作为带 `is_error: true` 的 `tool_result` 返回给模型，让它能自我纠正。**协议错误（Protocol Error）**（例如 `-32602` 这样的 JSON-RPC 错误）或传输故障更难恢复；宿主应当捕获它、记录日志，并且仍然返回一个 `is_error` 结果，而不是让循环崩溃。停下来是宿主的职责：一个 `max_steps` 预算，再加上对被拒绝确认的“不要重试”语义。

### 笔记服务器跑在 stdio 上。它能把草稿放在一个全局变量里吗？
可以，但不应该依赖它。2026-07-28 规范指出，一个连接——包括一个 stdio 进程——都不是会话：客户端可能交错发送不相关的请求，而且客户端不应当（SHOULD NOT）把进程生命周期绑定到一次对话上，所以进程可能在两次调用之间被重启。跨请求的状态必须（MUST）通过客户端每次都会传入的显式标识符来引用。把草稿放在以 `<user>:<handle>` 为键的存储里，让句柄（State Handle）不可猜测且会过期，并对未知句柄返回清晰的工具错误。

### 是什么阻止恶意客户端篡改 `requestState` 来跳过确认？
服务器把 `requestState`（请求状态）当作攻击者可控的输入。当它影响业务逻辑时，**必须（MUST）**对它做完整性保护（HMAC 或 AEAD），校验失败就拒绝；规范还建议把它绑定到已认证的主体、一个较短的过期时间以及发起它的那个请求。Python SDK 默认用 AES-GCM 封装它，并绑定主体、受众和 TTL。这个综合项目还在状态中加入内容摘要，使得对某份报告的批准不能用来发布另一份。如果某件事最多只能发生一次，也要在服务器端强制执行——仅靠封装过的状态并不能保证只使用一次。

### 你的两个服务器都暴露了一个叫 `search` 的工具。宿主如何应对？
工具名只在单个服务器内唯一，规范指出做聚合的客户端应当（SHOULD）实现一种消歧策略，例如加上服务器标识符作为前缀（Namespacing）——并且不应当（SHOULD NOT）依赖 `serverInfo.name`，因为它不保证唯一。使用宿主自己的连接键（`library__search`、`wiki__search`），让名字保持在 MCP 和你的模型提供方都接受的字符集内，并维护一张从带命名空间的名字到（客户端，原始名字）的路由表。在描述中按服务器对工具分组，让模型能推断该用哪一个。

## Glossary
- Host policy layer | 宿主策略层 | 宿主中决定模型可以看到什么、做什么的那一部分：命名空间前缀、白名单、缓存、截断、审计和链路追踪。
- Tool allowlist | 工具白名单 | 一个工作流可以调用的、带命名空间的工具的显式集合，既在工具目录中执行，也在调用时执行。
- Namespacing | 命名空间前缀 | 给工具名加上由宿主选定的服务器键作为前缀，以避免跨服务器的名称冲突。
- State handle | 状态句柄 | 一个由服务器生成的不透明标识符（例如 `draft_id`），作为工具参数传递，用于在无状态请求之间引用状态。
- `InputRequiredResult` | 需要输入的结果（`InputRequiredResult`） | 一种 `resultType: "input_required"` 的结果，携带 `inputRequests` 和/或 `requestState`，要求客户端收集输入后重试。
- `requestState` | 请求状态（`requestState`） | 由服务器拥有、在 MRTR 重试时由客户端原样回传的不透明状态；它不可信，因此在关系重大时必须做完整性保护。
- Audit trail | 审计日志 | 每次工具调用一条结构化记录（工具、参数、结果、延迟、trace id），用于问责和调试。
- `traceparent` | 链路追踪头（`traceparent`） | W3C Trace Context 的取值，在 MCP `_meta` 中被保留，让每次调用都能加入一条分布式链路。
- Scripted planner | 脚本化规划器（模拟 LLM） | 一个调用形态与真实 API 一致的确定性假模型，用于离线测试智能体系统。
- Prompt injection | 提示注入 | 隐藏在不可信内容（文档、工具结果）中的指令，试图让模型执行非预期的操作。

### 2. 走 stdio 的笔记服务器：用显式句柄完成有状态的工作
MCP 2026-07-28 **没有协议会话**，规范还指出，一个打开的 stdio 进程*也不是*会话。起草工具仍然需要跨调用的状态，所以服务器遵循规范中“有状态工具”的指导：`create_draft` **生成一个不透明、高熵的句柄（State Handle）**（`draft_id`），其他每个工具都以它为参数，生命周期写在描述中，未知句柄是一个模型可以从中恢复的工具执行错误（Tool Execution Error）。

状态存放在一个 JSON 文件里（代替数据库），以 `<user>:<handle>` 为键——用户来自环境变量，这正是 stdio 服务器获取凭据的方式。服务器日志写到 **stderr**（绝不写 stdout：那是 JSON-RPC 通道），我们把它捕获到一个文件中。

```python
NOTES_SERVER = WORKDIR / "notes_server.py"
NOTES_SERVER.write_text(textwrap.dedent('''
    import json, logging, os, secrets, sys, time
    from pathlib import Path
    from pydantic import BaseModel
    from mcp.server import MCPServer
    from mcp.server.caching import CacheHint
    from mcp.server.mcpserver.exceptions import ToolError

    logging.basicConfig(stream=sys.stderr, level=logging.INFO, format="notes[%(process)d] %(message)s")
    log = logging.getLogger("notes")
    STORE = Path(os.environ["NOTES_STORE"])      # the "database"
    USER = os.environ.get("NOTES_USER", "local") # stdio: identity comes from the environment, not OAuth
    TTL_SECONDS = 24 * 3600

    mcp = MCPServer("notes", log_level="WARNING",
                    cache_hints={"tools/list": CacheHint(ttl_ms=300_000, scope="public")})

    def _load():
        return json.loads(STORE.read_text()) if STORE.exists() else {}

    def _draft(db, draft_id):
        d = db.get(f"{USER}:{draft_id}")          # bound to the user: a guessed handle of someone else misses
        if d is None or time.time() - d["updated"] > TTL_SECONDS:
            raise ToolError(f"unknown or expired draft_id {draft_id!r} - call create_draft to start a new draft")
        return d

    def _save(db, draft_id, d):
        d["updated"], d["version"] = time.time(), d["version"] + 1
        db[f"{USER}:{draft_id}"] = d
        STORE.write_text(json.dumps(db))

    def _markdown(d):
        return f"# {d['title']}\\n\\n" + "\\n\\n".join(f"## {h}\\n{t}" for h, t in d["sections"])

    class DraftRef(BaseModel):        # pydantic return types -> outputSchema + structuredContent
        draft_id: str
        title: str

    class DraftChange(BaseModel):
        draft_id: str
        sections: list[str]
        version: int

    class Draft(BaseModel):
        draft_id: str
        version: int
        markdown: str

    @mcp.tool()
    def create_draft(title: str) -> DraftRef:
        """Create an empty report draft and return its handle `draft_id`. Pass draft_id to every other notes
        tool. Drafts expire after 24 hours without changes."""
        db, draft_id = _load(), "drf_" + secrets.token_urlsafe(12)
        db[f"{USER}:{draft_id}"] = {"title": title, "sections": [], "updated": time.time(), "version": 0}
        _save(db, draft_id, db[f"{USER}:{draft_id}"])
        log.info("created %s pid=%s", draft_id, os.getpid())
        return DraftRef(draft_id=draft_id, title=title)

    @mcp.tool()
    def add_section(draft_id: str, heading: str, text: str) -> DraftChange:
        """Append a section (markdown text under a heading) to a draft."""
        db = _load(); d = _draft(db, draft_id)
        d["sections"].append([heading, text]); _save(db, draft_id, d)
        return DraftChange(draft_id=draft_id, sections=[h for h, _ in d["sections"]], version=d["version"])

    @mcp.tool()
    def revise_section(draft_id: str, heading: str, text: str) -> DraftChange:
        """Replace the text of an existing section of a draft."""
        db = _load(); d = _draft(db, draft_id)
        for s in d["sections"]:
            if s[0] == heading:
                s[1] = text; _save(db, draft_id, d)
                return DraftChange(draft_id=draft_id, sections=[h for h, _ in d["sections"]], version=d["version"])
        raise ToolError(f"no section {heading!r}; existing sections: {[h for h, _ in d['sections']]}")

    @mcp.tool()
    def get_draft(draft_id: str) -> Draft:
        """Return the full draft as markdown."""
        d = _draft(_load(), draft_id)
        return Draft(draft_id=draft_id, version=d["version"], markdown=_markdown(d))

    if __name__ == "__main__":
        mcp.run(transport="stdio")
'''))
```

### 3. 走 Streamable HTTP 的发布服务器：Bearer 令牌 + 通过 MRTR 进行人工确认
第三个服务器是远程形态的：一个 Streamable HTTP 端点，作为 OAuth **资源服务器（Resource Server）**受到保护。SDK 的 `token_verifier` + `AuthSettings` 会拒绝没有有效 Bearer 令牌的请求，返回 `401` 以及指向受保护资源元数据（Protected Resource Metadata）的 `WWW-Authenticate` 头（见 6.1 课）。这里的“授权服务器”只是一个装着演示令牌的字典。

`publish` 是不可逆的，所以它会去问人。在 2026-07-28 中，服务器不能自己发送 `elicitation/create` 请求；它**返回**一个 `InputRequiredResult`（`resultType: "input_required"`），携带 `inputRequests` 和一个不透明的 `requestState`，客户端再带着 `inputResponses` 重试（见 5.3 课）。这个工具还会：

- 如果客户端没有声明 `elicitation` 能力（Capability），就以 `-32021` 拒绝（服务器不得（MUST NOT）发送客户端无法处理的输入请求）；
- 把确认绑定到内容摘要上，这样带着*不同*内容的重试就无法复用这次批准；
- 依靠 SDK 来**封装** `requestState`（AES-GCM，绑定到令牌的主体和一个 TTL）——客户端看到的只是一段不透明的数据。

```python
@publisher.tool()
async def publish(title: str, body: str, ctx: Context) -> types.CallToolResult | types.InputRequiredResult:
    """Publish a finished markdown report to the team wiki. Irreversible: the user is asked to confirm."""
    meta = ctx.request_context.meta or {}
    PUBLISHER_SAW.append({"user": get_access_token().subject, "traceparent": meta.get("traceparent"),
                          "round": "retry" if ctx.input_responses else "first"})
    caps = ctx.client_capabilities
    if caps is None or caps.elicitation is None:
        raise MCPError(types.MISSING_REQUIRED_CLIENT_CAPABILITY, "publish needs user confirmation (elicitation)",
                       {"requiredCapabilities": {"elicitation": {}}})
    digest = hashlib.sha256(f"{title}\n{body}".encode()).hexdigest()[:16]
    answer = (ctx.input_responses or {}).get("confirm")
    if answer is None:                                   # round 1: ask the human, keep no server-side state
        return types.InputRequiredResult(
            input_requests={"confirm": types.ElicitRequest(params=types.ElicitRequestFormParams(
                message=f"Publish the report '{title}' ({len(body)} chars) to the team wiki?",
                requested_schema=CONFIRM_SCHEMA))},
            request_state=json.dumps({"digest": digest}))
    if json.loads(ctx.request_state or "{}").get("digest") != digest:
        raise ToolError("the report changed after confirmation - call publish again")
    if answer.action != "accept" or not (answer.content or {}).get("approve"):
        return types.CallToolResult(is_error=True, content=[types.TextContent(
            type="text", text=f"The user declined publication (action={answer.action}). Do not retry.")])
    report_id = "rpt_" + secrets.token_hex(4)
    REPORTS[report_id] = {"title": title, "body": body, "owner": get_access_token().subject}
    url = f"https://wiki.example.com/reports/{report_id}"
    return types.CallToolResult(content=[types.TextContent(type="text", text=f"Published {report_id} at {url}")],
                                structured_content={"report_id": report_id, "url": url})


@publisher.tool()
def unpublish(report_id: str) -> str:
    """Delete a published report. Destructive."""
    REPORTS.pop(report_id, None)
    return f"deleted {report_id}"


pub_http = uvicorn.Server(uvicorn.Config(publisher.streamable_http_app(), host="127.0.0.1", port=PUB_PORT,
                                         log_level="warning"))
threading.Thread(target=pub_http.run, daemon=True).start()
```

### 6. 宿主：连接、命名空间、缓存、白名单、路由、审计
**宿主（Host）**是策略所在之处。服务器是不受信任的插件；由宿主决定模型可以看到什么、做什么：

| 职责 | 本宿主的做法 |
| --- | --- |
| 连接 | 每个服务器一个 `Client`，在一个 `AsyncExitStack` 中一起打开 |
| 命名空间前缀 | `server__tool` 形式的名字（规范指出聚合方应当（SHOULD）做消歧；`serverInfo.name` 并不唯一） |
| 缓存 | 缓存合并后的工具目录，直到最小的 `ttlMs` 过期 |
| 最小权限 | **白名单**既过滤工具目录，*又*在每次调用时再次检查 |
| 循环中的资源 | 一个宿主工具 `host__read_resource`，只读取已连接服务器的 URI，并做截断 |
| 可观测性 | 每次调用一条审计记录 + 每个请求的 `_meta` 中放一个 W3C `traceparent` |
| 上下文卫生 | 工具输出在到达模型之前被截断 |

```python
SEP = "__"
MAX_RESULT_CHARS = 1500


class Host:
    def __init__(self, factories: dict, allowlist: set[str]):
        self.factories, self.allowlist = factories, allowlist
        self.clients: dict[str, Client] = {}
        self.audit: list[dict] = []
        self.catalog_fetches = 0
        self._catalog, self._fresh_until = None, 0.0
        self.trace_id = secrets.token_hex(16)

    async def __aenter__(self):
        self._stack = AsyncExitStack()
        for name, factory in self.factories.items():
            self.clients[name] = await self._stack.enter_async_context(factory())
        return self

    async def __aexit__(self, *exc):
        await self._stack.aclose()

    # ---- discovery ------------------------------------------------------------------------------
    async def tools(self) -> list[dict]:
        """Anthropic-shaped tool list: namespaced, allowlisted, cached per ttlMs."""
        if self._catalog is not None and time.monotonic() < self._fresh_until:
            return self._catalog
        self.catalog_fetches += 1
        catalog, ttl = [], 3_600_000
        for server, client in self.clients.items():
            listing = await client.list_tools()
            ttl = min(ttl, listing.ttl_ms)
            for t in listing.tools:
                name = f"{server}{SEP}{t.name}"
                if name in self.allowlist:
                    catalog.append({"name": name, "description": f"[{server}] {t.description}",
                                    "input_schema": t.input_schema})
        catalog.append({"name": "host__read_resource",
                        "description": "Read a document by uri (e.g. library://docs/<id>) from a connected server. "
                                       "Long documents are truncated.",
                        "input_schema": {"type": "object", "properties": {"uri": {"type": "string"}},
                                         "required": ["uri"]}})
        self._catalog, self._fresh_until = catalog, time.monotonic() + ttl / 1000
        return catalog

    # ---- execution -----------------------------------------------------------------------------
    async def call(self, name: str, args: dict, step: int) -> tuple[str, bool]:
        """Route one model tool call. Returns (text for the model, is_error). Never raises."""
        traceparent = f"00-{self.trace_id}-{secrets.token_hex(8)}-01"
        record = {"step": step, "tool": name, "args": json.dumps(args)[:80], "traceparent": traceparent}
        started = time.perf_counter()
        try:
            text, is_error = await self._dispatch(name, args, traceparent)
            record["outcome"] = "tool_error" if is_error else "ok"
        except PermissionError as exc:
            text, is_error, record["outcome"] = f"Denied by host policy: {exc}", True, "denied"
        except MCPError as exc:                       # protocol error from a server
            text, is_error, record["outcome"] = f"Protocol error {exc.code}: {exc.message}", True, "protocol_error"
        except Exception as exc:                      # transport failure, timeout, ...
            text, is_error, record["outcome"] = f"Host error: {type(exc).__name__}: {exc}", True, "host_error"
        record["ms"] = round((time.perf_counter() - started) * 1000, 1)
        self.audit.append(record)
        if len(text) > MAX_RESULT_CHARS:
            text = text[:MAX_RESULT_CHARS] + f"\n[truncated {len(text) - MAX_RESULT_CHARS} chars]"
        return text, is_error

    async def _dispatch(self, name: str, args: dict, traceparent: str) -> tuple[str, bool]:
        meta = {"traceparent": traceparent}
        if name == "host__read_resource":
            uri = str(args.get("uri", ""))
            server = uri.split("://", 1)[0]
            if server not in self.clients:
                raise PermissionError(f"no connected server owns {uri!r}")
            result = await self.clients[server].read_resource(uri)
            return "\n".join(getattr(c, "text", "") or "" for c in result.contents), False
        if name not in self.allowlist:
            raise PermissionError(f"tool {name!r} is not on this workflow's allowlist")
        server, _, tool = name.partition(SEP)
        result = await self.clients[server].call_tool(tool, args, meta=meta)
        if result.structured_content is not None:
            text = json.dumps(result.structured_content, ensure_ascii=False)
        else:
            text = "\n".join(c.text for c in result.content if isinstance(c, types.TextContent))
        return text, result.is_error

    def print_audit(self):
        for r in self.audit:
            print(f"  step {r['step']:>2}  {r['outcome']:<14} {r['ms']:>7.1f} ms  {r['tool']:<26} {r['args'][:46]}")


ALLOWLIST = {"library__search_docs", "notes__create_draft", "notes__add_section", "notes__revise_section",
             "notes__get_draft", "publisher__publish"}          # note: publisher__unpublish is NOT allowed


def make_host(human: ScriptedHuman, allowlist=ALLOWLIST) -> Host:
    return Host({"library": lambda: Client(library),
                 "notes": notes_client,
                 "publisher": lambda: publisher_client("tok-alice-publisher", human)}, allowlist)


async with make_host(ScriptedHuman()) as host:
    tools = await host.tools()
    tools_again = await host.tools()
    print("model sees", len(tools), "tools:", [t["name"] for t in tools])
    print("catalog fetched", host.catalog_fetches, "time(s) for 2 requests (cached per ttlMs)")
    print(await host.call("publisher__unpublish", {"report_id": "x"}, step=0))
    print(await host.call("host__read_resource", {"uri": "file:///etc/passwd"}, step=0))
    host.print_audit()
```

### 7. 规划器与智能体循环
这个智能体循环（Agent Loop）就是标准的 Claude 工具调用循环：带着工具调用模型；只要 `stop_reason == "tool_use"`，就执行**每一个** `tool_use` 块，追加助手轮次，然后追加**一个**装有所有 `tool_result` 块（带 `is_error`）的用户轮次，再次调用模型——以 `max_steps` 为上限。

为了离线运行，`ScriptedPlanner` 是一个确定性的假 LLM，具有*相同的* `create(model=, max_tokens=, tools=, messages=)` 签名和 Anthropic 形态的 `tool_use` 块。它不是一份硬编码的调用脚本：它像模型一样读取 `messages` 中的工具结果（命中、URI、`draft_id`、错误）来选择下一步。`gullible` 标志会让它服从文档里发现的指令——相当于一个被成功提示注入（Prompt Injection）的模型。

```python
MODEL = "claude-opus-5-5"
TASK = ("Research how MCP servers scale horizontally, write a short cited report in my notes, "
        "and publish it to the team wiki.")


@dataclass
class Block:                       # mimics anthropic's TextBlock / ToolUseBlock
    type: str
    text: str | None = None
    id: str | None = None
    name: str | None = None
    input: dict | None = None


@dataclass
class FakeResponse:
    content: list
    stop_reason: str


def last_turn(messages):
    """(tool_use, result) pairs of the most recent assistant turn."""
    if len(messages) < 3:
        return []
    results = {r["tool_use_id"]: r for r in messages[-1]["content"]}
    return [(b, results[b.id]) for b in messages[-2]["content"] if b.type == "tool_use"]


class ScriptedPlanner:
    """A deterministic stand-in for Claude. Same call shape as client.messages.create."""

    def __init__(self, gullible: bool = False):
        self.gullible, self.n, self.hits, self.sources, self.draft_id = gullible, 0, [], [], None
        self.searches = 0

    def _use(self, name, **args):
        self.n += 1
        return Block(type="tool_use", id=f"toolu_{self.n:02d}", name=name, input=args)

    def create(self, *, model, max_tokens, tools, messages):
        blocks = self.plan(messages)
        if blocks and blocks[0].type == "tool_use":
            return FakeResponse([Block(type="text", text="(planning)")] + blocks, "tool_use")
        return FakeResponse(blocks, "end_turn")

    def plan(self, messages):
        turn = last_turn(messages)
        if not turn:
            self.searches += 1
            return [self._use("library__search_docs", query="stateless scaling load balancer")]
        call, result = turn[-1]
        text, failed = result["content"], result["is_error"]
        if call.name == "library__search_docs":
            if failed:                                       # transient failure: retry the same call once
                return [self._use(call.name, **call.input)]
            page = json.loads(text)
            self.hits += page["hits"]
            if page["next_cursor"] and self.searches < 2:
                self.searches += 1
                return [self._use(call.name, query=call.input["query"], cursor=page["next_cursor"])]
            top = sorted(self.hits, key=lambda h: -h["score"])[:2]
            return [self._use("host__read_resource", uri=h["uri"]) for h in top]   # parallel tool calls
        if call.name == "host__read_resource":
            self.sources = [(c.input["uri"], r["content"]) for c, r in turn if not r["is_error"]]
            injected = re.search(r"call (\w+) with report_id='([^']*)'", " ".join(t for _, t in self.sources))
            if self.gullible and injected:
                return [self._use(injected.group(1), report_id=injected.group(2))]
            return [self._use("notes__create_draft", title="How MCP servers scale horizontally")]
        if call.name == "publisher__unpublish":              # the injected detour failed; back on task
            return [self._use("notes__create_draft", title="How MCP servers scale horizontally")]
        if call.name == "notes__create_draft":
            self.draft_id = json.loads(text)["draft_id"]
            findings = "\n".join(f"- {body.split(chr(10))[-1].split('. ')[0]}. [{i}]"
                                 for i, (_, body) in enumerate(self.sources, 1))
            refs = "\n".join(f"[{i}] {uri}" for i, (uri, _) in enumerate(self.sources, 1))
            return [self._use("notes__add_section", draft_id=self.draft_id, heading="Findings", text=findings),
                    self._use("notes__add_section", draft_id=self.draft_id, heading="Sources", text=refs)]
        if call.name == "notes__add_section":
            summary = ("MCP 2026-07-28 requests are self-contained, so servers scale behind an ordinary "
                       "round-robin load balancer; keep cross-call state behind explicit handles. [1][2]")
            return [self._use("notes__revise_section", draft_id=self.draft_id, heading="Findings",
                              text=summary + "\n" + turn[0][0].input["text"])]
        if call.name == "notes__revise_section":
            return [self._use("notes__get_draft", draft_id=self.draft_id)]
        if call.name == "notes__get_draft":
            draft = json.loads(text)
            return [self._use("publisher__publish", title="How MCP servers scale horizontally",
                              body=draft["markdown"])]
        if call.name == "publisher__publish":
            if failed:
                return [Block(type="text", text=f"I drafted the report ({self.draft_id}) but did not publish it: {text}")]
            return [Block(type="text", text=f"Done. Published at {json.loads(text)['url']} (draft {self.draft_id}).")]
        return [Block(type="text", text=f"Stopping: unexpected state after {call.name}.")]


async def run_agent(llm, host: Host, task: str, max_steps: int = 12, verbose: bool = True) -> dict:
    """The manual Claude tool-use loop, with the host enforcing policy on every call."""
    tools = await host.tools()
    messages = [{"role": "user", "content": task}]
    response = llm.create(model=MODEL, max_tokens=16000, tools=tools, messages=messages)
    steps = 0
    while response.stop_reason == "tool_use":
        steps += 1
        if steps > max_steps:
            return {"final": f"stopped: exceeded max_steps={max_steps}", "steps": steps - 1, "messages": messages}
        messages.append({"role": "assistant", "content": response.content})
        results = []
        for block in response.content:
            if block.type == "tool_use":
                text, is_error = await host.call(block.name, block.input, step=steps)
                if verbose:
                    flag = "ERR" if is_error else "ok "
                    print(f"step {steps:>2} {flag} {block.name}({json.dumps(block.input)[:60]}) -> {text[:70]!r}")
                results.append({"type": "tool_result", "tool_use_id": block.id, "content": text,
                                "is_error": is_error})
        messages.append({"role": "user", "content": results})
        tools = await host.tools()                       # served from the host cache while fresh
        response = llm.create(model=MODEL, max_tokens=16000, tools=tools, messages=messages)
    final = "".join(b.text for b in response.content if b.type == "text")
    return {"final": final, "steps": steps, "messages": messages}
```

### 8. 端到端运行工作流
检索 →（下一页）→ 读取 ×2 → 创建草稿 → 添加章节 ×2 → 修改 → 获取 → 发布（带确认）。观察审计日志（Audit Trail）：每次调用都有一个结果、一个延迟，以及同一 trace id 下属于它自己的 `traceparent` span id。

### 9. 把它弄坏：一个不稳定的工具、一次提示注入、一个“不”
生产工作流必须扛住的三种故障：

1. **暂时性工具故障**——检索后端超时一次；错误以 `isError: true` 返回，规划器重试。
2. **提示注入（Prompt Injection）**——轻信的规划器服从了藏在文档里的“SYSTEM NOTE”，尝试调用 `publisher__unpublish`。**宿主白名单**在任何服务器看到它之前就拦下了它：防御在代码里，而不是在模型的良好表现里。
3. **人类拒绝**——`publish` 返回一个工具错误，循环干净地结束，什么也没有发布。

```python
REPORTS.clear()
SEARCH_FAULTS["remaining"] = 1
naysayer = ScriptedHuman(approve=False)
async with make_host(naysayer) as chaos_host:
    chaos = await run_agent(ScriptedPlanner(gullible=True), chaos_host, TASK)

print("\nFINAL:", chaos["final"])
print("published reports:", REPORTS)
outcomes = [r["outcome"] for r in chaos_host.audit]
print("outcomes:", {o: outcomes.count(o) for o in sorted(set(outcomes))})
chaos_host.print_audit()
```

### 11. 端到端测试
一个综合项目在经过测试之前不算完成。这些断言把真正重要的行为固定下来：正确的调用按正确的顺序发生、策略得到执行、状态由句柄（State Handle）承载、恰好问了人一次、链路追踪上下文得到传播，以及故障被转化为可恢复的错误。

```python
def test_happy_path():

def test_report_content():
    assert "## Findings" in published_body and "## Sources" in published_body
    assert "library://docs/" in published_body                           # citations survived
    assert "SYSTEM NOTE" not in published_body                           # injected text did not leak
```
