## Summary
提示模板（Prompt）是服务器的第三种原语（Primitive），也是唯一由**用户**控制的原语：它是可复用的参数化模板——“审查这段代码”“规划一次度假”——由人显式挑选，通常以**斜杠命令（Slash Command）**的形式出现。服务器用 `prompts/list` 列出它们，`prompts/get` 则用用户提供的参数把某个提示模板渲染成一组 `PromptMessage`，其中可以混合文本、图片、音频、资源链接和嵌入式资源。由于手工填写参数容易出错，MCP 为提示模板（以及资源模板）配备了**参数补全（Completion）**：`completion/complete` 会针对正在输入的参数返回最多 100 条按相关性排序的建议，并且会考虑已经选好的其他参数。本课涵盖 2026-07-28 规范中的这两个页面、它们的错误与安全规则，并搭建一个可运行的斜杠命令流程。

## Lesson
### 提示模板由用户控制
规范将提示模板（Prompt）定义为与语言模型交互的结构化消息和指令，客户端可以发现、获取它们，并用参数进行定制。它们是**用户控制（User-controlled）**的：之所以暴露出来，是为了让*用户*能够显式选择它们。规范还补充了一句精确的说明：这“指的是由谁决定何时使用该提示模板，而不是由谁编写其内容。提示模板的内容由服务器定义。”

这使得提示模板成为服务器作者交付**专业经验**的方式：比如针对*这个*代码库约定发起代码审查的最佳问法，或者一个知道要先查看日历资源、再调用天气工具的度假规划工作流。文档把它们描述为“预先构建的指令模板，告诉模型去使用特定的工具和资源”，也是一种“展示如何最好地使用该 MCP 服务器”的方式。

| | 工具 | 资源 | 提示模板 |
| --- | --- | --- | --- |
| 由谁决定使用 | 模型 | 应用 | **用户** |
| 典型触发方式 | LLM 发出工具调用 | 选择器 / 自动纳入 | `/command`、菜单、按钮 |
| 输出 | 结果内容 | 某个 URI 的内容 | 用于开启或引导对话的消息 |

宿主（Host）如何呈现它们由宿主自己决定。常见模式有：**斜杠命令（Slash Command）**（输入 `/` 就能看到 `/plan-vacation`）、命令面板、专用按钮、上下文菜单中的建议。好的 UI 会让提示模板易于发现，清楚说明每个模板的作用，带校验地收集参数，并对背后的模板保持透明。

### 能力、列举与获取
```json
{"capabilities": {"prompts": {"listChanged": true}}}
```
提供提示模板的服务器**必须（MUST）**在其 `DiscoverResult` 中声明此能力（Capability）。列表规则与工具和资源相同：`prompts/list` 返回请求方当前可用的提示模板，不得（MUST NOT）因连接不同或作为其他请求的副作用而变化，但可以（MAY）随授权而不同。它支持分页和缓存（`ttlMs`、`cacheScope`）。

```json
{"jsonrpc": "2.0", "id": 1, "result": {"resultType": "complete",
  "prompts": [{"name": "code_review", "title": "Request Code Review",
               "description": "Asks the LLM to analyze code quality and suggest improvements",
               "arguments": [{"name": "code", "description": "The code to review", "required": true}]}],
  "ttlMs": 600000, "cacheScope": "public"}}
```

一个 `Prompt` 包含 `name`（必填），以及可选的 `title`、`description`、`icons`、`arguments` 和 `_meta`。每个 `PromptArgument` 包含 `name`，以及可选的 `title`、`description` 和 `required`。注意*缺少*了什么：没有类型字段。在线路上，`prompts/get` 的参数是一个**字符串到字符串**的映射：

```json
{"jsonrpc": "2.0", "id": 2, "method": "prompts/get",
 "params": {"name": "code_review", "arguments": {"code": "def hello():\n    print('world')"}}}
```
```json
{"jsonrpc": "2.0", "id": 2, "result": {"resultType": "complete", "description": "Code review prompt",
  "messages": [{"role": "user", "content": {"type": "text",
                "text": "Please review this Python code:\ndef hello():\n    print('world')"}}]}}
```

> **陷阱。** 概念性页面 “Understanding MCP servers” 展示了一个 `plan-vacation` 提示模板，其参数带有 `"type": "number"` 和 `"type": "array"`。那只是示意；规范性模式（Schema）中的 `PromptArgument` 没有 `type`，参数值都是字符串。请在服务器端解析数字并进行校验。

`prompts/get` 也可能返回 `InputRequiredResult`（多轮往返）：服务器在能够解析该提示模板之前需要更多输入——比如一次征询（Elicitation）——客户端随后携带 `inputResponses` 和 `requestState` 重试（第 5.3 课）。

### `PromptMessage`：角色与内容
`GetPromptResult` 包含一个可选的 `description` 和 `messages`，其中每一项都是一个提示消息（PromptMessage），带有：

- `role`：`"user"` 或 `"assistant"`——因此提示模板可以预先铺垫一段多轮交流（少样本示例，或者一个用来框定任务的助手轮次），
- `content`：一个内容块。

内容类型与工具结果属于同一家族：

| 类型 | 说明 |
| --- | --- |
| `text` | 最常见的情况 |
| `image` | base64 编码的 `data` + 有效的 `mimeType`（**必须（MUST）**） |
| `audio` | base64 编码的 `data` + 有效的 `mimeType`（**必须（MUST）**） |
| `resource_link` | 客户端可获取的 URI，不内联内容 |
| `resource`（嵌入式） | 内联的服务器端内容；**必须（MUST）**包含有效的 URI、MIME 类型，以及 `text` 或 base64 编码的 `blob` 二者之一 |

它们都接受可选的 `audience` / `priority` / `lastModified` 注解（Annotations）。**嵌入式资源（Embedded Resource）**正是提示模板威力所在：一个 `review_against_style_guide` 提示模板可以把团队的风格指南和被审查的文件直接拉进对话，于是用户只需选一条命令，模型就能拿到所需的一切。

没有 `system` 角色。提示模板塑造的是*对话*；宿主仍然掌管它自己的系统提示词，并决定如何把 `PromptMessage` 转换成其模型提供商的消息格式。

### 列表变更、错误与良好实践
当提示模板集合发生变化时，声明了 `listChanged` 的服务器应当（SHOULD）发送列表变更通知（Notification）`notifications/prompts/list_changed`——在 2026-07-28 版本中，只发送给那些以 `promptsListChanged: true` 打开了 `subscriptions/listen` 流的客户端（第 3.4 课）。

错误采用标准 JSON-RPC：对于无效的提示模板名称和缺失的必需参数，服务器应当（SHOULD）返回 **`-32602`**；内部错误则返回 **`-32603`**。实现方面的考量：服务器应当（SHOULD）在处理前校验提示参数；客户端应当（SHOULD）为大型提示模板列表处理分页；双方都应当（SHOULD）遵守能力协商（Capability Negotiation）。安全方面，实现**必须（MUST）**仔细校验所有提示模板的输入和输出，以防止注入攻击或对资源的未授权访问——一个把用户参数插进指令的提示模板，或者按参数选择要嵌入哪个资源的提示模板，都是注入与数据访问的攻击面。

### 参数补全：为参数提供自动补全
提示参数和资源模板变量都是自由文本，但有效值往往是一个封闭的或可搜索的集合：编程语言、城市、机场代码、仓库名称。**参数补全（Completion）**提供类似 IDE 的体验：用户一边输入，客户端一边向服务器请求建议。

支持该功能的服务器**必须（MUST）**声明：

```json
{"capabilities": {"completions": {}}}
```

请求通过一个引用指明补全的*对象*，并给出参数及其当前值：

```json
{"jsonrpc": "2.0", "id": 1, "method": "completion/complete",
 "params": {"ref": {"type": "ref/prompt", "name": "code_review"},
            "argument": {"name": "language", "value": "py"}}}
```
```json
{"jsonrpc": "2.0", "id": 1, "result": {"resultType": "complete",
  "completion": {"values": ["python", "pytorch", "pyside"], "total": 10, "hasMore": true}}}
```

| 引用类型 | 标识对象 | 示例 |
| --- | --- | --- |
| `ref/prompt` | 按 `name` 标识的提示模板 | `{"type": "ref/prompt", "name": "code_review"}` |
| `ref/resource` | 按 `uri` 标识的资源 URI 或 URI 模板 | `{"type": "ref/resource", "uri": "file:///{path}"}` |

对于有**多个参数**的提示模板或资源模板，客户端应当在 `context.arguments` 中发送已确定的参数，这样建议就能依赖先前的选择：

```json
{"ref": {"type": "ref/prompt", "name": "code_review"},
 "argument": {"name": "framework", "value": "fla"},
 "context": {"arguments": {"language": "python"}}}
```
→ `{"completion": {"values": ["flask"], "total": 1, "hasMore": false}}`。如果是 `language: "javascript"`，同样的前缀永远不会建议 Flask。

结果规则：`values` 按相关性排序，**最多 100 项**；`total`（可选）是匹配总数，可能超过实际返回的数量；`hasMore`（可选）表示还有更多结果，即使确切总数未知。

### 补全的错误与实践
错误：不支持该能力时返回 `-32601`（方法未找到），无效的提示模板名称或缺失必需参数时返回 `-32602`，内部错误返回 `-32603`。服务器应当（SHOULD）按相关性排序，在合适时使用模糊匹配，进行**限流**并校验输入。客户端应当（SHOULD）对快速连续的请求做**防抖（Debounce）**（不要每敲一个键就发一次请求），在合适时缓存结果，并能应对缺失或不完整的结果。实现**必须（MUST）**校验输入、进行限流、控制对敏感建议的访问，并**防止基于补全的信息泄露**——如果对客户名称或私有仓库的自动补全无视调用方的授权（Authorization），那就是数据泄露。

### 把三种原语组合起来
文档中的多服务器旅行示例展示了预期的协作编排。**用户**调用 `/plan-vacation`，填入目的地、日期、预算（补全帮助选出 “Barcelona”）。用户选择**资源（Resource）**——他们六月的日历、旅行偏好、过往行程——由应用附加进来。提示模板的消息向**模型**下达指令，模型调用**工具（Tool）**——`searchFlights`、`checkWeather`，然后在获得批准后调用 `bookHotel`、`createCalendarEvent`、`sendEmail`。提示模板提供意图和结构，资源提供上下文，工具提供行动——各自归属自己的控制方。

## Key points
- 提示模板（Prompt）是**用户控制**的：用户决定*何时*使用；服务器定义*内容*。宿主通常把它们呈现为斜杠命令。
- 声明 `prompts`（`listChanged` 可选）；`prompts/list`（支持分页、可缓存）和 `prompts/get`（可能返回 `input_required`）。
- `PromptArgument` = `name`、`title?`、`description?`、`required?`——没有类型；`prompts/get` 的参数值都是**字符串**。
- `GetPromptResult.messages` 是一组提示消息（PromptMessage），`role` 为 `user`/`assistant`，并带一个内容块：文本、图片、音频、`resource_link` 或嵌入式 `resource`。
- 嵌入式资源（Embedded Resource）必须（MUST）包含 URI、MIME 类型以及 `text` 或 `blob`；它们让一条命令就能带上恰当的上下文。
- 提示模板错误：未知提示模板或缺失必需参数时为 `-32602`，内部错误为 `-32603`；要校验输入和输出以防注入。
- 参数补全（Completion）需要 `completions` 能力；`completion/complete` 接受 `ref`（`ref/prompt` 或 `ref/resource`）、`argument {name, value}` 以及可选的 `context.arguments`。
- 结果：`values` 已排序，**最多 100 项**，另有可选的 `total` 和 `hasMore`；客户端做防抖（Debounce），服务器做限流并防止信息泄露。

## Pitches
### 什么是 MCP 提示模板？服务器为什么要提供它们？
提示模板（Prompt）是用户显式调用的可复用模板，通常以斜杠命令的形式出现。用户挑一个，填几个参数；服务器就返回现成的消息，可能还嵌入了风格指南或某个文件这样的资源。这让服务器作者可以把专业经验打包起来——比如用这个服务器的工具来发起审查或制定迁移计划的正确方式——用户不用自己写提示词，就能得到一致、高质量的工作流。

### MCP 中的参数补全是如何工作的？
当用户填写提示参数或资源模板变量时，客户端（Client）会发送 completion/complete，带上对该提示模板或资源模板的引用、参数名、目前已经输入的内容，以及作为上下文的已选参数。服务器（Server）返回最多一百条排好序的建议、一个可选的总数，以及一个 hasMore 标志。客户端对按键做防抖，服务器做限流，并确保建议绝不会泄露调用方本来看不到的数据。

### 什么时候某个功能应该做成提示模板而不是工具？
我会问：应该由谁来决定使用它？如果模型应该能在对话中途主动去用，那它就是工具（Tool）。如果它是一个由人刻意发起的工作流——审查这个拉取请求、撰写发布说明、规划一次旅行——那它就是提示模板（Prompt），以斜杠命令的形式呈现。提示模板本身不执行任何东西；它们生成精心编写的消息，往往还嵌入了资源，引导模型去使用正确的工具。很多好的服务器两者都提供：工具负责行动，提示模板作为引导式入口。

## Interview
### 既然 AI 应用都能“使用”提示模板和工具，它们有什么区别？
区别在于控制方。工具（Tool）是**模型控制（Model-controlled）**的：LLM 在对话中途决定调用它，而且它可能有副作用。提示模板（Prompt）是**用户控制**的：由人显式挑选，通常是一个斜杠命令，它产出用于开启或引导对话的*消息*——自身并不执行任何操作。规范强调，用户控制指的是由谁决定何时使用，而不是由谁编写内容：内容由服务器编写。提示模板常常通过指示模型使用工具和资源来*编排*它们。

### 提示模板可以返回什么？什么时候应该嵌入资源？
返回一组 `PromptMessage`，每条带有 `user` 或 `assistant` 角色和一个内容块：文本、图片、音频（base64 编码并带有效的 MIME 类型）、`resource_link`，或者一个嵌入式 `resource`——它必须（MUST）携带 URI、MIME 类型以及 `text` 或 `blob`。当内容很小且肯定需要时就嵌入（Embedded Resource）——比如 `/review` 里的团队风格指南、`/fix-test` 里的失败测试——这样用户一条命令就能拿到完整上下文。当内容很大或可有可无时，就用资源链接（Resource Link），让宿主决定是否获取。

### 客户端发送了缺少必需参数的 `prompts/get`，应该怎么处理？
服务器应当（SHOULD）返回 JSON-RPC 错误 **`-32602`（Invalid params，无效参数）**，与未知提示模板名称的错误码相同；`-32603` 留给真正的内部故障。理想情况下，错误消息会指出缺失的是哪个参数，以便宿主（Host）提示用户填写。陷阱：有些 SDK 会把这些错误都折叠成 `-32603`；Python 的 `MCPServer` 就是如此，所以要遵循规范，你得自己做校验，并抛出带 `INVALID_PARAMS` 的 `MCPError`。

### 为一个带 `environment` 和 `service` 参数的 `deploy` 提示模板设计参数补全。
声明 `completions`。对于 `environment`，按前缀筛选，返回调用方有权部署的环境。对于 `service`，利用 `context.arguments.environment`，只列出该环境中存在的服务。按相关性排序（先精确前缀，再模糊匹配，再按最近使用），最多 100 个值，如实设置 `total` 和 `hasMore`。每一条建议都要对照调用方的令牌（Token）进行**授权（Authorization）**——补全绝不能泄露用户看不到的服务名称——并进行限流。在客户端一侧，对按键做防抖（约 200 ms），并按 `(ref, argument, value, context)` 缓存结果。

### 陷阱题：文档里展示了一个带 `"type": "number"` 的提示参数。我能声明带类型的提示参数吗？
在协议层面不能。那个示例来自概念性页面 “Understanding MCP servers”；规范性的 `PromptArgument` 只有 `name`、`title`、`description` 和 `required`，而 `prompts/get` 以字符串到字符串的映射发送 `arguments`。把期望的格式写进 `description`，为封闭集合提供参数补全（Completion），并在服务器端解析和校验，遇到错误值时返回 `-32602`。如果你需要丰富的带类型输入，带 `inputSchema` 的工具——或者一个征询（Elicitation）表单——才是更合适的选择。

## Glossary
- Prompt | 提示模板 | 由服务器定义、用户显式调用的参数化消息模板。
- User-controlled | 用户控制 | 由用户决定何时使用某个原语的交互模型。
- Slash command | 斜杠命令 | 一种 UI 模式：输入 `/` 即可列出用户可运行的提示模板。
- PromptArgument | 提示参数 | 提示模板的一个具名、可选择设为必需、取值为字符串的输入。
- PromptMessage | 提示消息 | 渲染后的提示模板中的一条消息，带有 `user`/`assistant` 角色和一个内容块。
- Embedded resource | 嵌入式资源 | 内联了资源的 URI、MIME 类型以及文本或二进制内容的内容块。
- Completion | 参数补全 | 服务器为提示模板和资源模板参数提供的自动补全建议。
- `ref/prompt` / `ref/resource` | 补全引用类型 | 标识正在被补全的提示模板或资源模板的引用类型。
- Debounce | 防抖 | 推迟发送请求，直到用户停止输入，以避免每次按键都发送一个请求。

## Notebook
### 1. 一个带三种提示模板的服务器
`@server.prompt()` 把一个函数变成提示模板（Prompt）：函数参数成为提示参数（没有默认值的即为必需，用 `Field(description=...)` 添加描述），文档字符串成为描述。函数可以返回一个字符串（一条用户消息），也可以返回由 `UserMessage` / `AssistantMessage` 和原始内容块组成的列表。

```python
import json
import logging
from typing import Annotated

from pydantic import Field

import mcp_types as types
from mcp import Client
from mcp.server import MCPServer
from mcp.server.mcpserver import AssistantMessage, UserMessage
from mcp.shared.exceptions import MCPError

logging.getLogger("mcp").setLevel(logging.CRITICAL)


def show(model, limit=1800):
    data = model.model_dump(by_alias=True, exclude_none=True, mode="json")
    data.pop("_meta", None)
    print(json.dumps(data, indent=2, ensure_ascii=False)[:limit])


STYLE_GUIDE = "1. Type hints everywhere.\n2. No bare except.\n3. Functions under 40 lines."

server = MCPServer("dev-workflows")


@server.resource("docs://style-guide", mime_type="text/markdown")
def style_guide() -> str:
    return STYLE_GUIDE


@server.prompt(title="Request Code Review")
def code_review(code: Annotated[str, Field(description="The code to review")],
                language: Annotated[str, Field(description="Programming language")] = "python") -> str:
    """Asks the LLM to analyze code quality and suggest improvements."""
    return f"Please review this {language} code:\n{code}"


@server.prompt(title="Plan a vacation")
def plan_vacation(destination: Annotated[str, Field(description="City or region")],
                  days: Annotated[int, Field(description="Trip length in days (whole number)")] = 7) -> list:
    """Guide the model through planning a trip, with a worked example of the expected format."""
    return [
        UserMessage("Plan a 2-day trip to Lisbon."),
        AssistantMessage("Day 1: Alfama + tram 28. Day 2: Belém + LX Factory. Budget: ~€180."),
        UserMessage(f"Great format. Now plan a {days}-day trip to {destination}. "
```

### 4. 宿主的斜杠命令处理器
是宿主（Host）而不是协议，负责把 `PromptMessage` 转换成其模型的消息格式。这里：解析 `/command key=value`，调用 `prompts/get`，再转换成 Anthropic 风格的消息（嵌入式资源变成带标签的文本；相邻的同角色消息会被合并，因为许多聊天 API 要求角色交替出现）。

```python
import shlex


def to_chat_messages(prompt_messages):
    chat = []
    for m in prompt_messages:
        c = m.content
        if c.type == "text":
            block = {"type": "text", "text": c.text}
        elif c.type == "resource":
            body = getattr(c.resource, "text", "<binary>")
            block = {"type": "text", "text": f"<resource uri='{c.resource.uri}'>\n{body}\n</resource>"}
        elif c.type == "image":
            block = {"type": "image", "source": {"type": "base64", "media_type": c.mime_type, "data": c.data}}
        else:
            block = {"type": "text", "text": f"[{c.type}]"}
        if chat and chat[-1]["role"] == m.role:
            chat[-1]["content"].append(block)
        else:
            chat.append({"role": m.role, "content": [block]})
    return chat


async def run_slash_command(client, line: str):
    name, *pairs = shlex.split(line.lstrip("/"))
    arguments = dict(pair.split("=", 1) for pair in pairs)
    result = await client.get_prompt(name, arguments)
    return to_chat_messages(result.messages)


async with Client(server) as client:
    messages = await run_slash_command(client, "/review_with_guide code='except: pass'")
print(json.dumps(messages, indent=2))
```

### 5. 动手破坏：错误参数与错误码
规范规定，未知提示模板名称和缺失必需参数应当（SHOULD）返回 `-32602`。来看看 SDK 实际发送的是什么。

```python
async with Client(server) as client:
    for label, name, args in [("missing required arg", "code_review", {}),
                              ("unknown prompt", "deploy", {}),
                              ("non-numeric days", "plan_vacation", {"destination": "Rome", "days": "a week"})]:
        try:
            await client.get_prompt(name, args)
        except MCPError as err:
            print(f"{label:<22} -> code={err.code} message={err.message!r}")
```

三种情况返回的都是 `-32603` “Internal server error”——这是 SDK 的一个缺口，而且对正在填写表单的用户毫无帮助。在处理函数中修正它：接收原始字符串，自行校验，并抛出带 `INVALID_PARAMS` 的 `MCPError`，SDK 会原样透传它。

```python
from mcp_types import INVALID_PARAMS


@server.prompt(title="Plan a vacation (validated)")
def plan_trip(destination: Annotated[str, Field(description="City or region")],
              days: Annotated[str, Field(description="Trip length in days, 1-30")] = "7") -> str:
    """Plan a trip; validates its arguments and reports problems as -32602."""
    if not days.isdigit() or not 1 <= int(days) <= 30:
        raise MCPError(INVALID_PARAMS, f"Argument 'days' must be a whole number from 1 to 30, got {days!r}",
                       data={"argument": "days"})
    return f"Plan a {int(days)}-day trip to {destination}."


async with Client(server) as client:
    try:
        await client.get_prompt("plan_trip", {"destination": "Rome", "days": "a week"})
    except MCPError as err:
        print("fixed:", err.code, err.message, err.data)
```

### 6. 为提示参数和模板变量提供参数补全
一个 `@server.completion()` 处理函数服务所有 `completion/complete` 请求；它接收 `ref`、`argument`（`name`、`value`），以及包含已确定参数的 `context`。注册它之后，服务器就会公布 `completions` 能力（Capability）。我们把值的数量上限设为 100，并报告 `total` / `hasMore`。

```python
LANGUAGES = ["python", "pytorch", "pyside", "perl", "php", "javascript", "java", "go", "rust"]
FRAMEWORKS = {"python": ["flask", "fastapi", "django"], "javascript": ["express", "fastify", "next"]}
CITIES = ["Paris", "Park City", "Parma", "Barcelona", "Barbados", "Berlin"]


@server.resource("weather://forecast/{city}/{date}", mime_type="application/json")
def forecast(city: str, date: str) -> str:
    return json.dumps({"city": city, "date": date, "high_c": 27})


@server.prompt()
def scaffold(language: str, framework: str) -> str:
    """Scaffold a new web service."""
    return f"Create a {framework} service in {language}."


def ranked(options, prefix, limit=100):
    matches = [o for o in options if o.lower().startswith(prefix.lower())]
    return types.Completion(values=matches[:limit], total=len(matches), has_more=len(matches) > limit)


@server.completion()
async def complete(ref, argument, context):
    resolved = (context.arguments if context and context.arguments else {})
    if isinstance(ref, types.PromptReference):
        if argument.name == "language":
            return ranked(LANGUAGES, argument.value)
        if argument.name == "framework":
            return ranked(FRAMEWORKS.get(resolved.get("language", ""), []), argument.value)
    if isinstance(ref, types.ResourceTemplateReference) and ref.uri == "weather://forecast/{city}/{date}":
        if argument.name == "city":
            return ranked(CITIES, argument.value)
    return None   # no suggestions -> empty values


prompt_ref = types.PromptReference(type="ref/prompt", name="scaffold")
template_ref = types.ResourceTemplateReference(type="ref/resource", uri="weather://forecast/{city}/{date}")

async with Client(server) as client:
    print("completions capability declared:", client.server_capabilities.completions is not None)
    show(await client.complete(prompt_ref, {"name": "language", "value": "py"}))
    print("framework 'f' with language=python:", (await client.complete(
        prompt_ref, {"name": "framework", "value": "f"}, {"language": "python"})).completion.values)
    print("framework 'f' with language=javascript:", (await client.complete(
        prompt_ref, {"name": "framework", "value": "f"}, {"language": "javascript"})).completion.values)
    print("city 'Par' for the forecast template:", (await client.complete(
        template_ref, {"name": "city", "value": "Par"})).completion.values)
```

先看通过 stdio 进行的原始 `completion/complete` 交换，然后把同样的请求发给一个从未注册补全处理函数的服务器：得到 `-32601` 方法未找到，与规范所列完全一致。

### 8. 客户端防抖
客户端应当（SHOULD）做防抖（Debounce）。模拟用户快速输入 `b`、`ba`、`bar`、`barc`，然后停顿：只有最后一个值会被发送出去。

```python
import asyncio

sent = []


async def debounced_complete(client, ref, arg_name, keystrokes, delay=0.15):
    pending = None

    async def fire(value):
        await asyncio.sleep(delay)
        sent.append(value)
        return (await client.complete(ref, {"name": arg_name, "value": value})).completion.values

    for value, gap in keystrokes:
        if pending:
            pending.cancel()
        pending = asyncio.create_task(fire(value))
        await asyncio.sleep(gap)
    return await pending


async with Client(server) as client:
    typing = [("b", 0.03), ("ba", 0.03), ("bar", 0.03), ("barc", 0.0)]
    values = await debounced_complete(client, template_ref, "city", typing)
print("keystrokes:", [k for k, _ in typing], "| requests actually sent:", sent, "| suggestions:", values)
```
