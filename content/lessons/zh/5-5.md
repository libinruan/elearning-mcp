## Summary
写出一个服务器（Server）只完成了一半工作，还得有人把它接入真实的宿主（Host）。本课沿着两份官方快速入门展开。**本地服务器（Local Server）** 由宿主根据 JSON 配置启动：Claude Desktop 的 `claude_desktop_config.json` 及其 `mcpServers` 配置表，其中每项由 `command`、`args` 和 `env` 组成；我们以官方的文件系统服务器（Filesystem Server）及其逐次操作审批为例说明。**远程服务器（Remote Server）** 则以自定义连接器（Custom Connector）的形式通过 URL 接入，在连接时完成认证（Authentication），并允许你限制可用的工具（Tool）。你将了解配置文件和日志存放在哪里、为什么绝对路径和显式的 `env` 如此重要，以及如何解读各种故障。随后你将亲自扮演宿主：解析配置、启动服务器、携带 bearer 令牌（Token）通过 HTTP 连接，并复现每一种典型错误。

## Lesson
### 宿主连接服务器的两种方式
模块 2 中的所有内容，在这里都变成了面向用户的选择：

| | 本地服务器 | 远程服务器 |
| --- | --- | --- |
| 传输 | **stdio**：宿主启动一个子进程 | **Streamable HTTP**：宿主连接一个 URL |
| 配置方式 | JSON 配置文件中的一条启动命令 | 在宿主界面中填写的 URL（在 Claude 中即*自定义连接器*） |
| 运行身份 | **你的用户账户**，在你的机器上 | 提供方的基础设施 |
| 认证 | 线路上通常没有认证；密钥通过 `env` 传入 | 通常在连接时走 OAuth（或 API 密钥、用户名/密码） |
| 可用范围 | 按设备：每台机器都要安装和配置 | 任何联网的 MCP 客户端都能使用 |
| 适用场景 | 文件、本地工具、开发环境 | SaaS 集成、基于 Web 的 AI 应用、服务端处理 |

文档通过 Claude 来演示这两种方式：本地服务器用 Claude Desktop，远程服务器用 Claude（网页版或桌面版）的自定义连接器。文档也强调，*“这些概念同样广泛适用于其他兼容 MCP 的客户端”*。

### Claude Desktop 中的本地服务器：配置文件
Claude Desktop 可在 macOS、Windows 和 Linux 上运行。要添加本地服务器（Local Server），请打开**系统菜单栏中的 Claude 菜单**（而不是聊天窗口里的设置）→ **Settings… → Developer → Edit Config**。如果配置文件不存在，这一步会创建它；否则会打开已有的文件：

- **macOS**：`~/Library/Application Support/Claude/claude_desktop_config.json`
- **Windows**：`%APPDATA%\Claude\claude_desktop_config.json`

快速入门的示例添加了官方的**文件系统服务器（Filesystem Server）**，它需要 Node.js（可用 `node --version` 检查）：

```json
{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": [
        "-y",
        "@modelcontextprotocol/server-filesystem",
        "/Users/username/Desktop",
        "/Users/username/Downloads"
      ]
    }
  }
}
```

逐个字段来看：

| 部分 | 含义 |
| --- | --- |
| `"filesystem"` | 服务器的友好名称，显示在 Claude Desktop 中（也用于其日志文件名） |
| `"command": "npx"` | 宿主启动的可执行程序，这里是 Node 的包运行器 |
| `"-y"` | 自动确认安装该包 |
| `"@modelcontextprotocol/server-filesystem"` | 服务器包 |
| 其余参数 | 服务器**被允许访问**的目录 |
| `"env"`（可选） | 传给服务器进程的额外环境变量 |

构建服务器的教程还给出了两种你会遇到的变体：Python 服务器用 `"command": "uv", "args": ["--directory", "/ABSOLUTE/PATH/…", "run", "weather.py"]`，而必须在项目目录中启动的服务器则使用 `"cwd"` 字段（绝对路径）。在 Windows 上，JSON 中的路径需要使用双反斜杠（`C:\\Users\\…`）或正斜杠。

> **安全提示。** *“只授予你愿意让 Claude 读取和修改的目录的访问权限。服务器以你的用户账户权限运行，因此它能执行你手动可以执行的任何文件操作。”* 本地服务器是你自己选择运行的代码。第 6.3 课会讲如何隔离它。

保存后，请**彻底退出并重新启动** Claude Desktop，因为配置只在启动时读取。然后在聊天输入框中打开 **“Add files, connectors, and more /”** 指示器 → **Connectors → Manage connectors**，选择该服务器即可查看它的工具。

### 审批如何运作
文件系统服务器（Filesystem Server）提供的工具（Tool）可以读取文件、列出目录、创建文件和文件夹、移动和重命名，以及按名称或内容搜索。文档承诺：*“所有操作在执行前都需要你的明确批准。”* 每次操作之前，Claude 都会显示一个审批请求，你可以拒绝。

这正是协议安全原则的具体体现。MCP 本身无法强制执行用户同意（Consent），必须由**宿主（Host）** 在调用工具之前取得同意，所以这道关卡位于客户端应用中，而不在服务器里。你自己的宿主也应如此：在 `tools/call` 前设置一道同意关卡，至少对所有有副作用的操作都要这样做。

### 本地服务器的故障排查
当服务器没有出现时，文档给出的检查清单是：

1. 彻底重启 Claude Desktop。
2. 检查 `claude_desktop_config.json` 的**语法**。多一个尾随逗号，就什么都加载不了。
3. 确认路径有效，并且是**绝对路径而不是相对路径**。
4. 阅读**日志**。
5. 在终端中用相同的命令和参数**手动运行服务器**，例如 `npx -y @modelcontextprotocol/server-filesystem /Users/username/Desktop …`，直接查看它的报错。

**日志。** Claude Desktop 把 MCP 日志写到 `~/Library/Logs/Claude`（macOS）或 `%APPDATA%\Claude\logs`（Windows）：

- `mcp.log`：关于 MCP 连接及连接失败的通用日志。
- `mcp-server-SERVERNAME.log`：该服务器的**标准错误（stderr）**。*“stdio 服务器可能把所有日志都写到 stderr，因此这些文件并不只包含错误。”*（在 stdio 上，stdout 承载协议消息，所以 stderr 是服务器唯一可以自由写日志的地方。）

```bash
tail -n 20 -f ~/Library/Logs/Claude/mcp*.log
```

调试指南解释了两个最常见的根本原因：

- **工作目录（Working Directory）。** 对于通过客户端配置启动的服务器，其工作目录*“可能是未定义的（例如 macOS 上的 `/`），因为客户端可能从任何位置启动。”* 在配置文件和 `.env` 文件中始终使用绝对路径。在你的终端里能用的 `./data`，放到应用里就会失败。
- **环境变量（Environment Variable）。** stdio 服务器*“只会自动继承有限的一部分环境变量（具体集合取决于平台）。”* 你在 shell 配置文件中导出的 API 密钥不会传到服务器，要把它写进 `env`。Python SDK 的 stdio 客户端也有同样的行为：它只传递一个白名单（POSIX 上为 `HOME`、`LOGNAME`、`PATH`、`SHELL`、`TERM`、`USER`），再与你的 `env` 合并。

文档还提到两点。在 **Windows** 上，如果出现提到 `${APPDATA}` 的 `ENOENT` 错误，可以把展开后的 `APPDATA` 值加入服务器的 `env` 来解决；而 `npx` 可能会一直失败，直到全局安装 npm（`npm install -g npm`）。如果**工具调用悄无声息地失败**，请检查日志，确认服务器能独立构建和运行，然后重启。对于客户端侧的错误，调试指南介绍了在 Claude Desktop 内启用 Chrome DevTools 的方法：在同一个 Claude 文件夹中的 `developer_settings.json` 里写入 `{"allowDevTools": true}`，然后按 `Command-Option-I` / `Ctrl+Alt+I`。

调试指南还把启动失败归为三类：**路径问题**（可执行文件路径错误、文件缺失、权限不足；可以尝试为 `command` 使用绝对路径，例如 `which uv` 的输出）、**配置错误**（JSON 无效、缺少字段、类型不匹配）以及**环境问题**（变量缺失或错误）。对于连接问题，请检查客户端日志，确认进程在运行，用 **MCP 检查器（Inspector）** 单独测试，并核实协议兼容性。调用 `server/discover` 可以查看服务器支持哪些版本（`-32022` 会在 `data` 中列出这些版本），同时确认每个请求的 `_meta` 都携带了 `protocolVersion` 和 `clientCapabilities`（缺少任一项都会得到 `-32602`）。

### 远程服务器：自定义连接器
远程服务器（Remote Server）*“托管在互联网上，而不是你的本地机器上”*，但它暴露的同样是工具、提示模板和资源。它的关键优势在于可访问性：无需逐台设备安装，任何联网的 MCP 客户端都能使用。在 Claude 中，远程服务器以**自定义连接器（Custom Connector）** 的形式添加，它是*“Claude 与远程 MCP 服务器之间的桥梁。”*

快速入门中的流程如下：

1. **Settings → Connectors。** 在 Claude Desktop 中使用 `Ctrl+Comma` 或菜单 → File → Settings；在浏览器中使用 `⌘⇧,` 或头像图标 → Settings。
2. **Add → “Add custom connector”**，然后粘贴服务器 URL，包括 `https://` 和路径。文档的示例是 `https://example-server.modelcontextprotocol.io/mcp`。
3. **完成认证（Authentication）。** *“大多数远程 MCP 服务器都需要认证”*，常见方式有 **OAuth**、API 密钥或用户名/密码。你可能会被重定向到第三方提供方。在底层，MCP 服务器通过 HTTP `401` 和一个 `WWW-Authenticate` 质询来表明需要认证，然后客户端执行模块 6 中介绍的 OAuth 2.1 流程。
4. 从 **“Add files, connectors, and more /”** 菜单 → Connectors → 该服务器的附件菜单中**使用资源（Resource）和提示模板（Prompt）**。它们属于应用控制和用户控制的原语（Primitive），所以由用户显式附加。
5. 在连接器的设置中**配置工具权限**：*“启用或禁用特定工具、设置使用限制，以及配置其他安全参数。”*

文档给出的**最佳实践**。安全方面：*“连接之前务必核实远程 MCP 服务器的真实性。只连接来自可信来源的服务器，并审查认证过程中请求的权限。”* 对敏感数据要保持谨慎。日常维护方面：你可以同时连接很多远程服务器，所以请按用途或项目组织连接器，并**定期移除不再使用的连接器**。你保留的每一个连接器都是攻击面，而且正如第 5.4 课所示，也都会消耗工具定义的令牌。

### Claude 之外：其他宿主中的相同理念
MCP 的要义在于：服务器并不关心是哪个宿主（Host）启动了它。文档列出了 Claude、ChatGPT、VS Code、Cursor、MCPJam 以及许多其他宿主。这套术语处处通用：一个**名称**，对于 stdio 是**启动命令 + 参数 + 环境变量**，对于 HTTP 则是 **URL + 请求头/认证**。MCP 检查器（MCP Inspector）自己的服务器目录文件（Catalog File）复用了 `mcpServers` 的结构，并增加了远程条目：

```json
{
  "mcpServers": {
    "my-stdio-server": {"command": "node", "args": ["build/index.js"], "env": {"API_KEY": "..."}},
    "my-modern-server": {"type": "http", "url": "https://api.example.com/mcp", "headers": {"X-Tenant": "acme"}}
  }
}
```

其他宿主各有自己的配置。VS Code 和 Cursor 等 IDE 使用 `mcp.json` 文件，Claude Code 则通过 `claude mcp add` 命令添加服务器。具体的文件名和键名因宿主和版本而异，请查阅各宿主的 MCP 文档。Inspector 文档还提供了一个好习惯：让密钥**远离**可共享的配置文件。Inspector 会把 `env` 中的值移入操作系统钥匙串，但会原样保存 `headers`，所以写在请求头里的凭据最终会出现在文件中。

### 这对你自己构建宿主意味着什么
亲自扮演宿主（Host）（就像 notebook 中那样）会让各项职责一目了然。在启动任何东西之前先解析并校验配置。用显式的 `env` 启动每个服务器。把每个服务器的 stderr 捕获到各自的日志中。清晰地呈现故障：一个崩溃的 stdio 服务器在客户端看来通常只是一句简单的“connection closed”，真正的原因在服务器日志里。用户同意之后才放行工具调用。对于远程服务器，按请求附加凭据（在 `Authorization` 中携带 bearer 令牌（Token）），并把 `401` + `WWW-Authenticate` 视为“开始认证流程”，而不是普通错误。

## Key points
- Claude Desktop 读取 `claude_desktop_config.json`（Claude Desktop 配置文件）：macOS 位于 `~/Library/Application Support/Claude/`，Windows 位于 `%APPDATA%\Claude\`。可通过 Settings → Developer → Edit Config 打开。
- 每个 `mcpServers` 条目都是一个友好**名称** → `command`、`args`、可选的 `env`（以及 `cwd`）。宿主（Host）通过 stdio **启动**服务器，修改配置后需要彻底重启。
- 文件系统服务器（Filesystem Server）的额外参数就是它**唯一可以访问的目录**。它以**你的用户权限**运行，并且在 Claude 中每个操作都需要你批准。
- 使用**绝对路径**：由配置启动的服务器，其工作目录（Working Directory）可能是未定义的（例如 macOS 上的 `/`）。
- stdio 服务器只继承**有限的一部分环境变量**（Environment Variable Inheritance）。请通过 `env` 传递密钥。
- 日志：`~/Library/Logs/Claude` 或 `%APPDATA%\Claude\logs` 中的 `mcp.log`（连接）和 `mcp-server-NAME.log`（该服务器的 stderr）。也可以手动运行命令，或用 MCP 检查器（Inspector）测试。
- 远程服务器（Remote Server）以**自定义连接器（Custom Connector）** 的形式通过 **URL** 添加（Settings → Connectors → Add custom connector），在连接时完成认证（通常是 OAuth），并且可以逐个启用或禁用工具。
- 只连接**可信的**远程服务器（Remote Server），审查所请求的权限，并移除不再使用的连接器。

## Pitches
### 如何把本地 MCP 服务器接入 Claude Desktop？
我会打开 Settings，进入 Developer，点 Edit Config，这样就会打开 claude_desktop_config.json。在 mcpServers 下面加一个条目，写上名称、启动命令、参数，以及需要的环境变量，比如用 npx 运行文件系统服务器（Filesystem Server）的包，再带上它可以访问的那些绝对路径目录。然后彻底重启应用，它会通过 stdio 把服务器拉起来。如果服务器没出现，我就检查 JSON、绝对路径和 env，看一下 mcp-server-name.log，再在终端里手动跑一遍同样的命令。

### 本地服务器还是远程服务器，怎么选？
本地 stdio 服务器（Local Server）跑在用户自己的机器上，用的是用户的权限，所以很适合文件、本地工具和开发环境，但每台设备都得各自安装和配置。远程服务器（Remote Server）就是一个 URL，背后是 Streamable HTTP，通常再加上 OAuth。它在任何客户端上都能用，包括网页应用，不需要安装，服务端处理和认证都交给提供方来做。所以数据在本机上我就选本地，共享的、SaaS 那类集成我就选远程。

### 你的 MCP 服务器在终端里能跑，在 Claude Desktop 里却不行。你会检查什么？
先看日志：mcp.log 看连接情况，mcp-server-name.log 看服务器自己的 stderr。最常见的罪魁祸首是相对路径，因为应用的工作目录（Working Directory）可能是根目录，而不是我的项目目录。其次是环境变量，stdio 服务器只继承一小部分，所以我 shell 配置里的 API 密钥根本传不过去，除非写进 env。再就是命令不在应用的 PATH 里，我会换成绝对路径，比如 which uv 的输出。最后才是 JSON 语法错误。

## Interview
### 请讲讲从保存 `claude_desktop_config.json` 到模型调用工具之间发生了什么。
重启时，宿主（Host）读取 `mcpServers`。对每个条目，它用 `args` 启动 `command`，环境变量由平台相关的继承子集加上 `env` 组成，stdin/stdout 作为 stdio 传输（Transport），stderr 被捕获到 `mcp-server-NAME.log`。接着客户端（Client）发现服务器（在 2026-07-28 中是 `server/discover`，对较旧的服务器则是 `initialize` 握手），并列出它的工具（Tool）。宿主把这些工具转换为提供给模型的工具定义。当模型发出工具调用时，宿主会显示一个**审批提示**。只有用户批准后，它才会通过 stdin 发送 `tools/call`，并把结果返回给模型。

### 为什么文档坚持要用绝对路径？
因为启动服务器的是宿主（Host），而不是你的 shell。由配置启动的服务器，其工作目录（Working Directory）*“可能是未定义的（例如 macOS 上的 `/`），因为客户端可能从任何位置启动。”* `args`、`command` 或服务器 `.env` 中的相对路径，都会相对于这个未知目录解析，从而悄无声息地指向别处。绝对路径（或绝对路径的 `cwd`）能让启动过程可复现。`command` 也是同理：GUI 应用的 `PATH` 往往与你的终端不同，所以文档建议对 `uv` 这类可执行文件使用完整路径。

### 一位同事的 API 密钥设置在 `~/.zshrc` 中，但服务器提示缺少该密钥。请解释原因。
stdio 服务器*“只会自动继承有限的一部分环境变量”*（Environment Variable Inheritance），具体集合取决于平台。例如 Python SDK 在 POSIX 上只传递 `HOME`、`LOGNAME`、`PATH`、`SHELL`、`TERM` 和 `USER`。此外，从程序坞启动的 GUI 应用根本没有执行过 `.zshrc`。解决办法是在该服务器的配置条目中使用 `env` 块。这是刻意的设计：它能防止无关的密钥泄漏到每一个服务器中。在 Windows 上，文档展示了一个相关案例：`${APPDATA}` 相关的错误可以通过把展开后的 `APPDATA` 值放进 `env` 来解决。

### 从用户和协议的角度看，连接远程服务器与连接本地服务器有何不同？
对用户来说，没有安装步骤，也没有命令：只需把 URL 粘贴到**自定义连接器（Custom Connector）** 中，登录（通常是 OAuth），然后就可以启用或禁用单个工具并设置使用限制。对协议来说，传输（Transport）是 **Streamable HTTP** 而不是 stdio。每个请求都是一个 HTTP POST，携带 `MCP-Protocol-Version`、`Mcp-Method` 以及 `Authorization` bearer 令牌（Token）；未经认证的请求会收到带 `WWW-Authenticate` 质询的 `401`，由此启动 OAuth 流程。服务器运行在提供方的基础设施上，因此信任转移到了提供方。要核实其真实性、审查所请求的权限，并移除不用的连接器。

### 陷阱题：你的 stdio 服务器用 `print()` 打印了“Server started!”，结果宿主连不上。为什么？
在 stdio 上，**stdout 是协议通道**。每一行都必须是一条 JSON-RPC 消息，所以一个多余的 `print()` 就会破坏数据流。应当改为把日志写到**标准错误（stderr）**。在 Claude Desktop 中，这些输出会进入 `mcp-server-NAME.log`，文档指出该文件可能包含服务器的全部日志，而不仅仅是错误。在终端里手动运行服务器，是查看此类输出最快的方法。

### 你会如何加固团队对本地和远程 MCP 服务器的使用？
本地方面：只给文件系统服务器（Filesystem Server）授予必需的目录，记住它以用户的权限运行。从可信来源安装服务器并固定版本，而不是用不断变化的 `npx -y` 最新版。把密钥放在 `env` 或钥匙串中，而不是放在提交到仓库的配置里。隔离有风险的服务器（第 6.3 课）。远程方面：只通过 HTTPS 连接经过核实的服务器，在授权同意时审查 OAuth 权限范围（Scope），禁用不需要的工具，并清理不用的连接器。两者共通的是：对有副作用的工具保留宿主的逐次调用审批（Tool Approval），并持续关注日志。

## Glossary
- `claude_desktop_config.json` | Claude Desktop 配置文件 | 一个 JSON 文件，其中的 `mcpServers` 配置表告诉 Claude Desktop 要启动哪些本地服务器以及如何启动。
- `mcpServers` | `mcpServers`（服务器配置表） | 把每个服务器的友好名称映射到其启动 `command`、`args` 和 `env` 的配置对象。
- Local server | 本地服务器 | 由宿主在用户机器上作为子进程启动、并通过 stdio 通信的 MCP 服务器。
- Remote server | 远程服务器 | 托管在互联网上、通过 URL 经 Streamable HTTP 访问的 MCP 服务器。
- Custom Connector | 自定义连接器 | Claude 中通过 URL 添加远程 MCP 服务器的界面机制，包括认证和工具权限设置。
- Filesystem Server | 文件系统服务器 | 官方参考服务器，提供文件操作，且仅限于作为参数传入的目录。
- Working directory | 工作目录 | 进程启动时所在的目录；对由配置启动的服务器来说它是未定义的，因此要使用绝对路径。
- Environment variable inheritance | 环境变量继承 | stdio 服务器只会收到宿主环境变量中的有限子集，外加配置中的 `env`。
- `mcp-server-NAME.log` | 服务器日志文件 | Claude Desktop 为每个服务器单独保存的日志文件，内容是该服务器的 stderr 输出。
- Tool approval | 工具调用审批 | 在执行工具调用之前，由宿主侧显示的用户同意提示。

```python
def validate_config(text: str) -> list[str]:
    try:
        data = json.loads(text)
    except json.JSONDecodeError as exc:
        return [f"invalid JSON at line {exc.lineno}, column {exc.colno}: {exc.msg}"]
    servers = data.get("mcpServers")
    if not isinstance(servers, dict):
        return ["top-level `mcpServers` object is missing"]
    problems = []
    for name, entry in servers.items():
        cmd = entry.get("command")
        if not isinstance(cmd, str) or not cmd:
            problems.append(f"{name}: `command` must be a non-empty string")
        elif not (Path(cmd).is_absolute() and Path(cmd).exists()) and shutil.which(cmd) is None:
            problems.append(f"{name}: command {cmd!r} not found on PATH (try an absolute path)")
        args = entry.get("args", [])
        if not isinstance(args, list) or not all(isinstance(a, str) for a in args):
            problems.append(f"{name}: `args` must be a list of strings")
        else:
            for a in args:
                looks_like_path = "/" in a or "\\" in a or a.startswith(".")
                if looks_like_path and not Path(a).is_absolute():
                    problems.append(f"{name}: relative path {a!r} (the host's working directory is undefined)")
        env = entry.get("env", {})
        if not isinstance(env, dict) or not all(isinstance(v, str) for v in env.values()):
            problems.append(f"{name}: `env` must map names to string values")
    return problems


print("our config:", validate_config(CONFIG_PATH.read_text()) or "OK")
broken = '''{
  "mcpServers": {
    "notes": {"command": "pyhton3", "args": ["./notes_server.py", "Desktop"], "env": {"PORT": 8080}},
  }
}'''
print("broken (trailing comma):", validate_config(broken))
print("broken (comma fixed):  ", *validate_config(broken.replace("},\n  }", "}\n  }")), sep="\n  ")
```

### 3. 扮演宿主：读取配置、启动所有服务器、列出工具
这就是 Claude Desktop 启动时所做的事：读取 `mcpServers`，用 `command`、`args` 和 `env` 把每个服务器作为子进程启动，并通过 stdio 与之通信。和真实应用一样，我们的宿主（Host）为**每个服务器写一个日志文件**，记录该服务器的 stderr（`mcp-server-NAME.log`），另外再写一个通用的 `mcp.log`。

```python
LOGS = work / "logs"
LOGS.mkdir(exist_ok=True)


def host_log(msg: str) -> None:
    with open(LOGS / "mcp.log", "a") as f:
        f.write(f"{time.strftime('%H:%M:%S')} {msg}\n")


def params_for(entry: dict) -> StdioServerParameters:
    return StdioServerParameters(command=entry["command"], args=entry.get("args", []),
                                 env=entry.get("env"), cwd=entry.get("cwd"))


async def connect_all(stack: AsyncExitStack, cfg: dict) -> dict[str, Client]:
    clients = {}
    for name, entry in cfg["mcpServers"].items():
        errlog = stack.enter_context(open(LOGS / f"mcp-server-{name}.log", "a"))
        host_log(f"[{name}] launching: {entry['command']} {' '.join(entry.get('args', []))}")
        try:
            clients[name] = await stack.enter_async_context(Client(stdio_client(params_for(entry), errlog=errlog)))
            host_log(f"[{name}] connected, protocol {clients[name].protocol_version}")
        except Exception as exc:
            host_log(f"[{name}] FAILED: {exc!r}")
    return clients


cfg = json.loads(CONFIG_PATH.read_text())
async with AsyncExitStack() as stack:
    clients = await connect_all(stack, cfg)
    for name, client in clients.items():
        tools = (await client.list_tools()).tools
        print(f"{name}: {[t.name for t in tools]}")
    notes = clients["notes"]
    files = (await notes.call_tool("list_files", {})).structured_content["result"]
    print("list_files ->", [Path(f).name for f in files])
    print("read_file  ->", (await notes.call_tool("read_file", {"path": files[0]})).content[0].text.strip())
    escape = await notes.call_tool("read_file", {"path": str(SERVER)})

print("\n--- mcp.log ---\n" + (LOGS / "mcp.log").read_text())
```

### 4. stdio 服务器实际拿到的是什么环境？
调试指南警告说，stdio 服务器**只继承有限的一部分环境变量**（Environment Variable Inheritance）。Python SDK 把这一点具体化了：它传递一个小小的白名单（POSIX 上为 `HOME`、`LOGNAME`、`PATH`、`SHELL`、`TERM`、`USER`），再与你的 `env` 合并。在 shell 中导出的密钥**不会**传到服务器，除非你把它写进 `env`。

```python
os.environ["MY_SHELL_SECRET"] = "only-in-the-host"
async with Client(params_for(cfg["mcpServers"]["notes"])) as c:
    seen = (await c.call_tool("visible_env", {})).structured_content["result"]
print("server sees:", seen)
print("MY_SHELL_SECRET visible?", "MY_SHELL_SECRET" in seen, "| NOTES_API_TOKEN visible?", "NOTES_API_TOKEN" in seen)
```

### 5. 审批如何运作：宿主中的同意关卡
在 Claude Desktop 中，*每一个*文件系统操作都要等待你的批准。这道关卡属于**宿主（Host）**，而不属于协议：在转发 `tools/call` 之前，宿主会询问用户。这里由一个脚本化的“用户”批准读操作、拒绝写操作。被拒绝的调用永远不会到达服务器。

```python
def ask_user(server: str, tool: str, args: dict) -> bool:
    decision = not tool.startswith("write")              # scripted user: allow reads, deny writes
    print(f"  [approval] {server}.{tool}({json.dumps(args)[:60]}) -> {'ALLOW' if decision else 'DENY'}")
    return decision


async def guarded_call(client: Client, server: str, tool: str, args: dict):
    if not ask_user(server, tool, args):
        return {"isError": True, "content": "The user declined this tool call."}
    r = await client.call_tool(tool, args)
    return {"isError": r.is_error, "content": r.structured_content or r.content[0].text}


async with Client(params_for(cfg["mcpServers"]["notes"])) as c:
    print(await guarded_call(c, "notes", "read_file", {"path": str(work / "Desktop" / "todo.md")}))
    print(await guarded_call(c, "notes", "write_file", {"path": str(work / "Desktop" / "poem.txt"), "text": "roses"}))
print("poem.txt exists?", (work / "Desktop" / "poem.txt").exists())
```

### 6. 故障排查：复现典型故障
下面每个案例都是现实中会犯的错误。请对比**宿主**看到的内容（往往只是一个被关闭的连接）和**服务器日志**中的内容。正是这种差距，让文档首先把你引向 `mcp-server-NAME.log`（服务器日志文件）。

```python
def root_cause(exc: BaseException) -> BaseException:
    while isinstance(exc, BaseExceptionGroup) and len(exc.exceptions) == 1:
        exc = exc.exceptions[0]
    return exc


good = cfg["mcpServers"]["notes"]
CASES = {
    "relative path": {**good, "args": [str(SERVER), "Desktop"]},
    "missing env var": {k: v for k, v in good.items() if k != "env"},
    "non-existent command": {**good, "command": "pyhton3"},
}
for label, entry in CASES.items():
    log_file = LOGS / f"case-{label.replace(' ', '-')}.log"
    t0 = time.time()
    try:
        with open(log_file, "w") as errlog:
            async with Client(stdio_client(params_for(entry), errlog=errlog)) as c:
                await c.list_tools()
        outcome = "connected?!"
    except BaseException as exc:
        cause = root_cause(exc)
        outcome = f"{type(cause).__name__}: {cause}"
    print(f"### {label}  ({time.time() - t0:.1f}s)\n  host sees : {outcome}")
    print(f"  server log: {log_file.read_text().strip() or '(empty: the process never started)'}\n")
```

这些修复方法与文档的检查清单一致：使用**绝对路径**（服务器把 `Desktop` 相对于宿主的工作目录（Working Directory）进行了解析），把必需的密钥放进 **`env`**，并让 `command` 是宿主能找到的程序。先手动运行一遍，或者给出绝对路径，例如 `which uv` 的输出。

### 7. 一个基于 Streamable HTTP、使用 bearer 令牌的“远程”服务器
远程服务器（Remote Server）通过 **URL** 而不是启动命令来访问。在 Claude 中，这就是自定义连接器（Custom Connector），客户端会在你连接时完成认证（通常是 OAuth）。这里用一个 localhost 服务器来代替互联网。一个小小的 ASGI 包装层会拒绝所有不带正确 `Authorization` 请求头的请求，返回 `401` 和一个 `WWW-Authenticate` 质询，这正是受保护的 MCP 服务器表明需要认证的方式（模块 6 会讲真正的 OAuth 流程）。

```python
import httpx2
import uvicorn
from mcp.client.streamable_http import streamable_http_client
from mcp.server import MCPServer

remote = MCPServer("tickets")


@remote.tool()
def open_tickets(team: str) -> list[str]:
    """Open tickets for a team."""
    return {"platform": ["PLAT-7 flaky deploy", "PLAT-9 disk alert"]}.get(team, [])


TOKEN = "demo-access-token"
requests_seen = []
mcp_app = remote.streamable_http_app()


async def protected(scope, receive, send):
    if scope["type"] == "http":
        headers = dict(scope["headers"])
        auth = headers.get(b"authorization", b"").decode()
        requests_seen.append((headers.get(b"mcp-method", b"-").decode(), "token" if auth else "no token"))
        if auth != f"Bearer {TOKEN}":
            await send({"type": "http.response.start", "status": 401,
                        "headers": [(b"content-type", b"application/json"),
                                    (b"www-authenticate", b'Bearer realm="tickets"')]})
            await send({"type": "http.response.body", "body": b'{"error": "invalid_token"}'})
            return
    await mcp_app(scope, receive, send)


sock = socket.socket()
sock.bind(("127.0.0.1", 0))
PORT = sock.getsockname()[1]
sock.close()
http_server = uvicorn.Server(uvicorn.Config(protected, host="127.0.0.1", port=PORT, log_level="warning"))
threading.Thread(target=http_server.run, daemon=True).start()
while not http_server.started:
    await asyncio.sleep(0.05)
URL = f"http://127.0.0.1:{PORT}/mcp"
print("remote server at", URL)
```

通过 URL 连接。要发送自定义请求头，就给 `streamable_http_client` 传入你自己的 `httpx2.AsyncClient`（SDK 使用的 HTTP 库），再把这个传输（Transport）传给 `Client`。

```python
async with httpx2.AsyncClient(headers={"Authorization": f"Bearer {TOKEN}"}, trust_env=False) as http:
    async with Client(streamable_http_client(URL, http_client=http)) as c:
        print("negotiated:", c.protocol_version)
        r = await c.call_tool("open_tickets", {"team": "platform"})
        print("open_tickets ->", r.structured_content)

try:
    async with Client(URL) as c:                       # no Authorization header
        await c.list_tools()
except BaseException as exc:
    print("\nwithout a token ->", type(root_cause(exc)).__name__, root_cause(exc))

async with httpx2.AsyncClient(trust_env=False) as raw:
    resp = await raw.post(URL, json={"jsonrpc": "2.0", "id": 1, "method": "server/discover", "params": {}},
                          headers={"Accept": "application/json, text/event-stream",
                                   "MCP-Protocol-Version": "2026-07-28", "Mcp-Method": "server/discover"})
print("raw HTTP:", resp.status_code, "| WWW-Authenticate:", resp.headers.get("www-authenticate"), "|", resp.text)
print("\nwhat the server saw (Mcp-Method, auth):", requests_seen)
```

SDK 只把未经认证的尝试报告为一个笼统的错误。真正告诉你这是认证问题的，是 **HTTP 状态码和 `WWW-Authenticate` 请求头**，这就是宿主日志（或 Inspector）之所以重要的原因。服务器日志还显示，客户端先探测了 `server/discover`，然后在放弃之前又重试了旧版握手（`-`，没有 `Mcp-Method`）。

### 8. 一份配置，本地与远程兼顾
许多工具复用了 `mcpServers` 的结构，并增加了一种远程条目类型。例如 MCP 检查器（MCP Inspector）的服务器目录文件（Catalog File）接受带有 `url` 和 `headers` 的 `"type": "http"`。Claude Desktop 自己的 `claude_desktop_config.json` 在文档中只用于**本地**启动条目；远程服务器在 Claude 中是通过 Settings → Connectors 以**自定义连接器**的形式添加的。下面是一个宿主函数，可以从这样的目录中连接任意一种服务器。

```python
catalog = {"mcpServers": {
    "notes": cfg["mcpServers"]["notes"],

}}

    return await stack.enter_async_context(Client(params_for(entry)))
```

### 9. 可选：让 Claude 使用已配置的服务器
设置了 `ANTHROPIC_API_KEY` 之后，这就是一个微型的 Claude Desktop：汇集所有已配置服务器的工具（Tool）（以 `server__tool` 形式加命名空间），使用第 5 节的同意关卡，以及第 5.2 课中的智能体循环（Agent Loop）。

```python
if os.environ.get("ANTHROPIC_API_KEY"):
    import anthropic

    llm = anthropic.Anthropic()
    async with AsyncExitStack() as stack:
        clients = await connect_all(stack, cfg)
        tools, route = [], {}
        for server_name, client in clients.items():
            for t in (await client.list_tools()).tools:
                tools.append({"name": f"{server_name}__{t.name}", "description": t.description or "",
                              "input_schema": t.input_schema})
                route[f"{server_name}__{t.name}"] = (server_name, client, t.name)
        messages = [{"role": "user", "content": "What's on my todo list? Then save a two-line poem about it "
                     "to my Desktop as poem.txt."}]
        response = llm.messages.create(model="claude-opus-5-5", max_tokens=16000, tools=tools, messages=messages)
        while response.stop_reason == "tool_use":
            messages.append({"role": "assistant", "content": response.content})
            results = []
            for block in response.content:
                if block.type == "tool_use":
                    server_name, client, tool = route[block.name]
                    out = await guarded_call(client, server_name, tool, block.input)
                    results.append({"type": "tool_result", "tool_use_id": block.id,
                                    "content": json.dumps(out["content"]), "is_error": out["isError"]})
```
