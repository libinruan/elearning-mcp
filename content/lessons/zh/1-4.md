## Summary
几乎每一次关于智能体的讨论里，都有三个词被混为一谈：**函数调用（Function Calling）**（也叫工具调用，Tool Use）、**MCP** 和**智能体技能（Agent Skills）**。它们并不是竞争关系——它们回答的是三个不同的问题。函数调用回答的是*“模型如何请求我的代码去做某件事？”*；MCP 回答的是*“工具和数据从哪里来，任何应用又如何接入它们？”*；技能回答的是*“智能体如何知道做这项工作的正确流程？”*。本课用一个类比（一位新员工：双手、工牌与插座、操作手册）把三者并排比较，展示它们如何在一次请求中层层叠加，并在 notebook 中围绕同一个小任务把三者全部实现一遍。

## Lesson
### 三个问题，三个答案
当有人说“我们给智能体加了一个工具”时，他可能指的是三件不同的事。按照各自回答的问题把它们区分开：

| 问题 | 答案 | 一句话说明 |
| --- | --- | --- |
| 模型如何*请求*执行一个动作？ | **函数调用 / 工具调用** | 模型 API 的一项功能：你用 JSON Schema 描述函数，模型回复一个结构化调用，由**你的代码**来执行。 |
| 动作和数据*从哪里来*，任何 AI 应用又如何接入它们？ | **MCP** | 一个开放协议：服务器（Server）暴露工具、资源和提示模板；任何 MCP 宿主都能在运行时发现并调用它们。 |
| 智能体如何知道*怎样把工作做好*？ | **智能体技能** | 一种用于打包专业知识的开放格式：一个包含 `SKILL.md`（说明）以及可选脚本、参考资料和素材的文件夹，只在相关时才加载。 |

一句好记的口号：**函数是双手，MCP 是插头，技能是操作手册。**

### 类比：新员工的第一天
想象你招了一位能干的新员工（也就是你的智能体（Agent）里的模型）。

- **函数调用 = 员工通过填写申请单来办事的能力。** 员工不能直接操作各个系统；他们填一张申请单（“为订单 #123 退款，金额 40 €”），再由别人去执行。申请单上的字段就是 JSON Schema，执行人就是你的宿主代码。没有申请单，员工就只能动嘴。
- **MCP = 公司统一的工牌与插座系统。** 每个部门——CRM、薪资、内部 wiki——都通过*同一种*插座提供服务，所以任何员工（或者来自其他公司的外包人员：Claude、ChatGPT、VS Code、你自己的智能体）都可以插上去，看看这个部门提供什么，而无需为每个部门单独布线。MCP 决定的是*有哪些申请单、以及申请单送到哪里*。
- **技能 = 标准作业流程的入职手册。** “如何关闭一张支持工单”“如何进行季度费用审查”：一步步的专业知识、检查清单和模板。手册的目录一直放在桌上（成本很低）；只有遇到相应任务时才翻开某一章；只有某一步需要时才去查附录。

三者单独使用时各有各的无用之处：只有手册没有插座，描述的工作没人能执行；只有插座没有手册，能接入系统却缺乏对流程的判断；而没有申请单，员工根本无法行动。

> 另一种记忆方式——厨房。**函数** = 按下某个电器的具体按钮（“烤箱，200 °C”）。**MCP** = 任何电器或供应商都能接入的标准插座和送货码头。**技能** = 菜谱卡片，告诉你按哪些按钮、按什么顺序、以及为什么这样做。

### 函数调用（工具调用）：模型 API 的机制
函数调用（Function Calling）是各家模型提供商 API 的一项功能。在 Claude Messages API 中，你传入 `tools=[{"name", "description", "input_schema"}]`；当模型想要执行动作时，它会以 `stop_reason: "tool_use"` 停下，并返回一个带参数的 `tool_use` 块；你的代码执行它，再发回一个 `tool_result`。关键特性：

- **定义在你的应用里。** 函数及其模式（Schema）都存在于你的代码中；其他任何人都无法发现它们。
- **每次请求都携带完整定义。** 每个工具的名称、描述和模式每次都是提示词的一部分——工具越多，令牌（Token）越多。
- **形态由提供商决定。** 每家厂商的 API 对工具定义和调用都有自己（相似的）格式。
- **它本身从不执行任何东西。** 模型只负责*请求*；由你的宿主来决定并执行。

### MCP：连接标准
MCP 位于更外面的一层。它并不取代函数调用（Function Calling）——而是为它**供货**。宿主（Host）连接到 MCP 服务器，调用 `tools/list`，把每个 MCP 工具（名称、描述、`inputSchema`）转换成模型提供商的工具格式；当模型发出工具调用时，再把它作为 `tools/call` 转发给对应的服务器。在普通函数之上，MCP 增加了：

- **位置无关与复用**——工具运行在独立进程中，可以是本地（stdio）也可以是远程（Streamable HTTP），写一次就能被任何 MCP 宿主使用（第 1.1、2.3 课）。
- **运行时发现**——宿主在运行时了解有哪些可用能力，而不是硬编码（`server/discover`、`tools/list`）。
- **不止于动作**——除了模型控制（Model-controlled）的工具，还有资源（Resource，由*应用*附加的数据）和提示模板（Prompt，由*用户*调用的工作流）（第 3 模块）。
- **生产级基础设施**——授权（Authorization）、缓存提示、征询（Elicitation）、版本管理和安全规则（第 2、5、6 模块）。

从模型的角度看，MCP 工具和任何其他函数定义*完全*一样；notebook 中会把两者并排比较来证明这一点。

### 智能体技能：打包好的流程性知识
[Agent Skills 规范](https://agentskills.io/specification)把技能（Skill）定义为一个**包含 `SKILL.md` 文件的目录**，该文件由 YAML 前置元数据（Frontmatter）和 Markdown 说明组成，另外还可选地包含 `scripts/`（可执行代码）、`references/`（文档）和 `assets/`（模板、资源）。前置元数据必须包含：

- `name`——1–64 个字符，仅限小写字母、数字和连字符，不能以连字符开头或结尾；
- `description`——1–1024 个字符，说明这个技能做什么**以及何时使用它**。

其核心思想是**渐进式披露（Progressive Disclosure）**，分为三个层级：

| 层级 | 加载什么 | 何时加载 | 典型开销 |
| --- | --- | --- | --- |
| 1. 元数据 | 每个已安装技能的 `name` + `description` | 启动时 | 每个技能约 100 个令牌 |
| 2. 说明 | 完整的 `SKILL.md` 正文 | 技能被激活时 | 建议 < 5,000 个令牌 |
| 3. 资源 | `scripts/`、`references/`、`assets/` 中的文件 | 只在某一步需要时 | 按需 |

因此，一个智能体可以“安装”几十个技能，代价只是它们的描述。规范还建议 `SKILL.md` 保持在 500 行以内，把细节移到参考文件中。技能**本身不包含任何新能力**：它的脚本通过智能体已有的执行类工具来运行，它的说明通常告诉智能体按什么顺序调用哪些工具——往往是 MCP 工具。

MCP 文档本身也在使用技能：*Build with Agent Skills* 页面提供了 `build-mcp-server`、`build-mcp-app` 和 `build-mcpb` 三个技能，引导编码智能体完成 MCP 服务器的设计。

### 并排比较
| | 函数调用 | MCP | 智能体技能 |
| --- | --- | --- | --- |
| **它是什么** | 模型 API 的一项功能 | 一个开放协议（JSON-RPC） | 一种开放的文件格式（文件夹 + `SKILL.md`） |
| **回答的问题** | 模型如何请求一个动作 | 工具/数据在哪里，应用如何连接 | 如何把一项任务做好 |
| **基本单元** | 一个函数定义 | 一个带有工具、资源、提示模板的服务器 | 一个技能目录 |
| **代码在哪里运行** | 在你的宿主进程中 | 在服务器进程中（本地或远程） | 脚本通过智能体自身的工具运行；说明“在模型的脑子里”运行 |
| **模型看到什么** | 每次请求都是完整模式 | 运行时发现的工具列表，再以函数定义的形式提供 | 元数据始终可见；激活时加载正文；按需加载文件 |
| **复用范围** | 一个应用 | 任何 MCP 宿主 | 任何支持该格式的智能体 |
| **典型作者** | 应用开发者 | 拥有该系统的团队 | 领域专家、运维、拥有该工作流的团队 |
| **最适合** | 少量应用专属的动作 | 对系统和数据的共享、受治理的访问 | 可重复的多步骤流程、规范、检查清单 |
| **主要风险** | 你自己代码中的 bug | 不可信的服务器、权限范围过大的令牌、被注入的工具结果 | 来自不可信来源的说明或脚本操纵智能体 |

### 三者如何在一次请求中叠加
以“审查上周的费用报销单并标出违规项”为例：

```text
User ──► Host/agent loop
           │ system prompt: skill catalog (name + description of each skill)   ← Skills level 1
           │ tools: MCP tools from the finance server, as function definitions ← MCP feeds function calling
           ▼
         Model: "this matches skill `expense-review`" ──► host loads SKILL.md  ← Skills level 2
         Model: follows step 2 → tool_use list_reports(week=41)               ← function calling
           host ──► tools/call list_reports on finance MCP server              ← MCP
         Model: step 3 needs the policy table ──► host reads references/policy.md ← Skills level 3
         Model: tool_use flag_report(id=…, reason=…) ──► tools/call …          ← function calling + MCP
         Model: final summary
```

它们在协议层面也有交汇：官方的**技能扩展（Skills Extension）**（`io.modelcontextprotocol/skills`，第 7.3 课）允许 MCP 服务器*提供*自己的技能，让专业知识随它所描述的服务一起发布。而 MCP 中由用户调用的模板——**提示模板（Prompt）**——在理念上与技能有重叠，但提示模板是用户挑选的单条参数化消息，而技能是一整个流程文件夹，智能体可以自行选择并分阶段加载。

### 实践中如何选择
- 只有你的应用需要的少量动作 → **普通函数调用**。
- 多个应用、团队或厂商需要访问同一个系统，或者它需要自己的认证、部署和安全边界 → **一个 MCP 服务器**。
- 智能体*已经有*工具，却总是把活干错、跳过步骤，或者需要遵循公司规范 → **一个技能**。
- 一个团队既拥有某个系统、*也*掌握使用它的正确方式 → **一个同时提供技能的 MCP 服务器**。

> **陷阱。** 不要把每个流程都做成一个巨大的“工作流工具”，也不要把每个流程都贴进系统提示词。需要判断的流程应该放进技能（Skill）（按需加载）；有副作用的能力应该做成工具（Tool），并放在用户同意的关卡之后。

## Key points
- **函数调用（Function Calling）** = 模型 API 的一项功能：输入模式，输出结构化调用，由*你的代码*执行。它定义了模型如何请求一个动作。
- **MCP** = 一个开放协议，规定工具（Tool）、资源（Resource）和提示模板（Prompt）存放在哪里，以及任何宿主如何发现并调用它们。MCP 工具是*通过*函数调用到达模型的。
- **智能体技能（Agent Skills）** = 一种承载流程性知识的开放格式：一个包含 `SKILL.md`（前置元数据 `name` + `description`）以及可选 `scripts/`、`references/`、`assets/` 的目录。
- 技能采用**渐进式披露（Progressive Disclosure）**：启动时加载元数据（约 100 个令牌），激活时加载正文（建议 < 5,000 个令牌），资源只在需要时加载。
- 类比：**双手（函数）、工牌与插座（MCP）、入职手册（技能）**。
- 三者是互补的：技能（Skill）告诉智能体调用*哪些* MCP 工具、按什么顺序；MCP 提供这些工具；函数调用则是每次调用的表达方式。
- MCP 的**技能扩展（Skills Extension）**（`io.modelcontextprotocol/skills`）允许服务器把技能和工具一起分发。
- 按需求选择：应用本地的动作 → 函数；共享且受治理的访问 → MCP；可重复的流程与判断 → 技能。

## Pitches
### 30 秒讲清 MCP、技能与函数调用
它们解决的是三个不同的问题，而且可以叠在一起用。函数调用（Function Calling）是模型 API 的机制：我用 JSON Schema 描述一个函数，模型请求调用它，我的代码去执行。MCP 是连接标准：工具、数据和提示模板放在服务器里，任何宿主都能发现和调用，而不是硬连在某一个应用里。技能（Skill）是打包好的专业知识——一个 SKILL.md，加上一些说明和文件，智能体只在任务需要时才加载。一句话：双手、插头和操作手册。

### 什么时候你会写一个技能，而不是一个 MCP 服务器？
当智能体缺少某种能力时，我会写一个 MCP 服务器（Server）——它需要接入某个系统，有自己的认证和安全边界，而且多个应用应该共享它。当能力已经存在、但智能体用得不好时，我会写一个技能（Skill）：比如它跳过步骤、不遵守我们的规范，或者需要一份检查清单。加一个技能成本很低，因为在真正需要之前，上下文里只放它的名称和描述。很多时候最好的答案是两者都要：服务器负责动作，技能负责流程。

### MCP 不就是多绕了几步的函数调用吗？
不是——MCP 是给函数调用（Function Calling）供货，而不是取代它。函数调用是某一个应用里的某一个模型，去请求执行这个应用自己定义的动作。MCP 标准化的是这些动作从哪里来：它们放在独立的服务器里，在运行时被发现，自带认证和版本管理，并且能在任何宿主中使用。它还加入了函数调用根本没有的概念，比如由应用附加的资源、由用户调用的提示模板。对模型来说，MCP 工具和任何其他函数看起来完全一样。

## Interview
### 比较函数调用、MCP 和智能体技能。它们之间是什么关系？
它们处在不同的层级。**函数调用（Function Calling）**是模型 API 层的契约：请求中携带工具定义（Tool Definition）（名称、描述、JSON Schema）；模型返回一个结构化调用；由应用来执行。**MCP** 是一个集成协议：服务器暴露工具、资源和提示模板；宿主（Host）在运行时发现它们，把 MCP 工具转换成提供商的函数定义，再通过 `tools/call` 把调用路由回去。**智能体技能（Agent Skills）**是一种内容格式：一个包含前置元数据（Frontmatter）和说明的 `SKILL.md`，加上可选的脚本、参考资料和素材，通过渐进式披露（Progressive Disclosure）加载。在一个智能体中：技能说明*做什么、按什么顺序做*，MCP 提供*完成它所需的工具*，函数调用则是*每次调用的表达方式*。

### 我们有一份 12 步的事故处理运行手册，用到了五个已经通过 MCP 暴露的工具。智能体总是跳步骤。你会构建什么？
一个**技能（Skill）**，而不是另一个服务器。能力已经具备；缺的是流程。我会写一个 `incident-response/SKILL.md`，其中 description 说明它适用于什么场景，正文是编号的步骤并写明要调用的 MCP 工具、决策点以及最后的检查清单；长篇材料（升级矩阵、过往的事后复盘）放到 `references/` 里，只在某一步需要时才加载。如果这份运行手册（Runbook）属于拥有这些工具的团队，我会通过技能扩展（Skills Extension）从他们的 MCP 服务器发布它，让它和工具一起做版本管理。我*不会*把这 12 步压缩成一个不透明的“run_incident”工具，因为这些步骤需要判断和人工检查点。

### 有了技能，MCP 是不是就没必要了？
不是。技能（Skill）本身不带来任何新能力：它的说明只是引导模型，它的脚本也只有在智能体已经拥有 shell 或代码沙箱（Sandbox）这类执行工具时才能运行。以 OAuth、租户隔离和审计日志的方式接入 CRM，或者把同一种能力提供给众多宿主，恰恰是 MCP 所标准化的东西。反过来，只有 MCP 则只有访问能力而没有流程。两者是互补的——这也正是 MCP 推出官方技能扩展、让服务器能够提供技能的原因。

### 比较这三者在上下文窗口上的开销。
普通函数定义和 MCP 工具最终都会以完整模式（Schema）出现在每一次模型请求中，所以开销随工具数量增长——几十个服务器可能意味着用户还没开口就已经用掉了几千个令牌（Token）。宿主会通过渐进式工具发现（Progressive Discovery）或代码模式（第 5.4 课）来缓解这一问题，并受益于 `tools/list` 顺序确定所带来的提示缓存（Prompt Caching）效果。技能正是为此而设计的：预先只加载 `name` + `description`（每个约 100 个令牌），激活时加载正文，按需加载文件。这就是为什么流程细节应该放在技能里，而不是工具描述或系统提示词中。

### 它们的安全风险有何不同？
**函数调用（Function Calling）**：代码是你自己的，所以风险来自你自己的 bug，以及你允许模型在未经审批的情况下触发了什么。**MCP**：服务器可能来自第三方或位于远程，所以工具描述和结果都是不可信输入（提示注入（Prompt Injection）、工具投毒（Tool Poisoning）、跑路式篡改（Rug Pull）），令牌必须绑定受众（Audience）并遵循最小权限，而本地服务器以你的权限运行（第 6 模块）。**技能（Skill）**：技能是说明加上可能的可执行脚本，所以恶意或被篡改的技能可以操纵智能体或运行代码——只从可信来源安装，审查脚本，固定版本；当技能通过 MCP 获取时，要校验完整性摘要，并在加载前获得用户批准（第 7.3 课）。

### 与技能相比，MCP 提示模板处在什么位置？
两者都封装了可复用的意图，但区别在于由谁触发、承载多少内容。MCP **提示模板（Prompt）**是用户控制（User-controlled）的：用户通过 `prompts/get` 挑选的单条参数化消息模板（通常是一个斜杠命令（Slash Command））。**技能（Skill）**通常由模型根据其描述来选择，也可以由用户激活，它是一整个目录，分阶段加载——先是说明，然后按需加载脚本和参考资料。一次性的、由人来调用的模板用提示模板；智能体应当识别并遵循的多步骤流程用技能。

## Glossary
- Function calling (tool use) | 函数调用（工具调用） | 模型 API 的一项功能：模型返回一个结构化请求，要求调用应用用 JSON Schema 描述过的某个函数。
- Tool definition | 工具定义 | 告诉模型某个函数做什么、如何调用它的名称、描述和输入 JSON Schema。
- Agent Skill | 智能体技能 | 一个打包好的流程性知识单元：一个包含 `SKILL.md` 以及可选脚本、参考资料和素材的目录。
- SKILL.md | SKILL.md（技能说明文件） | 技能的必需文件：YAML 前置元数据（`name`、`description`）后接 Markdown 说明。
- Frontmatter | 前置元数据 | `SKILL.md` 顶部存放技能元数据的 YAML 块。
- Progressive disclosure | 渐进式披露 | 分阶段加载信息——先加载元数据，激活时加载完整说明，只在需要时加载资源文件——以节省上下文。
- Context window | 上下文窗口 | 模型在一次请求中能够考虑的最大文本量（令牌数），由说明、工具和对话共同占用。
- Skills extension | 技能扩展 | 官方 MCP 扩展 `io.modelcontextprotocol/skills`，允许服务器暴露技能供客户端发现和读取。
- Runbook | 运行手册 | 一步步的运维操作流程——典型的适合做成技能的内容。

## Notebook
### 1. 一个任务，三个层级
我们会用三种方式实现同一个小任务——*“按照公司政策检查一笔费用”*——让差异变得具体可见。首先是**函数调用（Function Calling）**版本：一个 Python 函数，加上你会放进 Claude `tools=[...]` 列表中的工具定义（Tool Definition）。所有东西都在这个 notebook 里，它扮演“你的应用”。

```python
import json

POLICY = {"meals": 60, "hotel": 220, "taxi": 80}          # max EUR per item


def check_expense(category: str, amount: float) -> dict:
    """The business logic: is one expense within policy?"""
    limit = POLICY.get(category)
    if limit is None:
        return {"ok": False, "reason": f"unknown category {category!r}"}
    return {"ok": amount <= limit, "limit": limit, "over_by": max(0, amount - limit)}


# Function calling: YOU write the definition the model sees, by hand, inside your app.
FUNCTION_TOOL = {
    "name": "check_expense",
    "description": "Check one expense against company policy. Returns ok, the limit and how much it is over.",
    "input_schema": {
        "type": "object",
        "properties": {"category": {"type": "string", "enum": sorted(POLICY)},
                       "amount": {"type": "number", "description": "Amount in EUR"}},
        "required": ["category", "amount"],
    },
}

# What the model sends back when it wants the action (shape of a Claude `tool_use` block):
tool_use = {"type": "tool_use", "id": "toolu_01", "name": "check_expense",
            "input": {"category": "hotel", "amount": 260}}

# Your code executes it locally and returns a `tool_result` block:
result = check_expense(**tool_use["input"])
print(json.dumps({"type": "tool_result", "tool_use_id": tool_use["id"], "content": json.dumps(result)}, indent=2))
```

### 2. 同样的能力，做成 MCP 服务器
现在把逻辑移进一个 **MCP 服务器（MCP Server）**。宿主不再硬编码定义：它用 `tools/list` 来*发现*定义，再转换成模型的工具格式。注意转换后的定义与 `FUNCTION_TOOL` 的形状完全相同——**MCP 是给函数调用供货，而不是取代它。**

```python
from typing import Annotated, Literal

from pydantic import Field

from mcp import Client
from mcp.server import MCPServer

finance = MCPServer("finance")


@finance.tool()
def check_expense_tool(
    category: Annotated[Literal["hotel", "meals", "taxi"], Field(description="Expense category")],
    amount: Annotated[float, Field(description="Amount in EUR")],
) -> dict[str, object]:
    """Check one expense against company policy. Returns ok, the limit and how much it is over."""
    return check_expense(category, amount)


@finance.tool()
def list_expenses(employee: str) -> list[dict[str, object]]:
    """List last week's expenses for an employee."""
    return [{"id": 1, "category": "hotel", "amount": 300.0},
            {"id": 2, "category": "meals", "amount": 35.5},
            {"id": 3, "category": "taxi", "amount": 95.0}]


async with Client(finance) as client:
    mcp_tools = (await client.list_tools()).tools

# The host's one-line adapter: MCP tool -> model tool definition
as_model_tools = [{"name": t.name, "description": t.description, "input_schema": t.input_schema} for t in mcp_tools]
print(json.dumps(as_model_tools[0], indent=2))
print("\nsame keys as the hand-written function tool:", as_model_tools[0].keys() == FUNCTION_TOOL.keys())
```

### 3. 把专业知识做成智能体技能
工具说明的是*能做什么*。它们并没有说明*公司希望费用审查怎么做*：检查每一项、四舍五入到分、引用政策、超出 25 % 以上的一律升级。这套流程应该放进一个**技能（Skill）**：一个包含 `SKILL.md` 和一个参考文件的文件夹，写入一个临时目录。

```python
import tempfile
import textwrap
from pathlib import Path

skills_root = Path(tempfile.mkdtemp()) / "skills"
skill_dir = skills_root / "expense-review"
(skill_dir / "references").mkdir(parents=True)

(skill_dir / "SKILL.md").write_text(textwrap.dedent("""\
    ---
    name: expense-review
    description: Review an employee's expense report against company policy and flag violations. Use when asked to audit, check or approve expenses.
    ---
    # Expense review

    1. Call `list_expenses` for the employee.
    2. For EVERY item call `check_expense_tool` (never guess limits).
    3. If an item is more than 25% over its limit, mark it ESCALATE; otherwise mark it FLAG.
       The escalation rules are in references/escalation.md - read it only if something must be escalated.
    4. Finish with a table: id, category, amount, verdict.
"""))
(skill_dir / "references" / "escalation.md").write_text(
    "Escalations go to finance-approvals@example.com with the receipt attached, within 2 working days.\n")

for path in sorted(skill_dir.rglob("*")):
    print(path.relative_to(skills_root))
```

### 4. 一个带渐进式披露的迷你技能加载器
支持技能的宿主（Host）要做三件事：校验前置元数据（Frontmatter），只把**元数据**放进模型的上下文，以及**按需**加载正文或参考文件。观察每个层级的令牌估算值（≈ 字符数 ÷ 4）。

```python
import re

NAME_RULE = re.compile(r"^[a-z0-9]([a-z0-9-]{0,62}[a-z0-9])?$")   # 1-64 chars, a-z 0-9 -, no edge hyphens


def parse_skill(skill_md: Path) -> dict:
    text = skill_md.read_text()
    match = re.match(r"---\n(.*?)\n---\n(.*)", text, re.S)
    meta = dict(line.split(": ", 1) for line in match.group(1).splitlines())
    assert NAME_RULE.match(meta["name"]), f"invalid skill name {meta['name']!r}"
    assert 1 <= len(meta["description"]) <= 1024, "description must be 1-1024 characters"
    assert meta["name"] == skill_md.parent.name, "name should match the directory name"
    return {"name": meta["name"], "description": meta["description"], "body": match.group(2), "dir": skill_md.parent}


tokens = lambda s: len(s) // 4
catalog = {s["name"]: s for s in (parse_skill(p) for p in skills_root.glob("*/SKILL.md"))}

level1 = "\n".join(f"- {s['name']}: {s['description']}" for s in catalog.values())
print("LEVEL 1 - always in context (metadata):", tokens(level1), "tokens\n" + level1)
print("\nLEVEL 2 - on activation (SKILL.md body):", tokens(catalog["expense-review"]["body"]), "tokens")
ref = (catalog["expense-review"]["dir"] / "references" / "escalation.md").read_text()
print("LEVEL 3 - only if a step needs it (references/escalation.md):", tokens(ref), "tokens")
print("\nfor comparison, the MCP tool definitions sent with EVERY request:", tokens(json.dumps(as_model_tools)), "tokens")
```

### 5. 在一次智能体运行中用上全部三者
现在用一个智能体循环（Agent Loop）把所有东西串起来。一个脚本化的模型替身（Scripted Planner，因此可以离线运行）读取技能目录，激活 `expense-review`，通过发出 `tool_use` 调用来执行其中的步骤，宿主则通过 MCP 执行每一次调用。输出的跟踪信息会标出每一步由哪一层完成。

```python
def scripted_model(state: dict) -> dict:
    """A deterministic stand-in for the LLM that follows the skill's procedure step by step."""
    if "skill" not in state:
        return {"action": "activate_skill", "name": "expense-review"}            # chosen from level-1 metadata
    if "expenses" not in state:
        return {"action": "tool_use", "name": "list_expenses", "input": {"employee": "ana"}}
    pending = [e for e in state["expenses"] if e["id"] not in state["checked"]]
    if pending:
        e = pending[0]
        return {"action": "tool_use", "name": "check_expense_tool", "input": {"category": e["category"], "amount": e["amount"]}, "id": e["id"]}
    if any(v["over_by"] > 0.25 * v["limit"] for v in state["checked"].values()) and "escalation" not in state:
        return {"action": "read_skill_file", "path": "references/escalation.md"}
    return {"action": "final"}


state = {"checked": {}}
async with Client(finance) as client:
    while (step := scripted_model(state))["action"] != "final":
        if step["action"] == "activate_skill":
            state["skill"] = catalog[step["name"]]["body"]
            print(f"[SKILLS level 2]  load SKILL.md of {step['name']!r}")
        elif step["action"] == "read_skill_file":
            state["escalation"] = (catalog["expense-review"]["dir"] / step["path"]).read_text()
            print(f"[SKILLS level 3]  read {step['path']}")
        else:
            print(f"[FUNCTION CALL]   model emits tool_use {step['name']}({step['input']})")
            result = await client.call_tool(step["name"], step["input"])
            print(f"[MCP]             host sends tools/call to server 'finance' -> {result.structured_content}")
            if step["name"] == "list_expenses":
                state["expenses"] = result.structured_content["result"]   # lists are wrapped in {"result": ...}
            else:
                state["checked"][step["id"]] = result.structured_content     # a dict return is the object itself

print("\nid | category | amount | verdict")
for e in state["expenses"]:
    v = state["checked"][e["id"]]
    verdict = "OK" if v["ok"] else ("ESCALATE" if v["over_by"] > 0.25 * v["limit"] else "FLAG")
    print(f"{e['id']}  | {e['category']:<8} | {e['amount']:>6.2f} | {verdict}")
```

阅读这份跟踪信息：**技能（Skill）**决定了流程（检查每一项，只在需要时读取升级文件），**函数调用（Function Calling）**表达了每一个动作，**MCP** 则把每个动作送到拥有相应逻辑的服务器。

### 6. 可选：让真实模型来选择
设置了 `ANTHROPIC_API_KEY` 后，Claude 会在系统提示词中拿到技能目录、一个用于第 2 层级的 `load_skill` 函数，以及财务 MCP 工具——然后自行决定何时加载技能、调用哪些工具。没有密钥时，该单元格会说明本来会发生什么。

```python
import os

if os.environ.get("ANTHROPIC_API_KEY"):
    import anthropic

    llm = anthropic.Anthropic()
    load_skill = {"name": "load_skill", "description": "Load the full instructions of a skill by name.",
                  "input_schema": {"type": "object", "properties": {"name": {"type": "string"}}, "required": ["name"]}}
    system = "You can use these skills; call load_skill before following one.\n" + level1
    messages = [{"role": "user", "content": "Please audit ana's expenses from last week."}]
    async with Client(finance) as client:
        for _ in range(12):
            response = llm.messages.create(model="claude-opus-5-5", max_tokens=16000, system=system,
                                           tools=as_model_tools + [load_skill], messages=messages)
            if response.stop_reason != "tool_use":
                break
            messages.append({"role": "assistant", "content": response.content})
            results = []
            for block in response.content:
                if block.type != "tool_use":
                    continue
                if block.name == "load_skill":
                    print("[SKILLS] Claude loaded", block.input)
                    content, is_error = catalog.get(block.input["name"], {}).get("body", "no such skill"), False
                else:
                    print("[MCP]    Claude called", block.name, block.input)
                    r = await client.call_tool(block.name, block.input)
                    content, is_error = json.dumps(r.structured_content), r.is_error
                results.append({"type": "tool_result", "tool_use_id": block.id, "content": content, "is_error": is_error})
            messages.append({"role": "user", "content": results})
    print("\n".join(b.text for b in response.content if b.type == "text"))
else:
    print("skipped: set ANTHROPIC_API_KEY to watch Claude pick the skill from its description, "
          "load it, and then call the MCP tools in the order the skill prescribes.")
```
