## Summary
两类官方扩展（Extension）拓展了 MCP 能交付什么以及谁可以接入。**Skills over MCP**（`io.modelcontextprotocol/skills`）让服务器（Server）可以发布智能体技能（Agent Skill），即由工作流说明（`SKILL.md`）加上配套文件组成的文件夹。客户端（Client）通过 `skills/list` 和 `skills/get` 发现它们，并用普通的 `resources/read` 获取文件。每个文件都带有 SHA-256 摘要和大小，因此宿主（Host）能准确校验它加载的内容，并把用户批准绑定到这份清单上。**授权扩展**覆盖了核心 OAuth 流程处理得不好的场景。**OAuth 客户端凭据（Client Credentials）**服务于没有用户在场的机器对机器调用方，最好使用签名的 JWT 断言。**企业托管授权（Enterprise-Managed Authorization）**通过一个 ID-JAG 令牌（Token），让公司的身份提供方（Identity Provider，IdP）决定员工可以使用哪些 MCP 服务器。在 notebook 中，你将构建一个技能服务器和一个会做校验的宿主，然后针对一个模拟授权服务器运行真实的 SDK 授权提供者。

## Lesson
### 智能体技能，以及为什么要通过 MCP 提供它们
**智能体技能（Agent Skill）**是一个包含 `SKILL.md` 文件及可选配套文件的目录，由智能体技能规范（agentskills.io）定义。`SKILL.md` **必须（MUST）**以 YAML 前置元数据（Frontmatter）开头，其中至少包含 `name` 和 `description`，并且其父目录的最后一段**必须（MUST）**等于 `name`。技能把可复用的工作流打包起来，这些工作流往往需要组合多个工具或依赖参考资料，比如代码评审清单或文档处理流程。

通过 MCP 提供技能，**能让说明文档与它所描述的服务放在一起**。拥有服务器的团队也同时拥有这套工作流。客户端可以按元数据浏览可用的工作流，**仅在需要时**才加载说明和文件，从而节省上下文。该扩展**只定义发现与获取**。技能如何呈现由宿主决定：模型可以根据名称和描述挑选一个，用户也可以显式选择。

> **规范规则。** 用 `resources/read` 读取 `SKILL.md` **并不会**激活技能。要加载技能，宿主必须让这次读取走它的技能加载路径，该路径会先校验内容并执行所需的用户批准，然后才让任何内容进入模型的上下文。

### 声明扩展
支持 Skills 的服务器（Server）**必须（MUST）**在 `server/discover` 中同时声明 `resources` 能力（Capability）和该扩展（Extension）：

```json
{"capabilities": {"resources": {},
                  "extensions": {"io.modelcontextprotocol/skills": {"directoryRead": true}}}}
```

服务器**必须（MUST）**实现 `skills/list` 和 `skills/get`。技能文件通过普通的 `resources/read` 提供。可选的 `directoryRead` 设置（默认 `false`）表示支持 `resources/directory/read`。客户端只有在看到该声明之后才会发送 `skills/list` 和 `skills/get`。与任何 2026-07-28 版本的请求一样，每次调用都携带 `_meta` 信封。

### `skills/list` 与 `skills/get`
`skills/list` 支持分页（`cursor` / `nextCursor`）和缓存。其结果**必须（MUST）**携带 `resultType: "complete"`、`ttlMs` 和 `cacheScope`：

```json
{"resultType": "complete", "ttlMs": 300000, "cacheScope": "public",
 "skills": [{"uri": "skill://code-review/SKILL.md",
             "frontmatter": {"name": "code-review", "description": "Review code using the team's checklist."},
             "resources": [
               {"uri": "skill://code-review/SKILL.md",
                "digest": "sha256:d2489d6c182e8df9c178563ff9f2eac7998a0c1bb1278c52a7fd5306e4259160", "size": 149},
               {"uri": "skill://code-review/references/checklist.md",
                "digest": "sha256:dbab2de7bf7db9cc95cb6ce681c3690b26184db39f75b958a0287ca6d9e24e20", "size": 65}]}]}
```

| 条目字段 | 含义 |
| --- | --- |
| `uri` | 技能的 `SKILL.md` 的资源 URI |
| `frontmatter` | **全部** YAML 前置元数据字段，原样保留 |
| `resources` | 完整的**文件清单**（`SKILL.md` 及每个配套文件的 URI、SHA-256 `digest`、字节 `size`），对于生成的内容则为 `"dynamic"` |

列表中的每个条目都是完整的，因此无需再用 `skills/get` 获取更多元数据。一份清单永远不会被拆分到多页。缓存字段描述的是新鲜度和共享范围，与**完整性**无关，完整性由摘要负责。

`skills/get {"uri": ...}` 在 `result.skill` 下返回一个条目（外加 `resultType`、`ttlMs`、`cacheScope`）。当 URI 来自用户、另一个技能或服务器说明时，或者需要刷新某个条目时，就使用它。服务器可以（MAY）返回部分或空的列表，但对它提供的每一个技能都**必须（MUST）**响应 `skills/get`；宿主**必须（MUST）**支持按 URI 加载技能，即使该技能从未被列出。未知 URI 返回 `-32602`。

**身份**是二元组 *（来源服务器，技能 URI）*。名称只是标签，并不保证唯一，因此宿主（Host）**必须（MUST）**在注册表、批准记录和缓存中同时保存服务器身份和 URI。服务器应当（SHOULD）使用 `skill://` 协议，但可以（MAY）使用其他协议。宿主**不得（MUST NOT）**仅凭 URI 协议就判定某个东西是技能。

### 读取内容与目录
宿主（Host）用 `resources/read` 获取 `SKILL.md`，随后获取每个配套文件，并且始终从**同一个服务器**获取。相对引用以技能根目录为基准解析，因此 `references/checklist.md` 会变成 `skill://code-review/references/checklist.md`。宿主**不得（MUST NOT）在需要之前获取文件**：连接时、列举时、批准时都不行。批准绑定的是清单，因此无需下载文件即可完成批准。

`resources/directory/read {"uri": "skill://code-review/references"}` 列出某个目录的直接子项。目录 URI 不带结尾斜杠，子目录的 `mimeType` 为 `"inode/directory"`，结果支持分页。除非服务器声明了 `directoryRead: true`，否则客户端**不得（MUST NOT）**调用它。对于带清单的技能，宿主可以直接根据清单作答。实时的目录列举**永远不会扩充已保留的清单**：新列出的文件必须先刷新条目并重新获得批准，才算作技能的一部分。

### 完整性与校验
在技能使用期间，至少直到其 `SKILL.md` 离开模型上下文为止，宿主（Host）都会保留它所加载的条目。对于带清单的技能，宿主**必须（MUST）**：

1. 把**读取限制**在已保留清单中的 URI 范围内；
2. 在使用每个文件之前**校验其原始字节大小和 SHA-256 摘要**；
3. **解析 `SKILL.md` 的前置元数据，并逐字段**与条目的 `frontmatter` 比对。

未通过校验的内容**不得（MUST NOT）**使用。要从过期的元数据中恢复，用 `skills/get` 刷新条目。持久化的批准**必须（MUST）绑定到完整的文件 URI 与摘要集合**。任何文件被修改、新增或删除都会**撤销**该批准，宿主必须重新询问。校验通过的内容应当（SHOULD）按需缓存。磁盘缓存要么是不可变的，并且对模型、其工具和其他用户受保护；要么在每次访问时重新校验。缓存的文件必须远离文件系统的技能发现路径，并在重启后保留其 MCP 来源。

> **陷阱。** 摘要只能证明字节与服务器清单一致，**不能**证明内容可信。使用 `"resources": "dynamic"` 的技能没有稳定的摘要。宿主可以（MAY）拒绝它们，但仍必须校验前置元数据，且不得把过去的批准视为覆盖未来的内容。

服务器**必须（MUST）**提供合法的技能、保留全部前置元数据、**根据实际提供的字节**计算清单，并支持直接查找。每个技能不应当（SHOULD NOT）超过 **512 个文件或 16 MiB**，而宿主必须支持达到这些上限的技能。

**宿主的安全职责。** 同名技能不得悄无声息地相互替换。加载的内容要标注其来源服务器，读取也要绑定到该服务器。跨服务器读取需要针对每次调用的显式批准，并且要同时写明两个服务器。技能内容是**不可信输入**，因此宿主端的代码执行以及 `allowed-tools` 之类的授权需要针对每个技能的显式批准。嵌套技能需要重新征得同意，因为把它的 `SKILL.md` 当作配套文件读取并不会激活它。

| 情况 | 处理方式 |
| --- | --- |
| 未知技能或文件、无效的目录 URI | JSON-RPC `-32602` |
| 服务器内部故障 | `-32603` |
| 摘要、大小、前置元数据或清单不匹配 | 宿主端处理：拒绝该内容，刷新条目（不是协议错误） |

### 为什么需要授权扩展？
核心 MCP 授权（Authorization）（第 6.1 课）处理的是常见情形：**一个使用浏览器的用户**通过 OAuth 授予客户端（Client）对服务器的委托访问权。有两类真实部署并不符合这个模型：

- **机器对机器。** 后台服务、CI 流水线和守护进程没有人在场去点“允许”。
- **企业。** 公司的身份提供方（Identity Provider，IdP）应当集中执行策略。让每个员工逐一授权每个服务器既增加摩擦，又会**绕过现有的安全控制**。

`ext-auth` 仓库为这两种情况各提供了一个扩展（Extension）。两者都需要显式启用，都需要客户端的显式支持，也都使用标准的 `extensions` 协商。

### OAuth 客户端凭据（`io.modelcontextprotocol/oauth-client-credentials`）
客户端（Client）**以自身身份**进行认证（Authentication），使用的是应用凭据，而不是用户的委托授权；授权服务器（Authorization Server，AS）签发令牌（Token），无需重定向，也无需用户交互。该扩展建立在 OAuth 2.1、RFC 8414（AS 元数据）、RFC 9728（受保护资源元数据）和 **RFC 7523**（JWT 客户端认证）之上。它适用于 HTTP 传输。凭据是**带外预先注册的**，因此不使用动态客户端注册（Dynamic Client Registration）。

该流程的开头与核心 MCP 授权相同。客户端收到一个 `401`，其 `WWW-Authenticate` 指向受保护资源元数据；客户端读取它以找到 AS，再获取 AS 元数据。然后它使用以下两种客户端认证方式之一调用令牌端点：

```http
POST /token HTTP/1.1
Host: auth.example.com
Content-Type: application/x-www-form-urlencoded

grant_type=client_credentials
&client_assertion_type=urn%3Aietf%3Aparams%3Aoauth%3Aclient-assertion-type%3Ajwt-bearer
&client_assertion=eyJhbGciOiJSUzI1NiIsImtpZCI6IjIyIn0.eyJpc3Mi...
&resource=https%3A%2F%2Fmcp.example.com
&scope=mcp%3Aread
```

- **JWT 认证（推荐，RECOMMENDED）**，即 RFC 7523 §2.2，也称 `private_key_jwt`。客户端用其**私钥**签发一个短期有效的 JWT，AS 用注册的**公钥**验证它。典型声明有 `iss` 和 `sub`（都是客户端 ID）、`aud`、`exp` 和 `iat`，再加一个用于防重放的 `jti`。请求体中省略 `client_id`，因为 `sub` 声明已经标识了客户端。
- **客户端密钥（Client secret）**（OAuth 2.1 §2.4.1）：`grant_type=client_credentials&client_id=...&client_secret=...`。

> **文档说明。** 概览页的示意图把 JWT 流程标注为 `grant_type=urn:ietf:params:oauth:grant-type:jwt-bearer`，并说 `aud` 是令牌端点 URL。而规范性的 ext-auth 规范和 Python SDK 都使用 `grant_type=client_credentials` 加 `client_assertion`，这是 RFC 7523 §2.2 的*客户端认证*。`jwt-bearer` *授权许可*（§2.1）属于企业托管授权。SDK 按照 RFC 7523 的更新，把 `aud` 设为 **AS 的签发者标识符（issuer identifier）**。请确认你的授权服务器期望的是哪一种。

AS 元数据**必须（MUST）**在 `token_endpoint_auth_methods_supported` 中列出 `"private_key_jwt"` 或 `"client_secret_basic"`，并且在支持 JWT 认证时必须包含 `token_endpoint_auth_signing_alg_values_supported`。

> **陷阱：密钥是长期有效的。** 泄露的客户端密钥会让攻击者能够悄无声息地冒充你的服务进行认证，直到有人轮换它为止。把密钥放在密钥管理器中，定期轮换，并在任何疑似泄露后立即轮换，把权限范围降到最小，并且**优先使用 JWT 断言**：它们有效期短，而签名私钥永远不会离开客户端。

客户端声明该扩展，在连接之前获取令牌，发送 `Authorization: Bearer <token>`，并在过期前刷新，因为这类令牌往往有效期很短。服务器在每个请求上验证令牌的签名和声明（通常对照 AS 的 JWKS），检查权限范围（scope），并且应当（SHOULD）在 `server/discover` 中公布该扩展，以便客户端发现。在 Python SDK 中，`ClientCredentialsOAuthProvider`（密钥）和配合 `SignedJWTParameters(...).create_assertion_provider()` 使用的 `PrivateKeyJWTOAuthProvider`（JWT）都是 `httpx2.Auth` 对象，负责发现、令牌获取和刷新。关键字参数是 `scope=`，尽管文档示例传的是 `scopes=`。另外请传入 `issuer=`，因为省略它已被弃用。

### 企业托管授权（`io.modelcontextprotocol/enterprise-managed-authorization`）
在面向消费者的 MCP 中，每个用户逐一授权每个服务器，这对个人来说很好用。但在公司里就会出问题：员工不应该需要理解每个服务器的授权方式，安全团队无法执行一致的策略，入职意味着几十个同意页面，离职则意味着逐个服务撤销访问。这个扩展（Extension）（最初是 **SEP-990**）让**企业身份提供方（IdP）**（Okta、Azure AD、企业 SSO）成为决定每个员工可以使用哪些 MCP 服务器的权威。

其关键产物是**身份断言 JWT 授权许可（Identity Assertion JWT Authorization Grant，ID-JAG）**：

```text
1. SSO:   user signs in to the MCP client through the enterprise IdP -> client keeps the ID Token (or SAML assertion)
2. Leg 1: client -> IdP token endpoint (RFC 8693 token exchange)
          grant_type=urn:ietf:params:oauth:grant-type:token-exchange
          requested_token_type=urn:ietf:params:oauth:token-type:id-jag
          audience=<MCP authorization server issuer>   resource=<MCP server id>
          subject_token=<ID Token>  subject_token_type=urn:ietf:params:oauth:token-type:id_token
          IdP evaluates policy -> returns the ID-JAG (JWT with typ "oauth-id-jag+jwt")
3. Leg 2: client -> MCP authorization server token endpoint
          grant_type=urn:ietf:params:oauth:grant-type:jwt-bearer   assertion=<ID-JAG>
          AS validates the ID-JAG -> access token audience-restricted to the MCP server
4. Client calls the MCP server with the Bearer token
```

ID-JAG 的声明包括 `iss`（IdP）、`sub`、可选的 `email`、`aud`（MCP AS 的签发者）、`resource`（MCP 服务器）、`client_id`、`scope`、`exp`、`iat` 和 `jti`。该流程带来四个特性：**集中式策略**、**单点登录**（无需针对每个服务器的同意提示）、**在签发任何令牌之前执行策略**（未获授权员工的客户端永远拿不到令牌），以及在 IdP 处的**集中式撤销**。

各方都有自己的职责。**客户端**支持 SSO，保存身份断言，请求并交换 ID-JAG，并且**不会**把用户重定向到 MCP AS 的授权端点。管理员在组织层面配置 IdP 端点，客户端则要妥善处理权限范围错误。**MCP 服务器**在其授权元数据中声明该扩展，并可选择向 IdP 管理控制台发布资源描述符。**MCP AS** 对照 IdP 的 JWKS 验证 ID-JAG（签名、受众、签发者、过期时间），把声明映射为权限，并优先按 `sub` 关联账户，对于在启用企业授权之前创建的账户则回退到 `email`。客户端通过 AS 元数据字段 `authorization_grant_profiles_supported` 中的 `urn:ietf:params:oauth:grant-profile:id-jag` 来检测支持情况。在 Python SDK 中，`IdentityAssertionOAuthProvider` 执行第 2 段（leg 2）。第 1 段因部署而异，由你的 `assertion_provider` 回调提供。

### 选择合适的机制
| 场景 | 使用 |
| --- | --- |
| 后台服务、守护进程、CI/CD 流水线、服务器对服务器集成 | OAuth 客户端凭据 |
| 员工在工作中访问 MCP 服务器；组织范围的访问策略 | 企业托管授权 |
| 一个人以交互方式授权客户端 | 核心 MCP 授权，无需扩展 |

路线图中的*智能体身份（Agent Identity）*方向（第 7.4 课）在这一基础上进一步引入工作负载身份联合、ID-JAG 和 RFC 8693 令牌交换（Token exchange），因为智能体（Agent）越来越多地以自己的身份行事，或代表一个不在场的用户行事。

## Key points
- Skills over MCP（`io.modelcontextprotocol/skills`）：技能（Skill）是一个目录，包含 `SKILL.md`（带 `name` 和 `description` 的 YAML 前置元数据，父目录名等于 `name`）以及配套文件。服务器还必须声明 `resources`。
- 方法（Method）有 `skills/list`（可分页、可缓存）、`skills/get`（对每个提供的技能都必须（MUST）可用，未知时返回 `-32602`），以及用于读取文件内容的普通 `resources/read`。可选的 `resources/directory/read` 要求 `directoryRead: true`。
- 每个条目包含 `uri`、原样保留的 `frontmatter`，以及一份 `resources` 清单（每个文件的 URI、`sha256:` 摘要、字节大小）或 `"dynamic"`。技能身份（Identity）是服务器加 URI，绝不能只看名称。
- 宿主（Host）必须（MUST）只读取清单中的 URI，在使用前校验大小、SHA-256 和前置元数据，绝不预取，把批准绑定到完整的 URI 与摘要集合，并在任何变更后重新批准。摘要证明的是一致性，而不是可信性。
- 读取 `SKILL.md` 不会激活技能（Skill）。技能内容不可信，`allowed-tools` 和代码执行需要针对每个技能的显式批准。
- OAuth 客户端凭据（Client Credentials）用于没有用户参与的机器对机器访问。它使用 JWT 客户端认证（RFC 7523 `private_key_jwt`，推荐）或客户端密钥，凭据预先注册，不使用 DCR。
- JWT 断言（JWT assertion）的声明为 `iss` = `sub` = 客户端 ID，外加 `aud`、`exp`、`iat` 和 `jti`。它以 `client_assertion` 发送，并带上 `client_assertion_type=urn:ietf:params:oauth:client-assertion-type:jwt-bearer`。
- 企业托管授权（Enterprise-Managed Authorization）：IdP 执行策略，并通过 RFC 8693 令牌交换签发 **ID-JAG**。客户端用 `jwt-bearer` 授权许可把它提交给 MCP AS，并获得一个受众限定于该 MCP 服务器的访问令牌。
- 守护进程和 CI 选客户端凭据（Client Credentials），员工选企业托管授权，交互式用户选核心 OAuth。

## Pitches
### Skills 扩展给 MCP 带来了什么？
它让服务器不只交付工具，还能交付工作流知识。一个技能（Skill）就是一个文件夹，里面有一个 SKILL.md 和一些配套文件。服务器列出技能时会带上前置元数据，以及一份记录每个文件 SHA-256 摘要和大小的清单；宿主（Host）只在真正需要时，才用普通的 resources/read 去取文件。在把任何东西放进模型上下文之前，宿主会检查大小、摘要和前置元数据，并把用户批准绑定到这份确切的清单上，所以技能只要有任何改动，就得重新问用户。

### 什么时候会用 OAuth 客户端凭据扩展？
只要没有人在场批准访问，我就会用它：比如夜间任务、CI 流水线，或者一个后端去调用另一个后端的 MCP 服务器。这个服务预先在授权服务器（Authorization Server）上注册，以自己的身份认证，最好是用私钥签一个短期有效的 JWT，也就是 RFC 7523 的 private_key_jwt 方式，而不是发送一个长期有效的密钥。它拿到的是一个普通的 bearer 令牌（Token），MCP 服务器像对待其他任何令牌一样去验证它、检查权限范围。

### 企业托管授权是怎么运作的？
公司的身份提供方（Identity Provider，IdP）成了把关人。员工用企业 SSO 登录 MCP 客户端一次。当客户端需要某个 MCP 服务器时，它拿 ID 令牌到 IdP 换一个 ID-JAG，也就是一个限定给该服务器授权服务器的签名授权许可。IdP 就在这一步执行策略。然后客户端再用 ID-JAG 换取访问令牌。没人需要一个个点过每个服务器的同意页面，IT 也能集中授予或撤销访问。

## Interview
### 宿主加载了一个技能，一小时后服务器更新了 `references/checklist.md`。宿主必须怎么做？
已保留的清单与服务器现在提供的内容不再一致。下一次读取清单文件时，得到的字节其 SHA-256 或大小会与清单中的摘要不符，因此宿主（Host）**必须拒绝**该内容，并用 `skills/get` 刷新条目。刷新后的清单具有不同的摘要集合。持久化的批准绑定的是完整的 URI 与摘要集合，所以它会被**撤销**，宿主必须在加载或执行任何东西之前重新获得用户批准。宿主也绝不能仅仅因为新文件出现在列表或目录读取结果中，就悄悄开始使用它。

### 为什么 Skills 规范禁止预取文件，又禁止通过 URI 协议识别技能？
预取会在用户批准任何东西之前就把不可信内容拉进宿主（Host），而且对于从未被使用的技能（Skill）来说，这既浪费带宽又浪费上下文。批准绑定的是清单中的摘要，所以批准时并不需要这些字节。禁止基于协议识别，是因为 `skill://` 只是一个 SHOULD。服务器可以使用其他协议，而恶意服务器也可能把任意资源标记为 `skill://`，好让它被当作指令对待。一个资源只有来自 `skills/list` 或 `skills/get`，并以服务器身份加 URI 作为键时，才算作技能。

### 你会如何构建并发送一个 `private_key_jwt` 客户端断言？
生成一对密钥，并把公钥注册到授权服务器（Authorization Server）。每次请求令牌（Token）时，构建一个 JWT：`iss` 和 `sub` 设为客户端 ID，`aud` 设为 AS，`exp` 设得很短（几分钟），再加上 `iat` 和唯一的 `jti`。用 AS 在 `token_endpoint_auth_signing_alg_values_supported` 中列出的算法（例如 RS256 或 ES256）签名。以表单编码的方式 POST：`grant_type=client_credentials`、`client_assertion_type=urn:ietf:params:oauth:client-assertion-type:jwt-bearer`、`client_assertion=<jwt>`，外加 `resource` 和 `scope`。AS 会验证签名、声明、过期时间，以及该 `jti` 之前没有出现过。私钥始终不离开客户端。

### 客户端密钥还是 JWT 断言：各有什么取舍？
**客户端密钥（Client secret）**很简单，但它是一个长期有效的 bearer 凭据，每次请求令牌都要发送。一旦泄露，攻击者就能悄无声息地进行认证，直到有人轮换它。**JWT 断言**有效期短且只能使用一次（`jti`）。它证明的是对一把从不在网络上传输的私钥的持有，因此截获的断言几乎没有价值。它的代价是密钥管理，以及需要一个支持 `private_key_jwt` 的 AS。该扩展把 JWT 标为推荐（RECOMMENDED）。如果用密钥，就要配合密钥管理器、轮换和最小权限范围。

### 你的公司希望员工通过 Claude 使用内部 MCP 服务器，不需要逐个服务器同意，并且 IT 必须能立即切断访问。你会提出什么方案？
企业托管授权（Enterprise-Managed Authorization）。员工通过企业 IdP 登录客户端。对于每个 MCP 服务器，客户端在 IdP 处执行一次 RFC 8693 令牌交换（Token exchange），带上 `requested_token_type=urn:ietf:params:oauth:token-type:id-jag`，`audience` 设为 MCP AS 的签发者，`resource` 设为该服务器。IdP 评估组和角色策略并签发 ID-JAG。客户端用 `jwt-bearer` 授权许可把它提交给 MCP AS，AS 对照 IdP 的密钥验证它，并签发一个受众限定于该服务器的令牌。撤销在 IdP 处进行，于是不再签发新的 ID-JAG，而较短的令牌有效期意味着各处的访问都会很快终止。

### 陷阱题：一个服务器列出了技能 `code-review`，另一个服务器也列出了同名技能。可能出什么问题？规范有什么要求？
名称只是标签，不是身份。如果不加小心，第二个技能（Skill）可能会**遮蔽**第一个，导致模型以一个受信任的名称加载了另一个服务器的指令。宿主（Host）**必须（MUST）**防止同名技能悄无声息地相互替换。它们必须以 *（服务器身份，URI）* 作为注册表、批准记录和缓存的键，为加载的内容标注来源，并把文件读取绑定到来源服务器。跨服务器读取需要针对每次调用、同时写明两个服务器的显式批准。

## Glossary
- Agent Skill | 智能体技能 | 一个包含 `SKILL.md`（YAML 前置元数据加说明）和配套文件的目录，用来教智能体掌握一套工作流。
- `SKILL.md` | `SKILL.md`（技能说明文件） | 技能的入口文件；必须以包含 `name` 和 `description` 的前置元数据开头。
- Skill manifest | 技能文件清单 | 技能条目中的 `resources` 列表：每个文件的 URI、SHA-256 摘要和字节大小。
- Digest verification | 摘要校验 | 在使用文件之前，对照清单检查其原始字节大小和 SHA-256。
- `skills/list` / `skills/get` | `skills/list` / `skills/get`（技能列举/获取） | 返回技能条目（前置元数据加清单）的扩展方法，分别以分页方式或按 URI 返回。
- Client credentials grant | 客户端凭据授权 | 应用以自身身份认证、无需用户即可获得令牌的 OAuth 流程。
- JWT bearer client assertion | JWT 客户端断言（private_key_jwt） | 用客户端私钥签名的短期 JWT，用来代替密钥进行认证（RFC 7523 §2.2）。
- Identity provider (IdP) | 身份提供方 | 对员工进行认证并执行访问策略的企业系统（Okta、Azure AD……）。
- ID-JAG | 身份断言 JWT 授权许可（ID-JAG） | Identity Assertion JWT Authorization Grant：由 IdP 签名的 JWT，客户端用它换取 MCP 访问令牌。
- Token exchange (RFC 8693) | 令牌交换 | 客户端在 IdP 处用其 ID 令牌换取 ID-JAG 时所使用的 OAuth 授权许可。

## Notebook
### 1. 基于 SDK 扩展 API 构建的 Skills 服务器
Python SDK 没有内置的 Skills 扩展（Extension），所以我们自己写一个。它声明带 `directoryRead` 的 `io.modelcontextprotocol/skills`，把文件作为资源（Resource）提供，并绑定 `skills/list`、`skills/get` 和 `resources/directory/read`。按照规范要求，清单是**根据实际提供的字节计算出来的**。这些文件与文档中的示例完全相同，因此摘要应当与文档逐字符一致。

```python
import hashlib
import json
import logging
from typing import Any, Literal

import yaml

from mcp import Client
from mcp.server import MCPServer
from mcp.server.extension import Extension, MethodBinding, ResourceBinding
from mcp.server.mcpserver.resources import FunctionResource
from mcp.shared.exceptions import MCPError
from mcp_types import INVALID_PARAMS, PaginatedRequestParams, Request, RequestParams, Result

logging.getLogger("mcp").setLevel(logging.ERROR)
SKILLS = "io.modelcontextprotocol/skills"
FILES = {
    "skill://code-review/SKILL.md":
        "---\nname: code-review\ndescription: Review code using the team's checklist.\n---\n\n"
        "# Code review\n\nRead `references/checklist.md`, then review the diff.\n",
    "skill://code-review/references/checklist.md":
        "# Review checklist\n\nCheck correctness, tests, and compatibility.\n",
}


def sha256_digest(data: bytes) -> str:
    return "sha256:" + hashlib.sha256(data).hexdigest()


def frontmatter_of(text: str) -> dict:
    assert text.startswith("---\n"), "SKILL.md MUST begin with YAML frontmatter"
    return yaml.safe_load(text.split("---\n", 2)[1])


class SkillsListResult(Result):
    result_type: Literal["complete"] = "complete"
    skills: list[dict[str, Any]]
    next_cursor: str | None = None
    ttl_ms: int
    cache_scope: str


class SkillGetParams(RequestParams):
    uri: str


class SkillGetResult(Result):
    result_type: Literal["complete"] = "complete"
    skill: dict[str, Any]
    ttl_ms: int
    cache_scope: str


class DirectoryReadParams(RequestParams):
    uri: str
    cursor: str | None = None


class DirectoryReadResult(Result):
    result_type: Literal["complete"] = "complete"
    resources: list[dict[str, Any]]
    next_cursor: str | None = None


class SkillsExtension(Extension):
    identifier = SKILLS

    def __init__(self, files: dict[str, str]):
        self.files = files                                       # uri -> served text

    def settings(self):
        return {"directoryRead": True}

    def entry(self, skill_md_uri: str) -> dict:
        root = skill_md_uri.rsplit("/", 1)[0]
        manifest = [{"uri": u, "digest": sha256_digest(t.encode()), "size": len(t.encode())}
                    for u, t in sorted(self.files.items()) if u.startswith(root + "/")]
        return {"uri": skill_md_uri, "frontmatter": frontmatter_of(self.files[skill_md_uri]), "resources": manifest}

    def resources(self):   # FunctionResource reads the CURRENT bytes on every resources/read
        return [ResourceBinding(FunctionResource(uri=u, name=u.rsplit("/", 1)[1], mime_type="text/markdown",
                                                 fn=lambda u=u: self.files[u]))
                for u in self.files]

    def methods(self):
        async def list_skills(ctx, params: PaginatedRequestParams):
            entries = [self.entry(u) for u in self.files if u.endswith("/SKILL.md")]
            return SkillsListResult(skills=entries, ttl_ms=300_000, cache_scope="public")

        async def get_skill(ctx, params: SkillGetParams):
            if params.uri not in self.files or not params.uri.endswith("/SKILL.md"):
                raise MCPError(INVALID_PARAMS, f"Unknown skill: {params.uri}")
            return SkillGetResult(skill=self.entry(params.uri), ttl_ms=300_000, cache_scope="public")

        async def read_directory(ctx, params: DirectoryReadParams):
            prefix = params.uri + "/"
            children = {}
            for u in self.files:
                if u.startswith(prefix):
                    head, _, rest = u[len(prefix):].partition("/")
                    children[prefix + head] = ("inode/directory" if rest else "text/markdown", head)
            if not children:
                raise MCPError(INVALID_PARAMS, f"Invalid directory URI: {params.uri}")
            return DirectoryReadResult(resources=[{"uri": u, "name": n, "mimeType": m}
                                                  for u, (m, n) in sorted(children.items())])

        return [MethodBinding("skills/list", PaginatedRequestParams, list_skills),
                MethodBinding("skills/get", SkillGetParams, get_skill),
                MethodBinding("resources/directory/read", DirectoryReadParams, read_directory)]


skills_ext = SkillsExtension(dict(FILES))
server = MCPServer("team-skills", extensions=[skills_ext])
print(json.dumps(skills_ext.entry("skill://code-review/SKILL.md"), indent=2))
```

### 3. 会做校验的宿主：先批准清单，再按需加载
宿主（Host）保存条目，请求**绑定到 URI 与摘要集合**的批准，之后才读取 `SKILL.md`。它校验大小、SHA-256 和前置元数据（Frontmatter），在已保留的清单范围内解析相对引用，并拒绝清单之外的一切。

```python
from posixpath import normpath


class SkillLoadError(Exception):
    pass


class SkillHost:
    def __init__(self, client, server_label):
        self.client, self.server = client, server_label
        self.approvals: set[tuple] = set()           # persisted approvals: (server, uri, frozenset of (uri, digest))

    @staticmethod
    def approval_key(server, entry):
        return (server, entry["uri"], frozenset((f["uri"], f["digest"]) for f in entry["resources"]))

    def approve(self, entry, user_says_yes=True):
        files = [f["uri"] for f in entry["resources"]]
        print(f"   [consent] load skill {entry['frontmatter']['name']!r} from {self.server} ({len(files)} files)?",
              "yes" if user_says_yes else "no")
        if user_says_yes:
            self.approvals.add(self.approval_key(self.server, entry))

    async def read_verified(self, entry, uri):
        manifest = {f["uri"]: f for f in entry["resources"]}
        if uri not in manifest:                                       # MUST restrict reads to the manifest
            raise SkillLoadError(f"{uri} is not in the retained manifest")
        data = (await self.client.read_resource(uri)).contents[0].text.encode()
        if len(data) != manifest[uri]["size"] or sha256_digest(data) != manifest[uri]["digest"]:
            raise SkillLoadError(f"{uri}: size/digest mismatch -> reject and refresh with skills/get")
        return data.decode()

    async def load(self, entry):
        if self.approval_key(self.server, entry) not in self.approvals:
            raise SkillLoadError("no approval for this exact manifest")
        text = await self.read_verified(entry, entry["uri"])
        if frontmatter_of(text) != entry["frontmatter"]:              # field-by-field comparison
            raise SkillLoadError("frontmatter differs from the entry")
        name = entry["frontmatter"]["name"]
        if entry["uri"].rsplit("/", 2)[-2] != name:
            raise SkillLoadError("parent directory must equal `name`")
        return f"<skill name={name!r} origin={self.server!r}>\n{text}</skill>"

    async def read_reference(self, entry, relative):
        root = entry["uri"].rsplit("/", 1)[0]
        target = root + "/" + normpath(relative)
        return await self.read_verified(entry, target)


async with Client(server) as client:
    host = SkillHost(client, server_label="team-skills@https://mcp.example.com")
    entry = (await client.session.send_request(ListSkillsRequest(params=PaginatedRequestParams()),
                                               SkillsListResult)).skills[0]
    try:
        await host.load(entry)
    except SkillLoadError as exc:
        print("before approval:", exc)
    host.approve(entry)
    print(await host.load(entry))
    print("model asks for references/checklist.md ->", (await host.read_reference(entry, "references/checklist.md")).splitlines()[0])
    for sneaky in ("../../etc/passwd", "references/secret.md"):
        try:
            await host.read_reference(entry, sneaky)
        except SkillLoadError as exc:
            print("blocked:", exc)
```

### 5. 客户端凭据，第 1 部分：手工构造 `private_key_jwt` 断言
文档推荐使用非对称 JWT 断言（JWT assertion）而不是密钥。环境中已安装 `cryptography` 和 `PyJWT`，因此我们生成一个 RSA 密钥，签发一个断言，并用标准库解码它的各个部分，看清楚到底发送了什么。然后由授权服务器（Authorization Server）用**公钥**验证它。在本 notebook 中，授权服务器只是几行 Python 代码。

```python
import base64
import time
import uuid
from urllib.parse import parse_qs, urlencode

import jwt
from cryptography.hazmat.primitives import serialization
from cryptography.hazmat.primitives.asymmetric import rsa

AS_ISSUER, MCP_RESOURCE, CLIENT_ID = "https://auth.example.com", "https://mcp.example.com/mcp", "nightly-report-bot"
client_key = rsa.generate_private_key(public_exponent=65537, key_size=2048)
client_private_pem = client_key.private_bytes(serialization.Encoding.PEM, serialization.PrivateFormat.PKCS8,
                                              serialization.NoEncryption()).decode()
REGISTERED_KEYS = {CLIENT_ID: client_key.public_key()}       # what the AS stored at (out-of-band) registration


def b64url_json(segment: str) -> dict:
    return json.loads(base64.urlsafe_b64decode(segment + "=" * (-len(segment) % 4)))


now = int(time.time())
assertion = jwt.encode({"iss": CLIENT_ID, "sub": CLIENT_ID, "aud": AS_ISSUER, "iat": now, "exp": now + 300,
                        "jti": str(uuid.uuid4())}, client_private_pem, algorithm="RS256")
header, payload, signature = assertion.split(".")
print("JOSE header:", b64url_json(header))
print("claims:     ", b64url_json(payload))
print("signature:  ", signature[:24], "...", f"({len(signature)} chars)")

body = urlencode({"grant_type": "client_credentials",
                  "client_assertion_type": "urn:ietf:params:oauth:client-assertion-type:jwt-bearer",
                  "client_assertion": assertion, "resource": MCP_RESOURCE, "scope": "mcp:read"})
print("\nPOST /token body (first 200 chars):\n ", body[:200], "...")
```

### 6. 客户端凭据，第 2 部分：真实的 SDK 提供者对接模拟授权服务器
现在由 SDK 的 `PrivateKeyJWTOAuthProvider` 执行完整流程：`401` → 受保护资源元数据 → AS 元数据 → 令牌（Token）请求 → 带 `Bearer` 重试。一个 `httpx2.MockTransport` 同时扮演 MCP 服务器和 AS，而 AS 会**真正验证**断言：签名、`iss`/`sub`、`aud`、过期时间和 `jti` 重放。没有任何数据离开当前进程。

```python
import httpx2

from mcp.client.auth.extensions.client_credentials import (ClientCredentialsOAuthProvider,
                                                           PrivateKeyJWTOAuthProvider, SignedJWTParameters)

logging.getLogger("httpx2").setLevel(logging.WARNING)
AS_PRIVATE = rsa.generate_private_key(public_exponent=65537, key_size=2048)
seen_jti, wire_log = set(), []
AS_METADATA = {"issuer": AS_ISSUER, "token_endpoint": AS_ISSUER + "/token",
               "authorization_endpoint": AS_ISSUER + "/authorize", "response_types_supported": ["code"],
               "grant_types_supported": ["client_credentials"],
               "token_endpoint_auth_methods_supported": ["private_key_jwt", "client_secret_basic"],
               "token_endpoint_auth_signing_alg_values_supported": ["RS256", "ES256"]}
SECRETS = {"legacy-cron": "s3cr3t"}


def token_endpoint(form: dict, headers) -> httpx2.Response:
    if form.get("grant_type") != "client_credentials":
        return httpx2.Response(400, json={"error": "unsupported_grant_type"})
    if "client_assertion" in form:                          # private_key_jwt (RFC 7523 section 2.2)
        unverified = jwt.decode(form["client_assertion"], options={"verify_signature": False})
        client_id = unverified["sub"]
        try:
            claims = jwt.decode(form["client_assertion"], REGISTERED_KEYS[client_id], algorithms=["RS256", "ES256"],
                                audience=AS_ISSUER, issuer=client_id, options={"require": ["exp", "iat", "jti"]})
        except (KeyError, jwt.PyJWTError) as exc:
            return httpx2.Response(401, json={"error": "invalid_client", "error_description": str(exc)})
        if claims["jti"] in seen_jti:
            return httpx2.Response(401, json={"error": "invalid_client", "error_description": "assertion replayed"})
        seen_jti.add(claims["jti"])
    else:                                                   # client secret (basic or post)
        basic = headers.get("authorization", "")
        if basic.startswith("Basic "):
            client_id, _, secret = base64.b64decode(basic[6:]).decode().partition(":")
        else:
            client_id, secret = form.get("client_id"), form.get("client_secret")
        if SECRETS.get(client_id) != secret:
            return httpx2.Response(401, json={"error": "invalid_client"})
    token = jwt.encode({"iss": AS_ISSUER, "sub": client_id, "aud": form.get("resource", MCP_RESOURCE),
                        "scope": form.get("scope", ""), "exp": int(time.time()) + 300}, AS_PRIVATE, algorithm="RS256")
    return httpx2.Response(200, json={"access_token": token, "token_type": "Bearer", "expires_in": 300,
                                      "scope": form.get("scope", "")})


def mcp_endpoint(headers) -> httpx2.Response:
    auth = headers.get("authorization", "")
    try:
        claims = jwt.decode(auth.removeprefix("Bearer "), AS_PRIVATE.public_key(), algorithms=["RS256"],
                            audience=MCP_RESOURCE, issuer=AS_ISSUER)
    except jwt.PyJWTError:
        return httpx2.Response(401, headers={"WWW-Authenticate":
            'Bearer resource_metadata="https://mcp.example.com/.well-known/oauth-protected-resource/mcp"'})
    if "mcp:read" not in claims["scope"].split():
        return httpx2.Response(403, headers={"WWW-Authenticate": 'Bearer error="insufficient_scope", scope="mcp:read"'})
    return httpx2.Response(200, json={"hello": claims["sub"], "scope": claims["scope"]})


def router(request: httpx2.Request) -> httpx2.Response:
    body = request.content.decode()
    wire_log.append(f"{request.method} {request.url}" + (f"\n      {body[:160]}..." if body else ""))
    path = request.url.path
    if path.startswith("/.well-known/oauth-protected-resource"):
        return httpx2.Response(200, json={"resource": MCP_RESOURCE, "authorization_servers": [AS_ISSUER],
                                          "scopes_supported": ["mcp:read"]})
    if path.startswith("/.well-known/oauth-authorization-server") or path.startswith("/.well-known/openid-configuration"):
        return httpx2.Response(200, json=AS_METADATA)
    if path == "/token":
        return token_endpoint({k: v[0] for k, v in parse_qs(body).items()}, request.headers)
    if path == "/mcp":
        return mcp_endpoint(request.headers)
    return httpx2.Response(404)


class MemoryStorage:
    def __init__(self):
        self.tokens = self.client_info = None

    async def get_tokens(self):
        return self.tokens

    async def set_tokens(self, tokens):
        self.tokens = tokens

    async def get_client_info(self):
        return self.client_info

    async def set_client_info(self, info):
        self.client_info = info


jwt_provider = PrivateKeyJWTOAuthProvider(
    server_url=MCP_RESOURCE, storage=MemoryStorage(), client_id=CLIENT_ID, scope="mcp:read", issuer=AS_ISSUER,
    assertion_provider=SignedJWTParameters(issuer=CLIENT_ID, subject=CLIENT_ID,
                                           signing_key=client_private_pem).create_assertion_provider())
async with httpx2.AsyncClient(transport=httpx2.MockTransport(router), auth=jwt_provider) as http:
    response = await http.post(MCP_RESOURCE, json={})
print("private_key_jwt ->", response.status_code, response.json())
print("\n".join("  " + line for line in wire_log))

wire_log.clear()
secret_provider = ClientCredentialsOAuthProvider(server_url=MCP_RESOURCE, storage=MemoryStorage(), client_id="legacy-cron",
                                                 client_secret="s3cr3t", scope="mcp:read", issuer=AS_ISSUER)
async with httpx2.AsyncClient(transport=httpx2.MockTransport(router), auth=secret_provider) as http:
    response = await http.post(MCP_RESOURCE, json={})
token_call = next(l for l in wire_log if "/token" in l)
print("\nclient_secret_basic ->", response.status_code, response.json(), "\n  token call:", token_call.replace("\n", " "))
```

### 7. 企业托管授权：签发并交换 ID-JAG
我们在第 1 段扮演**身份提供方（Identity Provider，IdP）**。它检查策略，并签发一个 ID-JAG，其中 `typ: oauth-id-jag+jwt`，`aud` 设为 MCP AS 的签发者，`resource` 设为 MCP 服务器。SDK 的 `IdentityAssertionOAuthProvider` 执行第 2 段，即 `jwt-bearer` 授权许可；AS 在签发受众受限的令牌之前，会对照 IdP 的公钥验证该 ID-JAG。

```python
from mcp.client.auth.extensions.identity_assertion import IdentityAssertionOAuthProvider

IDP_ISSUER = "https://acme.idp.example"
IDP_KEY = rsa.generate_private_key(public_exponent=65537, key_size=2048)
POLICY = {"alice@acme.example": {MCP_RESOURCE}, "bob@acme.example": set()}   # who may reach which MCP server
AS_METADATA["authorization_grant_profiles_supported"] = ["urn:ietf:params:oauth:grant-profile:id-jag"]
AS_METADATA["grant_types_supported"].append("urn:ietf:params:oauth:grant-type:jwt-bearer")
MCP_CLIENTS = {"chat-client": "client-secret-at-mcp-as"}


def idp_token_exchange(user: str, audience: str, resource: str) -> str:
    """Leg 1 (RFC 8693): the IdP evaluates policy, then issues an ID-JAG."""
    if resource not in POLICY.get(user, set()):
        raise PermissionError(f"IdP policy denies {user} -> {resource}")
    now = int(time.time())
    return jwt.encode({"jti": uuid.uuid4().hex, "iss": IDP_ISSUER, "sub": "U019488227", "email": user,
                       "aud": audience, "resource": resource, "client_id": "chat-client",
                       "exp": now + 300, "iat": now, "scope": "mcp:read"},
                      IDP_KEY, algorithm="RS256", headers={"typ": "oauth-id-jag+jwt"})


def as_jwt_bearer(form: dict) -> httpx2.Response:
    """Leg 2: the MCP authorization server validates the ID-JAG."""
    if MCP_CLIENTS.get(form.get("client_id")) != form.get("client_secret"):
        return httpx2.Response(401, json={"error": "invalid_client"})
    try:
        if jwt.get_unverified_header(form["assertion"]).get("typ") != "oauth-id-jag+jwt":
            raise jwt.InvalidTokenError("not an ID-JAG")
        grant = jwt.decode(form["assertion"], IDP_KEY.public_key(), algorithms=["RS256"],
                           audience=AS_ISSUER, issuer=IDP_ISSUER)
    except jwt.PyJWTError as exc:
        return httpx2.Response(400, json={"error": "invalid_grant", "error_description": str(exc)})
    if grant["client_id"] != form["client_id"]:
        return httpx2.Response(400, json={"error": "invalid_grant", "error_description": "client mismatch"})
    token = jwt.encode({"iss": AS_ISSUER, "sub": grant["sub"], "aud": grant["resource"],   # audience-restricted
                        "scope": grant["scope"], "exp": int(time.time()) + 300}, AS_PRIVATE, algorithm="RS256")
    return httpx2.Response(200, json={"access_token": token, "token_type": "Bearer", "expires_in": 300,
                                      "scope": grant["scope"]})


def enterprise_router(request: httpx2.Request) -> httpx2.Response:
    if request.url.path == "/token":
        form = {k: v[0] for k, v in parse_qs(request.content.decode()).items()}
        print("  leg 2 token request: grant_type =", form["grant_type"], "| params:", sorted(form))
        return as_jwt_bearer(form)
    return router(request)


for user in ("alice@acme.example", "bob@acme.example"):
    async def fetch_id_jag(audience: str, resource: str, user=user) -> str:
        jag = idp_token_exchange(user, audience, resource)
        print(f"  leg 1: IdP issued ID-JAG typ={jwt.get_unverified_header(jag)['typ']} claims=",
              {k: v for k, v in jwt.decode(jag, options={"verify_signature": False}).items() if k in ("aud", "resource", "email")})
        return jag

    provider = IdentityAssertionOAuthProvider(server_url=MCP_RESOURCE, storage=MemoryStorage(), client_id="chat-client",
                                              client_secret="client-secret-at-mcp-as", issuer=AS_ISSUER,
                                              assertion_provider=fetch_id_jag, scope="mcp:read")
    print(user)
    try:
        async with httpx2.AsyncClient(transport=httpx2.MockTransport(enterprise_router), auth=provider) as http:
            r = await http.post(MCP_RESOURCE, json={})
        print("  MCP server ->", r.status_code, r.json())
    except PermissionError as exc:
        print("  blocked at the IdP:", exc)
```
