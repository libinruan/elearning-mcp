## Summary
纯文本回答能做的事有限。有时用户需要与数据*交互*：钻取一张图表、填写一个选项繁多的表单，或者拖动进度条浏览一段视频。**MCP Apps**（`io.modelcontextprotocol/ui`）让服务器（Server）可以下发一个交互式 HTML 界面，由宿主（Host）在对话中以沙箱化 iframe（Sandboxed iframe）的形式内联渲染。它的设计组合了两个已有的原语（Primitive）：一个**工具（Tool）**，其 `_meta.ui.resourceUri` 指向一个以 `text/html;profile=mcp-app` 提供的 **`ui://` 资源（Resource）**。之后应用与宿主通过承载在 `postMessage` 之上的一种 MCP 方言通信，使用 `ui/initialize`、工具结果通知以及经由宿主代理的 `tools/call`。本课讲解为什么 Apps 胜过一个独立的 Web 应用、资源与元数据格式、可见性（Visibility）、基于 CSP 的安全模型，以及构建与测试流程。在 notebook 中，你将用 SDK 的 `Apps` 辅助类构建一个应用，并亲自扮演宿主。

## Lesson
### 为什么不直接做一个 Web 应用？
你当然可以构建一个独立的 Web 应用，然后把链接发给用户。但文档列出了四个独立页面无法比拟的优势：

- **保留上下文（Context preservation）。** 应用就在对话里，紧挨着产生它的那段讨论。用户不用切换标签页，也不会忘记是哪个聊天里有那张仪表盘。
- **双向数据流（Bidirectional data flow）。** 应用可以调用其 MCP 服务器上的任意工具，宿主也可以把最新结果推送给它。独立应用需要自己的 API、认证和状态管理，而 MCP Apps 直接从现有的 MCP 模式中获得这些能力。
- **与宿主能力（Capability）的集成。** 应用可以向宿主请求一个*结果*，比如“安排这场会议”。宿主会在征得用户同意的前提下，通过用户已经连接好的能力来完成它，因此应用无需自建集成。
- **安全保证。** 应用运行在由宿主控制的沙箱化 iframe 中。它们无法访问父页面、窃取 cookie 或逃出容器，因此宿主可以在不完全信任服务器作者的情况下渲染第三方应用。

如果这些对你的场景都不重要，普通的 Web 应用可能更简单。

### 模式：一个工具加一个 `ui://` 资源
普通工具（Tool）返回文本、图片、资源或结构化数据。MCP Apps 允许工具**声明对一个交互式 UI 的引用**，由宿主（Host）就地渲染该 UI。当模型调用这样的工具时：

1. **UI 预加载。** 工具描述中携带 `_meta.ui.resourceUri`，指向一个 `ui://` 资源（Resource）。宿主可以**在工具被调用之前**就去获取它，这使得把工具输入流式传入应用之类的功能成为可能。
2. **获取资源。** 宿主用 `resources/read` 读取该资源。它是一个 HTML 页面，通常连同 JS 和 CSS 打包在一起。外部脚本和静态资源只允许来自 `_meta.ui.csp` 中声明的源（origin）。
3. **沙箱化渲染。** Web 宿主在沙箱化 iframe（Sandboxed iframe）中渲染 HTML。资源的 `_meta.ui` 可以请求 `permissions`（摄像头、麦克风……）并声明 `csp` 源。
4. **双向通信。** 应用与宿主通过 `postMessage` 交换 JSON-RPC 消息。其中一些消息与核心 MCP 相同（`tools/call`），一些相似（`ui/initialize`），大多数则是带 `ui/` 前缀的新消息。

把**模板**（静态的 `ui://` 资源）与**数据**（工具结果）分开是有意为之。宿主可以在连接时、任何工具运行之前，就对模板进行审查、计算哈希并缓存。

### UI 资源：格式与元数据
UI 资源（UI resource）就是一个普通的 MCP 资源（Resource），只是在其上叠加了一些约定：

- URI **必须（MUST）**使用 `ui://` 协议。路径结构由你决定，例如 `ui://get-time/mcp-app.html`。
- `mimeType` **必须（MUST）**是 `text/html;profile=mcp-app`。其他内容类型保留给未来版本。
- 内容以 `text` 或 base64 `blob` 的形式提供，并且**必须（MUST）**是一个合法的 HTML5 文档。

资源的 `_meta.ui` 对象（`UIResourceMeta`）用于配置安全与渲染：

| 字段 | 用途 |
| --- | --- |
| `csp.connectDomains` | fetch/XHR/WebSocket 可访问的源 → CSP `connect-src` |
| `csp.resourceDomains` | 脚本、样式、图片、字体、媒体的来源 → `script-src`、`style-src`、`img-src`、`font-src`、`media-src` |
| `csp.frameDomains` | 嵌套 iframe 的来源 → `frame-src`（默认 `'none'`） |
| `csp.baseUriDomains` | 允许的 base URI → `base-uri`（默认 `'self'`） |
| `permissions` | `camera`、`microphone`、`geolocation`、`clipboardWrite`，每项为 `{}`。宿主可以（MAY）予以支持，应用应当做特性检测 |
| `domain` | 专用的沙箱源（格式由宿主决定），适用于 OAuth 回调或 CORS 白名单 |
| `prefersBorder` | `true`/`false` 表示希望或不希望宿主绘制边框和背景。请显式设置，因为各宿主的默认值不同 |

> **规范规则（限制性默认值）。** 如果省略了 `ui.csp`，宿主**必须（MUST）**使用 `default-src 'none'; script-src 'self' 'unsafe-inline'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; media-src 'self' data:; connect-src 'none';`。宿主可以（MAY）进一步收紧，但**不得（MUST NOT）**放行未声明的域名，并且应当（SHOULD）记录 CSP 配置以供审计。

正因为这种默认拒绝的内容安全策略（Content Security Policy，CSP），构建指南才用 `vite-plugin-singlefile` 把 UI 打包成**单个 HTML 文件**。另一种做法是声明每一个外部源。

### 把工具关联到 UI，以及可见性
工具通过 `_meta.ui`（`McpUiToolMeta`）关联到它的 UI：

```json
{"name": "get_weather", "description": "Get current weather for a location",
 "inputSchema": {"type": "object", "properties": {"location": {"type": "string"}}},
 "_meta": {"ui": {"resourceUri": "ui://weather-server/dashboard-template",
                  "visibility": ["model", "app"]}}}
```

- 被引用的资源**必须（MUST）**存在，宿主（Host）**必须（MUST）**用 `resources/read` 获取它。宿主可以（MAY）预取并缓存。
- 服务器可以（MAY）在 `resources/list` 中省略仅供 UI 使用的资源，因为它们是通过工具元数据被发现的。
- 旧的扁平键 `_meta["ui/resourceUri"]` 已**弃用**，将在 GA 之前移除。请使用 `_meta.ui.resourceUri`。

`visibility`（可见性，Visibility）默认为 `["model", "app"]`。含 `"model"` 时，智能体（Agent）可以看到并调用该工具。含 `"app"` 时，应用可以调用它，但仅限于**同一个服务器连接**。除非可见性包含 `"model"`，否则宿主**不得（MUST NOT）**把该工具放进智能体的工具列表。`["app"]` 适合“刷新仪表盘”这类仅供 UI 使用的操作。对于不含 `"app"` 的工具，宿主**必须拒绝（MUST reject）**来自应用的 `tools/call`；而对仅供应用使用的工具，跨服务器调用一律被阻止。

### 宿主 ↔ 应用通信
从概念上讲，应用是一个 MCP 客户端（Client），宿主（Host）则充当一个 MCP 服务器，并把请求代理到真正的服务器。传输（Transport）是 `postMessage`，而不是 stdio 或 HTTP。你可以使用 `@modelcontextprotocol/ext-apps` 中的 `App` 类，也可以手写 JSON-RPC，因为一切都是标准的 Web 原语。

| 方向 | 消息 | 用途 |
| --- | --- | --- |
| 应用 → 宿主 | `ui/initialize`（请求） | 携带 `appInfo`、`appCapabilities`、`protocolVersion` 进行握手（Apps 规范单独版本化，例如 `2026-01-26`）。结果中包含 `hostInfo`、`hostCapabilities` 和 `hostContext`（主题、样式、显示模式、容器尺寸、语言区域……） |
| 应用 → 宿主 | `ui/notifications/initialized` | 握手完成。在此之前宿主不得（MUST NOT）向应用发送消息 |
| 宿主 → 应用 | `ui/notifications/tool-input-partial`（0..n 次）、`ui/notifications/tool-input` | 流式或完整的工具参数 |
| 宿主 → 应用 | `ui/notifications/tool-result` | 工具完成后的 `CallToolResult` |
| 宿主 → 应用 | `ui/notifications/tool-cancelled`、`ui/resource-teardown` | 取消，以及拆除（这是一个宿主应当（SHOULD）等待其响应的请求） |
| 应用 → 宿主 | `tools/call`、`resources/read`、`notifications/message`、`ping` | 标准 MCP，由宿主代理或处理 |
| 应用 → 宿主 | `ui/message`、`ui/update-model-context`、`ui/open-link`、`ui/request-display-mode` | 向聊天中发帖、为后续轮次更新模型上下文、打开 URL、切换到 `inline`/`fullscreen`/`pip` |
| 双向 | `ui/notifications/size-changed`、`ui/notifications/host-context-changed` | 布局与主题变化 |

```text
Host                         App (iframe)                 MCP server
 |-- tools/call (model chose the tool) ------------------------>|
 |<========== render ui:// HTML in sandbox ==========>|          |
 |<-- ui/initialize ----------------------------------|          |
 |--- result {hostContext, hostCapabilities} -------->|          |
 |<-- ui/notifications/initialized -------------------|          |
 |--- ui/notifications/tool-input {arguments} ------->|          |
 |<-------------------------------------------------- CallToolResult
 |--- ui/notifications/tool-result {content, structuredContent} ->|
 |<-- tools/call (user clicked) ----------------------|          |
 |--- tools/call (proxied, visibility checked) ------------------>|
```

关于工具结果的最佳实践是：`content` 存放发给模型以及纯文本宿主的文本；`structuredContent` 存放供 UI 使用的数据，这部分*不会*加入模型上下文；`_meta` 存放不打算给模型看的元数据。

**Web 宿主**还多一层：它们**必须（MUST）**在一个*不同的源*上渲染一个带 `allow-scripts` 和 `allow-same-origin` 的**沙箱代理（Sandbox proxy）** iframe。该代理发出 `ui/notifications/sandbox-proxy-ready`，通过 `ui/notifications/sandbox-resource-ready` 接收 HTML，用计算好的 CSP 将其加载到内层 iframe 中，并在两个方向上转发其余所有消息。

### 协商与优雅降级
宿主（Host）在其客户端能力（Capability）中声明对 Apps 的支持，且该设置对象**要求**提供 `mimeTypes`：

```json
"extensions": {"io.modelcontextprotocol/ui": {"mimeTypes": ["text/html;profile=mcp-app"]}}
```

服务器应当（SHOULD）在依赖 UI 之前先检查这一点。TypeScript 的辅助函数是 `getUiCapability()`，Python SDK 中则是 `client_supports_apps(ctx)`。服务器可以（MAY）针对不同宿主注册不同的工具变体。最重要的是，**即使 UI 可用，工具也必须（MUST）返回有意义的 `content` 数组**。不支持 Apps 的宿主只会把该工具当作普通工具对待，这就是优雅降级（Graceful degradation）。

### 安全模型
威胁模型假定存在一个发送有害 HTML 的**恶意服务器**，以及一个试图逃出沙箱（Sandbox）、执行未授权工具、窃取宿主数据或钓鱼用户的**被攻陷应用**。缓解措施层层叠加：

1. **iframe 沙箱化。** 所有应用内容**必须（MUST）**在沙箱化 iframe 中渲染。应用无法触碰父页面的 DOM、cookie 或本地存储，无法让父页面跳转，也无法在父页面上下文中运行脚本。
2. **可审计的通信。** 一切都通过 `postMessage` 上的 JSON-RPC 进行。宿主校验消息、拒绝格式错误的消息，并记录由应用发起的调用。应用能做什么由宿主决定，例如它可以调用哪些工具、是否允许 `ui/open-link`。宿主可以（MAY）要求用户批准。
3. **预先声明的资源审查。** 模板在执行之前就已到达，因此宿主可以扫描它们、计算哈希，并维护白名单或黑名单。
4. **CSP 强制执行。** 宿主只根据已声明的域名构建策略，并且必须（MUST）阻止其他一切。

剩余的风险是**社会工程**（UI 仍可能展示误导性内容，因此宿主应当清晰标示沙箱边界）和**资源耗尽**（宿主应当施加限制）。

### 何时使用 MCP Apps
文档列出了五种非常适合的场景：**探索复杂数据**（用一张可点击的地图代替一串数字）、**多选项配置**（一个表单代替二十个问题）、**查看富媒体**（可平移缩放的 PDF、3D 模型、图片）、**实时监控**（实时仪表盘），以及**多步骤工作流**（逐条审批报销或分拣问题，并保持持久状态）。

### 构建与测试一个应用
构建指南使用 TypeScript。在服务器端，`registerAppTool(server, "get-time", {..., _meta: {ui: {resourceUri}}}, handler)` 注册关联的工具，`registerAppResource(server, uri, uri, {mimeType: RESOURCE_MIME_TYPE}, read)` 提供打包好的 HTML。服务器通过可流式 HTTP 传输（Streamable HTTP）运行在 3001 端口。在 UI 端，使用 `new App({name, version})`、`app.connect()`（只调用一次）、`app.ontoolresult = ...` 接收宿主推送的结果，以及 `app.callServerTool({name, arguments})` 发起用户触发的调用。每次调用都是一次到服务器的往返，所以设计时要考虑延迟。搭建项目最快的方式是 `create-mcp-app` **技能（Skill）**，AI 编程智能体加载它后即可生成服务器、UI 和配置。

**Python SDK** 把 Apps 内置在核心中：`Apps()` 是一个 `Extension`（扩展，Extension），提供 `@apps.tool(resource_uri=..., visibility=...)` 和 `apps.add_html_resource(uri, html, csp=ResourceCsp(...), permissions=..., prefers_border=...)`，然后把它传给 `MCPServer(extensions=[apps])`。

测试有两种选择：

- **Claude**（Web 版或 Desktop）：用 `npx cloudflared tunnel --url http://localhost:3001` 暴露本地服务器，再把该 URL 添加为**自定义连接器（Custom Connector）**（Settings → Connectors → Add custom connector）。这需要付费套餐。
- `ext-apps` 仓库中的 **basic-host**：运行 `SERVERS='["http://localhost:3001/mcp"]' npm start`，然后打开 `http://localhost:8080`，调用工具并观察沙箱化渲染效果。

宿主开发者可以使用 `@mcp-ui/client`（React 组件），或者基于 SDK 的 **AppBridge** 模块进行构建，它负责沙箱化渲染、消息传递、工具调用代理和策略执行。官方提供了 React、Vue、Svelte、Preact、Solid 以及原生 JS 的入门模板。支持 MCP Apps 的有 Claude、Claude Desktop、VS Code GitHub Copilot、Microsoft 365 Copilot、Goose、Postman、MCPJam、Archestra.AI、ChatGPT、Cursor 等（参见客户端支持矩阵）。

## Key points
- MCP Apps（`io.modelcontextprotocol/ui`）= 一个带 `_meta.ui.resourceUri` 的**工具（Tool）** + 一个以 `text/html;profile=mcp-app` 提供的 **`ui://` 资源（Resource）**，在**沙箱化 iframe（Sandboxed iframe）**中渲染。
- 相比 Web 应用的优势（Advantage）在于：保留上下文（Context preservation）、经由 MCP 的双向数据流、把结果委托给宿主的能力，以及沙箱安全。
- 资源的 `_meta.ui` 携带 `csp`（`connectDomains`、`resourceDomains`、`frameDomains`、`baseUriDomains`）、`permissions`、`domain` 和 `prefersBorder`。如果省略内容安全策略（CSP），宿主使用限制性的默认拒绝策略，并且不得（MUST NOT）放行未声明的域名。
- `visibility`（可见性，Visibility）默认为 `["model","app"]`。仅供应用的工具对智能体隐藏，宿主会拒绝应用对不含 `"app"` 的工具的调用。
- 应用 ↔ 宿主（Host）通过 `postMessage` 使用一种 JSON-RPC 方言：`ui/initialize` → `ui/notifications/initialized`，然后是 `tool-input`、`tool-result`，以及应用发起的 `tools/call`、`ui/message`、`ui/update-model-context`、`ui/open-link`。
- 宿主的客户端能力（Capability）必须列出 `mimeTypes: ["text/html;profile=mcp-app"]`。工具仍必须（MUST）返回有意义的 `content`，让不支持 Apps 的宿主能够优雅降级（Graceful degradation）。
- `content` 给模型，`structuredContent` 给 UI（不会加入模型上下文），`_meta` 用于元数据（Metadata）。
- 用 `registerAppTool`/`registerAppResource` + `App` 类（TS）或 `Apps`（Python）构建。可在 Claude 中通过隧道和自定义连接器（Custom Connector）测试，或在本地用 **basic-host** 测试。

## Pitches
### 什么是 MCP Apps？
MCP Apps 是一个官方扩展（Extension），让 MCP 服务器不只返回文本，还能返回一个交互界面。工具上带一个 `_meta.ui.resourceUri`，指向一个 `ui://` 的 HTML 资源（Resource）。宿主（Host）去获取它，通常是提前获取，然后直接在聊天里用沙箱化 iframe（Sandboxed iframe）渲染出来。之后应用和宿主通过 postMessage 走 JSON-RPC 通信，应用就能接收工具结果、继续调用工具、发消息或者更新模型上下文，而这一切都在宿主的控制之下。

### 为什么我要做 MCP 应用，而不是普通 Web 应用？
当 UI 本身属于这段对话的时候，我会这么做。应用就在产生它的讨论旁边，谁都不会丢失上下文。它复用 MCP 来拿数据，所以不需要自己的 API、认证（Authentication）或状态层。像“安排这场会议”这样的结果，它可以交给宿主（Host）去完成，宿主本来就有用户的各种连接。而且宿主的沙箱（Sandbox）让渲染第三方 UI 变得安全。如果这些都不重要，那普通 Web 应用更简单。

### MCP 应用是怎么保证安全的？
有好几层防护。HTML 跑在沙箱化 iframe（Sandboxed iframe）里，对 Web 宿主来说还在一个独立的源上，所以它碰不到宿主页面、cookie 或存储。所有交互都走 postMessage 上可审计的 JSON-RPC，应用能调用哪些工具由宿主说了算。网络和静态资源访问遵循内容安全策略（Content Security Policy，CSP），这个策略只根据服务器声明的域名构建，兜底是默认拒绝。另外模板是预先声明的，宿主可以在任何东西运行之前先审查、算哈希。

## Interview
### 宿主如何知道一个工具带有 UI，又在什么时候去获取它？
`tools/list` 中的工具描述携带 `_meta.ui.resourceUri`，即一个 `ui://` URI。宿主（Host）**必须（MUST）**用 `resources/read` 获取它，并且可以**在工具被调用之前**就去获取，例如在列出工具后立即获取。这使得预加载、缓存、安全审查，以及把工具参数流式传入一个已渲染好的应用成为可能。该资源必须存在，必须以 `text/html;profile=mcp-app` 提供，并且必须是合法的 HTML5 文档。服务器可以在 `resources/list` 中省略仅供 UI 使用的资源，因为它们是通过工具元数据被发现的。旧的扁平键 `_meta["ui/resourceUri"]` 已弃用。

### `visibility` 有什么作用？请给出一个 `["app"]` 的用例。
`visibility`（可见性，Visibility）规定谁可以调用一个关联了 UI 的工具。默认值是 `["model","app"]`。含 `"model"` 时，智能体（Agent）能看到并调用它。含 `"app"` 时，应用可以通过宿主调用它，并且仅限同一个服务器连接。宿主不得（MUST NOT）向智能体展示不含 `"model"` 的工具，并且必须（MUST）拒绝应用对不含 `"app"` 的工具的调用。`["app"]` 的一个好例子是 `refresh_dashboard` 或 `load_page(n)`。UI 需要它来分页或刷新，但把它暴露给模型只会让工具列表更杂乱、浪费令牌（Token）。

### 某个 UI 需要从 `https://api.example.com` 获取数据，并从 CDN 加载一个图表库。你要配置什么？如果不配置会怎样？
在资源的 `_meta.ui.csp` 中声明它们：用于 fetch/XHR 的 `connectDomains: ["https://api.example.com"]`，以及用于脚本和样式的 `resourceDomains: ["https://cdn.jsdelivr.net"]`。宿主（Host）据这些列表构建 `connect-src` 和 `script-src`/`style-src`/`img-src`……。如果不声明，宿主会应用限制性默认内容安全策略（Content Security Policy，CSP）（`connect-src 'none'`，只允许内联或同源脚本），于是 fetch 和 CDN 脚本都会被阻止。这正是构建指南把所有内容打包成单个 HTML 文件的原因。宿主可以进一步收紧策略，但绝不能放行未声明的域名。

### 如何让一个 MCP 应用优雅降级？
始终从工具返回一个有意义的 `content` 数组，例如一段文本摘要，因为不支持 Apps 的宿主会把它当作普通工具，而模型无论如何都会读取 `content`。把丰富的、面向 UI 的数据放进 `structuredContent`。还可以选择用 `getUiCapability()` 或 `client_supports_apps(ctx)` 检查客户端能力（Capability）（`extensions["io.modelcontextprotocol/ui"].mimeTypes` 必须包含 `text/html;profile=mcp-app`）并据此调整，例如注册一个纯文本变体，或在不会渲染 UI 时在文本中加入更多细节。这就是优雅降级（Graceful degradation）。

### 请走一遍从模型调用 UI 工具到用户点击其中按钮之间发生的全过程。
宿主（Host）向服务器发送 `tools/call`，同时在沙箱（Sandbox）中渲染 `ui://` HTML（对 Web 宿主而言，要经过一个不同源的沙箱代理（Sandbox proxy））。应用发送带 `appInfo`、`appCapabilities` 和 `protocolVersion` 的 `ui/initialize`。宿主用 `hostContext`（主题、显示模式、尺寸）和 `hostCapabilities` 作答，应用再以 `ui/notifications/initialized` 确认。随后宿主发送带参数的 `ui/notifications/tool-input`，并在服务器响应后发送 `ui/notifications/tool-result`。用户点击时，应用通过 postMessage 发送 `tools/call`。宿主检查可见性和自身策略，把调用转发给服务器，并返回结果。应用还可以发送 `ui/update-model-context`，让模型知道用户做了什么。

## Glossary
- MCP App | MCP 应用 | 由 MCP 服务器下发、由宿主在沙箱化 iframe 中内联渲染的交互式 HTML 界面。
- UI resource | UI 资源 | 以 `text/html;profile=mcp-app` 提供、包含应用 HTML 模板的 `ui://` 资源。
- `_meta.ui.resourceUri` | `_meta.ui.resourceUri`（UI 资源链接） | 把工具关联到其 UI 资源的工具元数据字段。
- Visibility | 可见性 | `_meta.ui.visibility`：一个关联了 UI 的工具可以被模型调用、被应用调用，还是两者皆可。
- Sandboxed iframe | 沙箱化 iframe | 受限的 iframe，把应用与宿主页面、cookie、存储以及父页面导航隔离开来。
- Sandbox proxy | 沙箱代理 | Web 宿主用来加载应用并中转消息的、位于不同源上的中间 iframe。
- Content Security Policy (CSP) | 内容安全策略 | 宿主根据 `_meta.ui.csp` 构建的浏览器策略，用于限制应用可以从哪些源加载内容或与之建立连接。
- postMessage | postMessage（跨窗口消息） | 在应用与宿主之间承载 JSON-RPC 消息的浏览器 API。
- `ui/initialize` | `ui/initialize`（应用握手） | 应用的握手请求；宿主以宿主信息、能力和上下文作答。
- Host context | 宿主上下文 | 宿主提供给应用的主题、样式、显示模式、尺寸、语言区域等信息。

### 1. 使用 SDK 的 `Apps` 扩展构建 MCP 应用服务器
`mcp.server.apps.Apps` 是一个 `Extension`（扩展，Extension）。`@apps.tool(resource_uri=...)` 会在工具上打上 `_meta.ui`，`add_html_resource(...)` 则以 `text/html;profile=mcp-app` 提供一个 `ui://` 资源（Resource），并可附带 CSP 和权限。下面的 HTML 是一个原生 JS 应用，不借助任何 SDK，直接使用 postMessage 协议。注意 `content` 中的文本兜底。

```python

<html lang="en">
<head><meta charset="UTF-8"><title>Sales by region</title></head>
<body>
  <h1 id="title">Loading…</h1>
  <ul id="bars"></ul>
  <button id="refresh">Refresh</button>
  <script>
    let nextId = 1; const pending = {};
    const send = (method, params) => new Promise(resolve => {
      const id = nextId++; pending[id] = resolve;
      window.parent.postMessage({jsonrpc: "2.0", id, method, params}, "*");
    });
    const notify = (method, params) => window.parent.postMessage({jsonrpc: "2.0", method, params}, "*");
    const render = (sc) => {
      document.getElementById("title").textContent = "Sales " + sc.quarter;
      document.getElementById("bars").innerHTML = Object.entries(sc.regions)
        .map(([r, v]) => `<li>${r}: ${"#".repeat(v / 10)} ${v}</li>`).join("");
    };
    window.addEventListener("message", (e) => {
      const m = e.data;
      if (m.id && pending[m.id]) { pending[m.id](m.result); delete pending[m.id]; }
      if (m.method === "ui/notifications/tool-result") render(m.params.structuredContent);
    });
    send("ui/initialize", {appInfo: {name: "sales-dashboard", version: "1.0.0"},
                           appCapabilities: {}, protocolVersion: "2026-01-26"})
      .then(() => notify("ui/notifications/initialized", {}));
    document.getElementById("refresh").onclick = async () => {
      const r = await send("tools/call", {name: "refresh_sales", arguments: {quarter: "Q3"}});

</body>
</html>"""
```

### 3. 宿主端校验：关联关系、MIME 类型与 CSP 头
一个谨慎的宿主（Host）在渲染任何东西之前都会检查每一个关联。它确认 `ui://` 协议、资源存在、MIME 类型（MIME type）完全匹配以及 HTML5 doctype。然后它按照规范的构造方式，**只**根据已声明的域名构建 iframe 的内容安全策略（Content Security Policy，CSP），并把沙箱化文档写入一个临时文件，将策略作为 `<meta>` 标签注入其中。

```python
import tempfile
from html.parser import HTMLParser
from pathlib import Path


def build_csp(ui_meta: dict | None) -> str:
    csp = (ui_meta or {}).get("csp")
    if csp is None:   # spec's restrictive default when ui.csp is omitted
        return ("default-src 'none'; script-src 'self' 'unsafe-inline'; style-src 'self' 'unsafe-inline'; "
                "img-src 'self' data:; media-src 'self' data:; connect-src 'none';")
    res = csp.get("resourceDomains", [])
    directives = [
        ["default-src", "'none'"],
        ["script-src", "'self'", "'unsafe-inline'", *res],
        ["style-src", "'self'", "'unsafe-inline'", *res],
        ["connect-src", "'self'", *csp.get("connectDomains", [])],
        ["img-src", "'self'", "data:", *res],
        ["font-src", "'self'", *res],
        ["media-src", "'self'", "data:", *res],
        ["frame-src", *(csp.get("frameDomains") or ["'none'"])],
        ["object-src", "'none'"],
        ["base-uri", *(csp.get("baseUriDomains") or ["'self'"])],
    ]
    return "; ".join(" ".join(d) for d in directives) + ";"


class ExternalRefs(HTMLParser):
    def __init__(self):
        super().__init__()
        self.refs = []

    def handle_starttag(self, tag, attrs):
        for name, value in attrs:
            if name in ("src", "href") and value and value.startswith(("http://", "https://")):
                self.refs.append((tag, value))


async def validate_ui_links(client) -> dict:
    report = {}
    for tool in (await client.list_tools()).tools:
        uri = ((tool.meta or {}).get("ui") or {}).get("resourceUri")
        if not uri:
            continue
        assert uri.startswith("ui://"), f"{tool.name}: resourceUri must use ui://"
        content = (await client.read_resource(uri)).contents[0]
        assert content.mime_type == APP_MIME_TYPE, f"{uri}: wrong mimeType {content.mime_type}"
        assert content.text.lstrip().lower().startswith("<!doctype html>"), f"{uri}: not an HTML5 document"
        parser = ExternalRefs()
        parser.feed(content.text)
        report[tool.name] = {"uri": uri, "ui_meta": (content.meta or {}).get("ui"),
                             "external_refs": parser.refs, "html": content.text}
    return report


async with Client(server, extensions=[HOST_APPS_CAP]) as host:
    report = await validate_ui_links(host)

entry = report["sales_by_region"]
csp_header = build_csp(entry["ui_meta"])
print("linked tools:", {name: r["uri"] for name, r in report.items()})
print("external refs in HTML (must be covered by resourceDomains):", entry["external_refs"])
print("\nCSP for the iframe:\n ", csp_header.replace("; ", ";\n  "))

sandbox_dir = Path(tempfile.mkdtemp())
page = entry["html"].replace("<head>", f'<head><meta http-equiv="Content-Security-Policy" content="{csp_header}">', 1)
(sandbox_dir / "dashboard.html").write_text(page)
print("\nwrote", sandbox_dir / "dashboard.html", f"({len(page)} bytes) - open it in a browser to see the static shell")
print("default CSP if ui.csp were omitted:", build_csp(None))
```

### 4. 可见性：模型的工具列表与应用的工具列表
执行可见性（Visibility）规则的是宿主（Host），而不是服务器。智能体（Agent）只能看到可见性包含 `"model"` 的工具，这也是缺省 `visibility` 时的默认值。应用只能调用可见性包含 `"app"` 的工具，同样是缺省时的默认值。`email_report` 关联了 UI，但其可见性是 `["model"]`，因此模型可以发送邮件，而仪表盘不行。

```python
def visibility(tool) -> list[str]:
    ui = (tool.meta or {}).get("ui") or {}
    return ui.get("visibility", ["model", "app"])   # spec default; a stricter host may refuse non-UI tools

    all_tools = (await host.list_tools()).tools

app_tools = [t.name for t in all_tools if "app" in visibility(t)]
print("tools the LLM is offered:   ", model_tools)
print("tools the app may call:     ", app_tools)
print("hidden from the LLM:        ", sorted(set(t.name for t in all_tools) - set(model_tools)))
```

### 5. 模拟宿主 ↔ 应用的 postMessage 流程
Python 跑不了 iframe，但这个协议就是普通的 JSON-RPC，所以我们可以同时扮演双方。`FakeView` 的行为与上面的 HTML 应用一致。`Host` 渲染它、完成握手、推送工具输入和结果，并在检查可见性（Visibility）之后把应用的 `tools/call` **代理**给真正的 MCP 服务器。每条消息都会连同方向一起打印出来。

```python
class FakeView:
    """Stands in for the iframe: same messages the JS app sends."""
    def __init__(self):
        self.next_id, self.state = 1, None

    def request(self, method, params):
        msg = {"jsonrpc": "2.0", "id": self.next_id, "method": method, "params": params}
        self.next_id += 1
        return msg

    def on_message(self, msg):
        if msg.get("method") == "ui/notifications/tool-result":
            self.state = msg["params"]["structuredContent"]
            print(f"      [view renders] {self.state}")


class Host:
    def __init__(self, client, tools):
        self.client, self.tools = client, {t.name: t for t in tools}
        self.initialized, self.model_context = False, None

    def to_view(self, view, msg):
        assert self.initialized or msg.get("id"), "Host MUST NOT message the view before initialized"
        print("HOST -> APP ", json.dumps(msg)[:150])
        view.on_message(msg)

    async def from_view(self, view, msg):
        print("APP  -> HOST", json.dumps(msg)[:150])
        method, params = msg["method"], msg.get("params", {})
        if method == "ui/initialize":
            reply = {"protocolVersion": "2026-01-26", "hostInfo": {"name": "notebook-host", "version": "0.1"},
                     "hostCapabilities": {"serverTools": {}, "openLinks": {}},
                     "hostContext": {"theme": "dark", "displayMode": "inline",
                                     "containerDimensions": {"width": 400, "maxHeight": 600}}}
        elif method == "ui/notifications/initialized":
            self.initialized = True
            return
        elif method == "tools/call":
            tool = self.tools.get(params["name"])
            if tool is None or "app" not in visibility(tool):
                return self.to_view(view, {"jsonrpc": "2.0", "id": msg["id"],
                                           "error": {"code": -32000, "message": "Tool not callable from app"}})
            result = await self.client.call_tool(params["name"], params.get("arguments"))
            reply = result.model_dump(by_alias=True, exclude_none=True, mode="json")
        elif method == "ui/update-model-context":
            self.model_context, reply = params, {}
        else:
            reply = {}
        self.to_view(view, {"jsonrpc": "2.0", "id": msg["id"], "result": reply})


async with Client(server, extensions=[HOST_APPS_CAP]) as client:
    host, view = Host(client, (await client.list_tools()).tools), FakeView()
    args = {"quarter": "Q3"}                                   # the model decided to call sales_by_region
    await host.from_view(view, view.request("ui/initialize", {
        "appInfo": {"name": "sales-dashboard", "version": "1.0.0"},
        "appCapabilities": {}, "protocolVersion": "2026-01-26"}))
    await host.from_view(view, {"jsonrpc": "2.0", "method": "ui/notifications/initialized", "params": {}})
    host.to_view(view, {"jsonrpc": "2.0", "method": "ui/notifications/tool-input", "params": {"arguments": args}})
    result = await client.call_tool("sales_by_region", args)
    host.to_view(view, {"jsonrpc": "2.0", "method": "ui/notifications/tool-result",
                        "params": result.model_dump(by_alias=True, exclude_none=True, mode="json")})
    print("\n-- user clicks Refresh --")
    await host.from_view(view, view.request("tools/call", {"name": "refresh_sales", "arguments": args}))
    await host.from_view(view, view.request("ui/update-model-context", {
        "content": [{"type": "text", "text": "User refreshed the Q3 dashboard."}]}))
    print("\n-- a compromised app tries a model-only tool --")
    await host.from_view(view, view.request("tools/call", {"name": "email_report",
                                                               "arguments": {**args, "to": "attacker@example.com"}}))
    print("\nmodel context stored by host:", host.model_context)
```
