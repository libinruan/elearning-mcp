## Summary
Writing a server is only half the job. Someone has to plug it into a real host. This lesson follows the two official quickstarts. **Local servers** are launched by the host from a JSON config: Claude Desktop's `claude_desktop_config.json` and its `mcpServers` map of `command`, `args` and `env`, illustrated with the official Filesystem Server and its per-action approval. **Remote servers** are reached by URL as Custom Connectors, authenticate when you connect, and let you restrict tools. You will learn where the config and logs live, why absolute paths and explicit `env` matter, and how to read the failures. Then you act as the host yourself, parsing a config, spawning servers, connecting over HTTP with a bearer token, and reproducing every classic error.

## Lesson
### Two ways a host reaches a server
Everything from module 2 shows up here as a user-facing choice:

| | Local server | Remote server |
| --- | --- | --- |
| Transport | **stdio**: the host spawns a subprocess | **Streamable HTTP**: the host connects to a URL |
| Configured by | a launch command in a JSON config file | a URL entered in the host's UI (in Claude: a *Custom Connector*) |
| Runs as | **your user account**, on your machine | the provider's infrastructure |
| Auth | usually none on the wire; secrets passed via `env` | usually OAuth on connect (or API keys, username/password) |
| Availability | per device: install and configure on each machine | from any MCP client with an internet connection |
| Good for | files, local tools, dev environments | SaaS integrations, web-based AI apps, server-side processing |

The docs present both through Claude: Claude Desktop for local servers, Claude (web or desktop) Custom Connectors for remote ones. They stress that *"the concepts apply broadly to other MCP-compatible clients"*.

### Local servers in Claude Desktop: the config file
Claude Desktop runs on macOS, Windows and Linux. To add a local server, open the **Claude menu in the system menu bar** (not the settings inside the chat window) → **Settings… → Developer → Edit Config**. That creates the config file if it doesn't exist, or opens the existing one:

- **macOS**: `~/Library/Application Support/Claude/claude_desktop_config.json`
- **Windows**: `%APPDATA%\Claude\claude_desktop_config.json`

The quickstart's example adds the official **Filesystem Server**, which needs Node.js (`node --version` to check):

```json
{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": [
        "-y",
        "@modelcontextprotocol/server-filesystem",
        "/Users/username/Desktop",
        "/Users/username/Downloads"
      ]
    }
  }
}
```

Reading it field by field:

| Part | Meaning |
| --- | --- |
| `"filesystem"` | a friendly name for the server, shown in Claude Desktop (and used in its log file name) |
| `"command": "npx"` | the executable the host launches, here Node's package runner |
| `"-y"` | auto-confirms installing the package |
| `"@modelcontextprotocol/server-filesystem"` | the server package |
| remaining args | the directories the server is **allowed to access** |
| `"env"` (optional) | extra environment variables for the server process |

The build-server tutorial adds two variants you will meet: `"command": "uv", "args": ["--directory", "/ABSOLUTE/PATH/…", "run", "weather.py"]` for a Python server, and a `"cwd"` field (absolute) for servers that must start in a project directory. On Windows, JSON paths need double backslashes (`C:\\Users\\…`) or forward slashes.

> **Security.** *"Only grant access to directories you're comfortable with Claude reading and modifying. The server runs with your user account permissions, so it can perform any file operations you can perform manually."* A local server is code you chose to run. Lesson 6.3 covers isolating it.

After saving, **completely quit and restart** Claude Desktop, because the config is read at launch. Then open the **"Add files, connectors, and more /"** indicator in the chat input → **Connectors → Manage connectors**, and select the server to see its tools.

### How approval works
The Filesystem Server exposes tools to read files and list directories, create files and folders, move and rename, and search by name or content. The docs promise: *"All actions require your explicit approval before execution."* Before each operation Claude shows an approval request, and you can deny it.

This is the protocol's security principle made concrete. MCP itself cannot enforce consent. The **host** must obtain it before invoking a tool, which is why the gate lives in the client application and not in the server. Your own hosts should do the same: a consent gate in front of `tools/call`, at minimum for anything with side effects.

### Troubleshooting local servers
The docs' checklist when a server doesn't show up:

1. Restart Claude Desktop completely.
2. Check `claude_desktop_config.json` **syntax**. One trailing comma and nothing loads.
3. Make sure the paths are valid and **absolute, not relative**.
4. Read the **logs**.
5. **Run the server manually** in a terminal with the same command and args, e.g. `npx -y @modelcontextprotocol/server-filesystem /Users/username/Desktop …`, to see its errors directly.

**Logs.** Claude Desktop writes MCP logs to `~/Library/Logs/Claude` (macOS) or `%APPDATA%\Claude\logs` (Windows):

- `mcp.log`: general logging about MCP connections and connection failures.
- `mcp-server-SERVERNAME.log`: the **stderr** of that server. *"Stdio servers may use stderr for all their logging, so these files are not limited to errors."* (On stdio, stdout carries protocol messages, so stderr is the only place a server can log freely.)

```bash
tail -n 20 -f ~/Library/Logs/Claude/mcp*.log
```

The debugging guide explains the two most common root causes:

- **Working directory.** For servers launched from a client's config, the working directory *"may be undefined (like `/` on macOS) since the client could be started from anywhere."* Always use absolute paths in the config and in `.env` files. `./data` that works in your terminal fails inside the app.
- **Environment variables.** Stdio servers *"inherit only a limited subset of environment variables automatically (the exact set is platform-dependent)."* An API key exported in your shell profile does not reach the server. Put it in `env`. The Python SDK's stdio client shows the same behaviour: it passes only an allowlist (`HOME`, `LOGNAME`, `PATH`, `SHELL`, `TERM`, `USER` on POSIX) merged with your `env`.

Two more items from the docs. On **Windows**, an `ENOENT` error mentioning `${APPDATA}` is fixed by adding the expanded `APPDATA` value to the server's `env`, and `npx` may keep failing until npm is installed globally (`npm install -g npm`). If **tool calls fail silently**, check the logs, verify the server builds and runs on its own, and restart. For client-side errors, the debugging guide enables Chrome DevTools inside Claude Desktop by writing `{"allowDevTools": true}` to `developer_settings.json` in the same Claude folder, then pressing `Command-Option-I` / `Ctrl+Alt+I`.

The guide also groups startup failures into **path issues** (wrong executable path, missing files, permissions; try an absolute path for `command`, e.g. the output of `which uv`), **configuration errors** (invalid JSON, missing fields, type mismatches) and **environment problems** (missing or wrong variables). For connection problems, check client logs, confirm the process runs, test it standalone with the **Inspector**, and verify protocol compatibility. Call `server/discover` to see which versions the server supports (`-32022` lists them in `data`), and confirm each request's `_meta` carries `protocolVersion` and `clientCapabilities` (missing either gives `-32602`).

### Remote servers: Custom Connectors
A remote server is *"hosted on the internet rather than your local machine"* but exposes the same tools, prompts and resources. Its key advantage is accessibility: no per-device installation, available from any MCP client with an internet connection. In Claude, remote servers are added as **Custom Connectors**, *"the bridge between Claude and remote MCP servers."*

The flow from the quickstart:

1. **Settings → Connectors.** In Claude Desktop use `Ctrl+Comma` or the menu → File → Settings. In the browser use `⌘⇧,` or profile icon → Settings.
2. **Add → "Add custom connector"**, then paste the server URL, including `https://` and the path. The docs' example is `https://example-server.modelcontextprotocol.io/mcp`.
3. **Complete authentication.** *"Most remote MCP servers require authentication"*, commonly **OAuth**, API keys or username/password. You may be redirected to a third-party provider. Under the hood, an MCP server signals this with HTTP `401` and a `WWW-Authenticate` challenge, and the client runs the OAuth 2.1 flow from module 6.
4. **Use resources and prompts** from the **"Add files, connectors, and more /"** menu → Connectors → the server's attachment menu. These are application- and user-controlled primitives, so the user attaches them explicitly.
5. **Configure tool permissions** in the connector's settings: *"enable or disable specific tools, set usage limits, and configure other security parameters."*

**Best practices** from the docs. Security: *"Always verify the authenticity of remote MCP servers before connecting. Only connect to servers from trusted sources, and review the permissions requested during authentication."* Be cautious with sensitive data. Hygiene: you can connect many remote servers at once, so organise connectors by purpose or project and **regularly remove ones you no longer use**. Every connector you keep is attack surface and, as lesson 5.4 showed, tool-definition tokens.

### Beyond Claude: the same ideas in other hosts
MCP's point is that the server doesn't care which host launches it. The docs list Claude, ChatGPT, VS Code, Cursor, MCPJam and many others. The vocabulary carries over everywhere: a **name**, a **launch command + args + env** for stdio, or a **URL + headers/auth** for HTTP. The MCP Inspector's own catalog file reuses the `mcpServers` shape and adds remote entries:

```json
{
  "mcpServers": {
    "my-stdio-server": {"command": "node", "args": ["build/index.js"], "env": {"API_KEY": "..."}},
    "my-modern-server": {"type": "http", "url": "https://api.example.com/mcp", "headers": {"X-Tenant": "acme"}}
  }
}
```

Other hosts keep their own config. IDEs such as VS Code and Cursor use an `mcp.json` file, and Claude Code adds servers with the `claude mcp add` command. The exact file names and keys differ by host and version, so check each host's MCP documentation. The Inspector docs add a useful habit: keep secrets **out** of shareable config files. The Inspector moves `env` values into the OS keychain but saves `headers` verbatim, so a credential in a header ends up in the file.

### What this means when you build your own host
Acting as the host (as the notebook does) makes the responsibilities obvious. Parse and validate the config before launching anything. Spawn each server with an explicit `env`. Capture each server's stderr into its own log. Surface failures clearly: a crashed stdio server usually looks like a bare "connection closed" to the client, and the server log holds the real reason. Gate tool calls behind user consent. For remote servers, attach credentials per request (bearer tokens in `Authorization`) and treat a `401` + `WWW-Authenticate` as "start the auth flow", not as a generic error.

## Key points
- Claude Desktop reads `claude_desktop_config.json`: macOS `~/Library/Application Support/Claude/`, Windows `%APPDATA%\Claude\`. Open it via Settings → Developer → Edit Config.
- Each `mcpServers` entry is a friendly **name** → `command`, `args`, optional `env` (and `cwd`). The host **launches** the server over stdio, and changes need a full restart.
- The Filesystem Server's extra args are the **only directories it may access**. It runs with **your user's permissions**, and every action needs your approval in Claude.
- Use **absolute paths**: a config-launched server's working directory may be undefined (like `/` on macOS).
- Stdio servers inherit only a **limited set of environment variables**. Pass secrets through `env`.
- Logs: `mcp.log` (connections) and `mcp-server-NAME.log` (that server's stderr) in `~/Library/Logs/Claude` or `%APPDATA%\Claude\logs`. Also run the command by hand or test with the Inspector.
- Remote servers are added by **URL** as **Custom Connectors** (Settings → Connectors → Add custom connector), authenticate on connect (usually OAuth), and can have individual tools enabled or disabled.
- Connect only to **trusted** remote servers, review requested permissions, and remove connectors you no longer use.

## Pitches
### How do you connect a local MCP server to Claude Desktop?
I open Settings, then Developer, then Edit Config, which opens claude_desktop_config.json. Under mcpServers I add an entry with a name, the command to launch, its arguments and any environment variables, for example npx with the filesystem server package and the absolute directories it may access. Then I fully restart the app, which spawns the server over stdio. If it doesn't appear, I check the JSON, the absolute paths and the env, read mcp-server-name.log, and run the same command by hand.

### Local or remote server — how do you choose?
A local stdio server runs on the user's machine with their permissions, so it is right for files, local tools and development environments, but every device must install and configure it. A remote server is a URL behind Streamable HTTP and usually OAuth. It works from any client, including web apps, needs no installation, and lets the provider handle server-side processing and authentication. So I go local when the data lives on the machine, and remote for shared SaaS-style integrations.

### Your MCP server works in the terminal but not in Claude Desktop. What do you check?
First the logs: mcp.log for the connection and mcp-server-name.log for the server's own stderr. The usual culprits are relative paths, because the app's working directory may be root rather than my project. Next come environment variables, since stdio servers only inherit a small subset, so an API key from my shell profile never arrives unless I put it in env. Then a command not on the app's PATH, which I fix with an absolute path like the output of which uv. Last, a JSON syntax error.

## Interview
### Walk through what happens between saving `claude_desktop_config.json` and the model calling a tool.
On restart, the host reads `mcpServers`. For each entry it spawns `command` with `args` and an environment built from a platform-dependent inherited subset plus `env`, with stdin/stdout as the stdio transport and stderr captured into `mcp-server-NAME.log`. The client then discovers the server (`server/discover` in 2026-07-28, or the `initialize` handshake with an older server) and lists its tools. The host turns those into tool definitions for the model. When the model emits a tool call, the host shows an **approval prompt**. Only if the user approves does it send `tools/call` over stdin and return the result to the model.

### Why do the docs insist on absolute paths?
Because the host, not your shell, starts the server. A config-launched server's working directory *"may be undefined (like `/` on macOS) since the client could be started from anywhere."* Relative paths in `args`, in `command`, or in a server's `.env` resolve against that unknown directory and silently point somewhere else. Absolute paths (or an absolute `cwd`) make the launch reproducible. The same applies to `command`: GUI apps often have a different `PATH` from your terminal, so the docs suggest using the full path to executables like `uv`.

### A teammate's API key is set in `~/.zshrc`, but the server says it's missing. Explain.
Stdio servers *"inherit only a limited subset of environment variables automatically"*. The exact set is platform-dependent. The Python SDK, for instance, passes only `HOME`, `LOGNAME`, `PATH`, `SHELL`, `TERM` and `USER` on POSIX. Also, a GUI app launched from the dock never ran `.zshrc`. The fix is the `env` block in the server's config entry. That is deliberate: it keeps unrelated secrets from leaking into every server. On Windows the docs show a related case, where `${APPDATA}` errors are fixed by putting the expanded `APPDATA` value in `env`.

### How does connecting to a remote server differ from a local one, from the user's and the protocol's point of view?
For the user, there is no install or command: they paste a URL into a **Custom Connector**, sign in (usually OAuth), and can then enable or disable individual tools and set usage limits. For the protocol, the transport is **Streamable HTTP** instead of stdio. Each request is an HTTP POST with `MCP-Protocol-Version`, `Mcp-Method` and an `Authorization` bearer token, and an unauthenticated request gets `401` with a `WWW-Authenticate` challenge that starts the OAuth flow. The server runs on the provider's infrastructure, so trust shifts to the provider. Verify authenticity, review requested permissions and remove unused connectors.

### Gotcha: your stdio server prints "Server started!" with `print()` and the host can't connect. Why?
On stdio, **stdout is the protocol channel**. Every line must be a JSON-RPC message, so a stray `print()` corrupts the stream. Log to **stderr** instead. In Claude Desktop that output lands in `mcp-server-NAME.log`, which the docs note may contain all of a server's logging, not only errors. Running the server by hand in a terminal is the fastest way to see such output.

### How would you harden a team's use of local and remote MCP servers?
Local: grant the Filesystem Server only the directories needed, remembering it runs with the user's permissions. Install servers from trusted sources and pin versions rather than an ever-changing `npx -y` latest. Keep secrets in `env` or a keychain instead of committed config. Isolate risky servers (lesson 6.3). Remote: connect only to verified servers over HTTPS, review OAuth scopes at consent, disable tools you don't need, and prune unused connectors. Across both: keep the host's per-call approval for side-effecting tools and watch the logs.

## Glossary
- `claude_desktop_config.json` | Claude Desktop 配置文件 | The JSON file whose `mcpServers` map tells Claude Desktop which local servers to launch and how.
- `mcpServers` | `mcpServers`（服务器配置表） | The config object mapping each server's friendly name to its launch `command`, `args` and `env`.
- Local server | 本地服务器 | An MCP server the host launches as a subprocess on the user's machine and talks to over stdio.
- Remote server | 远程服务器 | An MCP server hosted on the internet and reached by URL over Streamable HTTP.
- Custom Connector | 自定义连接器 | Claude's UI mechanism for adding a remote MCP server by URL, including authentication and tool permissions.
- Filesystem Server | 文件系统服务器 | The official reference server that exposes file operations limited to the directories passed as arguments.
- Working directory | 工作目录 | The directory a process starts in; undefined for config-launched servers, hence absolute paths.
- Environment variable inheritance | 环境变量继承 | Stdio servers receive only a limited subset of the host's environment plus the config's `env`.
- `mcp-server-NAME.log` | 服务器日志文件 | Claude Desktop's per-server log file containing that server's stderr output.
- Tool approval | 工具调用审批 | The host-side consent prompt shown before a tool call is executed.

## Notebook
### 1. A local server that behaves like the filesystem server
The official Filesystem Server takes the directories it may touch as **command-line arguments**. Ours does the same, and like many real servers it also needs a secret in an **environment variable**. It writes its startup messages to **stderr**, which is where a host's per-server log comes from. Everything lives in a temp folder.

```python
import asyncio
import json
import logging
import os
import platform
import shutil
import socket
import sys
import tempfile
import textwrap
import threading
import time
from contextlib import AsyncExitStack
from pathlib import Path

from mcp import Client, StdioServerParameters
from mcp.client.stdio import stdio_client

for name in ("httpx", "httpx2", "mcp", "uvicorn"):
    logging.getLogger(name).setLevel(logging.WARNING)

work = Path(tempfile.mkdtemp())
(work / "Desktop").mkdir()
(work / "Downloads").mkdir()
(work / "Desktop" / "todo.md").write_text("- learn MCP\n- write a server\n")
(work / "Downloads" / "invoice.txt").write_text("Invoice #42: $120\n")

SERVER = work / "notes_server.py"
SERVER.write_text(textwrap.dedent('''
    import os
    import sys
    from pathlib import Path

    from mcp.server import MCPServer
    from mcp.server.mcpserver.exceptions import ToolError

    TOKEN = os.environ.get("NOTES_API_TOKEN")
    if not TOKEN:
        print("notes: NOTES_API_TOKEN is not set; refusing to start", file=sys.stderr)
        sys.exit(1)
    ROOTS = [Path(arg).resolve() for arg in sys.argv[1:]]
    for root in ROOTS:
        if not root.is_dir():
            print(f"notes: allowed directory {root} does not exist (cwd={os.getcwd()})", file=sys.stderr)
            sys.exit(1)
    print(f"notes: serving {len(ROOTS)} directories", file=sys.stderr)

    server = MCPServer("notes")


    def inside(path: str) -> Path:
        p = Path(path).resolve()
        if not any(p.is_relative_to(r) for r in ROOTS):
            raise ToolError(f"{path} is outside the allowed directories")
        return p


    @server.tool()
    def list_files() -> list[str]:
        """List every file in the allowed directories (absolute paths)."""
        return sorted(str(f) for r in ROOTS for f in r.rglob("*") if f.is_file())


    @server.tool()
    def read_file(path: str) -> str:
        """Read a text file inside an allowed directory."""
        return inside(path).read_text()


    @server.tool()
    def write_file(path: str, text: str) -> str:
        """Create or overwrite a text file inside an allowed directory."""
        inside(path).write_text(text)
        return f"wrote {len(text)} chars to {path}"


    @server.tool()
    def visible_env() -> list[str]:
        """Names (never values) of the environment variables this server process can see."""
        return sorted(os.environ)


    if __name__ == "__main__":
        server.run(transport="stdio")
'''))
print("server written to", SERVER)
```

### 2. Write and validate a `claude_desktop_config.json`
This is the exact shape Claude Desktop reads: a top-level `mcpServers` object whose keys are the friendly names shown in the UI and whose values say how to **launch** the server (`command`, `args`, optional `env`). Real locations, from the docs, are `~/Library/Application Support/Claude/claude_desktop_config.json` on macOS and `%APPDATA%\Claude\claude_desktop_config.json` on Windows. We write ours to the temp folder instead.

```python
config = {
    "mcpServers": {
        "notes": {
            "command": sys.executable,                      # absolute path to the interpreter
            "args": [str(SERVER), str(work / "Desktop"), str(work / "Downloads")],
            "env": {"NOTES_API_TOKEN": "demo-token-1234"},
        }
    }
}
CONFIG_PATH = work / "claude_desktop_config.json"
CONFIG_PATH.write_text(json.dumps(config, indent=2))

real_location = {"Darwin": "~/Library/Application Support/Claude/claude_desktop_config.json",
                 "Windows": r"%APPDATA%\Claude\claude_desktop_config.json"}
print("on this OS Claude Desktop would read:",
      real_location.get(platform.system(), "(not listed in the docs for this OS; use Settings → Developer → Edit Config)"))
print(CONFIG_PATH.read_text())
```

A host can't tell you much when a server never starts, so check the config before you restart the app. This validator encodes the troubleshooting checklist from the docs: valid JSON, the `mcpServers` key, absolute paths, a command that exists, and string-only `env` values.

```python
def validate_config(text: str) -> list[str]:
    try:
        data = json.loads(text)
    except json.JSONDecodeError as exc:
        return [f"invalid JSON at line {exc.lineno}, column {exc.colno}: {exc.msg}"]
    servers = data.get("mcpServers")
    if not isinstance(servers, dict):
        return ["top-level `mcpServers` object is missing"]
    problems = []
    for name, entry in servers.items():
        cmd = entry.get("command")
        if not isinstance(cmd, str) or not cmd:
            problems.append(f"{name}: `command` must be a non-empty string")
        elif not (Path(cmd).is_absolute() and Path(cmd).exists()) and shutil.which(cmd) is None:
            problems.append(f"{name}: command {cmd!r} not found on PATH (try an absolute path)")
        args = entry.get("args", [])
        if not isinstance(args, list) or not all(isinstance(a, str) for a in args):
            problems.append(f"{name}: `args` must be a list of strings")
        else:
            for a in args:
                looks_like_path = "/" in a or "\\" in a or a.startswith(".")
                if looks_like_path and not Path(a).is_absolute():
                    problems.append(f"{name}: relative path {a!r} (the host's working directory is undefined)")
        env = entry.get("env", {})
        if not isinstance(env, dict) or not all(isinstance(v, str) for v in env.values()):
            problems.append(f"{name}: `env` must map names to string values")
    return problems


print("our config:", validate_config(CONFIG_PATH.read_text()) or "OK")
broken = '''{
  "mcpServers": {
    "notes": {"command": "pyhton3", "args": ["./notes_server.py", "Desktop"], "env": {"PORT": 8080}},
  }
}'''
print("broken (trailing comma):", validate_config(broken))
print("broken (comma fixed):  ", *validate_config(broken.replace("},\n  }", "}\n  }")), sep="\n  ")
```

### 3. Be the host: read the config, launch every server, list tools
This is what Claude Desktop does at startup: read `mcpServers`, spawn each server as a subprocess with `command`, `args` and `env`, and talk to it over stdio. Like the real app, our host writes **one log file per server** with that server's stderr (`mcp-server-NAME.log`) plus a general `mcp.log`.

```python
LOGS = work / "logs"
LOGS.mkdir(exist_ok=True)


def host_log(msg: str) -> None:
    with open(LOGS / "mcp.log", "a") as f:
        f.write(f"{time.strftime('%H:%M:%S')} {msg}\n")


def params_for(entry: dict) -> StdioServerParameters:
    return StdioServerParameters(command=entry["command"], args=entry.get("args", []),
                                 env=entry.get("env"), cwd=entry.get("cwd"))


async def connect_all(stack: AsyncExitStack, cfg: dict) -> dict[str, Client]:
    clients = {}
    for name, entry in cfg["mcpServers"].items():
        errlog = stack.enter_context(open(LOGS / f"mcp-server-{name}.log", "a"))
        host_log(f"[{name}] launching: {entry['command']} {' '.join(entry.get('args', []))}")
        try:
            clients[name] = await stack.enter_async_context(Client(stdio_client(params_for(entry), errlog=errlog)))
            host_log(f"[{name}] connected, protocol {clients[name].protocol_version}")
        except Exception as exc:
            host_log(f"[{name}] FAILED: {exc!r}")
    return clients


cfg = json.loads(CONFIG_PATH.read_text())
async with AsyncExitStack() as stack:
    clients = await connect_all(stack, cfg)
    for name, client in clients.items():
        tools = (await client.list_tools()).tools
        print(f"{name}: {[t.name for t in tools]}")
    notes = clients["notes"]
    files = (await notes.call_tool("list_files", {})).structured_content["result"]
    print("list_files ->", [Path(f).name for f in files])
    print("read_file  ->", (await notes.call_tool("read_file", {"path": files[0]})).content[0].text.strip())
    escape = await notes.call_tool("read_file", {"path": str(SERVER)})
    print("outside the allowed dirs ->", escape.is_error, escape.content[0].text)

print("\n--- mcp.log ---\n" + (LOGS / "mcp.log").read_text())
print("--- mcp-server-notes.log ---\n" + (LOGS / "mcp-server-notes.log").read_text())
```

### 4. What environment does a stdio server actually get?
The debugging guide warns that stdio servers **inherit only a limited subset of environment variables**. The Python SDK makes this concrete: it passes a small allowlist (`HOME`, `LOGNAME`, `PATH`, `SHELL`, `TERM`, `USER` on POSIX), merged with your `env`. A secret exported in your shell does **not** reach the server unless you put it in `env`.

```python
os.environ["MY_SHELL_SECRET"] = "only-in-the-host"
async with Client(params_for(cfg["mcpServers"]["notes"])) as c:
    seen = (await c.call_tool("visible_env", {})).structured_content["result"]
print("server sees:", seen)
print("MY_SHELL_SECRET visible?", "MY_SHELL_SECRET" in seen, "| NOTES_API_TOKEN visible?", "NOTES_API_TOKEN" in seen)
```

### 5. How approval works: a consent gate in the host
In Claude Desktop, *every* filesystem operation waits for your approval. The gate belongs to the **host**, not the protocol: before forwarding `tools/call`, the host asks the user. Here a scripted "user" approves reads and denies writes. A denied call never reaches the server.

```python
def ask_user(server: str, tool: str, args: dict) -> bool:
    decision = not tool.startswith("write")              # scripted user: allow reads, deny writes
    print(f"  [approval] {server}.{tool}({json.dumps(args)[:60]}) -> {'ALLOW' if decision else 'DENY'}")
    return decision


async def guarded_call(client: Client, server: str, tool: str, args: dict):
    if not ask_user(server, tool, args):
        return {"isError": True, "content": "The user declined this tool call."}
    r = await client.call_tool(tool, args)
    return {"isError": r.is_error, "content": r.structured_content or r.content[0].text}


async with Client(params_for(cfg["mcpServers"]["notes"])) as c:
    print(await guarded_call(c, "notes", "read_file", {"path": str(work / "Desktop" / "todo.md")}))
    print(await guarded_call(c, "notes", "write_file", {"path": str(work / "Desktop" / "poem.txt"), "text": "roses"}))
print("poem.txt exists?", (work / "Desktop" / "poem.txt").exists())
```

### 6. Troubleshooting: reproduce the classic failures
Each case below is a real-world mistake. Watch what the **host** sees (often just a closed connection) versus what the **server log** says. That gap is why the docs send you to `mcp-server-NAME.log` first.

```python
def root_cause(exc: BaseException) -> BaseException:
    while isinstance(exc, BaseExceptionGroup) and len(exc.exceptions) == 1:
        exc = exc.exceptions[0]
    return exc


good = cfg["mcpServers"]["notes"]
CASES = {
    "relative path": {**good, "args": [str(SERVER), "Desktop"]},
    "missing env var": {k: v for k, v in good.items() if k != "env"},
    "non-existent command": {**good, "command": "pyhton3"},
}
for label, entry in CASES.items():
    log_file = LOGS / f"case-{label.replace(' ', '-')}.log"
    t0 = time.time()
    try:
        with open(log_file, "w") as errlog:
            async with Client(stdio_client(params_for(entry), errlog=errlog)) as c:
                await c.list_tools()
        outcome = "connected?!"
    except BaseException as exc:
        cause = root_cause(exc)
        outcome = f"{type(cause).__name__}: {cause}"
    print(f"### {label}  ({time.time() - t0:.1f}s)\n  host sees : {outcome}")
    print(f"  server log: {log_file.read_text().strip() or '(empty: the process never started)'}\n")
```

The fixes match the docs' checklist: use **absolute paths** (the server resolved `Desktop` against the host's working directory), put required secrets in **`env`**, and make `command` something the host can find. Run it by hand first, or give an absolute path such as the output of `which uv`.

### 7. A "remote" server over Streamable HTTP, with a bearer token
Remote servers are reached by **URL** instead of a launch command. In Claude this is a Custom Connector, and the client completes authentication (usually OAuth) when you connect. Here a localhost server stands in for the internet. A small ASGI wrapper rejects any request without the right `Authorization` header with `401` and a `WWW-Authenticate` challenge, the way a protected MCP server signals that auth is needed (module 6 covers the real OAuth flow).

```python
import httpx2
import uvicorn
from mcp.client.streamable_http import streamable_http_client
from mcp.server import MCPServer

remote = MCPServer("tickets")


@remote.tool()
def open_tickets(team: str) -> list[str]:
    """Open tickets for a team."""
    return {"platform": ["PLAT-7 flaky deploy", "PLAT-9 disk alert"]}.get(team, [])


TOKEN = "demo-access-token"
requests_seen = []
mcp_app = remote.streamable_http_app()


async def protected(scope, receive, send):
    if scope["type"] == "http":
        headers = dict(scope["headers"])
        auth = headers.get(b"authorization", b"").decode()
        requests_seen.append((headers.get(b"mcp-method", b"-").decode(), "token" if auth else "no token"))
        if auth != f"Bearer {TOKEN}":
            await send({"type": "http.response.start", "status": 401,
                        "headers": [(b"content-type", b"application/json"),
                                    (b"www-authenticate", b'Bearer realm="tickets"')]})
            await send({"type": "http.response.body", "body": b'{"error": "invalid_token"}'})
            return
    await mcp_app(scope, receive, send)


sock = socket.socket()
sock.bind(("127.0.0.1", 0))
PORT = sock.getsockname()[1]
sock.close()
http_server = uvicorn.Server(uvicorn.Config(protected, host="127.0.0.1", port=PORT, log_level="warning"))
threading.Thread(target=http_server.run, daemon=True).start()
while not http_server.started:
    await asyncio.sleep(0.05)
URL = f"http://127.0.0.1:{PORT}/mcp"
print("remote server at", URL)
```

Connect by URL. To send a custom header, give `streamable_http_client` your own `httpx2.AsyncClient` (the SDK's HTTP library) and pass that transport to `Client`.

```python
async with httpx2.AsyncClient(headers={"Authorization": f"Bearer {TOKEN}"}, trust_env=False) as http:
    async with Client(streamable_http_client(URL, http_client=http)) as c:
        print("negotiated:", c.protocol_version)
        r = await c.call_tool("open_tickets", {"team": "platform"})
        print("open_tickets ->", r.structured_content)

try:
    async with Client(URL) as c:                       # no Authorization header
        await c.list_tools()
except BaseException as exc:
    print("\nwithout a token ->", type(root_cause(exc)).__name__, root_cause(exc))

async with httpx2.AsyncClient(trust_env=False) as raw:
    resp = await raw.post(URL, json={"jsonrpc": "2.0", "id": 1, "method": "server/discover", "params": {}},
                          headers={"Accept": "application/json, text/event-stream",
                                   "MCP-Protocol-Version": "2026-07-28", "Mcp-Method": "server/discover"})
print("raw HTTP:", resp.status_code, "| WWW-Authenticate:", resp.headers.get("www-authenticate"), "|", resp.text)
print("\nwhat the server saw (Mcp-Method, auth):", requests_seen)
```

The SDK reports the unauthenticated attempt only as a generic error. The **HTTP status and `WWW-Authenticate` header** are what tell you it is an auth problem, which is why a host's logs (or the Inspector) matter. The server log also shows the client probing `server/discover` and then retrying the legacy handshake (`-`, no `Mcp-Method`) before giving up.

### 8. One config, local and remote
Many tools reuse the `mcpServers` shape and add a remote entry type. The MCP Inspector's catalog, for example, accepts `"type": "http"` with a `url` and `headers`. Claude Desktop's own `claude_desktop_config.json` is documented for **local** launch entries; remote servers are added in Claude as **Custom Connectors** through Settings → Connectors. Below is one host function that connects either kind from such a catalog.

```python
catalog = {"mcpServers": {
    "notes": cfg["mcpServers"]["notes"],
    "tickets": {"type": "http", "url": URL, "headers": {"Authorization": f"Bearer {TOKEN}"}},
}}


async def open_entry(stack: AsyncExitStack, entry: dict) -> Client:
    if entry.get("type") == "http":
        http = await stack.enter_async_context(httpx2.AsyncClient(headers=entry.get("headers"), trust_env=False))
        return await stack.enter_async_context(Client(streamable_http_client(entry["url"], http_client=http)))
    return await stack.enter_async_context(Client(params_for(entry)))


async with AsyncExitStack() as stack:
    for name, entry in catalog["mcpServers"].items():
        c = await open_entry(stack, entry)
        kind = "remote (Streamable HTTP)" if entry.get("type") == "http" else "local (stdio)"

http_server.should_exit = True
```
