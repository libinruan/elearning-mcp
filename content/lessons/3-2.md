## Summary
Tools let the model act; **resources** let an application *read*. A resource is any piece of context — a file, a database schema, a calendar, an API response — identified by a URI and served by `resources/read` as text or base64 binary. Servers advertise fixed resources through `resources/list` and whole families of them through **resource templates** (`resources/templates/list`), parameterised URIs following RFC 6570 such as `weather://forecast/{city}/{date}`. This lesson covers the application-driven interaction model, the `resources` capability and its `subscribe`/`listChanged` flags, the data types, annotations that help a host pick context, standard URI schemes, the new `-32602` not-found rule, how change notifications now flow through `subscriptions/listen`, and the security duties around URIs and paths.

## Lesson
### Resources are application-driven
The spec's one-line definition: resources let servers share data that provides context to language models — files, database schemas, application-specific information — each uniquely identified by a **URI** (RFC 3986). The crucial difference from tools is the controller. Resources are **application-driven**: the *host* decides what to fetch and how to use it — show a picker, let the user search and filter, auto-include context by heuristics, or let the model choose. Having fetched it, the application might pass everything to the model, select a slice, or index it with embeddings first. The protocol mandates none of this UI.

| | Tools | Resources |
| --- | --- | --- |
| Controlled by | the model | the application (often on the user's selection) |
| Effect | may change the world | read-only context |
| Addressed by | `name` + arguments | `uri` |
| Typical UI | approval dialog | file tree, picker, "@-mention" |

Use a resource when the data is something a user or app would *attach* (a document, a schema, today's on-call rota); use a tool when the model must *decide* to fetch or compute something mid-reasoning.

### The `resources` capability
```json
{"capabilities": {"resources": {"listChanged": true, "subscribe": true}}}
```
Both flags are optional and independent:

- `listChanged` — the server emits `notifications/resources/list_changed` when the set of available resources changes.
- `subscribe` — the server supports **per-resource update notifications** for URIs requested via the `resourceSubscriptions` filter of `subscriptions/listen`.

A server supporting neither may declare `"resources": {}`. As with tools, `resources/list` returns the resources currently available to the requester; the set MAY be empty and MAY change, **MUST NOT** vary per connection or as a side effect of other requests, and MAY vary by the request's authorization.

### Protocol operations
| Method | Purpose | Paginated | Cacheable |
| --- | --- | --- | --- |
| `resources/list` | Fixed ("direct") resources | yes | yes |
| `resources/templates/list` | Parameterised resource templates | yes | yes |
| `resources/read` | Fetch contents of one URI | no | yes |
| `subscriptions/listen` | Stream of change notifications (lesson 3.4) | — | — |

A `resources/list` entry:

```json
{"uri": "file:///project/src/main.rs", "name": "main.rs",
 "title": "Rust Software Application Main File", "description": "Primary application entry point",
 "mimeType": "text/x-rust", "icons": [{"src": "https://example.com/rust-file-icon.png", "mimeType": "image/png", "sizes": ["48x48"]}]}
```

The `Resource` fields are `uri` and `name` (required), plus optional `title`, `description`, `icons`, `mimeType`, `annotations`, `size` (bytes — lets a host warn before stuffing a 40 MB log into a context window) and `_meta`.

Reading is a single request by URI:

```json
{"jsonrpc": "2.0", "id": 2, "method": "resources/read", "params": {"uri": "file:///project/src/main.rs"}}
```
```json
{"jsonrpc": "2.0", "id": 2, "result": {"resultType": "complete",
  "contents": [{"uri": "file:///project/src/main.rs", "mimeType": "text/x-rust",
                "text": "fn main() {\n    println!(\"Hello world!\");\n}"}],
  "ttlMs": 60000, "cacheScope": "private"}}
```

Note `contents` is an **array**: a server MAY return several items for one read — reading a directory resource can return the contents of several files. Like tools and prompts, `resources/read` MAY answer with an `InputRequiredResult` (multi round-trip, lesson 5.3), and the client retries with `inputResponses` and `requestState`. If the URI is `https://`, a client may simply fetch it from the web itself.

### Text versus binary contents
Each item in `contents` carries exactly one of:

```json
{"uri": "file:///example.txt", "mimeType": "text/plain", "text": "Resource content"}
{"uri": "file:///example.png", "mimeType": "image/png", "blob": "base64-encoded-data"}
```

`text` is for anything textual (source, Markdown, JSON); `blob` is base64 for everything else — images, PDFs, archives. The `mimeType` tells the host how to handle the bytes: render a PNG, hand a PDF to a parser, syntax-highlight `text/x-rust`. Binary data **MUST** be properly encoded.

### Resource templates (RFC 6570)
Many data sources are not a fixed list: "the forecast for *any* city and date", "*any* file under the project". Enumerating them is impossible, so servers publish **templates** instead:

```json
{"uriTemplate": "weather://forecast/{city}/{date}", "name": "weather-forecast",
 "title": "Weather Forecast", "description": "Get weather forecast for any city and date",
 "mimeType": "application/json"}
```

The client **expands** the template with values (`weather://forecast/barcelona/2026-08-01`) and calls ordinary `resources/read`; the server **matches** the URI back to the template and extracts the variables. RFC 6570 supports more than simple `{var}`: `{+path}` (reserved expansion, so slashes survive — good for file paths), `{?q,lang}` (query parameters), and so on. Template arguments can be **auto-completed** via `completion/complete` with a `ref/resource` reference (lesson 3.3) — type "Par" and get "Paris", "Park City". `ResourceTemplate` fields: `uriTemplate`, `name`, optional `title`, `description`, `mimeType` (of every matching resource), `icons`, `annotations`, `_meta`.

The docs call fixed URIs **direct resources** (`calendar://events/2024`) and parameterised ones **resource templates** (`travel://activities/{city}/{category}`).

### Resources inside tool results and prompts
Resources also travel *inside* other primitives. A tool result or prompt message can carry a `resource_link` content block (`uri`, `name`, `mimeType`) — a pointer the client may fetch with `resources/read` or watch for changes — or an **embedded** `resource` block that inlines the same `text`/`blob` contents shape shown above. A link keeps a large result out of the model's context until someone decides it is needed; embedding saves a round trip when the content is small and certainly relevant. Links returned by tools are not guaranteed to appear in `resources/list`, and a server that embeds resources SHOULD declare the `resources` capability so clients can read them again later.

### Annotations: hints for choosing context
Resources, templates and content blocks support optional annotations:

| Annotation | Values | Use |
| --- | --- | --- |
| `audience` | array of `"user"`, `"assistant"` | who the data is for — show it, feed it to the model, or both |
| `priority` | 0.0 – 1.0 | 1 = effectively required, 0 = entirely optional |
| `lastModified` | ISO 8601, e.g. `"2025-01-12T15:00:58Z"` | display recency, sort, detect staleness |

A host with a limited context budget can filter by audience, include resources in priority order until the budget is spent, and show "edited 3 hours ago" in its picker. These are hints, not guarantees.

### Common URI schemes
The spec names a few, non-exhaustively:

- **`https://`** — a resource on the web. Servers **SHOULD** use it only when the client can fetch it directly *without* the server; otherwise prefer another or a custom scheme, even if the server itself downloads from the internet.
- **`file://`** — resources that *behave like* a filesystem; they need not map to a physical one. Non-regular files such as directories MAY use an XDG MIME type like `inode/directory`.
- **`git://`** — Git version control integration.
- **Custom schemes** (`weather://`, `calendar://`, `db://`) are fine but **MUST** conform to RFC 3986.

### Errors: not found is now `-32602`
If the requested resource does not exist, servers **MUST** return JSON-RPC error **`-32602` (Invalid Params)**; internal failures SHOULD be `-32603`.

```json
{"jsonrpc": "2.0", "id": 5, "error": {"code": -32602, "message": "Resource not found", "data": {"uri": "file:///nonexistent.txt"}}}
```

> **Changed in 2026-07-28.** Earlier revisions used `-32002` for "resource not found". It moved to `-32602` to align with JSON-RPC. For backwards compatibility clients **SHOULD** also accept `-32002` as not-found — you will still meet it in older servers.

> **Spec rule.** Servers **MUST NOT** return an empty `contents` array for a non-existent resource. An empty array is ambiguous: it could mean "exists but is empty" or "does not exist".

### Change notifications and subscriptions
Two kinds of change matter:

1. **The list changed** (a file was added): servers with `listChanged` SHOULD send `notifications/resources/list_changed`; the client re-lists.
2. **A specific resource's content changed**: the client asks to watch URIs by sending `subscriptions/listen` with them in `notifications.resourceSubscriptions`; the server delivers `notifications/resources/updated` on that stream whenever one changes, then the client re-reads.

```json
{"jsonrpc": "2.0", "method": "notifications/resources/updated",
 "params": {"_meta": {"io.modelcontextprotocol/subscriptionId": 4}, "uri": "file:///project/src/main.rs"}}
```

The notification carries only the URI — never the content — and the URI may be a *sub-resource* of the one subscribed to.

> **Changed in 2026-07-28.** The old `resources/subscribe` and `resources/unsubscribe` RPCs and the standalone HTTP GET stream were replaced by one mechanism, `subscriptions/listen`, with an explicit opt-in filter, acknowledgment and `subscriptionId` tagging. Lesson 3.4 covers it in full.

### Security considerations
1. Servers **MUST** validate all resource URIs.
2. Access controls **SHOULD** be implemented for sensitive resources, and permissions **SHOULD** be checked before operations.
3. Binary data **MUST** be properly encoded.
4. Servers **MUST** sanitise file paths to prevent **directory traversal** when serving `file://` resources — `file:///project/../../etc/passwd` must not escape the root.

Remember also that resource content flows into a model's context: a document can carry a prompt-injection payload. Treat resource text as untrusted data (module 6).

## Key points
- Resources are **application-driven** read-only context, each identified by a **URI**; the host decides what to fetch and how to use it.
- Capability `resources` with independent optional flags `listChanged` and `subscribe`; lists MUST NOT vary per connection but MAY vary by authorization.
- Operations: `resources/list`, `resources/templates/list` (both paginated, cacheable), `resources/read` (cacheable, may return several contents or `input_required`).
- Contents are either `text` or base64 `blob`, each with `uri` and `mimeType`; `Resource` may also declare `size` in bytes.
- **Templates** use RFC 6570 (`{city}`, `{+path}`, `{?q}`); clients expand, servers match; arguments can be auto-completed.
- Annotations `audience`, `priority` (0–1) and `lastModified` (ISO 8601) help hosts select and display context.
- Not found → **`-32602`** (was `-32002`; clients SHOULD accept both); never answer with an empty `contents` array.
- Per-resource updates now arrive as `notifications/resources/updated` on a **`subscriptions/listen`** stream (`resources/subscribe` is gone).
- Servers MUST validate URIs and sanitise `file://` paths against directory traversal; resource content is untrusted input for the model.

## Pitches
### What is an MCP resource and how is it different from a tool?
A resource is read-only context the server exposes under a URI — a file, a schema, a calendar. The application decides when to read it, usually because the user picked it or a heuristic says it's relevant, and then chooses how much to give the model. A tool is the opposite: the model decides to call it and it may change things. So I expose a document or a database schema as a resource, and searching, writing or anything with side effects as a tool.

### What are resource templates for?
Templates are for data you can't enumerate. Instead of listing every forecast or every file, the server publishes a pattern like weather colon slash slash forecast, city, date, following RFC 6570. The client fills in the variables — with completion helping the user pick valid values — and does an ordinary resources/read on the expanded URI. The server matches it back and extracts the parameters. It keeps discovery small and self-documenting while still giving access to a huge space of resources.

### How does a client learn that a resource changed in 2026-07-28?
It opens a subscriptions/listen request and puts the URIs it cares about in the resourceSubscriptions filter. The server acknowledges which parts of the filter it honours, then sends notifications/resources/updated on that stream, tagged with the subscription id, whenever one changes. The notification only names the URI, so the client re-reads the resource. This replaced the old resources/subscribe RPC and the HTTP GET stream with one mechanism that works the same over stdio and HTTP.

## Interview
### A client reads a URI that doesn't exist. What should the server return?
A JSON-RPC error with code **`-32602` (Invalid Params)**, ideally with the URI in `data` — for example `{"code": -32602, "message": "Resource not found", "data": {"uri": "..."}}`. Internal failures while reading should be `-32603`. The server **MUST NOT** return an empty `contents` array, because that is indistinguishable from an existing empty resource. Bonus points: earlier protocol versions used `-32002`, so a robust client treats both codes as not-found.

### When would you return `blob` instead of `text`, and what does `mimeType` do?
`text` for anything textual — source, Markdown, JSON, CSV; `blob` (base64) for binary such as PNGs, PDFs or archives, which would be corrupted as text. `mimeType` tells the host how to treat the bytes: render an image, run a PDF extractor, highlight code, or decide the item isn't model-readable at all. Binary data MUST be properly encoded; declaring `size` on the listing lets a host avoid fetching something too large for its context budget.

### Design the resources for a "project files" server.
Expose a template like `file:///{+path}` (reserved expansion keeps slashes) or a custom `project://{+path}`, plus a few direct resources for key files (`README.md`, a schema). Set accurate `mimeType`s, `size`, and `lastModified` annotations; mark generated or huge files with low `priority`. Return a directory's children as multiple `contents` or an `inode/directory` item. Normalise and confine every path to the project root to block directory traversal, apply access checks, declare `subscribe` and emit `notifications/resources/updated` when files change, and support completion for the `path` argument.

### Can `resources/list` return different resources to different users?
Yes, but only by **authorization**: the set MAY vary by the credentials on the request, e.g. only the documents the token can access. It MUST NOT vary per connection or because of earlier requests — there are no sessions in 2026-07-28, so any instance must give the same answer to the same request. If the list is per-user, mark the result `cacheScope: "private"` so shared caches don't leak it across users.

### Gotcha: a client subscribed to `file:///repo/` receives an update for `file:///repo/src/a.py`. Bug?
No. The schema says the URI in `notifications/resources/updated` "might be a sub-resource of the one that the client actually subscribed to" — subscribing to a directory-like resource can legitimately produce updates for things beneath it. A client should match updates hierarchically (not only by exact string), invalidate any cached `resources/read` for the affected URI, and re-read it. Remember the notification carries no content, and the stream it arrived on is identified by the `subscriptionId` in `_meta`, which tells the client which of its subscriptions asked for it.

## Glossary
- Resource | 资源 | Read-only context data exposed by a server and identified by a URI.
- URI | 统一资源标识符 | The RFC 3986 identifier that names a resource, e.g. `file:///project/README.md`.
- Direct resource | 直接资源 | A resource with a fixed URI listed by `resources/list`.
- Resource template | 资源模板 | An RFC 6570 URI template advertising a parameterised family of resources.
- RFC 6570 | URI 模板规范（RFC 6570） | The standard defining URI template syntax and expansion, e.g. `{var}`, `{+path}`, `{?q}`.
- MIME type | MIME 类型（媒体类型） | A label such as `image/png` that tells the client how to interpret contents.
- Blob | 二进制内容（base64） | Base64-encoded binary resource contents.
- Annotations | 注解 | Hints (`audience`, `priority`, `lastModified`) that help clients choose and display content.
- Directory traversal | 目录穿越 | An attack using `..` or absolute paths to escape an allowed directory.
- `notifications/resources/updated` | 资源更新通知 | Notification on a `subscriptions/listen` stream saying a watched resource changed.

### 1. A server with direct resources and templates
`MCPServer` decides by the URI: no `{...}` means a direct resource (in `resources/list`), any variable makes it a template (in `resources/templates/list`). Returning `str` gives `text`, returning `bytes` gives a base64 `blob`. We also register a real file with `FileResource` under a `file://` URI.

```python
import base64
import json
import logging
import struct
import tempfile
import zlib
from pathlib import Path

import mcp_types as types
from mcp import Client
from mcp.server import MCPServer
from mcp.server.mcpserver.resources.types import FileResource
from mcp.shared.exceptions import MCPError

logging.getLogger("mcp").setLevel(logging.CRITICAL)


def show(model, limit=1500):
    data = model.model_dump(by_alias=True, exclude_none=True, mode="json")
    data.pop("_meta", None)
    print(json.dumps(data, indent=2, ensure_ascii=False)[:limit])


def tiny_png() -> bytes:
    chunk = lambda kind, body: (struct.pack(">I", len(body)) + kind + body
                                + struct.pack(">I", zlib.crc32(kind + body) & 0xFFFFFFFF))
    return (b"\x89PNG\r\n\x1a\n" + chunk(b"IHDR", struct.pack(">IIBBBBB", 1, 1, 8, 2, 0, 0, 0))
            + chunk(b"IDAT", zlib.compress(b"\x00\xff\x00\x00")) + chunk(b"IEND", b""))


project = Path(tempfile.mkdtemp())
(project / "README.md").write_text("# Trip planner\nPlan trips with MCP.\n")

server = MCPServer("travel-data")
server.add_resource(FileResource(uri=(project / "README.md").as_uri(), path=project / "README.md",
                                 name="README.md", title="Project README", mime_type="text/markdown"))


@server.resource("calendar://events/2026", title="2026 calendar", mime_type="application/json",
                 annotations=types.Annotations(audience=["assistant"], priority=0.9,
                                               last_modified="2026-07-28T09:00:00Z"))
def calendar() -> str:
    return json.dumps({"busy": ["2026-08-03", "2026-08-04"]})


@server.resource("travel://preferences", title="Travel preferences",
                 annotations=types.Annotations(audience=["user", "assistant"], priority=0.6))
def preferences() -> str:
    return "Window seat. Prefers boutique hotels. Vegetarian."


@server.resource("images://logo.png", title="Company logo", mime_type="image/png",
                 annotations=types.Annotations(audience=["user"], priority=0.1))
def logo() -> bytes:
    return tiny_png()


@server.resource("weather://forecast/{city}/{date}", title="Weather Forecast", mime_type="application/json",
                 description="Get weather forecast for any city and date")
def forecast(city: str, date: str) -> str:
    return json.dumps({"city": city, "date": date, "high_c": 29, "conditions": "sunny"})


@server.resource("travel://activities/{city}/{category}", title="Activities", mime_type="application/json")
def activities(city: str, category: str) -> str:
    catalogue = {"museums": ["Picasso Museum", "MNAC"], "beaches": ["Barceloneta", "Bogatell"]}
    return json.dumps({"city": city, "category": category, "items": catalogue.get(category, [])})


DOCS = {"guides/packing.md": "Bring an adapter.", "guides/visas.md": "Check visa rules early."}


@server.resource("docs://{+path}", title="Travel guides", mime_type="text/markdown")
def docs(path: str) -> str:
    return DOCS[path]


print("defined:", server.name)
```

### 3. Read text, binary and templated resources
Templates are expanded **client-side** with RFC 6570 rules (here with the SDK's `UriTemplate`; note the percent-encoding of the space and `ã`), then read with ordinary `resources/read`.

```python
from mcp.shared.uri_template import UriTemplate

async with Client(server) as client:
    show(await client.read_resource("calendar://events/2026"))

    blob = (await client.read_resource("images://logo.png")).contents[0]
    raw = base64.b64decode(blob.blob)
    png_ok = raw.startswith(bytes([0x89]) + b"PNG")
    print(f"\nblob: mimeType={blob.mime_type}, {len(raw)} bytes after base64 decoding, PNG signature ok: {png_ok}")

    uri = UriTemplate.parse("weather://forecast/{city}/{date}").expand({"city": "São Paulo", "date": "2026-08-01"})
    print("\nexpanded:", uri)
    print("contents:", (await client.read_resource(uri)).contents[0].text)

    uri = UriTemplate.parse("docs://{+path}").expand({"path": "guides/packing.md"})
    print("reserved expansion keeps slashes:", uri, "->", (await client.read_resource(uri)).contents[0].text)
```

### 4. Not found is `-32602` — and never an empty array
Read a URI that matches nothing and one where the template matches but the data is missing. Then see the same error as raw JSON on the wire, via a stdio subprocess.

```python
async with Client(server) as client:
    for uri in ["calendar://events/1999", "docs://guides/nonexistent.md"]:
        try:
            await client.read_resource(uri)
        except MCPError as err:
            print(f"{uri:<32} -> code={err.code} message={err.message!r} data={err.data}")
```

The second case shows an SDK detail: a template handler that raises (here a `KeyError`) becomes `-32603` *internal error*, not not-found. To follow the spec, raise the SDK's `ResourceNotFoundError` from the handler:

```python
from mcp.server.mcpserver.exceptions import ResourceNotFoundError


@server.resource("guides://{+path}", mime_type="text/markdown")
def guides(path: str) -> str:
    if path not in DOCS:
        raise ResourceNotFoundError(f"Resource not found: guides://{path}")
    return DOCS[path]


async with Client(server) as client:
    try:
        await client.read_resource("guides://nope.md")
    except MCPError as err:
        print("fixed:", err.code, err.message, err.data)


def is_not_found(err: MCPError) -> bool:
    """Client-side: accept the 2026-07-28 code and the legacy one."""
    return err.code in (-32602, -32002)


print("treat as not found:", is_not_found(MCPError(-32002, "Resource not found")))
```

### 5. Break it: directory traversal
The spec says servers MUST sanitise paths. The SDK's templates reject `..` components and absolute paths in extracted parameters by default (`ResourceSecurity`), so the request never reaches our handler.

```python
async with Client(server) as client:
    for uri in ["docs://guides/visas.md", "docs://../../etc/passwd", "docs:///etc/passwd", "docs://guides/%2e%2e/%2e%2e/secret"]:
        try:
            text = (await client.read_resource(uri)).contents[0].text
            print(f"{uri:<38} OK   {text}")
        except MCPError as err:
            print(f"{uri:<38} {err.code} {err.message}")
```

If you build paths yourself (a custom low-level handler, a `FileResource` factory), do the same check: resolve the path and verify it is still inside the root.

```python
def safe_join(root: Path, relative: str) -> Path:
    candidate = (root / relative).resolve()
    if not candidate.is_relative_to(root.resolve()):
        raise PermissionError(f"path escapes root: {relative}")
    return candidate


for rel in ["README.md", "../../etc/passwd"]:
    try:
        print(rel, "->", safe_join(project, rel))
    except PermissionError as exc:
        print(rel, "->", exc)
```

### 6. A host that picks context with annotations
Resources are application-driven: the host chooses. This tiny selector keeps only items meant for the assistant, orders by priority, and stops at a character budget.

```python
async def select_context(client, budget_chars=120):
    resources = (await client.list_resources()).resources
    for_model = [r for r in resources
                 if not r.annotations or not r.annotations.audience or "assistant" in r.annotations.audience]
    ranked = sorted(for_model, key=lambda r: (r.annotations.priority if r.annotations and r.annotations.priority is not None else 0.5),
                    reverse=True)
    chosen, used = [], 0
    for r in ranked:
        item = (await client.read_resource(str(r.uri))).contents[0]
        text = getattr(item, "text", None)
        if text is None or used + len(text) > budget_chars:
            print(f"skip   {r.uri} ({'binary' if text is None else 'over budget'})")
            continue
        chosen.append((str(r.uri), text))
        used += len(text)
        print(f"attach {r.uri} ({len(text)} chars)")
    return chosen


async with Client(server) as client:
    context = await select_context(client)
print("\nprompt context:\n" + "\n".join(f"<resource uri='{u}'>{t.strip()}</resource>" for u, t in context))
```

The logo (`audience: ["user"]`) is never considered for the model, the calendar (priority 0.9) goes first.

### 7. Preview: watching a resource for changes
In 2026-07-28 a client watches URIs with `subscriptions/listen` (lesson 3.4 has the details). A tool changes the calendar and publishes `notifications/resources/updated`; the notification names only the URI, so the client re-reads.

```python
from mcp.server.mcpserver import Context

busy_days = ["2026-08-03", "2026-08-04"]


@server.resource("calendar://busy", mime_type="application/json")
def busy() -> str:
    return json.dumps(busy_days)


@server.tool()
async def block_day(day: str, ctx: Context) -> str:
    """Mark a day as busy in the calendar."""
    busy_days.append(day)
    await ctx.notify_resource_updated("calendar://busy")
    return f"blocked {day}"


async with Client(server) as client:
    print("before:", (await client.read_resource("calendar://busy")).contents[0].text)
    async with client.listen(resource_subscriptions=["calendar://busy"]) as sub:
        await client.call_tool("block_day", {"day": "2026-08-10"})
        event = await anext(sub)
        print("event:", event)
        print("after: ", (await client.read_resource(event.uri)).contents[0].text)
```
